# 护甲详情冻结规格

## 目的

本规格冻结 `统一护甲详情原型.html` 的信息架构和交互边界。正式实现必须进入 `packages/ui`，Prototype、Web 和 Desktop 共用同一护甲详情组件；静态 HTML 只作为视觉与行为基准。

## 页面骨架

- 护甲详情与武器详情共用“档案工具栏、身份区、章节导航、连续正文、右侧实例操作栏”的页面骨架。
- 正文固定为五章：属性与获取、护甲配置、目标匹配、升级状态、AI 分析。
- 章节导航只滚动定位，不使用互斥 Tab 隐藏正文内容。
- 宽度大于 `1360px` 时显示 `330px` 右侧实例栏；不大于 `1360px` 时改为带遮罩、标题和关闭按钮的右侧抽屉，支持 `Escape` 关闭。
- 档案正文和实例抽屉只允许纵向滚动；章节导航、对象摘要、目标来源和数据表格必须换行或重排，不得出现水平滚动条。

## 数据语义

- 资料库定义、商人 Offer 和账号实例是三种不同当前对象，不能互相补造数据。
- 属性只显示基础值和当前实际值，同时显示基础总属性、当前总属性和升级状态。
- 资料库定义没有固定 Roll 时显示明确空状态，不模拟六维属性。
- 当前实际值只包含能确认归属于单件护甲的强化和已安装模组影响；不展示目标值、最高属性或星象等角色级加成。
- 获取来源只使用当前 Manifest 和实时 Vendor 数据；实时读取失败时不回退显示旧 Offer。

## 护甲配置

- 当前 Armor 3.0 护甲按五个玩家可配置模组位展示：一个通用或活动模组位、三个部位模组位、一个护甲等级 5 解锁的调整模组位。
- 原型中的“移民号陨落腿铠”使用当前版本 `hash=1452324269`。该定义有 12 个原始 Socket，但玩家配置区只显示其中 5 个模组位。
- 原始 Socket 中的护甲升级、护甲定位、随机属性内部数据、着色器和外观不计入模组数量，并分别进入升级、能力、属性或隐藏区域。
- 特殊活动护甲可以用活动专属模组类别替换通用模组类别；页面必须根据当前装备版本分类，不能按固定原始索引或旧版本 Hash 复制。
- 传说套装护甲显示套装规则、当前兼容角色已装备件数、激活档位、真实插槽和已安装模组。
- 异域护甲显示异域固有能力、异域限制、真实插槽和已安装模组。
- 其他护甲能力按实际定义显示，例如诡计护甲、特殊规则或特殊插槽。
- 不显示系统生成的推荐模组，不把定义支持的模组冒充为当前已安装模组。
- 玩家界面不显示 `Manifest`、`Profile`、`Vendor API` 或内部 Socket 分类名称；统一使用“游戏资料”“账号最新状态”“商人实时数据”等玩家可理解文案。

## 目标匹配

- 使用个人目标、配装与攻略、社区来源三个独立数据源 Tab。
- 每条来源只显示条件、当前事实和匹配结果，不合并排序，不生成购买、保留或升级结论。
- DIM Wishlist、社区记录和个人知识可以作为可追溯数据源，但必须保留原始来源身份。

## 实例与操作

- 始终列出账号中当前版本、当前 Hash 且职业兼容的实例。
- 实例卡显示总属性、六维数字、位置、升级状态、锁定状态、标签和特殊插槽。
- 护甲只能装备或转移到兼容职业；不提供游戏 API 不支持的拆解操作。
- 当前实例支持装备、转移、锁定或解锁、本地标签、备注、复制摘要和加入配装草稿。
- 切换顶部当前对象或护甲类型时关闭响应式抽屉，避免旧操作上下文覆盖新对象。

## AI 分析

- 主观解释只出现在 AI 分析章；前四章保持事实和条件匹配。
- AI 可以结合 Manifest、Vendor、Profile、个人目标、配装攻略和社区来源。
- 外部查询必须由用户选择，并保留引用；AI 结果不会自动写入可靠数据区。
- 保存个人知识前必须由用户明确确认。
