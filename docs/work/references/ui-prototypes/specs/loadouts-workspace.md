# 配装功能契约

稳定契约标识：`loadouts.workspace`。

## 对象边界

- Bungie 游戏内配装是主对象：只显示官方返回的名称、图标、角色、槽位和装备实例，不显示颜色或未返回的完整配置。
- 本地配装方案是独立辅助对象：按职业绑定，应用清单只包含三把武器与五件护甲（动能、能量、威能、头盔、臂铠、胸甲、腿甲、职业物品）；不能与游戏内配装混称或自动同步。
- 机灵、载具、飞船、公会战旗、徽标、终结技和动作不是配装应用对象，不得进入装备计数、缺失分析或执行计划。
- 本地方案可独立记录职业分支、星象、碎片和技能。它们不属于武器 / 护甲切换清单；只有保存了职业分支实例、`socket_index`、`plug_hash`，并由当前实例的 `reusable_plugs` 验证可用时，才可以进入 `InsertSocketPlug` 执行步骤。其余配置必须显示为“仅记录”或“不可用”，不得伪造切换成功。
- 游戏内配装支持直接应用，以及把当前角色状态保存到用户选择的槽位；不伪造重命名和删除能力。
- 本地配装方案支持新建、重命名、删除、显式保存和批量应用；保存方案不触发 Bungie 写操作。
- 本地配装方案可从 DIM 配装分享链接（`dim.gg/...`）单向导入，不依赖 AI。必须先读取并展示结构化装备 / 明确 Perk 预览，用户确认后才写入本机；链接读取失败、格式不支持或字段不足时不得创建半成品方案。
- 普通文字、网页、视频和图片的攻略导入必须有已配置 AI；DIM Wishlist 是 Roll 规则，不属于配装导入。
- 主列表只显示有内容的游戏内槽位；空槽只在“保存当前配装”的选择器中出现。

## 装备定位

每个游戏内配装装备显示名称、槽位、账号位置和是否已定位。定位使用实例 ID；找不到实例时不得用同名物品替代。应用游戏内配装直接调用 Bungie，由 Bungie 决定最终结果。

本地方案条目保存指定实例；候选仅用于编辑时选择。应用本地方案前必须展示完整执行计划：武器 / 护甲可使用现有批量 `EquipItems` 能力，已验证的职业分支 socket / Plug 可使用 `InsertSocketPlug`，其余构筑配置只保留记录。失败时停止后续步骤并刷新真实账号状态。

## 状态

没有本地方案或有效游戏内栏位时显示明确空状态。部分缺失时继续展示已定位条目；操作禁用原因紧邻按钮，进行中保留原位置直到 API 成功。

## 视觉骨架与语义

页面排版已由 `loadouts-visual-contract.md` 冻结为“角色上下文 + 配装类型 Tab + 状态带 + 目录 / 详情 / 摘要工作区”。角色切换是 `ContextSwitcher`，以 `aria-pressed` 表达当前角色；游戏内配装与本地方案是完整 `tablist` / `tab` / `tabpanel`，必须有 `aria-controls` 并支持左右、Home、End 键。

目录、装备定位条目和核对摘要都是连续数据行，使用 `RowLine`，不能退化成圆角卡片。目录当前项、已定位、缺失和进行中状态必须分别使用 `aria-pressed` 或 `data-status`，不以局部 class 或颜色单独传达。
