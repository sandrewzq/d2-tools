# 配装功能契约

稳定契约标识：`loadouts.workspace`。

## 对象边界

- Bungie 游戏内配装是主对象：只显示官方返回的名称、图标、角色、槽位和装备实例，不显示颜色或未返回的完整配置。
- 本地配装方案是独立辅助对象：按职业绑定，可保存装备条件、目标 Perk、指定实例和未拥有条目；不能与游戏内配装混称或自动同步。
- 游戏内配装支持直接应用，以及把当前角色状态保存到用户选择的槽位；不伪造重命名和删除能力。
- 本地配装方案支持新建、重命名、删除、显式保存和批量应用；保存方案不触发 Bungie 写操作。
- 本地配装方案可从 DIM 配装分享链接（`dim.gg/...`）单向导入，不依赖 AI。必须先读取并展示结构化装备 / 明确 Perk 预览，用户确认后才写入本机；链接读取失败、格式不支持或字段不足时不得创建半成品方案。
- 普通文字、网页、视频和图片的攻略导入必须有已配置 AI；DIM Wishlist 是 Roll 规则，不属于配装导入。
- 主列表只显示有内容的游戏内槽位；空槽只在“保存当前配装”的选择器中出现。

## 装备定位

每个游戏内配装装备显示名称、槽位、账号位置和是否已定位。定位使用实例 ID；找不到实例时不得用同名物品替代。应用游戏内配装直接调用 Bungie，由 Bungie 决定最终结果。

本地方案条目保存指定实例；候选仅用于编辑时选择。应用本地方案前必须展示完整执行计划，一次确认后才转移、装备和切换目标 Perk；失败时停止后续步骤并刷新真实账号状态。

## 状态

没有本地方案或有效游戏内栏位时显示明确空状态。部分缺失时继续展示已定位条目；操作禁用原因紧邻按钮，进行中保留原位置直到 API 成功。

具体页面排版尚未冻结。不得把本规格当作三栏或其他固定布局的依据；新原型确认前，只能按上述对象、数据和操作边界实施。
