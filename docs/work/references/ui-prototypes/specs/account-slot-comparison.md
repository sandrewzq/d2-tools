# 账号装备位置对照契约

## 目标

账号页必须按装备类型和位置组织当前角色装备与背包候选，不能把所有已装备物品和所有背包物品拍平成两个长列表。

稳定契约标识：`account.slot-comparison`。

## 分类与顺序

分类顺序与当前应用工作区保持一致：

1. 武器
2. 护甲
3. 装备
4. 其他

已知位置按以下顺序排列：

1. 动能武器
2. 能量武器
3. 威能武器
4. 头盔
5. 臂铠
6. 胸甲
7. 腿甲
8. 职业物品
9. 职业分支
10. 机灵
11. 飞船
12. 载具
13. 徽标
14. 公会战旗
15. 终结技
16. 动作

其他无法识别的位置继续按账号工作区规则归入记忆水晶、任务与追踪、材料与货币、消耗品、模组与外观、收藏与纪念或未识别物品。

## 位置对照行

每个位置必须包含：

- 位置名称。
- 当前装备数量。
- 当前角色背包候选数量。
- 当前装备列。
- 背包候选列。
- 每件物品的图标、名称、光等、类型和可用的 Roll / 属性摘要。
- 方案命中、写操作处理中等已有状态。
- 打开统一装备详情的入口。

背包候选允许默认只展示固定数量，但必须显示总数、剩余数量和“显示全部”操作，不能静默丢弃。

## 数据来源

- 当前装备和背包：当前 Profile 快照。
- 分类与位置：Manifest bucket 定义和账号工作区的稳定映射。
- Roll、属性、方案命中和写操作状态：当前实例 ViewModel。

不得通过装备名称猜测位置；不得把仓库物品混入当前角色背包候选。

## 状态

| 状态 | 行为 |
|---|---|
| 正常 | 按分类和位置显示全部对照行 |
| 位置为空 | 保留位置标题，在对应列显示“暂无” |
| 背包候选较多 | 显示预览数量和“显示全部” |
| 写操作中 | 只标记目标物品，不锁住其他位置 |
| 账号刷新中 | 保留位置结构，分别显示骨架 |
| 读取失败 | 不把旧角色装备冒充为当前快照 |

## 还原映射

- 原型：`[data-contract-id="account.slot-comparison"]`
- 共享 UI：`AccountSlotComparison`
- 工作区：`slotComparisonRows`
- 行字段：`label`、`category`、`equippedItems`、`inventoryItems`

正式还原时必须复用当前完整位置对照组件。禁止通过 `flatMap` 生成独立的“当前装备”和“角色背包”长列表，也不得创建只在某个视觉变体中使用的简化 DOM。
