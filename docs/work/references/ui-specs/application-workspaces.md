# 应用工作区合同

> 本文件合并共享 Shell、设置、首页、账号、资料库、仓库和商人的结构、真实数据与状态边界。视觉细节统一遵守 [全局视觉合同](global-visual-contract.md)。

## 共享 Shell

稳定契约：`shell.topbar`、`shell.status-strip`、`shell.sidebar`、`shell.page-header`、`shell.page-content`、`shell.assistant`。

| 区域 | 真实绑定 | 约束 |
|---|---|---|
| 顶部栏 | 品牌、主题、GitHub、设置、AI、窗口控制 | 单一连续 Shell chrome；无平台窗口能力时只隐藏窗口控制 |
| 状态组 | `ShellStatusItem[]` 与对应 action | 状态项组成连续边界；状态 key 负责逻辑，label 只负责文案，不使用独立胶囊卡片 |
| 侧栏 | 当前账号摘要、主导航、底部动作 | 一级导航使用稳定图标和 `aria-current`；窄栏保留可访问名称 |
| 页面标题 | `ProductShellHost` 页面元数据与真实页面 action | 内容页不得复制第二个页头 |
| 主内容 | 当前菜单共享页面 | 普通页面唯一纵向滚动所有者，不建立同轴嵌套滚动 |
| AI 助手 | 会话、上下文、任务与真实 action | 宽屏停靠，`980px` 及以下转 Drawer；对话和任务使用完整 Tab 语义 |

Shell、页头、页面 gutter、首层分栏和全局 token 由共享层持有；菜单 CSS 不得覆盖 `.shell-*` 或无菜单前缀的工作区规则。

页面动作权重由当前页面职责、人工使用频率、自动刷新覆盖和阻断状态共同决定，不按“刷新”文案统一映射颜色：

| 页面与状态 | 主操作 | 次操作 |
|---|---|---|
| 账号正常 | 页头 `刷新账号`；承担账号页核心数据更新 | 页头 `重新授权`；低频身份维护 |
| 账号无数据 | 内容空态中的授权或刷新入口；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 仓库正常 | 页头 `刷新账号装备`；同步当前工作区 | — |
| 仓库无数据 | 内容空态中的 `刷新账号`；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 首页正常 | — | `刷新公开情报`；启动、重置边界和失败重试已有自动机制 |
| 首页读取失败 | 错误 Callout 内的 `重新读取公开情报` | 页头不重复显示同一刷新动作 |
| 商人正常 | — | `刷新商人库存`；进入页面和仄边界已有自动刷新 |
| 商人后台同步 | — | 页头刷新保持可点击；后台读取状态只在商人状态区反馈 |
| 商人读取失败且仍有缓存 | 页头 `刷新商人库存` 临时升权 | — |
| 商人完全无数据 | 内容空态中的 `重新加载商人库存` | 页头不重复显示同一操作 |
| 商人无账号 | — | 页头不显示无法执行的刷新动作，先通过账号入口完成读取 |
| 设置账号分区 | `刷新账号`；该行的主要数据操作 | `重新授权`；低频维护入口 |

同一业务动作可以因页面职责不同使用不同权重。每个页面或局部失败状态最多突出一个主操作；空态或错误区已持有主恢复入口时，页头不得重复同一操作。进行中保持原标签和稳定宽度，通过 `aria-busy`、禁用状态和邻近反馈表达进度。

商人刷新必须区分后台同步和手动请求：进入页面、详情补全和仄边界更新属于后台同步，不得禁用页头刷新；只有用户已经发起的手动刷新可以临时禁用该按钮。手动请求使用后发请求优先的现有序号机制接管后台请求。

## 设置

稳定契约：`settings.workspace`。

固定八个分区：概览、语言与外观、账号、资料库、Bungie 接口、AI 助手、数据备份与迁移、诊断与操作日志。不得为了视觉简化删除已有设置。

| 区域 | 真实字段与 action | 状态边界 |
|---|---|---|
| 概览与更新 | `appUpdateSnapshot`、账号/资料库/Bungie/AI/后台任务摘要、检查/下载/安装/诊断 | 未检查保持中性；只有发现版本后允许下载，下载完成后允许安装 |
| 语言与外观 | `languagePreferences`、`colorMode`、`density` | 界面语言与资料库语言分开建模；跟随开启时禁用独立资料库语言 |
| 账号 | `accountSummary`、读取状态、刷新时间、写操作开关 | 加载中禁用刷新；未授权保留重新授权入口 |
| 资料库 | Manifest 状态、检查、更新、修复 | 失败时保留上一份可用资料；进行中禁用冲突操作 |
| Bungie | API Key、Client ID、Client Secret、回调地址和数据目录 | 密钥只掩码展示，不进入仓库示例或诊断快照；保存失败保留用户输入 |
| AI | 协议、Key、Base URL、模型、light.gg 能力 | 无配置、加载、测试中、失败和不支持能力分别呈现 |
| 备份与迁移 | 创建/恢复备份、清缓存、迁移说明、打开目录 | 调用真实平台能力，不伪造完成结果 |
| 诊断与日志 | `backgroundTasks`、`actionLog`、筛选、刷新、复制诊断 | 空日志保留筛选和诊断入口；失败项提供脱敏诊断 |

布局合同：

- `>1280px` 目录 `240px`，`981-1280px` 为 `210px`，`761-980px` 为 `190px`；`760px` 及以下目录置顶并限制高度。
- 状态摘要使用单一 `4px` `SurfaceFrame`，内部连续单元直角；三列，`1280px` 以下两列，`980px` 以下单列。
- 设置行使用弹性说明列和右侧控制列；宽屏控制列 `282px`，中屏 `260px`，`980px` 以下单列。
- 重复操作按钮使用 `34px × 144px`；Select 和 Field 填满控制列。
- 账号、资料库、更新和日志的精确时间使用本地时区 `YYYY/MM/DD HH:mm:ss`。
- OAuth token、Bungie API Key、Client Secret 和 AI Key 不得写入仓库快照。

## 首页

稳定契约：`home.workspace`、`home.vendor-stock`。

| 区域 | 真实绑定 | 关键状态 |
|---|---|---|
| 刷新节奏 | `dailySummary.daily_reset`、`weeklySummary.weekly_reset` | 使用本地系统时区；顶部刷新矩阵只展示每日和每周重置，绝对更新时间靠右，动态倒计时使用全应用统一时间强调色 |
| 核心活动 | `weeklySummary.priorities.*.entries` | 未确认时显示 pending，不用历史或 mock 补齐 |
| 铁旗信号 | `weeklySummary.iron_banner`、角色 Activity Challenge、VisibleRewards | 与“本周加成”按约 `60% / 40%` 同行；只展示玩法、开放状态、倒计时、当前角色挑战和明确的直接奖励。当前角色进度使用“当前角色挑战”，账号范围使用“账号内 N 个角色可参与”，不得将两个维度写成同一句角色状态。萨拉丁库存、聚焦数量、具体装备、价格和购买条件只在商人页展示；条件可见的通用熔炉掉落不进入首页奖励摘要 |
| 周信号 | `special_event`、`weekly_bonus` | 本周加成固定展示；其他限时活动确认后独立展示，不覆盖铁旗 |
| 仄库存 | `dailySummary.sources.vendors`、`HomeBriefing.fetched_at`、`isXurActiveAt`、`nextXurBoundaryAt` | 整体使用单一 `summary-frame`，标题、到访/离开时间、库存状态和来源同框；内部摘要不重复外框；不使用 Vendor `nextRefreshDate` 替代；加载、不可用或失败时不回退旧库存 |
| 操作 | `onRefreshDaily`、`onNavigate("vendors")`、`onOpenXurOffer`、`onOpenWeeklyActivityReward` | 只有可确认且含 Hash 的奖励或武器/护甲 Offer 可打开统一详情 |

首页保持“刷新矩阵、活动摘要、周信号、商人库存”四层信息结构。核心活动保留日落、轮换突袭和轮换地牢三张独立卡片，桌面同排展示；桌面活动条目统一为 `98px` 固定行高。突袭和地牢按真实条目数量决定内容高度，单条目的日落卡只拉伸外框与同排双条目卡片底边对齐，日落内容在拉高区域内垂直居中，不拉伸标题或奖励条目。描述最多展示一行，奖励在固定行内按可用宽度优先并排；`760px` 以下恢复内容自适应高度。铁旗与本周加成在周信号层同行且等高，其他已确认限时活动另起一行；没有挑战时不显示 `0/0`，不在首页显示任何 Vendor 零值计数或具体库存。仄库存模块使用唯一首层 `summary-frame`，内部状态和摘要不再叠加框线；Offer 仍是对象卡。宽屏 Offer 四列，`1280px` 以下两列，`980px` 以下单列。

## 账号

稳定契约：`account.slot-comparison`。

- 账号目录使用完整 `tablist / tabpanel`；角色使用 `ContextSwitcher` 和 `aria-pressed`，不是页面导航。
- 装备按武器、护甲、装备、其他分类，再按稳定位置组织“当前装备 / 当前角色背包候选”两列对照；“其他”只显示记忆水晶位置。
- 位置来源使用 Manifest bucket 与稳定映射，不按名称猜测；仓库物品不得混入当前角色背包。
- 每个位置显示名称、当前装备数、候选总数、对象事实、配装命中和写操作状态；背包候选较多时完整换行展示，不折叠或隐藏。
- 装备对照使用“位置 `112px` / 当前装备 `236px` / 背包候选占满剩余空间”的连续行布局；背包候选始终完整展开，宽屏五列自动换行，`1280px` 三列，`980px` 两列，`480px` 以下单列。
- 当前装备列使用稳定的选中背景和强调边界，背包候选列保持中性表面；两种来源不能只依赖重复文案区分。
- 武器与护甲对象卡统一使用稳定的三行结构和 `72px` 高度：名称、核心事实、对象状态各占一行。来源由桌面列标题或窄屏面板标题表达，槽位由左侧行标题表达，卡片内部不重复“当前角色装备 / 当前角色背包候选”和槽位名称。武器核心事实显示武器类型、稀有度与光等；护甲核心事实显示稀有度与光等，末行显示总值、锁定及“配装 / 打开中”等状态。状态不得新增第四行或通过整行拉伸改变同槽位卡片高度，完整状态说明通过 tooltip 和无障碍名称保留。
- 装备详情允许立即显示账号快照中的身份、当前属性和当前配置，但关键几何结构必须从首帧稳定：账号实例的属性表固定预留资料库标准值与差异列，比较区常态固定为“标准值 / 当前差异与修正”两行，待应用变化并入同一列，缺失数据以“读取中 / 未返回”占位，不得因定义或配置状态变化增减列或为隐藏占位增加额外行高。加载状态按定义、实例和辅助数据分区记录，`is_detail_loading` 只作为两条关键请求的总忙碌状态；版本静态值与多版本下拉必须共用同一字段外壳，实时来源和推荐等辅助数据只能在已存在区域内更新。
- 只有武器和护甲对象可打开统一详情；装备、材料、任务、货币和其他对象保持只读。
- 刷新、失败和空态保留当前 Tab、角色和位置骨架，不使用整页遮罩抹掉结构。

核心字段：`characters[]`、`slotComparisonRows`、Activity History、材料集合和邮政官只读物品。写操作中只锁定目标对象，不阻断其他位置。

## 资料库

稳定契约：`library.workspace`。

- 上方使用资料库状态摘要，主体使用“查询侧栏 + 连续结果列表”的工作区。
- 装备与“Perk 与框架”是互斥模式，使用完整 Tab 语义；搜索、筛选和清空是普通 Control。
- 摘要显示激活版本、最新版本、激活时间、检查时间、语言、定义数量和缺失组件。
- 装备、Perk、框架、历史和收藏来自当前 Manifest 与本地历史，不使用固定名称、别名或数量。
- 同名装备存在多个可确认发布版本时，结果行名称旁直接显示玩家可识别的年份、赛季、资料片或内容包摘要；不要求展开详情，不显示 Hash 或内部 release trait。
- 定义对象与账号实例必须区分。只有匹配到真实实例时才显示位置、Roll 和账号详情入口。
- Perk 反查武器使用可追踪关联，不按武器名称模糊猜测。
- Perk 结果默认保持紧凑；展开“关联装备”后显示 Manifest 关系返回的装备图标、名称、类型和发布版本，并可直接打开统一装备详情。普通结果返回最多 40 件；达到上限时必须明确标记截断，不能把样本数冒充完整总数。没有关联时显示明确空态，不用名称字符串伪造关系。
- 未初始化、部分组件缺失、更新中、检查失败、历史为空和搜索无结果分别呈现；更新失败保留上一份可用资料库。

结果区使用连续 `SurfaceList`，每行只画 `RowLine`，不把普通结果改成对象卡。

## 仓库

稳定契约：`vault.workspace`。

仓库固定包含筛选列表、同名整理和推荐数据三个 `tabpanel`，共同消费同一份账号实例集合。清理不再维护独立工作台：玩家在筛选列表或同名整理中写入“可清理”，后续游戏内处理仍以该明确状态为边界。

| 工作区 | 数据与操作边界 |
|---|---|
| 筛选列表 | 左侧常驻筛选、右侧十列紧凑装备网格；Profile 实例、Manifest 定义、玩家整理状态、锁定、排序和保护信号共同参与筛选 |
| 同名整理 | 按 Hash 和实例 ID 分组；左侧按整理进度选择同名组，右侧使用比较基准突出实例差异并暂存本组整理状态 |
| 推荐数据 | DIM Wishlist、授权社区来源和个人目标分别显示来源与状态，不合并成系统评分 |

筛选范围只提供武器、护甲和装备，不提供“全部”与“其他”入口。武器槽位只显示动能、能量和威能；护甲部位显示头盔、臂铠、胸甲、腿甲和职业物品。武器类型使用真实 `item_type`，稀有度使用 `tier`，装备阶级使用 `instance.gear_tier` 并包含 T0，伤害属性使用实例伤害类型；护甲职业使用 `class_type`。护甲套装选项目录来自当前语言 Manifest 的完整 `DestinyEquipableItemSetDefinition`，账号装备摘要中的真实 `equipableItemSetHash` 只用于匹配物品和计算持有数量；未持有的套装仍保留在目录中并允许选择，命中为空属于正常筛选结果。目录加载中或不可用时必须显示明确状态，不得回退成账号持有套装列表。缺少稳定账号字段的制作状态或框架不得用固定选项补造。

筛选列表中的装备单元固定复用全局 `44px` 游戏图标，一般桌面宽度每行十列；较窄窗口按八列、六列和四列响应。装备阶级直接使用 `DestinyInventoryItemConstantsDefinition.gearTierOverlayImagePaths` 的官方覆盖图，并与 DIM 一样叠在图标左上区域；不得用 CSS 自绘竖条或从左下角堆点。T0 不显示覆盖图，缺失阶级在产品层按 T0 参与筛选和显示。武器对象卡分成身份、事实和状态三层：身份层显示图标、名称、类型和槽位；事实层显示游戏化弹药图标、官方彩色伤害属性图标与光等；状态层显示玩家整理状态和配装引用。护甲沿用相同三层结构：身份层显示图标、名称、职业和部位；事实层显示总属性、当前最高单项属性和光等；状态层显示玩家整理状态和配装引用，完整六项属性仍在详情和同名整理中展开。锁定使用绿色锁形状态标记，固定在卡片底部状态行右侧并使用主题状态底板，不再覆盖装备图标；配装引用使用应用状态文字和既有选中边框，不使用右上角单字方块。Perk、框架、品质、护甲能量、外部推荐证据和长备注留在详情或同名整理，不进入普通十列网格。

玩家整理状态统一为未标记、保留、待复查和可清理。`farm / loadout` 继续作为既有用途标签保存，但不进入整理状态控件。锁定、配装引用、愿望单、个人目标和社区推荐属于系统证据，只显示或筛选事实，不自动生成保留、待复查或可清理结论。普通十列装备单元只显示一份玩家整理状态，并保留锁定与配装引用角标；愿望单、个人目标和社区推荐继续参与筛选并在详情或同名整理中展开，不再同时显示推导决定。

护甲多条件为 AND，同一属性只保留一条；总属性只作为排序维度。保护与匹配支持多选并按 AND 收窄结果。重置筛选与结果摘要位于结果区顶部，不单独占用一行。

同名整理默认使用已标记保留的实例作为比较基准，否则使用本组第一件；基准只用于突出相同与差异，不属于系统推荐，不自动修改状态，也不限制一组只能保留一件。基准使用单选语义，切换后武器按真实 Socket 顺序和玩家可识别的插槽名称比较，护甲展示总值与完整六维；差异必须同时提供文字标记，不能只依赖颜色。武器默认比较“完整 Roll”：进入同名组后按需读取组内实例详情，每列集合由当前启用项与 `reusable_plugs` 中来源包含 `instance` 的实际拥有项组成，排除只来自 `character / profile / manifest` 的解锁项和定义池候选；当前启用项只作为集合内状态，不参与完整 Roll 的相同判定。详情未齐时只能明确显示并比较“当前启用”，不得把账号紧凑快照中的 `socket_plugs` 冒充完整 Roll 或提前给出完整集合结论；读取失败必须提供重试。辅助“当前启用”模式只比较每列当前选择。集合关系显示为相同、部分重合或完全不同，同名整理只读比较，切换游戏内 Perk 仍在装备详情完成。比较矩阵采用“单元格差异状态 + 无框 Perk 行”两层结构：差异通过左侧状态条和短文字标签表达，不使用整格描边；Perk 行只使用分隔线，当前或可切换状态固定在右侧，仅此实例拥有的 Perk 在名称旁显示短标签。Roll 列应保证可读宽度并允许矩阵横向滚动，不得为了塞入视口压缩名称和状态。Roll 单元中的 Perk 图标必须复用资料库和武器详情的 `game-definition-icon` 原语，以主题适配底板、边框和 `contain` 保留透明官方图标的可读性，不得按普通装备缩略图使用 `cover` 裁切。

实例保护与推荐证据分开展示。锁定和精确实例 ID 配装引用属于实例保护；仅按 Hash 或部位匹配的配装需求明确标为“配装同款”，愿望单、个人目标和社区数据保留在推荐证据中，不得让同 Hash 的每个实例都显示为精确配装引用。

单件整理状态先在当前组暂存，左侧组目录和右侧行必须明确显示未保存状态；只有草稿与已保存状态不同时才开放“应用本组状态”。“填充：基准保留，其余待复查”只修改草稿。存在未保存草稿时不能直接进入下一未整理组。带实例保护或推荐证据的装备若被标记为可清理，应用前必须二次确认。应用只写本地整理状态，不转移、不解锁、不拆解。

写操作继续调用真实 action / IPC，失败前不得提前修改锁定、位置或标签显示。

## 商人

稳定契约：`vendors.workspace`。

- 目录按真实地点和稳定 `vendorHash` / ID 分组，使用紧凑文字行，不显示头像或首字母占位。
- 详情按库存、子库存、任务、声望和等级奖励纵向排列，不用分类摘要替代完整库存。
- 每个 Offer 显示真实图标或缺图态、名称、类型、摘要、成本、数量、购买状态和失败原因。
- 角色相关库存显示当前角色上下文，不跨角色合并库存。
- 武器和护甲 Offer 可打开统一详情；材料、任务、解码器和其他对象只显示库存事实。
- 读取时间和重置边界使用原始时间字段在渲染时格式化，不保存预格式化文案。
- 加载、未开放和失败时清除过期轮换；部分可用时展示已确认销售数据并标记缺失属性或插槽。

Offer 使用响应式对象卡网格：宽屏五列，`1280px` 三列，`980px` 两列，`760px` 单列。章节和目录保持连续直角结构，不建立水平商品轨道。

## 配装边界

稳定契约：`loadouts.workspace`。本文件记录共享配装页必须保持的页面与交互边界；本地方案、DIM、攻略、护甲求解和方案应用已接入同一工作台。

- 一级视图只保留 `游戏内配装` 和 `本地配装方案`。护甲优化器不是第三个一级页面、方案类型或来源。
- 游戏内配装显示 Bungie 官方槽位与直接应用能力；“复制到本地工作台”只复制官方可读字段并打开预填工作台，不立即创建已保存方案。
- 本地方案目录只显示已经显式保存的方案。新建、当前装备复制、攻略解析和游戏内槽位复制直接进入工作台；DIM 先完成链接读取与预览，再进入同一个工作台。
- 本地方案工作台采用“配置目录 / 当前编辑区域 / 方案摘要”三栏结构。配置目录固定包含基础信息、子职业、武器、护甲、属性与模组、核对与执行。
- 武器和护甲必须选择真实账号实例；同名多实例不静默代选。子职业、目标 Perk、星象、碎片、技能和模组只有在稳定 Hash 与可写能力可验证时才进入执行计划，其余保持“仅记录”。
- 护甲章节负责选择、锁定、排除和固定异域；属性与模组章节负责六维最低目标、碎片变化、模组预算、计算多个候选和选择结果。未选择候选不写入方案，也不持久化全部临时候选。
- “保存本地方案”只写入本机；保存后才能应用。应用使用 `plan / execute / refresh` 边界，失败时停止后续步骤并展示真实结果。
- 只有本地方案应用成功并刷新账号核对后，才开放“保存到游戏内槽位”；覆盖已有 Bungie 槽位必须明确确认，本地方案不会因发布而自动删除或同步。

状态矩阵必须覆盖：首次读取、空目录、链接读取失败、DIM 部分解析、候选计算中、无满足约束候选、方案未保存、方案有未保存修改、应用计划不可执行、应用部分失败、应用成功待发布、槽位覆盖确认和发布失败。已确认字段继续显示，缺失字段不得按名称或相似配置补造。

### 配装状态矩阵

| 状态 | 可见区域 | 允许操作 | 不允许伪造 |
|---|---|---|---|
| 首次读取 / 空目录 | 目录和创建入口 | 新建、当前装备复制 | 不展示旧模板或虚构方案。 |
| 未保存草稿 | 三栏工作台和摘要 | 编辑、选择实例、显式保存 | 不显示为目录中的已保存方案。 |
| 已保存但账号未读 | 方案详情和来源 | 编辑、删除 | 不声明装备已拥有或可执行。 |
| 多实例待选择 | 对应装备行和摘要 | 选择具体实例 | 不按名称、Hash 或最近位置静默选定。 |
| 目标 Plug 不可用 / 装备缺失 | 对应装备行 | 编辑目标、查看现有候选 | 不将不可验证 Plug 加入执行计划。 |
| DIM 链接读取失败 / 攻略解析失败 | 创建入口和操作状态 | 修正链接或文本并重试 | 不创建半成品方案，不显示模拟预览或成功状态。 |
| 护甲计算中 / 无候选 | 护甲章节和摘要 | 取消、调整约束、重新计算 | 不复用旧候选或把无候选表示为已优化。 |
| 应用计划不可执行 / 部分失败 | 执行核对和操作状态 | 查看已完成、失败和未执行步骤 | 不回滚成功步骤或报告虚构事务成功。 |
| 应用成功待发布 / 槽位覆盖 | 发布区域 | 选择真实 Bungie 槽位并明确确认 | 不自动覆盖槽位，不同步或删除本地方案。 |

## 通用状态要求

所有菜单必须保留正常、首次加载、刷新中、空、失败、部分失败、无权限、禁用和进行中状态。状态只影响所属区域；已确认事实继续显示，缺失字段不补造，写操作成功前不更新事实值。
