# 应用工作区合同

> 本文件合并共享 Shell、设置、首页、账号、资料库、仓库、商人、导航和配装的结构、真实数据与状态边界。视觉细节统一遵守 [全局视觉合同](global-visual-contract.md)。

## 共享 Shell

稳定契约：`shell.topbar`、`shell.status-strip`、`shell.sidebar`、`shell.page-header`、`shell.page-content`、`shell.assistant`。

| 区域 | 真实绑定 | 约束 |
|---|---|---|
| 顶部栏 | 品牌、主题、GitHub、设置、AI、窗口控制 | 单一连续 Shell chrome；无平台窗口能力时只隐藏窗口控制 |
| 状态组 | `ShellStatusItem[]` 与对应 action | 状态项组成连续边界；状态 key 负责逻辑，label 只负责文案，不使用独立胶囊卡片 |
| 侧栏 | 当前账号摘要、一级导航、底部动作 | 桌面侧栏保持固定展开，不提供手动隐藏入口；窄窗口由响应式布局自动切换为紧凑栏。一级导航使用稳定图标和 `aria-current`，紧凑栏隐藏文字但保留按钮 `title` 与可访问名称；账号摘要名称截断时可通过悬浮查看完整名称 |
| 页面标题 | `ProductShellHost` 页面元数据与真实页面 action | 内容页不得复制第二个页头 |
| 主内容 | 当前菜单共享页面 | 普通页面由主内容持有唯一纵向滚动；仓库宽屏是明确的双栏例外，页面标题与工作流固定，筛选栏和结果栏分别滚动且不得把滚轮传递给外层 |
| AI 助手 | 会话、页面上下文、只读能力结果与数据引用 | 宽屏停靠，`980px` 及以下转 Drawer；只保留单一 AI 工作台，不建立固定任务 Tab |

Shell、页头、页面 gutter、首层分栏和全局 token 由共享层持有；菜单 CSS 不得覆盖 `.shell-*` 或无菜单前缀的工作区规则。

页面可以向 `ProductShellHost` 注册单一离开保护，只用于确实会因菜单卸载而丢失的未提交用户输入。Shell 侧栏、页内跨菜单动作和自绘窗口关闭命中保护时必须停留在当前页面并显示共享结构化确认弹窗；刷新、系统关闭或其他原生卸载路径使用平台 `beforeunload` 保护。取消后焦点回到来源操作，确认后才执行原导航或关闭动作。确认弹窗通过顶层 Portal 脱离可能被抽屉设为 `inert` 的页面内容，显示期间隔离应用背景，并始终位于 AI 抽屉、详情或菜单内容之上。弹窗打开时初始焦点落在安全的取消操作，`Escape` 等同取消，`Tab / Shift+Tab` 不得离开弹窗。新增或改造的共享页面确认流程不得调用 `window.confirm`，也不得把已持久化状态或普通筛选条件登记为离开保护。

顶部状态按行动紧迫度分为 `quiet / standard / attention / critical`，不按状态项数量平均分配视觉权重。正常配置、健康确认和当前版本属于低权重事实；发现新版、下载进度、待重启安装、资料库修复和真实失败属于可操作事件。状态项位置必须稳定，不得因状态或权重变化重新排序；高权重事件只通过颜色、背景、图标和文字增强，并保持连续边界，不建立独立胶囊卡片。窄窗口的“状态”入口显示待处理数量，展开后继续保持相同顺序。

应用更新状态必须区分 `idle / checking / not_available / available / downloading / downloaded / error`：未检查不得显示“最新”；已是最新只显示中性版本号；发现新版显示目标版本并使用信息色；下载中显示目标版本和进度；下载完成显示“待重启安装”并升为最高操作权重；失败使用错误色。顶部更新项只负责进入设置页更新区，不直接触发下载或重启安装。

应用更新与资料库更新共用 `SystemUpdateProgress`：顶部状态持续显示对象、阶段和可用百分比，不因临时通知收起而消失；任务开始、等待重试、失败或阻断时，可在顶部栏下方显示使用紧凑模式的临时通知，并在并行任务存在时提示剩余数量。通知可手动收起，运行和等待重试状态会自动收起，收起只影响展示，不取消任务；任务状态类别变化后可重新出现。设置页与资料库页使用详细模式显示阶段说明、下载量、总量、速度、旧数据可用性和重试时间。正常检查、下载、解压、校验和索引使用 `pending` 信息态；只有等待重试或能力受限使用 `warning`，失败和阻断使用 `error`，明确完成使用 `success`。无法计算进度时使用不定进度，不得伪造最低百分比。所有进度条必须提供 `progressbar`、当前值或不定状态的可访问语义。

AI 工作台发送前可以按用户问题自动运行受控只读能力，每轮最多三项。当前覆盖装备定义、Perk、账号实例、当前商人 Offer、本地配装检查和 `armor.plan`；宽泛整理或推荐问题不得伪造实体查询。Armor 调用必须同时识别当前六维数值目标和明确职业，旧六维、缺职业、缺目标或升级基线不明确时不得猜测。确定性结果随完整 `result_id` 进入模型上下文，回答底部显示缩短后的数据引用和状态；失败、无结果、未登录或缓存不可用必须保留真实限制。AI 工作台不得调用写操作、后台刷新或把聊天文本当作确认。

AI 只有在设置页完成数据发送确认后才能接收游戏上下文。设置页必须常驻展示发送目标、会发送与不会发送的内容；启用协议但未确认时阻止保存，旧配置和便携备份恢复默认未确认，更换协议或 Base URL 后立即撤销确认。未确认时模型列表可以继续工作；底层连接测试只发送固定测试文本、不携带游戏上下文，但“保存并测试连接”仍受保存确认约束。AI 对话、装备分析、仓库建议和外部知识查询不得在未确认时发送游戏数据。模型上下文不得包含 Bungie / AI 凭据、账号名、Membership、角色、装备实例、物品或 Plug 标识。

每次成功问答必须创建轻量上下文快照，消息保存快照 ID，快照保存页面和账号范围、Manifest 版本、基础上下文指纹、实际提示指纹及能力结果引用，不保存完整提示、装备正文或凭证。恢复会话后，当前上下文与最近快照不一致时顶部状态显示“已恢复历史快照”，上下文抽屉显示快照时间；继续提问只携带有限前文并创建新的当前快照。请求失败时恢复发送前消息，不写入无回答的历史条目。

只读能力调用审计保存在 renderer 本地存储，最多 100 条，只记录能力名、脱敏输入摘要、结果 ID、状态、耗时、警告码、结果数量和证据 ID。设置页“复制脱敏诊断导出”在主进程诊断后附加最近能力审计；不得写入完整提示、能力完整结果、账号装备正文、Token、Cookie 或 API Key。

明确的配装、构筑或攻略整理回答可以在消息底部显示单一 `guide_capture` 成果行，包含草稿标题、确定性结果引用数量和“交给配装页”命令。成果行是消息内连续区域，不嵌套对象卡。交接后关闭 AI Drawer、打开配装页攻略导入区并预填未保存文本；玩家仍需选择角色、执行解析与账号核对并显式保存，不得直接创建方案或触发写操作。

`armor.plan` 返回候选时，消息成果行优先显示 `armor_solution_comparison`，标明规划模式和达标候选数量。交接文本只包含原始职业、六维目标、候选 ID 和结果引用，不复制候选最终六维作为约束；配装页显示“复核 AI 护甲方案”，重新解析并要求复核模组预算、套装、位置范围和真实实例。

页面动作权重由当前页面职责、人工使用频率、自动刷新覆盖和阻断状态共同决定。全应用主要操作统一使用绿色表面：手动刷新、同步当前数据和失败后的重新读取使用带刷新图标的 Refresh Control；下载、保存、创建、应用和登录等通用 Primary 使用同一绿色家族，但不显示刷新图标。不同动作依靠动词、图标、所在操作组和忙碌状态区分，不再用蓝绿按钮割裂页面风格：

| 页面与状态 | 主操作 | 次操作 |
|---|---|---|
| 账号正常 | 页头 `同步装备数据`；从游戏更新角色装备、背包、仓库和配装，并更新所有账号消费者 | 页头 `重新登录 Bungie`；仅用于登录失效、权限异常或切换账号 |
| 账号未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新或登录动作 |
| 账号未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 账号无数据 | 内容空态中的授权或刷新入口；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 仓库正常 | 页头 `同步装备数据`；与账号页执行同一个完整装备同步并更新共享 Store | — |
| 仓库未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示 `刷新账号` |
| 仓库未登录 | 内容空态中的 `登录 Bungie` | 不显示 `刷新账号` |
| 仓库无数据 | 内容空态中的 `同步装备数据`；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 首页正常 | — | 页头次级 `刷新首页情报`；带刷新图标，启动、重置边界和失败重试已有自动机制 |
| 首页读取失败 | 错误 Callout 内的主操作 `重新读取首页情报` | 页头不重复显示同一刷新动作 |
| 商人正常 | — | `刷新商人库存`；进入页面、切换商人或收到明确数据事件时按需刷新 |
| 商人后台同步 | — | 页头刷新保持可点击；后台读取状态只在商人状态区反馈 |
| 商人读取失败且仍有缓存 | 页头 `刷新商人库存` 临时升权 | — |
| 商人完全无数据 | 内容空态中的 `重新加载商人库存` | 页头不重复显示同一操作 |
| 商人未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新动作 |
| 商人未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 设置账号分区 | `同步装备数据`；该行明确说明游戏内或其他设备发生变化后使用 | `重新登录 Bungie`；独立一行说明只处理登录失效、权限异常或切换账号 |

首次启动时仍挂载完整 `ProductShellHost`，但由共享启动门禁统一推进“Bungie 配置 → 登录 Bungie → 首页”；资料库与登录并行，未完成前只允许进入设置和当前步骤，不显示半可用首页。配置区必须提供 Bungie 官方 Application 页面入口、字段对应关系和固定 OAuth 回调地址。配置保存后自动在后台准备资料库，不创建独立向导页或第二套配置表单；资料库准备失败时保留明确原因和重试动作，不阻塞 OAuth 登录和账号原始读取，名称、图标及高级解析在资料库完成后补齐。步骤区下方固定两行 `startup-gate-legal` 声明：d2-tools 是非官方社区工具、与 Bungie, Inc. 无从属关系，以及 Bungie Game Content Usage Rules 要求的英文商标声明；这两行不随步骤状态变化，也不得删减。

同一业务动作可以因页面职责不同使用不同权重。每个页面或局部失败状态最多突出一个主操作；空态或错误区已持有主恢复入口时，页头不得重复同一操作。进行中保持原标签和稳定宽度，通过 `aria-busy`、禁用状态和邻近反馈表达进度。

账号与仓库同步使用单一共享快照和事件驱动更新，不得由菜单私有资源请求只更新状态标签而不更新页面数据。应用启动或登录后执行一次可见的初始同步；应用可见期间每 10 分钟静默同步一次，重新回到前台、恢复网络且上次同步超过 2 分钟时补同步，不因切换页面触发请求。自动同步复用已有 in-flight 请求、不清空旧数据、不占用手动按钮，失败时继续显示旧快照。本地缓存只用于首屏和失败回退，必须明确显示“本地缓存”。所有菜单把这项操作统一命名为“同步装备数据”：账号页、仓库页、设置页、AI 空状态和配装状态不得再使用“同步游戏账号”“同步仓库”“读取账号数据”等不同名称。用户点击后必须绕过账号、Profile 和请求 Broker 缓存；若已有初始或后台请求，手动请求排在其后重新读取，完成后原子更新共享账号快照并让首页、账号、仓库、配装等消费者同时更新。普通快照超过自动同步窗口时显示“待同步”，不得称为游戏数据延迟。写接口成功后共享 Store 立即显示预计位置并登记逐实例 Pending；新 Profile 先更新最后确认快照，再重放尚未反映的 Pending，相同或更旧版本不得整份覆盖页面，暂时缺失实例也不得让成功写入的装备消失。全局账号状态持续说明“n 项待确认 / 等待游戏状态 / 正在核对最终状态”；只有写操作确认超过 90 秒时标记“游戏数据延迟”。只有 Profile 明确前进且仍与写入冲突时才能撤销预计位置；超时、网络不可用或 Profile 未前进不得伪装成已核对。后台确认不借用手动同步按钮的忙碌状态，玩家仍可主动发起权威同步。“重新登录 Bungie”只表达身份恢复或账号切换，不得与日常装备同步混为同一操作。

商人刷新必须区分后台同步和手动请求：进入页面、切换商人、账号页当前角色变化和明确数据事件属于按需后台同步，不使用固定间隔定时器或轮询；Xur 到访 / 离开边界属于低频明确事件，可以保留一次性边界定时器。后台同步不得清空当前库存，也不得禁用页头刷新。只有用户已经发起的手动刷新可以临时禁用该按钮。切换商人使用短防抖，快速浏览目录时只请求最后停留的商人；手动请求使用后发请求优先的现有序号机制接管后台请求。

## 设置

稳定契约：`settings.workspace`。

固定九个分区：概览、语言与外观、账号、资料库、Bungie 接口、AI 助手、数据备份与迁移、数据来源与鸣谢、诊断与操作日志。设置只承载应用配置和公开来源说明，不承载攻略导入、推荐数据导入或其他业务工作流。

“数据来源与鸣谢”公开区分 Bungie 官方事实、社区资料来源和已参考项目与功能；每项保留完整外部链接、用途、关系边界和许可提示。本地用户导入内容不进入公开清单。账号事实和实时轮换必须标明以 Bungie 为准，参考项目不得伪装成运行时依赖。

| 区域 | 真实字段与 action | 状态边界 |
|---|---|---|
| 概览与更新 | `appUpdateSnapshot`、账号/资料库/Bungie/AI/后台任务摘要、检查/下载/安装/诊断 | 未检查保持中性；只有发现版本后允许下载，下载完成后允许安装 |
| 语言与外观 | `languagePreferences`、`colorMode`、`density` | 界面语言与资料库语言分开建模；跟随开启时禁用独立资料库语言 |
| 账号 | `accountSummary`、同步状态、刷新时间 | 同步中禁用重复同步；未登录保留“重新登录 Bungie”入口；写操作由对应页面确认，不设置应用级总开关 |
| 资料库 | Manifest 状态、检查、更新、修复 | 失败时保留上一份可用资料；进行中禁用冲突操作 |
| Bungie | 官方 Application 入口、API Key、Client ID、Client Secret、回调地址和数据目录；保存后自动准备资料库 | 三个配置值均明文展示；三者都不进入仓库示例或诊断快照，诊断导出仍须脱敏；字段不完整时阻止保存；资料库准备失败不回滚已保存配置 |
| AI | 协议、Key、Base URL、模型、数据发送确认 | 常驻说明发送范围；无配置、待确认、已确认、加载、测试中和失败分别呈现；更换协议或 Base URL 后重新确认 |
| 备份与迁移 | 创建/恢复备份、清缓存、迁移说明、打开目录 | 调用真实平台能力，不伪造完成结果 |
| 诊断与日志 | `backgroundTasks`、`actionLog`、AI 只读能力审计、筛选、刷新、复制诊断 | 空日志保留筛选和诊断入口；失败项提供脱敏诊断；能力审计通过统一诊断导出附带 |

布局合同：

- `>1280px` 目录 `240px`，`981-1280px` 为 `210px`，`761-980px` 为 `190px`；`760px` 及以下目录置顶并限制高度。
- 状态摘要使用单一 `4px` `SurfaceFrame`，内部连续单元直角；三列，`1280px` 以下两列，`980px` 以下单列。
- 设置行使用弹性说明列和右侧控制列；宽屏控制列 `282px`，中屏 `260px`，`980px` 以下单列。
- 重复操作按钮使用 `34px × 144px`；Select 和 Field 填满控制列。
- 账号、资料库、更新和日志的精确时间使用本地时区 `YYYY/MM/DD HH:mm:ss`。
- OAuth token、Bungie API Key、Client Secret 和 AI Key 不得写入仓库快照。

## 首页

稳定契约：`home.workspace`、`home.vendor-stock`。

| 区域 | 真实绑定 | 关键状态 |
|---|---|---|
| 刷新节奏 | `dailySummary.daily_reset`、`weeklySummary.weekly_reset` | 使用本地系统时区；顶部刷新矩阵只展示每日和每周重置，绝对更新时间靠右，动态倒计时使用全应用统一时间强调色 |

## 账号

稳定契约：`account.slot-comparison`。

账号菜单长期定位为“角色状态与待处理中心”，优先回答当前角色是否安全、是否已准备好进入活动以及接下来需要处理什么。跨角色库存浏览、筛选与整理归仓库菜单；完整配装列表、编辑和执行归配装菜单；首页只保留本周活动的紧凑摘要，完整的待办入口归账号菜单；收藏、成就、催化剂和外观归资料库。账号菜单不得复制这些菜单的完整工作区。

- 容量、物品位置、光等、邮政官和角色进度扩展必须继续消费中央账号 Store 或明确拆分的共享异步资源，不建立账号菜单私有刷新、缓存或轮询模型。
- 页面必须区分请求完成、服务器 Profile 前进和目标状态确认；同步尚未确认时持续显示进行中或等待状态，旧 Profile 不能覆盖更新版本或本地仍在等待确认的预计状态。
- 三角色待处理对比是容量、光等、任务和进度能力的聚合视图。每项能力接入真实数据后再加入汇总，不创建独立假数据面板，也不预留静态数字和空壳操作。
- 新装备识别、历史记录和完整 Feed 归共享账号状态或仓库领域；账号菜单未来只允许消费已确认的摘要，不单独维护新装备状态。
- 强力、巅峰、赛季和声望等扩展进度使用独立异步资源、独立缓存和独立失败状态，不得加入装备首屏的阻塞加载链。
- 新增容量风险、光等成长、邮政官批量处理、任务与赏金或角色进度能力时，必须先确认在现有目录中的位置；如需改变目录与信息架构，先更新本合同，不得直接隐藏或删除现有真实功能。

- 账号页面先在三个工作模式之间切换，再显示模式内的内容，不把作用域、资料类型和每周行动混在一条目录里：
  - **角色状态**：战斗装备、角色物品与配置、邮政官；这些内容以当前角色为主。
  - **待办**：一张清单加五个二级入口；一级回答“有哪些事没做完”，二级回答“多急”。清单模型见 `docs/work/backlog/T91-todo-list.md`。
  - **账号资料**：材料与货币、账号战绩；这些内容属于整个账号。
- 「待办」只有一张清单、一套分桶和一套排序。清单先按**时限**分桶（日常 / 周常 / 不限时），段的顺序固定，不按完成状态分组——按完成状态会把每日赏金和地牢周挑战塞进同一个格子里，看不出哪个今天不做就没了。完成状态是段内排序的第一维。二级入口分两种轴：全部 / 日常 / 周常 / 不限时按**多急**切，「提光」按**给什么**切、横跨三个时限段，产品用分隔线（`data-axis="kind"`）把它与时限桶隔开，这条线属于账号菜单二级目录自己的样式，不改通用目录组件。二级入口只过滤、不重排、不重算结论、不改变分桶；同一个行动行可以同时出现在多个入口里。入口不得各自维护价值判断、完成条件或排序规则。时限只读 Bungie 返回的到期时间与活动身份，不读名称，也不读 `itemTypeDisplayName`。
- 「刷取」不是导航项，是行动行展开后的一个事实面：提光在行正面（游戏返回的官方奖励名原文），刷取在展开里（掉落武器 + 推荐 + 图样缺口），两个挂在同一行的两个面上。
- 「全部」末尾常驻一段账号级事实：光等、邮政官、容量三行，只读、可折叠，不参与分桶、过滤和排序，也不出现在其他二级入口里。三行只在真有事实可报时出现，读不到的行不显示，不补占位值；每行的数据时间取账号快照时间，与清单的数据时间分开。容量行的任务槽位上限读任务 Bucket 定义，占用数按当前角色计，仓库占用为账号级。
- 行动项必须逐条显示事实来源与数据时间；事实缺失时显示「无法确认 + 原因」，不从清单里删除，也不被静默过滤。
- 模式入口是稳定的一级导航，模式内二级入口是二级 `tablist / tabpanel`。目录顺序不得按运行状态动态重排；该入口的计数必须等于该面板的可见行数，不手写数字；其他真实数量只显示在邮政官等需要快速识别的清单上，不用任务数量或普通物品数量制造虚假优先级。角色使用 `ContextSwitcher` 和 `aria-pressed`，不是页面导航。
- 账号工作区内容宽度大于 `700px` 时，一级模式和二级分区使用稳定的上下方向键，朝内容区方向的方向键将焦点送入当前面板；进入 `700px` 以下后，一级模式和二级分区都改为单行横向滚动，分别使用左右方向键，`Home / End` 跳到各自列表首尾。当前模式切换后，焦点进入该模式的首个可用分区或首个主要操作。
- 账号首屏根据当前模式改变上下文：角色状态回答“当前角色是否安全、装备和光等是否准备好”；待办回答“还有哪些事没做完、哪些今天不做就没了”；账号资料回答“账号级材料与近期活动状态”。账号名、同步状态和快照时间可以作为轻量公共上下文保留，但容量、角色装备和最高光等摘要不得在待办或账号资料面板前重复铺开。
- 写操作结果、物品操作进行中和配装消息统一挂在账号名与同步状态下方，三个工作模式共用这一个位置；不跟随只在角色状态下出现的容量摘要，也不预留固定高度的空槽。
- 容量与风险摘要位于角色切换和账号操作之间，使用单一紧凑 `summary-frame` 展示当前角色邮政官、账号仓库和当前角色携带风险汇总；不展示三武器、五护甲的八张逐槽容量卡。携带槽位占用仍按同一装备槽 Hash 的“已装备 + 背包”计算，不能只数背包候选；容量上限来自 Manifest bucket 定义，空容器也必须主动请求对应定义。仓库已满、邮政官覆盖风险、携带槽位已满和接近上限必须同时用文字、数值与状态样式表达，不只靠颜色；未知上限显示“容量上限待确认”，不得显示 `0 / 0`。三角色切换项显示各自的容量风险短摘要，不新增第二套角色选择器。
- 背包槽位剩余 0 格为危险、剩余 1 格为警告；邮政官剩余 0 格为覆盖危险、剩余少于 6 格为警告；仓库剩余 0 格为危险、剩余不超过 `max(10, ceil(容量 × 2%))` 为警告。账号总风险取仓库与三角色中最严重状态，未知状态只在没有更严重已确认风险时显示。刷新中继续显示上一次真实容量并标明同步阶段；写操作已投影但服务器尚未确认时显示“等待游戏状态确认”，容量随中央账号 Store 的预计位置即时更新，不建立账号页私有缓存或轮询。
- 角色切换项同时显示当前装备光等和遵守职业、异域同时装备限制的账号最高光等；最高光等使用整数加 `/8` 余数展示。摘要操作区使用“最高光等方案”作为只读预览入口，点击后打开账号菜单私有浮层；真正执行写操作的按钮独立使用“一键装备最高光等”。桌面浮层覆盖内容区、窄屏回到文档流，不改变共享 Shell chrome；点击触发按钮与浮层之外的区域自动关闭，`Escape` 关闭后焦点返回触发按钮。
- 「待办 → 提光」只展示可证事实：活动挑战、角色、完成状态、官方奖励名原文和数据来源时间；行上带不带等级占位词，只说明官方奖励名里有没有那个词，**不得据此推断提升幅度或推荐优先级**，不得出现「巅峰奖励」这类结论性文案，也不得写「可能补齐低光槽位」这类提光推断。面板顶部的状态矩阵按可执行性分四格（可执行 / 已完成待处理 / 已结束 / 状态待确认），四格相加等于面板行数。每行给出**怎么拿到**——来源活动正式名称、挑战名称和进入入口，给的是路径不是结论。奖励名无法确认时显示「无法确认 + 原因」，不从清单里删除。奖励名按角色挑战 Objective 关联 Manifest 活动挑战的 `displayRewards[].itemQuantity`，并兼容旧定义的 `dummyRewards`；不得使用 `visibleRewards` 代替挑战奖励。账号奖励掉落基准与逐槽缺口只在角色状态的光等详情里展示，不在本入口重复铺开，也不作为某个角色的推荐理由。不新增首页 T44 卡片。刷新复用首页简报资源和 in-flight 请求，刷新中保留旧结果并显示状态，失败不清空清单；账号手动刷新必须同时刷新挑战状态。口径细节见 `docs/work/backlog/T91-todo-list.md` 第 7.3 节。
- 窄屏横向模式栏保留“角色状态 / 待办 / 账号资料”可见分组标记；进入模式后再显示该模式的二级入口栏。每个模式和分区控件的无障碍名称同时包含模式与功能作用域，横向滚动不得改变顺序或隐藏作用域含义。光等浮层在短视口中限制最大高度并在浮层内部滚动，不能把底部说明裁出可视区域。
- 分类切换必须自动关闭光等浮层；横向目录存在实际溢出时显示边缘渐隐并让当前选中项滚入视口，内容未溢出时不显示误导性的滚动提示。
- 光等浮层只展示真实的最高光等装备方案，不再提供不满足同时装备条件的“八槽最高”理论视图。顶部以“当前装备光等 → 装备后光等”表达结果变化，八个槽位按三武器、五护甲排序，使用明确列头显示位置、装备与来源、光等及相对方案整数均值的正负差值；缺少任一槽位时仍保留完整八槽并明确显示方案数据不完整。
- 账号最高光等允许读取其他角色持有的可用装备，邮政官不参与计算；当前一键装备只使用目标角色与仓库。两者一致时明确说明当前方案已达到账号最高光等；两者不一致时只显示账号最高光等和跨角色来源限制，不再通过第二套槽位列表制造可直接执行的错觉。
- 装备按武器、护甲、装备、其他分类，再按稳定位置组织“当前装备 / 当前角色背包候选”两列对照；“其他”只显示记忆水晶位置。
- 位置来源使用 Bungie 容器、Manifest 规范装备槽位与稳定映射，不按名称猜测；邮政官容器 Hash 与动能/能量/威能等装备槽位分开保存，仓库物品不得混入当前角色背包。
- 每个位置显示名称、当前装备数、候选总数、对象事实、配装命中和写操作状态；背包候选较多时完整换行展示，不折叠或隐藏。
- 角色物品与配置合并当前使用的职业分支、机灵、飞船、载具、徽标等配置，以及角色携带、外观、可选配置和未分类只读数据；账号材料与货币独立为账号级页面，不随顶部角色切换改变作用域。待办里的任务与赏金行固定聚合三个角色，并在每行显示所属角色；在 Bungie 返回可见目标时显示真实目标进度、完成状态和进度条，不用条目总数冒充待处理数量。
- 「待办 → 任务与赏金」使用独立账号资源，不阻塞装备首屏；行按 `time_frame` 落进日常 / 周常 / 不限时三段，段内顺序为“可执行、已完成待处理、已结束、状态待确认”，同档再按到期时间、稳定 Hash、角色顺序排。段在有条目时才出现，二级入口上的计数等于面板可见行数。`completed_pending_action` 只包含确实可领取、可兑换或可继续处理的项目；只能确认完成、不能确认领取状态时使用「完成状态已知，领取状态待确认」，不得显示成已完成待处理。计数与排序必须来自同一时间基准，磁盘缓存在跨天后不得出现计数与列表不一致。行动行正面给状态与时限，展开后给这份行上所有事实的来源、数据时间与状态，整行都是展开开关（点名称、图标或行内空白处都算），不用行末小字；行可聚焦，`Tab` 停得住、`Enter` / `Space` 能展开和收起。失败时显示失败原因、上次确认时间和重新拉取任务、赏金与活动挑战的入口；该资源只在「待办」展示，不接入首页常驻卡片，并在用户进入「待办」后才加载。

## 资料库

稳定契约：`library.workspace`。

- 上方使用资料库状态摘要，主体使用“查询侧栏 + 连续结果列表”的工作区。
- 资料库只保留“装备”和“Perk 与框架”两个互斥查询模式，使用完整 Tab 语义并支持左右循环导航；搜索、筛选和清空只属于这两个查询模式。本周刷取不再作为资料库查询模式，资料库通过活动或装备深链接进入账号的待办。
- 查询侧栏首屏承载模式、主搜索和当前模式该有的筛选；最近查询、收藏计数和别名管理统一收进默认折叠的“搜索辅助”，不得与主搜索并列抢占首屏高度。
- 两个查询模式的筛选面不同，共用同一条查询侧栏。装备按名称精确匹配、结果不多，只保留模式、主搜索和清空，不提供任何筛选控件；筛选控件只在 Perk 模式出现。
- Perk 模式的侧栏先放“关联分类”“关联装备”两个作用于 Perk 列表的筛选，其下才是作用于关联武器的高级筛选。高级筛选固定四个维度：位置、属性、弹药类型、框架；取值来自当前展开 Perk 的关联武器，不使用固定清单，也不因取值多寡增删维度。
- 高级筛选只作用于当前展开的那一个 Perk 的关联武器。没有展开任何 Perk 时，面板只说明筛选对象尚未出现，不渲染四个维度。切换展开的 Perk 清空已选条件——条件只对上一个 Perk 有意义，留着会让新 Perk 的结果被一个看不见的旧条件过滤；收起再展开同一个 Perk 不清。已选取值在结果为空时仍可取消。
- 每个取值旁的数字是“再选上它会剩几件”：统计该取值时排除它自己这一维已选条件，否则选完一项后同维其余取值全变 0，再也切不回去。数字为 0 且当前未选中的取值禁用。
- 摘要显示激活版本、最新版本、激活时间、检查时间、语言、定义数量和缺失组件。
- 装备、Perk、框架、历史和收藏来自当前 Manifest 与本地历史，不使用固定名称、别名或数量。
- 同名装备存在多个可确认发布版本时，结果行名称旁直接显示玩家可识别的年份、赛季、资料片或内容包摘要；不要求展开详情，不显示 Hash 或内部 release trait。
- 装备结果首层按“名称与版本 / 类型、槽位、框架、弹药和伤害属性 / 当前获取、账号持有和来源可信度 / 操作”排列；完整定义描述、起源特性、历史来源和实时渠道进入同一来源详情，不在首层重复铺开。收藏是低权重操作，武器和护甲的“查看详情”仍是唯一主操作。
- 定义对象与账号实例必须区分。只有匹配到真实实例时才显示位置、Roll 和账号详情入口。
- Perk 反查装备使用可追踪的具体 Hash / Manifest 关系，不按装备名称模糊扩展。搜索列表以 Logical Perk / Perk Family 为用户实体：家族身份由 Inventory Plug 的规范化名称、官方图标和 Plug / Item 类别共同确定，不把描述或 Sandbox Perk Hash 直接当作列表身份。普通、强化和其他官方变体在同一结果内保留各自 Sandbox Perk Hash、Plug Hash、描述和关联数量；例如“爆炸箭头”只显示一行，行内分别展示普通效果与强化差异。
- 高级筛选的图标与配色复用共享战斗图标语言：位置用槽位字形、属性用官方伤害图标、弹药类型用弹条，配色走同一组元素 token；选中态压过元素色。面板顶部写明当前作用对象和命中数（“作用于「狂乱」的 23 件关联武器（共 334 件）”），让筛选范围不靠猜。
- Perk 搜索结果只返回精确关联总数和分类；展开“关联装备”时一次读取该 Perk 的全部关联武器，不设静默固定上限——取值旁的件数要拿全量算，只取回一部分会把数字算小。读取完成前面板按“未就绪”呈现，不拿部分结果充当数字。展开结果按 Perk key 缓存在 workspace，折叠不清除，新搜索或 Manifest 版本变化时清理。展开区覆盖加载、失败重试和空结果状态。
- 关联装备继续使用连续列表，每个具体发布版本独立成行。左侧显示约 `40px` 官方装备图标并叠加官方版本水印；名称旁始终显示玩家可识别的发布版本，缺失时显示“版本待确认”；概要显示稀有度、装备类型、框架、弹药、伤害属性、专家标记，以及该版本支持“普通 / 可强化”的哪种 Perk 变体，随后显示历史来源或当前获取状态待确认，并可直接打开统一装备详情。同一发布版本的技术重复定义通过 canonical Hash 合并，不同发布版本保留且相邻排列；家族关联总数按所有变体的 canonical 发布版本实体取并集，不把各变体数量直接相加。
- Renderer 与 Desktop main / preload 的资料库合同必须显式握手。合同版本不支持 Perk 家族、分页关系或变体匹配时，仍可显示基础 Perk 搜索结果，但关联装备区必须提示重新构建并重启，不得把旧版固定上限摘要渲染成完整结果，也不得用空图标和“版本待确认”伪装合同正常。
- 未初始化、部分组件缺失、更新中、检查失败、历史为空和搜索无结果分别呈现；更新失败保留上一份可用资料库。
- 搜索、实时来源、收藏和别名使用独立错误状态，只影响所属区域。搜索更新期间可以保留上一份可见结果以稳定几何结构，但必须明确标记为上一次内容并在结果区使用 `aria-busy` 和独立状态播报。
- 结果操作支持键盘方向导航：同一行左右切换操作，上下移动到相邻结果的对应操作；统一装备详情关闭后焦点返回来源按钮。`760px` 及以下查询区回到页面文档流，不设置独立高度和纵向滚动；Manifest 摘要保持两列，极窄宽度再转单列。

结果区使用连续 `SurfaceList`，每行只画 `RowLine`，不把普通结果改成对象卡。

## 仓库

.xlsx），最后校验预览并确认写入；模板与选文件属于同一条导入流程，不得拆到导出分组。“从链接同步”同样走独立弹框，并且链接输入、读取后的预览与命名确认都在框内完成：读完不收框，关掉弹框（“关闭”、`Escape`、点框外）即放弃这次导入——读到的内容不得因为关掉弹框而落到页面上变成一张待确认的卡片。同一时刻只存在一份待确认的预览：打开任一愿望单弹框即开始一次新的导入，另一个框里尚未确认的预览随之放下（它同样没有写入任何数据）。“导入文本文件”同样走独立弹框：入口先开框，框内第一步是「选择文件」，选到的预览与命名确认也在本框内完成，关框即放弃——不得把预览卡摆在页面导入区（T68：同一张卡摆在页面上时被工作区宽度撑到弹框内的 3 倍宽，实测来源名输入框 1476px vs 490px，用户看到的就是“起名样式不一样”）。校验后的预览卡按“文件与来源说明 / 导入件数 / 后续动作”分栏，命名与确认（来源名输入框加“新建 / 覆盖”两个互斥动作）独占卡片的一整行，不得挤进内容分栏；来源名预填一个默认值供用户修改——本地文件导入取文件名去掉扩展名（只剥最后一段扩展名，剥不出东西时退回原名），从链接导入取链接末段文件名去掉扩展名（同样只剥最后一段，百分号转义先还原），对已有来源再同步时预填该来源现在的名字（于是只剩“覆盖”可点），这一层是统一的命名规则，不得按导入格式分岔。链接弹框内的反馈（例如链接读取失败的原因）必须显示在该弹框内，不得只写在被遮罩盖住的页面上。来源名预填一个默认值供用户修改——本地文件导入取文件名去掉扩展名（只剥最后一段扩展名，剥不出东西时退回原名），从链接导入取链接末段文件名去掉扩展名（同样只剥最后一段，百分号转义先还原），对已有来源再同步时预填该来源现在的名字（于是只剩“覆盖”可点），这一层是统一的命名规则，不得按导入格式分岔。每个来源行直接提供“查看详情”和启用 / 停用 / 移除操作。同一页的导入区与来源列表共用一次存储改动：导入、覆盖、移除或清空成功后，页内的来源列表、规则数、武器数和启用状态必须当场同步，不允许出现“上面已列出这份来源、下面仍写着还没有可管理的推荐来源”的旧快照。“已导入来源”清单在一页里只有一份（来源管理区），导入区只保留导入与导出操作，不复述同一份清单；“移除全部来源”这类整份清空的确认文案必须指向保留下来的那个删除入口。所有需要二次确认的动作（停用 / 启用 / 逐份删除 / 移除规则 / 移除全部来源 / 清空规则）都走共享确认弹框：确认是盖在页面上的一层，清单原地不动，取消或 `Escape` 收回后焦点回到触发它的那个按钮；不得在内容流末尾条件渲染确认条，那会把清单顶下去、被问的那一行还留在上面，同一件事也会因此有两份实现。框里的确认按钮取「确认 + 行上那个动作」，与触发它的行内按钮不同名——同名按钮在一页上出现两次时，遮罩只挡得住点击，挡不住查询与读屏。确认弹框叠在详情弹框之上时，下层把键盘整个交出去（判断自己是否已 `inert`），否则 `Escape` 会先把下层关掉、`Tab` 会把焦点抢回来。逐份删除也只有这一个入口，不得保留第二条按名字直接删文档的旁路实现。来源行的计数分三句说、一句话占一行，不许混为一谈：第一句是这份来源写了多少条规则（`N 条规则`），第二句是它**点名了哪些武器**（`列出 M 把武器`——“列出”说的是这份清单提到了哪些，与你有几件无关），第三句是**对你的影响**、两个范围并排（`仓库 A 件 / 全账号 B 件`）。三句必须真的分行：数字栏定死 `210px`，拼成「`N 条规则 · 列出 M 把武器`」时实测 198px、只剩 12px，规则数上万就会把「武器」挤到下一行——排版改动以真实样式表量出的数字为准，不拿截图看着正常交差。全账号含角色身上、背包与邮政官；两个数由服务端同一次算出（全账号 = 仓库 + 角色侧），界面不得自己各数一遍。行上的“仓库”数与仓库浏览页来源清单上那个数同一口径（清单那个跟着当前筛选走，未筛选时两处相等）。三句数字上要挂一句悬停说明，解释“列出”“仓库”“全账号”各指什么；每一句在来源列表行（两处标记）与详情弹框标题三处共用同一组文案函数（弹框标题是一行通排、不设宽度的文字，可以用前两句拼成的长句），不得各拼各的。来源列表的粒度是“一次导入 = 一行”：行名取导入名，“移除”作用于整份导入，仓库浏览装备里的来源筛选与它同一把键——事实层仍按具名来源逐条登记，消费层必须先按名册给出的对应关系把事实归到所属的那一行再筛选，不得两处各拿一把键直接比对，否则勾选来源后整页计数会归零。来源行的命中筛选按“分段控件的边框只包住自己的选项”排布，不得把分段控件撑满整栏（框内会空出一大片，且各行空得多寡不一）；控件保持在原位，不为了填满空当把它推成靠左或靠右的一团，两个下拉各占一个定宽栏目以保证逐行对齐；窄屏放不下时换行而不是撑成空框。来源行的计数栏不从属于这一行自己有几个按钮：按钮栏的宽度由这份清单里最宽的一行决定（清单与行共用同一套栏宽），于是删掉一行、或某行的按钮换成长短不同的文案都不会让计数栏逐行错位；计数栏定宽并靠右对齐，不用等宽数字以外的排布。窄屏收回单栏时清单与行必须一起收回，只收其中一个会让另一个继续按两栏排。详情、规则列表、来源作者 / 清单分组和完整匹配依据统一使用带焦点限制和返回焦点的弹框，不在页面中展开长列表。

一个愿望单文本导入文件是一个顶层来源，但文件内**具名的**作者、攻略站或专题 block 各自成为一个来源实例，在来源选择列表里各占一行（来源名取该 block 的标题 / 作者，与人工推荐 CSV 的“推荐来源”列同级；没有名字的 block 归入文档级来源，不生成“未标注来源 #N”行）。多个不同的愿望单文本文件按文档标题、来源地址或指纹分别显示。管理面（导入、覆盖、停用、移除）按**导入文档**为单位，一个导入就是一条可管理来源；对整份文档的停用 / 移除会继承到它下面全部来源实例。该文档内作者、主题分组的完整列表在文档详情弹框中查看。

发布方来源原始规则只读；玩家点击“移除规则”时写入可恢复的本地排除层。所有来源均可按来源停用或移除，且只影响该来源；整份数据删除必须二次确认。来源或规则变化通过推荐 revision 事件局部更新受影响武器，不触发 Bungie Profile。批量整理预览存在时禁止修改来源；revision 变化后旧预览立即失效。

武器推荐知识库 CSV 是主要中文推荐数据：选择文件后只展示文件名、武器数、来源记录数、来源数和错误摘要，完整校验成功后仍需明确确认才替换 SQLite 知识库。愿望单文本是玩家导入的来源格式之一，与人工推荐表格同级，不转换成 CSV；应用不内置上游地址、不替玩家挑来源，也不在启动或后台自动同步，只提供两条由玩家发起、都要确认才写入的入口：把一份愿望单文本的链接贴进弹框，或在一个弹框里选择一个本地 `.txt` / `.wishlist` 文件。两个入口的弹框都按内容收窄（与人工表格导入弹框同一宽度），链接输入与「读取链接」同一行、按钮与输入框底对齐，说明单独一行灰色写在下面；本地文件那条框内先是一行「选择愿望单文本文件」加一个「选择文件」按钮，选到的内容与链接读来的走同一张预览卡（第一栏的文件名换成文件名与来源说明）。窄窗口下三者依次纵向排列，互不重叠。删掉一个入口时，它挂在样式表里的选择器要一起办：类名换了而样式没跟上，表现不是“少了一块样式”，而是退回默认流——按钮贴到输入框下沿、说明与按钮挤在同一行，看着像样式写错了。链接读来的内容与本地文件走**同一条流水线**——语法解析、定义池校验、预览（可导入条数 / 跳过行数 / 问题示例）、命名与显式新建或覆盖，两条路对同一个文件必须给出同样的校验结果。链接随来源记下，来源管理行上的“同步”可再次拉取：内容指纹没变就明确告知“已是最新”且不动库，变了才进入覆盖确认；本地文件来源没有链接，因此没有“同步”。失败一律保持当前活动数据不变，并给出改用本地文件这条退路。没有“粘贴文本”通道，也没有任何写死的上游地址。名称、规则数和武器数按来源展示在来源管理区，每一行在来源名下面、启用状态前面标出这份来源的**来源格式**（「推荐表格」/「愿望单文本」）：说法取自导入时记在存储里的来源类型，不按来源名、链接或来源键猜，界面只负责照原样显示——加一种来源格式只需要给格式补一个用户说法，界面代码不动。已导入来源不再按 commit 之类的上游元数据命名或对账。两种格式的导入或替换都必须先解析并展示预览，再由用户明确确认；失败时保持当前活动数据不变。愿望单文本预览除统计信息外，还要列出被忽略的问题行数、涉及武器数、整体跳过的武器数与每一类问题的示例：笔误行按行忽略，其余正常行照常导入；**丢弃问题行把原本写全的一组候选拆残时，该武器这部分规则整体跳过**（作者本来就写成互不相干独立组合的，仍按“不能归约时保持一行一个完整组合”展示，不因一行笔误连带删掉其余好组合）。按行忽略的判据是「这一行按来源本意无法成立」：写法不成立、同行重复写同一个 Perk、同一栏写了两个 Perk；资料库里查不到该武器的定义时不做归栏判定——那是应用看不见，不是来源写错。作者把「每栏任选其一」摊开写成多行时，多写的行同样落成「同一栏写了两个 Perk」，但那不是笔误：这些行写到的 Perk 已被同一把枪留下的某一行整个包含，丢掉不改变任何匹配，读取期本来就会把留下的行归约成同一组候选。这类行按**展开写法的冗余**单独计数（行数 + 涉及武器数），既不进问题清单也不算跳过行数，用中性语气说明，不得与红框抢位置；写进库的规则与从前逐条相同。认作冗余要同时成立：留下的行确实凑得出完整一组候选、被丢的那行写到的 Perk 全在留下的某一行里、且这行本身没把同一个 Perk 写两遍（写了两遍的优先按笔误报，否则「你把一个 Perk 写了两遍」这条提示永远不会出现）。一份正常文件因此不再因为展开写法被报成「坏了一大半」。保存、替换或移除后自动重新计算当前账号匹配，不要求刷新整个账号或重启应用。

推荐结果首屏直接显示当前账号装备和已配置来源的命中结果。来源列表行内提供启用状态与命中条件，默认展示第一个可用来源的结果；玩家可以在来源行切换来源或叠加多个来源，所有来源按同一套栏位口径筛选（组合集合可无损归约的归约为逐栏候选，不能归约的按最佳组合）。来源即使当前账号覆盖为 0 也保持可见。每行显示武器身份、真实位置、来源命中摘要和“查看依据”，其他来源、作者分组、六项证据、用途与保护原因进入详情弹框。没有推荐数据时显示中性空态和两个导入入口；不得把 Hash、JSON、SQLite 路径或 CSV 逐列规则编辑暴露给普通用户。

正常状态保持安静：仓库页只显示账号最近同步时间和必要的推荐可用状态；推荐来源工作区允许常驻紧凑来源列表，但不再显示四格矩阵、逐阶段扫描说明或重复结果解释。规则总数、revision、commit、作者分组和“复制验收报告”归入来源详情弹框或设置诊断。异常、部分可用或未配置状态使用固定高度状态区显示原因和唯一主操作。

Armor Planner 缺口继续提供“查看 Planner 引用”，只携带稳定 `result_id / candidate_id`，不承诺恢复完整求解结果；仓库不再提供独立个人目标编辑或目标工作区。

筛选范围只提供武器、护甲和装备，不提供“全部”与“其他”入口。武器槽位只显示动能、能量和威能；武器模式另设“查看范围”，默认进入“仓库整理”，只向玩家提供仓库整理、当前背包、当前已装备、当前邮政官和其他角色，并固定在结果命令栏展示，不再进入左侧筛选栏。“随身待检查”与下方具体位置重复，“全账号武器”只属于内部跨页定位范围，二者均不显示为筛选按钮。跨页定位具体武器时允许临时使用内部全账号范围，退出定位或重置筛选后恢复仓库整理。切换到护甲时隐藏位置范围并保持护甲只读仓库数据的原有语义；护甲部位显示头盔、臂铠、胸甲、腿甲和职业物品。武器类型使用真实 `item_type`，稀有度使用 `tier`，装备阶级使用 `instance.gear_tier` 并包含 T0，伤害属性使用实例伤害类型；护甲职业使用 `class_type`。护甲套装选项目录来自当前语言 Manifest 的完整 `DestinyEquipableItemSetDefinition`，账号装备摘要中的真实 `equipableItemSetHash` 只用于匹配物品和计算持有数量；未持有的套装仍保留在目录中并允许选择，命中为空属于正常筛选结果。目录加载中或不可用时必须显示明确状态，不得回退成账号持有套装列表。制作状态只使用 Bungie `DestinyProfileItem.state` 的 `Crafted` 状态位，并结合 `DestinyInventoryItemDefinition.inventory.recipeItemHash` 确认“锻造”；不得按名称、Perk 或图样进度猜测。缺少稳定账号字段的框架不得用固定选项补造。武器模式提供锻造状态筛选，只分“可锻造 / 非锻造”两档：`crafting.kind` 为 `crafted` 即“可锻造”，其余全部归“非锻造”（含普通武器）。武器框架使用单选下拉展示（全部框架 / 单个框架，各自带命中数量），不使用多选 chips 或展开列表。锻造与武器框架在切出武器组时重置为全部，并参与重置按钮与已生效条件摘要。

筛选列表保留现有左侧条件，武器与护甲按实际结果容器宽度布局。武器卡片宽度固定：标准 `260px`、紧凑 `224px`、舒适 `296px`；一行排几张由结果列宽度决定（窗口宽减左侧菜单栏），容器内 `auto-fill` 自动降列，卡片不再被拉伸去填满行宽。AI 抽屉打开后按剩余宽度重排，不维护互相覆盖的固定列数。武器卡片默认使用 `44px` 游戏图标（紧凑 `40px`、舒适 `52px`），并按密度固定高度：标准 `184px`、紧凑 `178px`、舒适 `196px`；同档必须等高，改高度要同步原生网格的 `contain-intrinsic-size`——二维虚拟网格只在第一格量一次行距。卡片高度是算出来的：2 边框 + 14 内边距 + 主区（图标身份行 + 事实行 + 3px 行距 + 来源面板）+ 底部行（按钮 + 4px 上边距）。卡片底部只有一行：左边是位置 / 锻造 / 整理状态 / 锁定与配装引用，右边是快捷操作按钮，两者并排而不是各占一行。卡片保持单一焦点目标，以便方向键移动和恢复焦点。纯护甲视图继续复用全局 `44px` 游戏图标和现有卡片内容；混合视图不套用武器专属宽度、字段或来源区域。装备阶级直接使用 `DestinyInventoryItemConstantsDefinition.gearTierOverlayImagePaths` 的官方覆盖图；锻造实例使用同一定义中的 `craftedOverlayPath` 和 `craftedBackgroundPath`，与 DIM 一样按官方图层叠在装备图标上，不用 CSS 仿造游戏图标。普通武器不挂载空图层。T0 不显示阶级覆盖图，缺失阶级在产品层按 T0 参与筛选和显示。

武器浏览模式在结果列顶部显示推荐筛选：已配置且启用的来源均可多选，允许跨格式混选并按各来源条件 AND 叠加。来源采用竖向来源列表，每个来源一行独立条件；未选中来源只显示行头，勾选后展开该来源自己的核心命中分段、其他状态下拉和完整命中下拉，行头 toggle 使用 `aria-pressed`。多个已选来源按各自条件做 AND 叠加，每个来源独立解析自己的命中事实，不要求来源之间事实键一致；每个来源的“全部”表示该来源有记录的候选。人工来源继续显示核心 Perk 的真实 `x/y / 未要求 / 无法判断 / 未收录 / 全部`，再用下拉选择完整要求的真实 `x/y`；两种来源格式使用同一套栏位口径：来源的组合集合是各栏候选的笛卡尔积时归约成「每栏任选其一」，显示 `Perk x/y · 完整 x/y`，不再显示「符合 N 套」；未归约的组合来源仍显示最佳组合 `x/y / 未指定组合 / 无法判断 / 未收录 / 全部`，不显示完整命中下拉。每行数量徽标按“其他已选来源条件 + 左侧筛选”后该来源可得到的候选计算，切换选项后数量随之更新；因此同名的命中档在不同来源行不是同一把尺子（三个来源都停在 `2/2`，各行数量各不相同属于正常），不跨行横向比较。未选择来源时显示全部当前范围装备，不用多来源综合结论作为默认筛选。宽屏行头与条件同行，结果列变窄时条件在行内换行，极窄容器再折为上下两行，不横向溢出。“浏览装备”和“推荐来源”共用同一份实例轻量筛选事实索引；浏览装备保留每来源条件，看推荐证据面板继续展示当前首个来源，切换工作区后保留来源选择。推荐核对尚未完成时，没有现成实例结果的武器不能计入“未收录”。数量为 0 的按钮保留位置并禁用。切换到护甲或装备时隐藏并重置全部推荐筛选。左侧不再显示“保护与匹配”：愿望单文本由结果列来源筛选承接，配装引用作为卡片保护事实，个人目标不再作为仓库筛选来源。

仓库带数量的筛选项使用统一分面口径：物品范围标明账号总数；武器槽位、查看范围、武器类型和框架应用除自身维度外的其他已生效条件，展示切换该选项后可得到的数量。结果区标题、结果列推荐筛选的“全部”和当前选中范围必须使用同一最终结果基数，不能让同名“仓库整理”同时展示全仓库数量和当前条件数量。

仓库结果和分面共享同一实例查询索引。物品范围、锁定、槽位、位置、弹药、武器类型、稀有度、装备阶级、职业、伤害属性、套装和框架先通过 ID Set 交集缩小候选，再执行搜索文本、玩家标签、推荐来源和护甲属性阈值等精确规则；单件锁定或位置 Patch 只更新该实例的索引记录。结果、槽位、位置、框架和类型数量不得各自重新遍历完整账号装备。

武器对象卡固定分成身份、事实、推荐 Roll 匹配与状态四层：身份层显示图标、最多两行名称、“槽位 · 类型”以及贴卡片右缘的光等；事实层显示游戏化弹药图标、官方彩色伤害属性图标和可有可无的勇士词条；匹配层紧跟事实层，标题右侧显示来源总数。正文按“来源名 / 结果”对齐展示，卡片上最多列两条：1～2 个来源必须全部显示，3 个以上显示前两个，并在标题明确显示“另有 n 个”；来源更多时卡片不放高，完整来源列表留在详情。所有来源同级，不按来源类型排权重：按该来源的符合程度排序，平级按来源名。人工来源摘要使用 `Perk 2/2 · 完整 5/6`、`Perk 1/2 · 完整 4/6` 或 `Perk 未要求 · 完整 2/3`；存在真正不可比较的要求时追加 `n 项无法判断`，只推荐武器时显示 `仅推荐武器 · 未指定 Roll`。DIM 与人工来源使用同一套摘要，显示 `Perk x/y · 完整 x/y`（来源的组合集合可无损归约成「每栏任选其一」时）或最佳组合 `x/y`，不再显示「符合 N 套」；没有来源时显示“暂无推荐来源”。每条来源摘要使用小状态点和同色结果文字，来源名称保持普通文字，不能整张卡染色，也不能只靠颜色表达结论。状态层显示真实位置、锻造文字、玩家整理状态、锁定与配装引用，并与快捷操作按钮同处卡片底部一行：状态占左侧剩余宽度并可以省略，按钮靠右，两边不再各占一行；位置使用“仓库 / 泰坦 · 背包 / 猎人 · 已装备 / 术士 · 邮政官”等玩家文案。锻造状态必须同时有官方图层和“锻造”文字，不依赖颜色或悬停理解，也不得增加第五层或改变卡片固定高度。普通浏览时没有玩家整理状态就留空，进入整理模式后才显示“未整理”；保留、待定和清理继续常驻。卡片只保留对象外框，匹配区使用单一 `4px` 内嵌状态面，不在每层重复画分隔线。

非整理模式下，对有实例 ID 的装备卡在主入口下方提供快捷操作区。武器卡的快捷操作区与卡片状态共用卡片底部这一行（状态在左、按钮在右），不再为状态单开一行；护甲与混合卡保持原来的独立操作行。未锁定装备显示“加锁”，已锁定装备在同一位置显示“解锁”；只有仓库实例显示“取出”，目标固定为当前角色。单件加锁、解锁和取出不弹确认框，同时只能运行一个快捷写操作；成功后继续由账号 Patch 维护真实状态，不额外启动账号同步或后台确认，失败显示 Bungie 返回原因。快捷操作与卡片主入口必须是兄弟节点，支持 Tab，不能嵌套按钮；加锁或解锁后焦点回到原卡片，当前锁定筛选使卡片离开结果时焦点转移到相邻卡片；取出导致当前卡片消失时使用相同规则。虚拟网格必须按快捷操作后的固定卡片高度测量和恢复焦点。

人工推荐源按已证明的武器发布身份共享来源要求：同一 `release_group` 的普通版与专家、失时、痛苦或全息箔兄弟版可以共享未限定特殊形态的人工推荐；同名历史复刻、不同赛季版本和未知括号名称必须分开。正式知识库中保留的明确推荐项全部进入分母，同栏多个候选为任选其一、不同栏分别核对，实例实际拥有即符合、没有即不符，当前 Hash 的定义池不能删除要求。Perk 1/2 是核心；玩家首层先看实际要求的 Perk 栏位命中数，再看全部明确要求栏位的完整命中数，分母按来源真实要求计算，最大为六，不固定写死。`0/2` 只表示两个核心栏都已完整核对且均未命中；核心栏数据不完整必须显示“无法判断”，不能混入 `0/2`；来源未要求核心栏显示“未要求”，来源没有该武器规则显示“未收录”。内部继续保留“全部符合 / 核心符合 / 接近推荐 / 关键缺失 / 未符合 / 仅推荐这把武器 / 无法判断”七种来源汇总状态，只用于派生、排序、保护和冲突判断，不作为逐栏、筛选或标题主文案。同一来源的多条规则在卡片、结果行和筛选事实中只占一个来源名额，并按相同优先级选取最有帮助的一条，不能跨规则累计命中。来源的组合集合可无损归约成「每栏任选其一」时归约为逐栏候选，不能归约时保持一行一个完整组合、多行任选其一；两种格式共用这一套口径，都不跨组合累计 Perk。所有来源统一按「同一 Perk Hash 或同一 Perk 名称」判定，锻造强化特征能满足同名的普通特性要求，不能因为两者 Hash 不同就判为未命中；匹配结论只能来自匹配结果（事实层）一次算出的逐栏状态，仓库卡片、推荐筛选、武器详情、推荐来源和验收报告一律消费同一份结果，任何界面都不得自行比较插件 Hash 或名称，也不得自行截断来源列表；武器详情按来源分组全量展示该武器的来源规则：组合集合可无损归约时展示逐栏候选，不能归约时展示完整组合，条目标识一律使用规则稳定 ID 而不是数组下标；卡片、详情与筛选只消费事实层算出的同一份匹配结果，摘要统一为 `Perk x/y · 完整 x/y`（可归约）或最佳组合 `x/y`（不可归约），不再按格式分别统计「符合组合数」。多个来源不累计分数；同一用途出现明确符合与明确不符合时，推荐列表显示“部分符合”；存在真正无法核对的来源时优先显示“无法判断”。`general` 与 PVE、PVP 均视为用途重叠，PVE 与 PVP 之间不直接构成冲突。来源显示名一律使用导入内容里的来源名（允许玩家自定义任意名称），来源 key 由来源名派生，不再维护固定来源字典或白名单。可选紧凑模式只缩减网格宽度和间距，不删除详情中的证据。护甲沿用现有身份、事实和状态结构，不接入 T20 来源摘要。锁定使用绿色锁形状态标记，固定在卡片底部状态行右侧并使用主题状态底板（武器卡上与快捷操作同行，锁标落在这行按钮的左侧），不再覆盖装备图标；配装引用使用应用状态文字和既有选中边框，不使用右上角单字方块。完整 Perk、框架、品质、护甲能量、逐项推荐证据和长备注留在详情，不进入普通网格。仓库页必须只生成一次实例来源摘要与轻量筛选事实索引，卡片、推荐筛选、推荐结果和账号紧凑摘要共同复用派生结果，不得在每张卡片渲染或每次筛选时重新遍历 Wishlist 和来源记录。

玩家整理状态面向玩家只提供 `全部 / 保留 / 待定 / 清理` 四个筛选入口；未设置继续作为内部“尚未作出决定”保存，不迁移或覆盖现有玩家数据。“全部”只表示取消整理状态筛选，不是玩家整理状态。内部 `keep / review / junk` 分别显示为保留、待定和清理；`farm / loadout` 继续作为既有用途标签保存，但不进入整理状态控件。锁定、配装引用和推荐来源属于系统证据，只展示事实并参与保护，不自动生成玩家整理结论。普通装备单元只显示一份玩家整理状态，并保留锁定与配装引用角标。

结果区的批量能力与正式筛选分层：普通状态只保留一条结果命令栏，同时承载推荐来源、常用精确命中、其他特殊状态、完整命中、范围与结果数摘要和“批量选择”，不再为推荐筛选、结果标题、已生效条件或批量提示分别占用整行。搜索输入、来源、其他状态和完整命中依靠控件自身文字表达，不在上方重复标题；完整筛选当前值必须带“完整”前缀。核心 Perk 或最佳组合的选项可见文字使用裸的命中档（如 `2/2`）加独立数量徽标，不能显示成难以断句的 `2/2 110`；分段组左侧已经挂着可见标签“perk 命中”，组内不再重复写“命中 2/2”。悬停与可访问名称必须由同一句说明讲清来源要求几项、其中命中几项（分子是命中数、分母是要求数），不得只把档位名念一遍：把“命中 x/y / 未命中 x/y”这类带动词的说法接在“perk 命中”之后会念成“perk 命中 命中 1/2”，不得再出现。未要求、无法判断和未收录收入“其他状态”下拉。全部筛选的重置入口与左侧搜索输入同一行，不放在结果列最右侧；按钮始终占位并使用独立计数徽标，宽屏随左侧独立滚动保持可见，无条件时使用清晰禁用态，窄屏取消固定以避免覆盖顶部工作流。

左侧筛选不复用操作按钮外观：物品范围、槽位、装备阶级和整理状态采用整体外框、内部单线分隔的分段结构；锁定是 `全部 / 已锁定 / 未锁定` 三段单选，`全部` 只表示取消该条件，不是第三种游戏状态；查看范围固定在结果命令栏，采用横向分段按钮并各自带数量，不占用左侧筛选区；稀有度、弹药、伤害属性、反勇士、武器槽位和锻造状态使用低饱和游戏事实色并在选中时增强底色与内描边。武器槽位用自绘字形区分：动能＝方块·中性蓝灰、能量＝三角·绿色、威能＝圆形·紫色；锻造沿用仓库卡片的菱形语言，可锻造＝实心琥珀、非锻造＝空心中性，两处都不得仿造游戏图标，也不得只靠颜色表达状态。左侧筛选不再使用分区标题，改为固定顺序的连续筛选块：搜索 → 类型 → 模式专属条件 → 锁定 → 玩家标记 → 结果排序。武器模式的专属条件顺序固定为槽位 → 弹药 → 伤害 → 反勇士 → 阶级 → 稀有度 → 锻造 → 武器类型 → 武器框架；护甲模式为部位 → 职业 → 阶级 → 稀有度 → 护甲套装 → 护甲属性条件；装备模式为位置。顺序不能因为数量变化动态跳动；同一控件的动态选项按可得到数量降序，数量相同保持稳定语义顺序。字段边框弱于 Secondary 操作边框，焦点仍使用共享 `2px` 焦点环。进入批量选择后，在命令栏下方展开“已选 n 件 / 选择当前结果 / 清空选择”和独立批量操作区。不得保留“浏览 / 选择候选”伪 Tab、重复物品范围下拉或按清理、待定、备注再次选候选的下拉。玩家先通过左侧与结果列推荐筛选形成当前结果，再显式选择当前结果。批量整理只提供保留、待定和清理；“清理”是可逆本地状态，不使用危险按钮表面。批量加锁、接收角色和移动仓库所选属于写操作，不得混入筛选。没有已标记清理装备时不显示清理转移说明；已标记清理装备的转移入口保持为独立已保存状态操作。

“推荐结果”按武器实例逐行展示，不按 `itemHash` 合并同名副本。结果主文案直接显示所选来源的精确事实，所有来源共用同一套口径：组合集合可无损归约时显示 `Perk x/y · 完整 x/y`，没有核心要求显示 `Perk 未要求`，不可归约的组合来源显示 `最佳组合 x/y`；无法判断、未指定组合和未收录必须使用独立文字，不能再回退为“符合推荐 / 部分符合 / 未符合”三种模糊描述。来源之间不再互相改变筛选事实，多来源冲突只在综合摘要、保护判断和详情依据中保留。筛选只帮助玩家找到下一步，不生成保留或分解决策。用途、位置、玩家标记和更细状态作为“更多筛选”，允许重叠。只有完整核对状态才允许列出所选来源未收录的实例；部分或失败状态继续保留上次结果。每行只显示实例身份、真实位置、所选来源精确命中摘要，并提供“查看依据”；人工标记、全部来源、六栏逐项证据、完整来源组合和规则说明进入详情。“如何判断”解释这些是匹配证据而非系统评分，来源未收录与来源已有规则但零命中必须区分。

账号武器推荐核对仍维护 idle、scanning、partial、complete 和 error 五种运行状态；玩家文案固定为“尚未核对 / 正在核对推荐 / 部分核对完成 / 已核对 N 件 / 推荐核对失败”，不得使用容易与逐栏结果混淆的“待核对 / 部分可用”。正常完成态只更新短状态与时间，不占用独立统计区。只有已完成状态才能把空结果解释为当前账号没有来源记录；正在核对、部分核对完成和失败不得把未显示的武器解释为未收录。账号刷新后旧结果保留到新核对完成，重新核对失败继续显示上次结果并说明其状态，不得清空已有结果，也不得把推荐核对错误混入最近活动错误。资料库未准备、资料库版本落后和推荐知识库不可用使用稳定结构化原因，不从错误字符串推断。推荐扫描只处理武器实例，护甲不进入 T20 扫描；“复制验收报告”移入设置诊断，只读取当前账号和扫描结果，不写标签或游戏数据。

护甲多条件为 AND，同一属性只保留一条；总属性只作为排序维度。仓库结果排序保留名称、分组、品质、光等和护甲属性等规则；选择“推荐权重”时按推荐优先级（优先级 → 比较 → 未收录）、同级命中率与命中数、来源权重和稳定名称排序。工作流栏只承担两个任务入口、当前角色切换和必要运行状态；切换器夹在页签与右侧状态徽标之间，账号武器总数、当前结果数等重复统计不得挤占工作流栏。推荐筛选、结果摘要、查看范围与批量入口按上述单条结果命令栏承载；重置全部和结果排序固定归属左侧筛选区，排序不得移入结果命令栏。

同名整理工作台已移除；同名装备继续在普通仓库结果中按实例展示，比较和完整 Roll 证据统一进入装备详情。

实例保护与匹配依据分开展示。锁定和精确实例 ID 配装引用属于实例保护；仅按 Hash 或部位匹配的配装需求明确标为“配装同款”，推荐来源和历史社区数据保留在匹配依据中，不得让同 Hash 的每个实例都显示为精确配装引用。

同名装备不再提供独立整理工作台；需要比较实例、完整 Roll 或来源证据时，直接打开装备详情。

写操作继续调用真实 action / IPC，失败前不得提前修改锁定、位置或标签显示。

## 商人

稳定契约：`vendors.workspace`。

- 商人工作区使用“地点目录 / 商人详情”两栏结构，不保留重复的右侧上下文栏。来源、读取时间、重置边界、可见条目和当前角色库存上下文合并到商人头部与状态条；普通产品界面不显示角色长 ID，也不使用全局核验总量占据当前商人的决策空间。
- 商人页不单独维护角色选择器，角色视角由账号页的当前角色统一决定；账号页切换角色后，商人页通过新的 `character_ids` 请求重新读取并替换当前角色快照。仓库工作流栏的切换器是同一份当前角色的第二个入口，改的是同一个共享状态，不是仓库自建的选择器，商人页口径不变。商人页不得伪造账号合并库存、静默保留旧角色库存或把角色长 ID作为可见标签；当前角色上下文只显示玩家可识别的角色信息与机灵状态。
- 目录按真实地点和稳定 `vendorHash` / ID 分组，使用紧凑文字行，不显示头像或首字母占位。目录提供商人、物品和分类搜索，命中当前商人物品时详情同步收窄到匹配条目，命中商人名称时保留完整库存；搜索保留真实地点归属。正常商人行只显示条目数量，读取失败和部分可用才追加异常状态。窄屏目录转为单行横向滚动，方向键随布局切换为左右导航。
- 详情先显示声望与等级，其余章节保持商人结构定义的业务顺序；未配置的基础服务和任务位于已配置的主库存、周常奖励、聚焦等核心章节之后。不用分类摘要替代完整库存。声望面板必须明确显示等级上限、距离下一等级和“可领取下一等级奖励 / 已达等级上限”状态，不得把无法确认的奖励节点伪装成可领取按钮。商人状态条下方提供单行吸顶章节导航，滚动后固定在共享页面标题栏正下方，只定位现有章节，不切换或隐藏库存；当前章节必须有明确选中态，窄屏允许横向滚动。
- 每个商人章节标题必须显示真实业务作用域和动作（如“当前角色 · 游戏内购买”“账号 · 领取”“公会 · 获取”）；业务作用域来自 ViewModel 的 `scope`，动作来自 `action`，不得根据章节名称猜测或把账号级奖励写成当前角色库存。这里的业务作用域不是角色选择器，当前角色只有账号页和仓库工作流栏两个入口，两处改的是同一份状态。
- 商人状态条提供局部“只看可负担”和“账号无同身份实例”筛选，使用 `aria-pressed` 表达当前状态。“账号无同身份实例”只作用于武器和护甲，账号状态未知时保持禁用，不把材料、任务或未知状态误判为缺失。筛选只改变当前详情的呈现，不修改快照、目录数量或真实库存；结果为空时保留清除筛选入口，章节导航只包含筛选后仍有内容的章节。
- Offer 网格中的可打开装备卡支持左右切换、按当前列数上下跳转以及 `Home / End` 首尾定位，焦点移动时滚动到可见区域；只读材料、任务和服务行不进入装备卡导航。
- 没有应用内操作能力的非装备直接库存和任务继续保留真实 Bungie 事实，但使用紧凑信息行并明确标记“游戏内使用 / 领取”或条件状态，不得显示成可在应用内点击购买的装备卡。
- 每个 Offer 显示真实图标或缺图态、名称、类型、摘要、成本、数量、购买状态和失败原因。成本在余额可用时同时显示“持有 / 需要”；购买能力必须写成“游戏内可购买”或对应失败原因，装备卡的应用内动作明确为“查看详情”，不得暗示应用可以直接购买。
- Offer 在身份信息下方显示账号拥有短状态；随机 Roll 武器与护甲使用“账号有 N 件同身份装备 / 账号无同身份实例”的中性文案，非装备条目使用“账号已有 N 件 / 账号未拥有”。状态未知或部分读取时必须明确表达，不能伪装为未拥有；装备详情同时展示已有实例位置和账号数据时间。商人页不生成推荐分数或“必买”结论。
- 角色相关库存显示当前角色上下文，不跨角色合并库存。
- 武器和护甲 Offer 可打开统一详情；材料、任务、解码器和其他对象只显示库存事实。
- 读取时间和重置边界使用原始时间字段在渲染时格式化，不保存预格式化文案。
- 加载、未开放和失败时清除过期轮换；部分可用时展示已确认销售数据并标记缺失属性或插槽。

Offer 使用响应式对象卡网格：宽屏五列，`1280px` 三列，`980px` 两列，`760px` 单列。章节和目录保持连续直角结构，不建立水平商品轨道。

## 工具导航

稳定契约：`directory.workspace`。

- 这个菜单是单页，进去就是工具站清单，不再套子页导航。站点数据在 `packages/ui/src/directory/toolDirectory.ts`，只存公开地址和一句话用途，不复制站点内容、图标或数据，也不发网络请求。
- 顶部命令条放分类分段控件、关键词搜索框、结果计数和「清空筛选」。分类与搜索是与关系：先按分类过滤，再在结果里按 `name` / `purpose` / `note` 做大小写不敏感的子串匹配。筛不到结果时给出空状态和清空入口，不显示空分组。
- 主区按分类分组，每组一个小标题和计数，下面是卡片网格。卡片是独立对象，用 `object-card` 面；网格本身不画外框。
- 「仅参考」「已归档」级别的站点收在页面底部的折叠区，展开前不占首层位置。
- 每条站点保留调研里的真实字段：站名原文（不翻译）、一句话用途、使用方式、注意事项和可用地址。没有的地址不显示，也不写「未提供」。
- 所有外链走平台 `openExternal` 回调，页面组件内不调用 `window.open`；桌面端用系统浏览器打开，Web 端用 adapter。没有外部回调时退回 `<a target="_blank" rel="noreferrer">`。
- 分类条是分段控件，选中态使用共享分段控件配方；键盘按横向 roving focus 移动。页面按容器宽度响应，搜索框在窄屏放开宽度限制，卡片网格收成一列。

## 配装边界

稳定契约：`loadouts.workspace`。本文件记录共享配装页必须保持的页面与交互边界；游戏内配装与应用配装是两种独立业务对象，应用配装的方案库、对比、决策工作区、自动配甲和安全穿戴共享同一产品实现。

当前领域能力已落地应用配装页面栈、方案库只读详情、2–3 方案差异矩阵、固定三武器/五护甲槽位、逐槽位实例选择、自动配甲、穿戴核对与保存到游戏内槽位后续动作。应用配装编辑器使用“完整构筑画布 / 实时摘要”两部分工作区；自动配甲、候选比较和更多规划方式在护甲区域原位展开，不替换完整构筑上下文。Desktop 与 Web 通过同一共享页面消费应用层 ViewModel。账号 freshness、未保存离开保护、焦点恢复和 `1280px / 980px / 760px` 响应式边界属于该稳定合同。

- 全局侧栏只保留一个 AI 工作台，不显示固定“任务”Tab 或攻略任务树。攻略链接、正文和 AI 整理文本统一从配装页的攻略导入区进入。旧侧栏保存的攻略文本只做一次性恢复，成功生成草稿后清除。
- AI 工作台的 `guide_capture` 交接会直接打开配装页并预填一份未保存的攻略文本；玩家继续选择角色、执行解析与账号核对，再决定是否保存方案。`armor_solution_comparison` 与 `equipment_target_candidates` 仍进入配装页对应的专用审阅。
- AI 工作台的 `equipment_target_candidates` 交接使用专用候选审阅，不经过攻略文本解析。候选列表必须区分账号真实实例和仅 Manifest 定义，允许逐项复选并显示目标角色；确认后只生成 `assistant-targets` 未保存草稿。真实实例绑定 `selected_instance_id`，仅定义候选只写 `item_hash` 并保持待获取、待选择，不能伪造实例或自动保存。
- 一级视图只保留 `游戏内配装` 和 `应用配装`。两者不是同一方案的来源筛选：游戏内配装是 Bungie 官方角色槽位，应用配装是本应用保存的完整构筑方案。自动配甲不是第三个一级页面、方案类型或来源。两侧的数量上限不同：游戏内槽位每个角色只有 10 个，由官方数据决定；应用配装只受本地存储限制，能存多少套没有上限。同一套构筑可以同时出现在两侧，界面保留两条独立记录，不合并、不互相覆盖，也不因为内容相同而隐藏其中一条。
- 两个来源之间靠标记互相引用，不靠合并记录。应用配装一侧标出该方案在游戏内槽位上的状态：与方案一致的槽位、当前已装备的槽位、当前角色可穿戴的槽位；游戏内槽位一侧标出它对应哪个应用配装。标记只在账号已核对时出现，账号未读或槽位内容变化后回到未核对状态，不按名称或相似配置猜对应关系。判定只覆盖**装备与子职业**两层：护甲约束、优先级和备注是应用侧独有的设置，游戏内不返回，参与相等判断会把每一套都判成不一致。比对结果是「一致 / 不一致 / 未返回」三值，未返回不等于不一致。应用配装一侧按「内容一致的槽位 → 角色当前装备就是这一套 → 目标角色身上有可穿戴对应槽位 → 未对应游戏内槽位」取第一条成立的；游戏内槽位一侧只认内容一致。两侧都只在说得清时才给标记，账号快照未读时不出现，标记本身是即时派生值、不写回方案文件。
- 游戏内配装显示 Bungie 官方槽位与官方应用能力；核心操作使用 `应用游戏内配装`、`复制到应用配装`、`用当前装备覆盖槽位` 和 `清空槽位`。复制只携带官方实际返回且可确认的字段，打开未保存的应用配装编辑器，不立即创建已保存方案。
- 应用配装默认进入已保存方案库，首屏提供搜索/筛选、只读详情、穿戴状态、`对比方案`、`新建配装`、`穿戴此方案` 和 `编辑方案`。目录只显示已经显式保存的应用配装；草稿不进入目录。
- 应用配装对比允许选择 2–3 个方案并默认突出差异。游戏内配装可以作为只读参照快照参与共同字段比较，但未知字段必须显示 `未返回`，不得因此转化为应用配装或与应用方案共用身份。
- 新建和编辑推入唯一的应用配装决策工作区。宽屏主区持续展示子职业紧凑摘要、三件武器和五件护甲，右侧持续显示最终六维、目标差值、缺口、浪费、套装、能量、缺失和可执行状态。六维、碎片、套装、实例限制和逐部位模组规则都在护甲区域展开；候选不会替换完整构筑画布。顶部保存状态、`保存` 和 `穿戴` 持续可见；点击槽位在当前画布上打开真实实例选择抽屉，关闭或选择后恢复来源焦点和编辑状态。
- 进入编辑、自动配甲、穿戴核对或发布等聚焦流程后，收起配装菜单外层的角色/视图/新建工具栏和常驻就绪状态，只保留当前任务需要的返回、方案身份、保存状态、保存与穿戴操作；错误和进行中状态仍在邻近区域显示。保存不得在顶部和底部重复出现。
- 装备槽位使用鼠标优先交互：空槽和已选装备的主体区域均为完整点击目标，悬停时明确显示选择方向；清空等破坏性较低的次操作保持独立按钮。点击槽位在当前构筑画布上打开右侧实例选择抽屉，抽屉提供槽位内搜索、候选数量、整行选择、遮罩关闭和 `Escape` 关闭；候选必须基于真实账号位置区分已装备、角色库存和仓库，当前已选实例置顶并显示“当前”，同时展示位置、光等、武器真实 Perk 或护甲最高属性等选择信息，搜索可以匹配 Perk 名称。选择后写入草稿、关闭抽屉并恢复原槽位焦点，不推入一张替代构筑画布的整页列表。
- 编辑头部的目标对象优先选择当前账号真实角色，并同步职业与目标角色 ID；账号不可用时才保留职业文本输入。方案名称、保存状态、保存和穿戴收敛在同一个吸顶编辑栏中。
- 新建空草稿不得只展示大面积空装备卡。中央先提供“从当前装备开始”“按属性目标自动配甲”“手动选择装备”三个真实起点；三武器使用紧凑横排，五护甲作为中央主要决策内容。子职业优先表达已确认的分支、星相、碎片和技能语义，Hash 只作为未解析诊断信息；没有真实编辑 action 时必须明确标记“当前仅记录”，保持静态对象样式，不伪装成可点击入口。
- 新建、当前装备复制、攻略链接或正文解析、AI 成果和游戏内槽位复制都进入同一个未保存应用配装编辑器；DIM 先完成链接读取与预览，再进入该编辑器。攻略导入区是配装页内的统一入口，不维护独立攻略页面或平行编辑 DOM。草稿在进入编辑器时自动创建，保存是玩家的显式动作：没点 `保存` 就不写本地文件，草稿不出现在方案库里，离开编辑器时按未保存修改拦截。编辑栏持续显示 `尚未保存` / `有未保存修改` / `已保存`，三个状态各自对应真实的落盘情况。
- 新建应用配装的入口按玩家的四种动机组织，不按功能模块组织：**存下现在这一身**（读当前角色正穿的武器、护甲和子职业落成草稿）、**抄一套**（攻略、视频或 DIM 链接解析后填进草稿）、**凑一套**（起点是仓库，不读当前装备）、**改一套**（从方案库打开已存方案改一件）。四条路共用同一条主干：定来源 → 装武器 → 定子职业 → 调护甲 → 挑候选 → 核对能不能穿 → 落盘；差别只在第一步带进来什么、哪几步是空的。存下现在这一身不强制跑护甲规划，这身的六维没达标也能原样存下来；凑一套一进来就是护甲规划，三把武器先空着，护甲落定后再补；改一套的出口有两个——`存回原方案`（覆盖原方案）或 `另存为新配装`（新建一套，原来那套不动），游戏内槽位那一侧没有对应能力，Bungie 的槽位只能整体覆盖。
- 武器和护甲必须选择真实账号实例；同名多实例不静默代选。子职业、目标 Perk、星象、碎片、技能和模组只有在稳定 Hash 与可写能力可验证时才进入执行计划，其余保持“仅记录”。
- 护甲规划位于应用配装编辑器的护甲区域，玩家入口文案使用 `按属性目标自动配甲`。它是护甲构筑主命令和编辑器内部状态，不新增第三个一级页面。展开后只保留“配装设置 / 推荐方案”两部分，方案摘要进入推荐方案顶部，不再维持第三个固定侧栏；接受方案后原位填入五个护甲槽位并收起规划区，不立即保存或穿戴。默认直接使用“当前库存”；“理论上限 / 待刷目标 / 升级路径”与套装、固定/排除、碎片变化和位置范围一起放入折叠的更多条件，不要求普通玩家先选模式。
- 属性模组输入以头盔、臂铠、胸甲、腿甲和职业物品五条独立规则为真相，每条使用 `自动 / 不安装 / +5 / +10`；固定 `+5 / +10` 后允许继续锁定具体属性。全局 `+5 × N / +10 × N` 只从五条规则和候选结果派生，用于摘要、比较和旧方案兼容，不得继续作为新方案的唯一输入。
- 属性模组输入分别使用 `+5 属性模组` 与 `+10 属性模组` 的精确数量，总数不超过五件护甲；T5 护甲调整由计算器逐件自动选择，零能量且不计入属性模组数量。库存与升级候选必须按五个具体部位的 Socket、草稿耗能功能 Plug、候选未覆盖 Socket 的现有耗能 Plug 和剩余能量分配属性模组；未安装属性模组的部位必须规划真实零能量清空 Plug。页面逐件显示护甲调整、属性模组、其他模组占用和最终能量，不得只展示五件聚合预算。
- 护甲约束支持 Manifest 可确认的 `2件 / 4件 / 2+2`、位置范围、固定异域、锁定和排除。理论模式不要求账号且只输出理论身份；待刷模式区分已有、待升级、待核对和待获取；库存与升级模式才允许选择真实实例组合。
- 护甲计算统一消费 `@d2-tools/app/armor` 的 `ArmorPlannerWorkspaceState`，页面不得继续直接调用旧 `solveLoadoutArmorCandidates`。Desktop Adapter 在主进程补齐当前 Manifest 规则集、套装目录和账号护甲快照；页面只提交职业、目标、约束、位置和实例选择条件。
- 护甲重算是手动动作，不随输入变化自动开跑。会作废候选的输入分三类：护甲要求（六维最低值）、模组调整（逐部位属性模组规则与 `+5 / +10` 预算）、技能与碎片读数；规划方式、优先顺序、套装要求、装备范围和装备目标的改动同样作废。改动后屏幕上的候选继续显示，同时打上 `设置已变化，需要重新计算`，重算按钮成为该区域唯一的主操作。脏状态要点名是哪一类设置变了，不能只写一句“设置已变化”，因为重算范围不同：模组改了装备组合往往不变，六维目标或碎片改了可能整套都要换。这条脏状态必须同时禁用 `使用这套方案`，玩家不能把按旧设置算出来的护甲写进草稿；重算失败或中途离开再回来，脏状态还在，只有重算成功才清除。`stale / error / indeterminate / unreachable / invalid` 必须分别显示真实状态和领域警告。
- `使用这套方案` 的禁用不是提示，是护甲要求和碎片这两类输入唯一的一道闸门。模组调整在执行前还有一次核对：`validatePlannedArmorAssignments` 会逐部位比对 `自动 / 不安装 / +5 / +10` 规则、指定属性和旧式预算，不一致就判缺口并清空执行步骤，报错至少发生在穿戴那一刻。六维最低值与 `fragment_stat_bonuses` 没有被任何执行前校验消费，改动后拿旧候选执行会被放行，摘要区显示的差值只是文字、不拦人。
- 手动重算的依据是实测耗时：在 389 件术士护甲池、strict 模式、默认 `state_limit` 2000 下，一次计算的中位耗时从 1.7 秒到 23 秒，随每件护甲的可选装法数量增长。基准把 `installation` 按规则集常数合成补上快照缺的字段，这份数字读作耗时包络，不是某次真实点击的精确毫秒。
- 搜索截断必须让玩家看见。`truncated` 目前只到 ViewModel，没有任何界面区域消费它；推荐方案区要把它渲染成真实警告并说明结果被搜索上限截断，不能让截断结果看起来像完整搜索。
- 四种推荐方案共用逐属性比较、必须满足的要求、距离目标、模组用量、超出目标的属性和套装效果；首层直接显示六维、目标差值、距离目标、超出目标、套装以及转移/替换/缺失数量，展开后逐件显示部位、护甲、调整、属性模组、其他模组、能量和状态。理论方案显示框架、第三属性和调整身份，待刷方案显示缺失与已有匹配，库存方案显示位置与转移数，升级方案显示保留件、替换数和步骤。允许选择 2–3 个方案进行比较；比较不修改草稿，选择库存或升级方案只填入应用配装的五个护甲槽位并返回编辑器，不立即保存，也不触发 Bungie 写操作。
- 屏幕上声明的数量必须与真实渲染的条数一致。推荐方案区写「N 个结果」就要给出 N 个候选卡；游戏内槽位按每个角色 10 个画满，不能只列有内容的那几条。数量对不上时玩家会当成结果被截断或漏算，而不是当成省略。

- 护甲设置中的五个部位直接提供 `自动 / 不装 / +5 / +10`；固定数值后才出现属性选择。属性优先使用可见的有序列表，不使用无序复选框保存隐藏点击顺序。数据尚未读取时只显示一条中性说明，确认安装冲突后才显示对应部位和玩家可行动原因。
- 普通玩家路径统一使用 `模组插槽 / 模组 / 当前游戏数据 / 具体装备 / 配装要求 / 必须满足 / 推荐方案`。英文 `Socket / Plug / Manifest` 仅保留在领域合同、诊断复制内容或显式技术详情中，不进入标题、表单标签、常驻状态或普通错误恢复文案。
- `保存应用配装` 只持久化应用方案；保存后才能稳定生成穿戴计划。`穿戴此方案` 使用 `plan / execute / refresh` 边界，包含真实转移、来源角色释放、当前装备替换和可验证 Plug 写入，失败时停止后续步骤并展示真实结果。
- 攻略链接、正文和 AI 整理文本只作为当前导入来源，不保存独立文章、正文快照或派生关系。来自装备目标的 Armor 引用只展示缩短后的结果与候选标识，并明确要求按当前账号和规则重新计算，不伪恢复未持久化候选。
- DIM 导出位于方案应用区，只对当前账号已核对的完整真实实例方案开放。导出使用当前 DIM `equipped / unequipped` 内联格式并保留可定位的 `socketOverrides`；理论、待刷、实例缺失、Hash 不一致或 Plug 无法映射时显示结构化阻断原因，不生成伪链接。
- 只有应用配装穿戴步骤已由轻量 Profile 确认在游戏内生效后，才开放 `保存到游戏内槽位`；覆盖已有 Bungie 槽位必须明确确认，应用配装不会因发布而自动删除或同步。发布必须生成独立不可变计划，绑定来源执行计划、账号、角色、已确认实例和目标槽位内容指纹；确认前再次核对当前已确认装备事实，装备状态或槽位变化时保持零写入。写入后按目标范围重新读取并核对槽位实例，使用发布计划、确认、执行和步骤 ID 写入验证记录。草稿变化必须立即废弃旧执行与发布报告。

状态矩阵必须覆盖：首次读取、空目录、链接读取失败、DIM 部分解析、候选计算中、设置已变化待重算、搜索被截断、无满足约束候选、方案未保存、方案有未保存修改、穿戴计划不可执行、穿戴部分失败、穿戴成功待发布、槽位覆盖确认和发布失败。已确认字段继续显示，缺失字段不得按名称或相似配置补造。

| DIM / 攻略 / AI 成果入口 | `previewDimLoadoutImport`、`createDimLoadoutExport`、`readGuideSource`、`parseBuildGuide`、`matchBuildGuide`、`createGuideLoadoutDraft`、`equipment_target_candidates` | DIM 只接受包含 `loadout` 数据的自包含完整链接，在本地解析且不访问 DIM 分享接口；不支持需要联网解析的 `dim.gg` 短链接。导入必须先显示预览；攻略链接、正文和 `guide_capture` 直接进入配装页统一导入区，选择角色后解析并按账号核对。所有导入与成果交接都只生成未保存草稿，不直接写入方案。 |
| 穿戴与发布 | `createLocalLoadoutPlanExecutionPlan`、`createLocalLoadoutPlanPublishPlan`、实例级 write action、刷新核对与 Bungie 槽位 action | 保存应用配装、穿戴和保存到游戏内槽位是三个独立动作；步骤失败停止后续执行，只有真实刷新核对成功后才允许发布。发布前复核账号、已装备实例和槽位指纹，发布后核对目标槽位实例并记录验证。 |

- 攻略中的护甲属性是五件护甲聚合目标，必须预填到 `armor_constraints.stat_minimums`，不得按单件护甲属性筛选账号实例。
- 当前 Armor 3.0 六维可直接预填；旧六维名称必须显示映射说明并进入待确认，用户复核前不得伪装成已确认事实。
- 只有唯一且带实例 ID 的异域命中可以预填固定异域；同名多实例必须由用户选择。攻略没有明确给出逐部位属性模组安排时，五个部位保持 `自动` 并显示复核提示，不从聚合数量猜测具体位置。
- 接受库存或升级候选后必须保存稳定 `result_id`、候选 ID、规则版本、来源 revision 和真实实例 ID；`cache_key` 只用于短期复用。方案摘要显示缩短后的结果引用，缓存过期只提示重新计算，不得让已保存真实实例伪装成失效或自动替换。
- 应用配装穿戴计划必须显示计划引用和完整步骤。用户确认后、第一步写操作前强制刷新账号并重建计划；账号、目标角色、实例、位置、来源角色替换、可写 Plug 或缺口变化时显示“计划已失效”，不得执行部分旧步骤。
- 执行前复核失败与执行后刷新验证失败是两个独立状态；前者必须是零写入，后者显示逐项完成数、失败步骤和账号刷新核对结果。
- 用户确认后生成独立确认 ID 和执行 ID；应用配装的每个转移、装备与 Plug 步骤必须把计划、确认、执行和步骤 ID 传入操作日志。穿戴确认页显示缩短后的执行引用，设置页日志保留完整 ID 的悬停信息和复制诊断。
- 执行后必须写入同一执行 ID 下的验证记录，状态为 `verified / partial / mismatch / unavailable`。设置页提供“执行验证”类型筛选；部分完成和验证不可用使用警告状态，不得统一显示成普通成功或失败。

### 配装状态矩阵

| 状态 | 可见区域 | 允许操作 | 不允许伪造 |
|---|---|---|---|
| 首次读取 / 空目录 | 目录和创建入口 | 新建、当前装备复制 | 不展示旧模板或虚构方案。 |
| 未保存草稿 | 槽位式应用配装编辑器和实时摘要 | 编辑、选择实例、显式保存 | 不显示为目录中的已保存方案。 |
| 已保存但账号未读 | 方案详情和来源 | 编辑、删除 | 不声明装备已拥有或可执行。 |
| 多实例待选择 | 对应装备行和摘要 | 选择具体实例 | 不按名称、Hash 或最近位置静默选定。 |
| 目标 Plug 不可用 / 装备缺失 | 对应装备行 | 编辑目标、查看现有候选 | 不将不可验证 Plug 加入执行计划。 |
| DIM 完整链接本地解析失败 / 攻略解析失败 | 创建入口和操作状态 | 改用包含 `loadout` 数据的完整链接，或修正攻略链接与文本后重试 | 不联网解析 `dim.gg` 短链接，不创建半成品方案，不显示模拟预览或成功状态。 |
| DIM 导出阻断 | 方案应用区 | 选择真实实例、修正 Hash 或 Plug 后重试 | 不为理论、待刷、缺失实例或无法定位插槽的方案生成伪完整链接。 |
| 护甲计算中 / 设置已变化待重算 / 搜索被截断 / 过期 / 无候选 | 护甲章节和摘要 | 调整约束、重新计算 | 不显示旧模式候选，待重算时不允许接受候选，不把理论身份或待刷要求伪装为真实实例，不把无候选或截断结果表示为已优化。 |
| 穿戴计划不可执行 / 部分失败 | 执行核对和操作状态 | 查看已完成、失败和未执行步骤 | 不回滚成功步骤或报告虚构事务成功。 |
| 穿戴成功待发布 / 槽位覆盖 | 发布区域 | 选择真实 Bungie 槽位并明确确认；确认后再次刷新并执行失效校验 | 不自动覆盖槽位，不使用已变化的装备状态或槽位内容，不同步或删除应用配装。 |

## 通用状态要求

所有菜单必须保留正常、首次加载、刷新中、空、失败、部分失败、无权限、禁用和进行中状态。状态只影响所属区域；已确认事实继续显示，缺失字段不补造，写操作成功前不更新事实值。
