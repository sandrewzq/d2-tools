# 应用工作区合同

> 本文件合并共享 Shell、设置、首页、账号、攻略、资料库、仓库和商人的结构、真实数据与状态边界。视觉细节统一遵守 [全局视觉合同](global-visual-contract.md)。

## 共享 Shell

稳定契约：`shell.topbar`、`shell.status-strip`、`shell.sidebar`、`shell.page-header`、`shell.page-content`、`shell.assistant`。

| 区域 | 真实绑定 | 约束 |
|---|---|---|
| 顶部栏 | 品牌、主题、GitHub、设置、AI、窗口控制 | 单一连续 Shell chrome；无平台窗口能力时只隐藏窗口控制 |
| 状态组 | `ShellStatusItem[]` 与对应 action | 状态项组成连续边界；状态 key 负责逻辑，label 只负责文案，不使用独立胶囊卡片 |
| 侧栏 | 当前账号摘要、主导航、底部动作 | 一级导航使用稳定图标和 `aria-current`；窄栏保留可访问名称 |
| 页面标题 | `ProductShellHost` 页面元数据与真实页面 action | 内容页不得复制第二个页头 |
| 主内容 | 当前菜单共享页面 | 普通页面唯一纵向滚动所有者，不建立同轴嵌套滚动 |
| AI 助手 | 会话、页面上下文、只读能力结果与数据引用 | 宽屏停靠，`980px` 及以下转 Drawer；只保留单一 AI 工作台，不建立固定任务 Tab |

Shell、页头、页面 gutter、首层分栏和全局 token 由共享层持有；菜单 CSS 不得覆盖 `.shell-*` 或无菜单前缀的工作区规则。

顶部状态按行动紧迫度分为 `quiet / standard / attention / critical`，不按状态项数量平均分配视觉权重。正常配置、健康确认和当前版本属于低权重事实；发现新版、下载进度、待重启安装、资料库修复和真实失败属于可操作事件。状态项位置必须稳定，不得因状态或权重变化重新排序；高权重事件只通过颜色、背景、图标和文字增强，并保持连续边界，不建立独立胶囊卡片。窄窗口的“状态”入口显示待处理数量，展开后继续保持相同顺序。

应用更新状态必须区分 `idle / checking / not_available / available / downloading / downloaded / error`：未检查不得显示“最新”；已是最新只显示中性版本号；发现新版显示目标版本并使用信息色；下载中显示目标版本和进度；下载完成显示“待重启安装”并升为最高操作权重；失败使用错误色。顶部更新项只负责进入设置页更新区，不直接触发下载或重启安装。

AI 工作台发送前可以按用户问题自动运行受控只读能力，每轮最多三项。当前覆盖装备定义、Perk、账号实例、当前商人 Offer、本地配装检查和 `armor.plan`；宽泛整理或推荐问题不得伪造实体查询。Armor 调用必须同时识别当前六维数值目标和明确职业，旧六维、缺职业、缺目标或升级基线不明确时不得猜测。确定性结果随完整 `result_id` 进入模型上下文，回答底部显示缩短后的数据引用和状态；失败、无结果、未登录或缓存不可用必须保留真实限制。AI 工作台不得调用写操作、后台刷新或把聊天文本当作确认。

每次成功问答必须创建轻量上下文快照，消息保存快照 ID，快照保存页面和账号范围、Manifest 版本、基础上下文指纹、实际提示指纹及能力结果引用，不保存完整提示、装备正文或凭证。恢复会话后，当前上下文与最近快照不一致时顶部状态显示“已恢复历史快照”，上下文抽屉显示快照时间；继续提问只携带有限前文并创建新的当前快照。请求失败时恢复发送前消息，不写入无回答的历史条目。

只读能力调用审计保存在 renderer 本地存储，最多 100 条，只记录能力名、脱敏输入摘要、结果 ID、状态、耗时、警告码、结果数量和证据 ID。设置页“复制脱敏诊断导出”在主进程诊断后附加最近能力审计；不得写入完整提示、能力完整结果、账号装备正文、Token、Cookie 或 API Key。

明确的配装、构筑或攻略整理回答可以在消息底部显示单一 `guide_capture` 成果行，包含草稿标题、确定性结果引用数量和“送到攻略页”命令。成果行是消息内连续区域，不嵌套对象卡。交接后关闭 AI Drawer、打开攻略页并预填未保存正文草稿；必须继续经过保存、要求识别、人工确认、账号匹配和显式保存，不得直接创建方案或触发写操作。

`armor.plan` 返回候选时，消息成果行优先显示 `armor_solution_comparison`，标明规划模式和达标候选数量。交接文本只包含原始职业、六维目标、候选 ID 和结果引用，不复制候选最终六维作为约束；配装页显示“复核 AI 护甲方案”，重新解析并要求复核模组预算、套装、位置范围和真实实例。

页面动作权重由当前页面职责、人工使用频率、自动刷新覆盖和阻断状态共同决定，不按“刷新”文案统一映射颜色：

| 页面与状态 | 主操作 | 次操作 |
|---|---|---|
| 账号正常 | 页头 `刷新账号`；承担账号页核心数据更新 | 页头 `重新授权`；低频身份维护 |
| 账号未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新或登录动作 |
| 账号未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 账号无数据 | 内容空态中的授权或刷新入口；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 仓库正常 | 页头 `刷新账号装备`；同步当前工作区 | — |
| 仓库未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示 `刷新账号` |
| 仓库未登录 | 内容空态中的 `登录 Bungie` | 不显示 `刷新账号` |
| 仓库无数据 | 内容空态中的 `刷新账号`；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 首页正常 | — | `刷新公开情报`；启动、重置边界和失败重试已有自动机制 |
| 首页读取失败 | 错误 Callout 内的 `重新读取公开情报` | 页头不重复显示同一刷新动作 |
| 商人正常 | — | `刷新商人库存`；进入页面和仄边界已有自动刷新 |
| 商人后台同步 | — | 页头刷新保持可点击；后台读取状态只在商人状态区反馈 |
| 商人读取失败且仍有缓存 | 页头 `刷新商人库存` 临时升权 | — |
| 商人完全无数据 | 内容空态中的 `重新加载商人库存` | 页头不重复显示同一操作 |
| 商人未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新动作 |
| 商人未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 设置账号分区 | `刷新账号`；该行的主要数据操作 | `重新授权`；低频维护入口 |

首次启动时仍挂载完整 `ProductShellHost`，但由共享启动门禁统一推进“Bungie 配置 → 登录 Bungie → 首页”；资料库与登录并行，未完成前只允许进入设置和当前步骤，不显示半可用首页。配置区必须提供 Bungie 官方 Application 页面入口、字段对应关系和固定 OAuth 回调地址。配置保存后自动在后台准备资料库，不创建独立向导页或第二套配置表单；资料库准备失败时保留明确原因和重试动作，不阻塞 OAuth 登录和账号原始读取，名称、图标及高级解析在资料库完成后补齐。

同一业务动作可以因页面职责不同使用不同权重。每个页面或局部失败状态最多突出一个主操作；空态或错误区已持有主恢复入口时，页头不得重复同一操作。进行中保持原标签和稳定宽度，通过 `aria-busy`、禁用状态和邻近反馈表达进度。

商人刷新必须区分后台同步和手动请求：进入页面、详情补全和仄边界更新属于后台同步，不得禁用页头刷新；只有用户已经发起的手动刷新可以临时禁用该按钮。手动请求使用后发请求优先的现有序号机制接管后台请求。

## 设置

稳定契约：`settings.workspace`。

固定八个分区：概览、语言与外观、账号、资料库、Bungie 接口、AI 助手、数据备份与迁移、诊断与操作日志。设置只承载应用配置，不承载攻略导入、推荐数据导入或其他业务工作流。

| 区域 | 真实字段与 action | 状态边界 |
|---|---|---|
| 概览与更新 | `appUpdateSnapshot`、账号/资料库/Bungie/AI/后台任务摘要、检查/下载/安装/诊断 | 未检查保持中性；只有发现版本后允许下载，下载完成后允许安装 |
| 语言与外观 | `languagePreferences`、`colorMode`、`density` | 界面语言与资料库语言分开建模；跟随开启时禁用独立资料库语言 |
| 账号 | `accountSummary`、读取状态、刷新时间 | 加载中禁用刷新；未授权保留重新授权入口；写操作由对应页面确认，不设置应用级总开关 |
| 资料库 | Manifest 状态、检查、更新、修复 | 失败时保留上一份可用资料；进行中禁用冲突操作 |
| Bungie | 官方 Application 入口、API Key、Client ID、Client Secret、回调地址和数据目录；保存后自动准备资料库 | 三个配置值均明文展示；三者都不进入仓库示例或诊断快照，诊断导出仍须脱敏；字段不完整时阻止保存；资料库准备失败不回滚已保存配置 |
| AI | 协议、Key、Base URL、模型、light.gg 能力 | 无配置、加载、测试中、失败和不支持能力分别呈现 |
| 备份与迁移 | 创建/恢复备份、清缓存、迁移说明、打开目录 | 调用真实平台能力，不伪造完成结果 |
| 诊断与日志 | `backgroundTasks`、`actionLog`、AI 只读能力审计、筛选、刷新、复制诊断 | 空日志保留筛选和诊断入口；失败项提供脱敏诊断；能力审计通过统一诊断导出附带 |

布局合同：

- `>1280px` 目录 `240px`，`981-1280px` 为 `210px`，`761-980px` 为 `190px`；`760px` 及以下目录置顶并限制高度。
- 状态摘要使用单一 `4px` `SurfaceFrame`，内部连续单元直角；三列，`1280px` 以下两列，`980px` 以下单列。
- 设置行使用弹性说明列和右侧控制列；宽屏控制列 `282px`，中屏 `260px`，`980px` 以下单列。
- 重复操作按钮使用 `34px × 144px`；Select 和 Field 填满控制列。
- 账号、资料库、更新和日志的精确时间使用本地时区 `YYYY/MM/DD HH:mm:ss`。
- OAuth token、Bungie API Key、Client Secret 和 AI Key 不得写入仓库快照。

## 首页

稳定契约：`home.workspace`、`home.vendor-stock`。

| 区域 | 真实绑定 | 关键状态 |
|---|---|---|
| 刷新节奏 | `dailySummary.daily_reset`、`weeklySummary.weekly_reset` | 使用本地系统时区；顶部刷新矩阵只展示每日和每周重置，绝对更新时间靠右，动态倒计时使用全应用统一时间强调色 |
| 核心活动 | `weeklySummary.priorities.*.entries` | 未确认时显示 pending，不用历史或 mock 补齐 |
| 铁旗信号 | `weeklySummary.iron_banner`、角色 Activity Challenge、VisibleRewards | 与“本周活动焦点”按约 `60% / 40%` 同行；只展示玩法、开放状态、倒计时、当前角色挑战和明确的直接奖励。当前角色进度使用“当前角色挑战”，账号范围使用“账号内 N 个角色可参与”，不得将两个维度写成同一句角色状态。萨拉丁库存、聚焦数量、具体装备、价格和购买条件只在商人页展示；条件可见的通用熔炉掉落不进入首页奖励摘要 |
| 周信号 | `special_event`、`weekly_bonus` | 本周活动焦点固定展示；只读取活动修饰词明确标记为“焦点活动”的内容，其他限时活动确认后独立展示，不覆盖铁旗 |
| 仄库存 | `dailySummary.sources.vendors`、`HomeBriefing.fetched_at`、`isXurActiveAt`、`nextXurBoundaryAt` | 整体使用单一 `summary-frame`，标题、到访/离开时间、库存状态和来源同框；内部摘要不重复外框；不使用 Vendor `nextRefreshDate` 替代；加载、不可用或失败时不回退旧库存 |
| 操作 | `onRefreshDaily`、`onNavigate("vendors")`、`onOpenXurOffer`、`onOpenWeeklyActivityReward` | 只有可确认且含 Hash 的奖励或武器/护甲 Offer 可打开统一详情 |

首页保持“刷新矩阵、周信号、活动摘要、商人库存”四层信息结构。周信号层优先展示正在开放的铁旗和本周活动焦点，但不承担配置、登录或“下一步行动”引导。核心活动保留日落、轮换突袭和轮换地牢三张独立卡片，桌面同排展示；桌面活动条目最小行高为 `98px`，`1280px` 以下允许内容撑开。突袭和地牢按真实条目数量决定内容高度，单条目的日落卡只拉伸外框与同排双条目卡片底边对齐，日落内容在拉高区域内垂直居中，不拉伸标题或奖励条目。描述最多展示两行，奖励按可用宽度优先并排；`760px` 以下恢复内容自适应高度。铁旗与本周活动焦点在周信号层同行且等高，其他已确认限时活动另起一行；没有挑战时不显示 `0/0`，不在首页显示任何 Vendor 零值计数或具体库存。仄库存模块使用唯一首层 `summary-frame`，内部状态和摘要不再叠加框线；Offer 仍是对象卡。宽屏 Offer 四列，`1280px` 以下两列，`980px` 以下单列。

## 账号

稳定契约：`account.slot-comparison`。

- 账号目录使用完整 `tablist / tabpanel`；角色使用 `ContextSwitcher` 和 `aria-pressed`，不是页面导航。
- 账号首屏优先回答“当前角色、当前 / 八槽 / 可装备最高光等、装备与背包差异”。摘要只显示账号名、角色数、仓库容量、快照时间以及“缓存 / 刷新 / 已同步”状态，不突出 Membership 长 ID。角色切换使用真实角色徽标，并支持方向键、`Home`、`End`；`760px` 以下目录和角色切换均保持单行横向滚动，不堆叠成多行按钮墙。
- 角色切换项同时显示 Bungie 当前光等和八槽最高光等；最高光等使用整数加 `/8` 余数展示。点击最高光等打开账号菜单私有浮层，桌面覆盖内容区、窄屏回到文档流，不改变共享 Shell chrome；点击触发按钮与浮层之外的区域自动关闭，`Escape` 关闭后焦点返回触发按钮。
- 光等浮层提供“可装备最高 / 八槽最高”两个完整 Tab，并支持左右方向键切换；打开后焦点进入当前 Tab，键盘焦点移出触发按钮与浮层范围时自动关闭。可装备最高遵守目标职业及一件异域武器、一件异域护甲限制；八槽最高同样过滤目标职业不兼容护甲，但按账号内各槽位最高值计算，不要求这些装备能同时穿上，用于查看光等提升进度。八个槽位按三武器、五护甲排序，使用明确列头显示位置、装备与来源、光等及相对整数光等的正负差值；缺少任一槽位时仍保留完整八槽并明确显示数据不完整。
- 账号最高允许读取其他角色持有的可用装备，邮政官不参与计算。当前一键装备仍只使用目标角色与仓库；两者不一致时必须显示来源提示，不得让理论账号最高冒充当前可执行方案。
- 装备按武器、护甲、装备、其他分类，再按稳定位置组织“当前装备 / 当前角色背包候选”两列对照；“其他”只显示记忆水晶位置。
- 位置来源使用 Manifest bucket 与稳定映射，不按名称猜测；仓库物品不得混入当前角色背包。
- 每个位置显示名称、当前装备数、候选总数、对象事实、配装命中和写操作状态；背包候选较多时完整换行展示，不折叠或隐藏。
- 装备区标题在存在活动配装时显示配装名称和当前角色命中数。账号刷新必须保留已有装备卡片，仅首次没有位置数据时显示空态；当前装备图片优先读取，背包候选图片延迟读取，长槽位区允许浏览器跳过屏外绘制但不能改变数据完整性。
- 装备对照使用“位置 `112px` / 当前装备 `236px` / 背包候选占满剩余空间”的连续行布局；背包候选始终完整展开，宽屏五列自动换行，`1280px` 三列，`980px` 两列，`480px` 以下单列。
- 当前装备列使用稳定的选中背景和强调边界，背包候选列保持中性表面；两种来源不能只依赖重复文案区分。
- 武器与护甲对象卡统一使用稳定的三行结构和 `72px` 高度：名称、核心事实、对象状态各占一行。来源由桌面列标题或窄屏面板标题表达，槽位由左侧行标题表达，卡片内部不重复“当前角色装备 / 当前角色背包候选”和槽位名称。武器核心事实显示武器类型、稀有度与光等；护甲核心事实显示稀有度与光等，末行显示总值、锁定及“配装 / 打开中”等状态。状态不得新增第四行或通过整行拉伸改变同槽位卡片高度，完整状态说明通过 tooltip 和无障碍名称保留。
- 装备详情允许立即显示账号快照中的身份、当前属性和当前配置，但关键几何结构必须从首帧稳定：账号实例的属性表固定预留资料库标准值与差异列，比较区常态固定为“标准值 / 当前差异与修正”两行，待应用变化并入同一列，缺失数据以“读取中 / 未返回”占位，不得因定义或配置状态变化增减列或为隐藏占位增加额外行高。加载状态按定义、实例和辅助数据分区记录，`is_detail_loading` 只作为两条关键请求的总忙碌状态；版本静态值与多版本下拉必须共用同一字段外壳，实时来源和推荐等辅助数据只能在已存在区域内更新。
- 只有武器和护甲对象可打开统一详情；装备、材料、任务、货币和其他对象保持只读。
- 刷新、失败和空态保留当前 Tab、角色和位置骨架，不使用整页遮罩抹掉结构。
- 一键最高光等使用类型化过程反馈：刷新、转移、装备和权威确认显示进行中；确认后明确区分成功、部分成功和失败，不通过中文文案关键字推断状态颜色，也不得在 Bungie 已受理但游戏内尚未确认时提前显示成功。

核心字段：`characters[]`、`slotComparisonRows`、Activity History、材料集合和邮政官只读物品。写操作中只锁定目标对象，不阻断其他位置。

## 资料库

稳定契约：`library.workspace`。

- 上方使用资料库状态摘要，主体使用“查询侧栏 + 连续结果列表”的工作区。
- 装备与“Perk 与框架”是互斥模式，使用完整 Tab 语义；搜索、筛选和清空是普通 Control。
- 查询侧栏首屏只承载模式、主搜索、基础筛选和默认折叠的高级筛选；最近查询、收藏计数和别名管理统一收进默认折叠的“搜索辅助”，不得与主搜索并列抢占首屏高度。
- 摘要显示激活版本、最新版本、激活时间、检查时间、语言、定义数量和缺失组件。
- 装备、Perk、框架、历史和收藏来自当前 Manifest 与本地历史，不使用固定名称、别名或数量。
- 同名装备存在多个可确认发布版本时，结果行名称旁直接显示玩家可识别的年份、赛季、资料片或内容包摘要；不要求展开详情，不显示 Hash 或内部 release trait。
- 装备结果首层按“名称与版本 / 类型、槽位、框架、弹药和伤害属性 / 当前获取、账号持有和来源可信度 / 操作”排列；完整定义描述、起源特性、历史来源和实时渠道进入同一来源详情，不在首层重复铺开。收藏是低权重操作，武器和护甲的“查看详情”仍是唯一主操作。
- 定义对象与账号实例必须区分。只有匹配到真实实例时才显示位置、Roll 和账号详情入口。
- Perk 反查装备使用可追踪的具体 Hash / Manifest 关系，不按装备名称模糊扩展。搜索列表以 Logical Perk / Perk Family 为用户实体：家族身份由 Inventory Plug 的规范化名称、官方图标和 Plug / Item 类别共同确定，不把描述或 Sandbox Perk Hash 直接当作列表身份。普通、强化和其他官方变体在同一结果内保留各自 Sandbox Perk Hash、Plug Hash、描述和关联数量；例如“爆炸箭头”只显示一行，行内分别展示普通效果与强化差异。
- Perk 搜索结果只返回精确关联总数和分类；展开“关联装备”后按需分页读取完整装备摘要，并在 workspace 按 Perk key 缓存，折叠不清除，新搜索或 Manifest 版本变化时清理。展开区覆盖加载、失败重试、空结果和加载更多状态，不设置静默固定上限。
- 关联装备继续使用连续列表，每个具体发布版本独立成行。左侧显示约 `40px` 官方装备图标并叠加官方版本水印；名称旁始终显示玩家可识别的发布版本，缺失时显示“版本待确认”；概要显示稀有度、装备类型、框架、弹药、伤害属性、专家标记，以及该版本支持“普通 / 可强化”的哪种 Perk 变体，随后显示历史来源或当前获取状态待确认，并可直接打开统一装备详情。同一发布版本的技术重复定义通过 canonical Hash 合并，不同发布版本保留且相邻排列；家族关联总数按所有变体的 canonical 发布版本实体取并集，不把各变体数量直接相加。
- Renderer 与 Desktop main / preload 的资料库合同必须显式握手。合同版本不支持 Perk 家族、分页关系或变体匹配时，仍可显示基础 Perk 搜索结果，但关联装备区必须提示重新构建并重启，不得把旧版固定上限摘要渲染成完整结果，也不得用空图标和“版本待确认”伪装合同正常。
- 未初始化、部分组件缺失、更新中、检查失败、历史为空和搜索无结果分别呈现；更新失败保留上一份可用资料库。
- 搜索、实时来源、收藏和别名使用独立错误状态，只影响所属区域。搜索更新期间可以保留上一份可见结果以稳定几何结构，但必须明确标记为上一次内容并在结果区使用 `aria-busy` 和独立状态播报。
- 结果操作支持键盘方向导航：同一行左右切换操作，上下移动到相邻结果的对应操作；统一装备详情关闭后焦点返回来源按钮。`760px` 及以下查询区回到页面文档流，不设置独立高度和纵向滚动；Manifest 摘要保持两列，极窄宽度再转单列。

结果区使用连续 `SurfaceList`，每行只画 `RowLine`，不把普通结果改成对象卡。

## 攻略

稳定契约：`guides.workspace`。

- 攻略页使用“筛选目录 / 结果列表 / 阅读或编辑”三栏连续工作区。左栏负责全部、使用中、已归档、收藏和分类筛选；中栏负责全文搜索、结果选择和新建入口；右栏只显示当前文档或当前草稿，不建立第二套弹窗编辑器。
- 攻略文档保存标题、分类、标签、收藏、归档状态、来源和正文。来源类型分为粘贴文本、个人笔记和来源链接；链接读取只能由用户在编辑区手动触发，先显示最终地址、正文分段、读取大小、警告和正文预览，用户选择“采用为正文”后才填入草稿，仍需再次保存攻略。
- 搜索覆盖标题、分类、标签、来源名称、来源 URL 和当前正文。状态、收藏和分类筛选可以组合；搜索无结果、库为空和未选择文档必须分别呈现。
- 新建和编辑必须要求非空标题与正文；来源类型为链接时还必须提供有效的 HTTP(S) 地址。保存写入本机；标题、分类、标签、收藏、归档或来源元数据变化只更新文档，只有规范化后的正文变化才创建新的不可变快照。
- 阅读区显示当前正文、来源、最近更新时间和正文快照数量。存在多个快照时显示按时间倒序的历史摘要和内容指纹短码；基础切片不提供旧快照恢复，也不把指纹当作玩家需要输入的标识。
- Desktop 链接读取只允许公开 HTTP(S) 地址，逐次校验重定向目标，阻断本机、局域网、带凭证地址、不支持内容类型、超过五次重定向、超过 15 秒和超过 2 MB 的响应；不执行页面脚本，不绕过登录、验证码或付费墙。Web 预览明确显示远程读取不可用。
- 保存正文时为每个不可变快照生成确定性章节分段。阅读区可以对当前快照运行本地确定性提取，候选覆盖职业、子职业、异域护甲、武器、护甲属性、模组、星相和碎片，并显示置信度与原文行引用。所有候选默认进入复选审阅；只有点击确认后才保存轻量确认记录，未确认结果不得成为装备目标、Armor 约束或配装。
- 提取确认绑定攻略文档 ID、正文快照 ID、正文指纹和解析器版本。正文变化或解析器版本不兼容时，旧确认只保留历史关系，不显示为当前正文已确认；确认文件损坏时不得覆盖为新的空记录。
- “派生成果与追溯”位于确认成果之后、正文之前，连续列出正式装备目标、Armor 约束、账号配装候选，以及从 Armor 约束或账号候选显式保存的本地方案。列表消费版本化 `GuideDerivedRelation`，只保存稳定 ID、关系、标签和时间，不复制攻略正文、账号快照或完整成果；有现有页面落点时提供明确跳转，没有落点的成果保持只读记录。
- 正式装备目标跳转必须打开仓库“推荐数据”并定位具体目标行；本地方案跳转必须选择具体方案。反向返回攻略时重新读取关系索引确认来源仍有效，不从摘要、guidance 或显示文案解析 ID；攻略删除后派生业务对象继续可用，但不得显示假定位成功。
- 收藏、归档、恢复和删除都调用真实持久化 action。归档文档从“使用中”筛选移出并可在“已归档”恢复；删除后目录和当前选择必须同步更新，不显示假成功提示。
- 加载时保留三栏结构和筛选控件；读取失败、保存失败或删除失败显示可见错误，不能用空库覆盖错误语义。编辑中和保存中保持草稿内容，保存失败后允许继续修改并重试。
- Desktop 使用本地 `guide-library.json`、轻量 `guide-extractions.json` 和版本化 `guide-derived-relations.json`，Web 只提供同一共享页面的会话内预览 adapter。便携备份包含攻略正文、提取确认和派生关系，但不包含 AI 密钥、OAuth token、远程网页缓存或未采用的链接预览。

宽屏三栏比例由攻略菜单 CSS 持有；窄屏按筛选、目录、正文顺序纵向排列。普通目录行使用连续列表表面，正文阅读和编辑区使用页面工作区表面，不把三栏分别包装成对象卡。

## 仓库

稳定契约：`vault.workspace`。

仓库固定包含筛选列表、同名整理和推荐数据三个 `tabpanel`，共同消费同一份账号实例集合。清理不再维护独立工作台：玩家在筛选列表或同名整理中写入“可清理”，后续游戏内处理仍以该明确状态为边界。

| 工作区 | 数据与操作边界 |
|---|---|
| 筛选列表 | 左侧常驻筛选、右侧十列紧凑装备网格；Profile 实例、Manifest 定义、玩家整理状态、锁定、排序和保护信号共同参与筛选 |
| 同名整理 | 按 Hash 和实例 ID 分组；左侧按整理进度选择同名组，右侧使用比较基准突出实例差异并暂存本组整理状态 |
| 目标与匹配 | 先显示当前账号真实命中的 Wishlist 组合、适用模式和匹配依据，再显示个人装备目标；DIM Wishlist 作为仓库内低频导入操作按需展开，不合并成系统评分 |

DIM Wishlist 是仓库武器匹配的低频辅助数据，不是攻略来源。入口只位于仓库“目标与匹配”，默认收起；文件导入为主，粘贴文本为次级入口。导入或替换必须先解析并展示待启用预览，再由用户明确确认；移除需要二次确认。保存或移除后立即更新装备目标兼容数据并重新计算当前账号匹配，不要求刷新整个账号或重启应用。

仓库只显示与当前账号装备直接相关的结果：命中装备数、命中组合数、PVE / PVP / 通用模式覆盖和匹配依据。没有 Wishlist 时显示中性空态和低权重导入操作；不得把 Hash、JSON 或 CSV 规则编辑暴露给普通用户。历史版本已保存的自定义规则继续由 Core / Services 兼容读取，仅在确实存在旧数据时显示“遗留自定义规则”，不提供新建、替换或粘贴入口。AI / light.gg 实时分析不参与仓库批量扫描，只在用户明确打开单件装备分析时调用。

推荐数据中的独立装备目标按稳定目标 ID 接受跨页定位请求，并使用既有选中表面 token 聚焦目标行。攻略来源目标提供“返回攻略”，但必须通过派生关系索引确认文档仍存在；Armor Planner 缺口提供“查看 Planner 引用”，只携带稳定 `result_id / candidate_id`，不承诺恢复完整求解结果。

筛选范围只提供武器、护甲和装备，不提供“全部”与“其他”入口。武器槽位只显示动能、能量和威能；护甲部位显示头盔、臂铠、胸甲、腿甲和职业物品。武器类型使用真实 `item_type`，稀有度使用 `tier`，装备阶级使用 `instance.gear_tier` 并包含 T0，伤害属性使用实例伤害类型；护甲职业使用 `class_type`。护甲套装选项目录来自当前语言 Manifest 的完整 `DestinyEquipableItemSetDefinition`，账号装备摘要中的真实 `equipableItemSetHash` 只用于匹配物品和计算持有数量；未持有的套装仍保留在目录中并允许选择，命中为空属于正常筛选结果。目录加载中或不可用时必须显示明确状态，不得回退成账号持有套装列表。缺少稳定账号字段的制作状态或框架不得用固定选项补造。

筛选列表中的装备单元固定复用全局 `44px` 游戏图标，一般桌面宽度每行十列；较窄窗口按八列、六列和四列响应。装备阶级直接使用 `DestinyInventoryItemConstantsDefinition.gearTierOverlayImagePaths` 的官方覆盖图，并与 DIM 一样叠在图标左上区域；不得用 CSS 自绘竖条或从左下角堆点。T0 不显示覆盖图，缺失阶级在产品层按 T0 参与筛选和显示。武器对象卡分成身份、事实和状态三层：身份层显示图标、名称、类型和槽位；事实层显示游戏化弹药图标、官方彩色伤害属性图标与光等；状态层显示玩家整理状态和配装引用。护甲沿用相同三层结构：身份层显示图标、名称、职业和部位；事实层显示总属性、当前最高单项属性和光等；状态层显示玩家整理状态和配装引用，完整六项属性仍在详情和同名整理中展开。锁定使用绿色锁形状态标记，固定在卡片底部状态行右侧并使用主题状态底板，不再覆盖装备图标；配装引用使用应用状态文字和既有选中边框，不使用右上角单字方块。Perk、框架、品质、护甲能量、外部推荐证据和长备注留在详情或同名整理，不进入普通十列网格。

玩家整理状态统一为未标记、保留、待复查和可清理。`farm / loadout` 继续作为既有用途标签保存，但不进入整理状态控件。锁定、配装引用、愿望单、个人目标和社区推荐属于系统证据，只显示或筛选事实，不自动生成保留、待复查或可清理结论。普通十列装备单元只显示一份玩家整理状态，并保留锁定与配装引用角标；愿望单、个人目标和社区推荐继续参与筛选并在详情或同名整理中展开，不再同时显示推导决定。

护甲多条件为 AND，同一属性只保留一条；总属性只作为排序维度。保护与匹配支持多选并按 AND 收窄结果。重置筛选与结果摘要位于结果区顶部，不单独占用一行。

同名整理默认使用已标记保留的实例作为比较基准，否则使用本组第一件；基准只用于突出相同与差异，不属于系统推荐，不自动修改状态，也不限制一组只能保留一件。基准使用单选语义，切换后武器按真实 Socket 顺序和玩家可识别的插槽名称比较，护甲展示总值与完整六维；差异必须同时提供文字标记，不能只依赖颜色。武器默认比较“完整 Roll”：进入同名组后按需读取组内实例详情，每列集合由当前启用项与 `reusable_plugs` 中来源包含 `instance` 的实际拥有项组成，排除只来自 `character / profile / manifest` 的解锁项和定义池候选；当前启用项只作为集合内状态，不参与完整 Roll 的相同判定。详情未齐时只能明确显示并比较“当前启用”，不得把账号紧凑快照中的 `socket_plugs` 冒充完整 Roll 或提前给出完整集合结论；读取失败必须提供重试。辅助“当前启用”模式只比较每列当前选择。集合关系显示为相同、部分重合或完全不同，同名整理只读比较，切换游戏内 Perk 仍在装备详情完成。比较矩阵采用“单元格差异状态 + 无框 Perk 行”两层结构：差异通过左侧状态条和短文字标签表达，不使用整格描边；Perk 行只使用分隔线，当前或可切换状态固定在右侧，仅此实例拥有的 Perk 在名称旁显示短标签。Roll 列应保证可读宽度并允许矩阵横向滚动，不得为了塞入视口压缩名称和状态。Roll 单元中的 Perk 图标必须复用资料库和武器详情的 `game-definition-icon` 原语，以主题适配底板、边框和 `contain` 保留透明官方图标的可读性，不得按普通装备缩略图使用 `cover` 裁切。

实例保护与匹配依据分开展示。锁定和精确实例 ID 配装引用属于实例保护；仅按 Hash 或部位匹配的配装需求明确标为“配装同款”，Wishlist、个人目标和历史社区数据保留在匹配依据中，不得让同 Hash 的每个实例都显示为精确配装引用。

单件整理状态先在当前组暂存，左侧组目录和右侧行必须明确显示未保存状态；只有草稿与已保存状态不同时才开放“应用本组状态”。“填充：基准保留，其余待复查”只修改草稿。存在未保存草稿时不能直接进入下一未整理组。带实例保护或推荐证据的装备若被标记为可清理，应用前必须二次确认。应用只写本地整理状态，不转移、不解锁、不拆解。

写操作继续调用真实 action / IPC，失败前不得提前修改锁定、位置或标签显示。

## 商人

稳定契约：`vendors.workspace`。

- 目录按真实地点和稳定 `vendorHash` / ID 分组，使用紧凑文字行，不显示头像或首字母占位。
- 详情先显示声望与等级，其余章节保持商人结构定义的业务顺序；未配置的基础服务和任务位于已配置的主库存、周常奖励、聚焦等核心章节之后。不用分类摘要替代完整库存。商人状态条下方提供单行吸顶章节导航，滚动后固定在共享页面标题栏正下方，只定位现有章节，不切换或隐藏库存；当前章节必须有明确选中态，窄屏允许横向滚动。
- 没有应用内操作能力的非装备直接库存和任务继续保留真实 Bungie 事实，但使用紧凑信息行并明确标记“游戏内使用 / 领取”或条件状态，不得显示成可在应用内点击购买的装备卡。
- 每个 Offer 显示真实图标或缺图态、名称、类型、摘要、成本、数量、购买状态和失败原因。
- 角色相关库存显示当前角色上下文，不跨角色合并库存。
- 武器和护甲 Offer 可打开统一详情；材料、任务、解码器和其他对象只显示库存事实。
- 读取时间和重置边界使用原始时间字段在渲染时格式化，不保存预格式化文案。
- 加载、未开放和失败时清除过期轮换；部分可用时展示已确认销售数据并标记缺失属性或插槽。

Offer 使用响应式对象卡网格：宽屏五列，`1280px` 三列，`980px` 两列，`760px` 单列。章节和目录保持连续直角结构，不建立水平商品轨道。

## 配装边界

稳定契约：`loadouts.workspace`。本文件记录共享配装页必须保持的页面与交互边界；本地方案、DIM、攻略、护甲求解和方案应用已接入同一工作台。

- 全局侧栏只保留一个 AI 工作台，不显示固定“任务”Tab 或攻略任务树。攻略链接、正文和 AI 整理文本统一从攻略页进入；配装页只接收攻略页已经确认并完成账号匹配的成果。旧侧栏保存的攻略文本只做一次性恢复，成功生成草稿后清除。
- AI 工作台的 `guide_capture` 交接会打开攻略页并预填一份未保存的正文草稿，继续经过保存、要求识别、人工确认和账号匹配；不得直接打开配装页或创建方案。`armor_solution_comparison` 与 `equipment_target_candidates` 仍进入配装页对应的专用审阅。
- AI 工作台的 `equipment_target_candidates` 交接使用专用候选审阅，不经过攻略文本解析。候选列表必须区分账号真实实例和仅 Manifest 定义，允许逐项复选并显示目标角色；确认后只生成 `assistant-targets` 未保存草稿。真实实例绑定 `selected_instance_id`，仅定义候选只写 `item_hash` 并保持待获取、待选择，不能伪造实例或自动保存。
- 一级视图只保留 `游戏内配装` 和 `本地配装方案`。护甲优化器不是第三个一级页面、方案类型或来源。
- 游戏内配装显示 Bungie 官方槽位与直接应用能力；“复制到本地工作台”只复制官方可读字段并打开预填工作台，不立即创建已保存方案。
- 本地方案目录只显示已经显式保存的方案。新建、当前装备复制、攻略成果交接和游戏内槽位复制直接进入工作台；DIM 先完成链接读取与预览，再进入同一个工作台。创建菜单不得提供独立的攻略文本粘贴入口。
- 本地方案工作台采用“配置目录 / 当前编辑区域 / 方案摘要”三栏结构。配置目录固定包含基础信息、子职业、武器、护甲、属性与模组、核对与执行。
- 武器和护甲必须选择真实账号实例；同名多实例不静默代选。子职业、目标 Perk、星象、碎片、技能和模组只有在稳定 Hash 与可写能力可验证时才进入执行计划，其余保持“仅记录”。
- 护甲规划保留在本地方案工作台内，不新增第三个一级页面。规划模式使用分段控件切换“库存成装 / 理论上限 / 待刷目标 / 升级路径”；同一组六维目标、碎片变化、模组预算、优先级和套装约束在四种模式间复用。
- 护甲约束支持 Manifest 可确认的 `2件 / 4件 / 2+2`、位置范围、固定异域、锁定和排除。理论模式不要求账号且只输出理论身份；待刷模式区分已有、待升级、待核对和待获取；库存与升级模式才允许选择真实实例组合。
- 护甲计算统一消费 `@d2-tools/app/armor` 的 `ArmorPlannerWorkspaceState`，页面不得继续直接调用旧 `solveLoadoutArmorCandidates`。Desktop Adapter 在主进程补齐当前 Manifest 规则集、套装目录和账号护甲快照；页面只提交职业、目标、约束、位置和实例选择条件。
- 修改六维、碎片、模组预算、优先级、锁定、排除或位置范围后，必须立即废弃旧候选。计算中可以保留上一结果作为内部恢复数据，但不得继续显示为可选择候选；`stale / error / indeterminate / unreachable / invalid` 必须分别显示真实状态和领域警告。
- 四种候选共用逐属性比较、硬约束、属性缺口、模组用量、浪费和套装覆盖；理论候选显示框架、第三属性和调整身份，待刷候选显示缺失与已有匹配，库存候选显示位置与转移数，升级候选显示保留件、替换数和步骤。选择库存或升级候选只预填本地方案的护甲实例，不立即保存，也不触发 Bungie 写操作。
- “保存本地方案”只写入本机；保存后才能应用。应用使用 `plan / execute / refresh` 边界，失败时停止后续步骤并展示真实结果。
- 攻略来源方案的摘要区显示结构化来源并提供“返回原攻略”；入口通过 `source.source_id` 查询派生关系，不解析 guidance 文案。关系失效时方案仍可继续使用并显示提示。来自装备目标的 Armor 引用只展示缩短后的结果与候选标识，并明确要求按当前账号和规则重新计算，不伪恢复未持久化候选。
- DIM 导出位于方案应用区，只对当前账号已核对的完整真实实例方案开放。导出使用当前 DIM `equipped / unequipped` 内联格式并保留可定位的 `socketOverrides`；理论、待刷、实例缺失、Hash 不一致或 Plug 无法映射时显示结构化阻断原因，不生成伪链接。
- 只有本地方案应用成功并刷新账号核对后，才开放“保存到游戏内槽位”；覆盖已有 Bungie 槽位必须明确确认，本地方案不会因发布而自动删除或同步。发布必须生成独立不可变计划，绑定来源执行计划、账号、角色、已确认实例和目标槽位内容指纹；确认后再次刷新账号，装备状态或槽位变化时保持零写入。写入后重新读取账号并核对槽位实例，使用发布计划、确认、执行和步骤 ID 写入验证记录。草稿变化必须立即废弃旧执行与发布报告。

状态矩阵必须覆盖：首次读取、空目录、链接读取失败、DIM 部分解析、候选计算中、无满足约束候选、方案未保存、方案有未保存修改、应用计划不可执行、应用部分失败、应用成功待发布、槽位覆盖确认和发布失败。已确认字段继续显示，缺失字段不得按名称或相似配置补造。

## 通用状态要求

所有菜单必须保留正常、首次加载、刷新中、空、失败、部分失败、无权限、禁用和进行中状态。状态只影响所属区域；已确认事实继续显示，缺失字段不补造，写操作成功前不更新事实值。
