# T19：护甲详情三对象重设计

> 状态：开发完成，待整体验收
> 优先级：P1
> 范围：共享护甲详情；覆盖账号已有护甲、资料库版本和商人当前售卖，不改武器详情和其他菜单外壳

## 背景

护甲详情已经具有 `account_item / definition / vendor_offer` 三种对象模型，但页面长期以账号实例语义为主，导致资料库和商人模式出现“账号当前配置”“当前能量”“基础属性未返回”等不适用表达。首次打开时，定义和实例加载状态也没有进入内容层，容易把读取中的空数组误认为最终空态。

## 设计目标

1. 三种对象继续共用一个 `ArmorDetailContent`，保持资料库、商人、仓库、账号和首页入口样式一致。
2. 护甲保持“属性与获取”第一章，不复制武器的 Roll 优先结构。
3. 账号护甲只显示本件基础/当前属性、已安装配置和强化状态。
4. 商人护甲只显示本次售卖属性、价格、购买状态、刷新时间和售卖配置。
5. 资料库版本只显示随机属性规则、固定能力、套装规则、定义支持项和获取方式，不模拟单件属性或升级进度。
6. 定义和实例按真实完成顺序渐进更新；加载中保留稳定摘要和内容尺寸，不显示假空态。

## 固定章节

1. 属性与获取
2. 护甲配置
3. 目标匹配
4. 强化状态
5. AI 分析

## 三种对象首屏

| 对象 | 四格摘要 |
|---|---|
| 当前装备 | 当前查看、基础总属性、当前总属性、强化状态 |
| 当前售卖 | 当前查看、售卖总属性、购买状态与价格、刷新时间 |
| 资料库版本 | 当前查看、属性规则、固定内容、获取状态 |

## 数据边界

- 资料库定义没有固定六维属于正常规则，使用属性规则说明，不显示错误式空态。
- 商人售卖没有基础属性拆分时只展示售卖实际值，不显示“基础未返回”。
- 完整定义支持项不得冒充售卖配置或本件已安装内容。
- 护甲 Socket 优先保留真实 `socket_index`，按通用/活动、部位、调整、特殊和强化语义命名；数据不足时使用保守的部位模组位编号。
- 目标匹配按当前装备、当前售卖和资料库版本分别表达；资料库没有单件属性时保持未知，不生成命中结果。
- AI 默认问题跟随对象变化，主观结论不写入属性、购买状态或强化事实。

## 本轮实施结果

- 已增加三种对象独立的四格摘要、章节标题、数据来源和空态文案。
- 已接入定义/实例加载状态，属性、来源、配置、固定能力和强化区支持局部骨架与部分可用状态；局部定义仍在读取时不会提前落入最终空态。
- 已修正商人预览的细分加载标记，并把价格、购买状态和刷新时间传入护甲详情。
- 已区分资料库支持项、商人售卖配置和账号本件配置；资料库不再显示账号能量和单件属性。
- 已将右栏统一为“我的同版本护甲”，移除默认玩家区域的 Hash 和实例编号文案。
- 已为护甲备注补齐关闭和切换同版本护甲时的未保存保护。
- 已保持共享档案外壳、五章连续滚动和宽屏停靠；`1360px` 以下 Drawer 补齐关闭态焦点隔离、焦点返回、Escape 与减少动态效果适配。

## 验收重点

- 分别从资料库、商人、账号/仓库打开护甲，确认首屏摘要和事实来源不互相混用。
- 首次打开账号护甲时，已有属性或配置先显示，未完成内容保持局部读取状态。
- 商人护甲显示本次售卖总属性、购买条件、价格和刷新信息，不显示账号基础属性或能量占位。
- 资料库护甲明确说明属性随机，不出现虚假的六维、已安装模组或升级进度。
- 同版本护甲 Drawer、关闭按钮、遮罩、实例切换和未保存备注保护可用。
- `light / dark × 1280 / 980 / 760` 下无横向滚动，长套装名、能力说明和来源文案可换行。
