# Bug #93：导入弹框里「来源名」与两个按钮挤在预览卡右栏，且每次都要自己起名

> 状态：🟢 已修复并自检通过（2026-09-16）
> 现象（用户截图）：导入人工推荐表格弹框里，预览卡内的「来源名」输入框与「新建来源 / 覆盖同名来源」
> 挤在卡片右侧一栏，把左边的文件名与「455 条可导入」压变形，按钮还越过了卡片右边界；
> 同一份来源名输入框是空的，每导入一份表格都要用户自己打字。用户原话「样式乱了，而且可以默认生成一个名字」。

## 核实：命名块既没样式，也站错了位置

两件事叠在一起，看起来才那么乱：

1. **它没有样式规则。** 命名块的类名是 DIM 时代的旧名（`vault-dim-import-choice`），
   而 T56 删掉 DIM 第三身份时删的是一个旧的按名字直接删文档的通道，命名块沿用了那块旧样式名，
   全仓 `*.css` 里**一条对应的规则都没有**。于是它是一个彻底裸奔的 `label + input + 两个按钮`。
2. **它站错了位置。** 预览卡是三栏栅格（文件名与说明 / 计数 / 动作），命名块是卡片里的第 4 个子元素，
   按栅格自动流进了第三栏。第三栏只有 `auto` 宽，输入框又要把宽度撑开，于是左栏被挤扁、按钮越界。

四个导入入口（表格 / DIM 文件 / 在线 DIM / 粘贴）用的是同一块命名与确认，所以四处都乱，不止截图上那一处。

> 2026-09-17 校正（[T63](T63-dim-source-link-sync.md)）：DIM 这一组的入口已收成两条——「导入文本文件」与「从链接同步」，
> 粘贴文本通道与固定地址在线导入都已删除。下表后两行的口径随之更新，**「同一条命名规则、不按格式分岔」这条不变量不变**。

## 处置

**位置**：命名与确认独占预览卡的一整行（整行铺开，不与文件名和计数抢栏目），
左栏放名字输入、右栏放两个互斥动作、提示语另起一行；类名去掉格式名（`vault-import-identity`）。
这条也钉进了架构守卫：改坏成「不横跨整行」时守卫变红，防止下次再把输入框塞回栏目里。

**默认名**：输入框预填「这次预览显示的名字」，用户可改。

| 入口 | 默认名 | 理由 |
|---|---|---|
| 表格文件 | 文件名去扩展名（「YXCRALLXY推荐表_导入模板.csv」→「YXCRALLXY推荐表_导入模板」） | 是用户自己的文件，改名最省事；重名即落回覆盖 |
| DIM 本地文件 | 同左 | 同上 |
| DIM 链接 | 链接末段文件名去扩展名（先还原百分号转义）；对已有来源再同步时预填该来源现在的名字 | 用户没为链接起过名，末段文件名是最接近「文件名」的东西；再同步时名字锁死，于是只剩「覆盖」可点 |

四处**用的是同一条命名与确认**，不按格式分岔——「名字怎么来的」属于消费层的统一规则，
按格式分支只允许出现在解析 / 适配那一层。去掉扩展名时只剥最后一段，
「推荐表 v1.2.xlsx」得到「推荐表 v1.2」而不是「推荐表 v1」；只剩下扩展名（`.csv`）时退回原名，不留空。

## 验证（自检，非用户要求）

| 改坏 | 结果 |
|---|---|
| 表格导入不预填默认名（退回每次手打） | 默认名用例与两条依赖默认名的既有用例一起变红 |
| 去掉扩展名改成原样返回文件名 | 默认名用例与「只剥扩展名、不剥名字里的点」用例变红 |
| 命名块不再横跨整行 | 架构守卫变红 |

三处改坏均已还原，`grep -rn MUTATION` 无残留。五道闸门在最终代码上全绿：
`pnpm typecheck`（7 包）、`pnpm test:behavior`（573 条）、`pnpm test:architecture`（68 条）、
`pnpm docs:check`、`pnpm test:quality`，另 `pnpm check` 通过。

## 验收判据

1. 打开导入弹框：预览卡里文件名、件数各占自己的位置，不被输入框挤压；按钮不越出卡片边界。
2. 选完文件后来源名输入框已经有默认值，直接点「新建来源」即可完成导入。
3. 把默认名改成库里已有的名字时，提示与按钮切换成覆盖（原有语义不回退）。
4. 四个导入入口的命名与确认是同一块，位置与默认名规则一致。
5. 五道闸门全绿。

## 请用户复验

重新打包后打开 仓库 → 推荐来源 → 导入表格文件，选一份表格：
先看排版是否归位（文件名与件数不再被挤、按钮不越界），再看来源名是否已经填好——
不改名直接点「新建来源」应当就能导入。
