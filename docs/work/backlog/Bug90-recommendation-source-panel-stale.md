# Bug #90：导入成功后，同一页下方的「已导入来源」管理面板仍显示「当前来源 0 个」

> 状态：🟠 代码已改，待用户复验（2026-09-16）
> 现象（用户截图，v0.0.26）：仓库 → 推荐来源**同一页**上下两栏对不上——
> 上栏「已导入来源（1）」写着 `sayalarry · 文件导入 · 70 条规则`，下栏「已导入来源」却写着
> 「当前来源 0 个」「已启用 0 个」「还没有可管理的推荐来源」。

## 排查：数据没问题，是下栏没有重读

先把「是不是导入没写进去」排掉：拿用户那份库（`~/Library/Application Support/d2-tools/knowledge/weapon-recommendations.sqlite`）的副本直接跑服务层的读取接口，返回的正是**1 个来源**——名字 `sayalarry`、状态 `active`、70 条规则、127 把武器。上栏那份清单读的也是同一个库。所以库里有，界面上没有。

真正的原因在两栏各自的重读时机：

| 位置 | 什么时候重读 |
|---|---|
| 上栏（导入入口 + 已导入来源清单） | 导入 / 覆盖 / 移除 / 清空成功后显式重读一次 |
| 下栏（来源管理：当前来源、启用状态、查看详情） | **只在挂载时读一次**——它的重读依赖是稳定的，导入发生在这之后，不会触发它再读 |

用户当天的时间线正好落在这个缺口上：先在这一页（下栏已挂载、读到 0 个），再在**同一页**完成导入。上栏自己刷新成 1，下栏保持挂载时那份旧快照。切走再切回来会重新挂载，所以这个缺陷只在「导入前后一直停在这一页」时出现，也正是最自然的操作路径。

## 处置：导入链路写完后，让同页的来源管理也重读一次

不把两栏合并成一个状态源（下栏自己还有停用 / 启用 / 删除 / 移除规则这些写动作，合并会把「谁拥有快照」搞乱），只补一条**通知**：导入面板每次做完改动（新建 / 覆盖 / 移除整份 / 清空）回调一次，上层用一个自增的刷新计数传给下栏管理面板，管理面板把它加进重读依赖。

要点：计数只在**真的发生改动**时自增，所以「每次渲染都重读」这种蒙对的写法不算修复；下栏自己操作时仍然由它自己的返回值更新快照，两者不冲突。

## 验收判据

1. 在推荐来源页导入（新建或覆盖）后，下栏「当前来源 N 个 / 已启用 N 个」与来源行**当场**变成最新，不需要切页或重启。
2. 移除已有来源后同样当场同步。
3. 下栏自己的操作（停用 / 启用 / 删除 / 移除规则 / 恢复规则）行为不变，正在看的规则明细不会因为上层计数变化而丢失。
4. 没有发生导入时不会多读一次（不能靠「每次渲染都重读」通过）。
5. 判据 1–4 各配一处变异，各自只让对应用例变红；`pnpm typecheck` / `pnpm test:behavior` / `pnpm test:architecture` / `pnpm docs:check` 全绿。

### 验证结果（2026-09-16）

判据 1–4 由 `packages/ui/test/vault-recommendation-sources-refresh.test.tsx`（4 条用例）覆盖。夹具是**一份假存储**：写动作改它、两个面板各自读它，所以「下栏读到旧值」只可能来自它没重读，而不是数据没写进去。用例 1 走的是用户的真实路径——点开「导入人工推荐表格」、选文件、填来源名、点「新建来源」；用例 2 走「移除整份来源」，两条都断言**读取次数**从 1 变 2（少了第二次通知，次数不会变）。

四处变异，各自只让对应用例变红：

| 变异 | 改法 | 变红的用例 |
|---|---|---|
| 通知不发出 | 删掉导入面板写完后那一次回调 | 用例 1、2 |
| 通知不落地 | 渲染时不把刷新计数传给下栏 | 用例 1、2 |
| 计数不参与重读 | 下栏重读依赖里去掉刷新计数 | 用例 1、2 |
| 通知时机挪错 | 把通知挪到「挂载也会走」的那一步（读取清单之后） | 用例 1、2 的次数断言 + 用例 3 |
| 下栏不再用返回值更新自己 | 停用 / 启用分支不再写回快照 | 用例 4 |

判据 5 全绿：

- `pnpm typecheck` 7 包 ✅
- `pnpm test:behavior` **139 文件 / 563 用例** ✅（新增 1 文件 4 用例）
- `pnpm test:architecture` 15 文件 / 66 用例 ✅
- `pnpm docs:check` / `pnpm test:quality`（含 UI 合同与许可证）✅

合同同步：`ui-specs/application-workspaces.md` 的推荐来源工作区段落补上「同一页的导入区与来源列表共用一次存储改动」。

**边界**：只补了「写完之后通知对方重读」这一件事，没有把两栏合并成一个状态源——下栏自己还有停用 / 启用 / 删除 / 移除规则这些写动作，合并会把「谁拥有快照」搞乱。**待确认**：在应用里再走一遍「先待在这一页 → 导入」，确认下栏当场跟上。
