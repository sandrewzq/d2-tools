# 命运之小日向能力参考

> 状态：搁置
> 更新时间：2026-08-07

## 定位

命运之小日向只作为外部产品能力参考，不作为 `d2-service` 的数据源、领域模块、运行时依赖或产品名称。当前不把其能力纳入应用实施范围，也不复制其机器人形态、指令体系或实现代码。

若后续重新评估，只提炼适合当前应用的产品能力，并基于 Bungie 官方接口、Destiny Manifest、用户授权账号数据和 `d2-service` 现有模块重新设计、原生实现。

## 最终判断

小日向仍有参考价值，但集中在以下四点：

- 高频信息的优先级。
- 日报 / 周报的摘要结构。
- 一句话查询的低操作成本。
- 主动提醒和变化通知。

## 可参考能力

### 高频信息的优先级

首页不应把全部活动、商人和轮换信息等权平铺。应根据时效、玩家目标、账号拥有情况和操作价值突出最值得关注的少量信息，其余事实保留在对应领域页面。

### 日报 / 周报的摘要结构

摘要应回答“今天或本周发生了什么变化、哪些内容即将结束、玩家现在可以做什么”，并保留更新时间、官方证据和无法确认状态。它是首页领域数据的压缩视图，不建立第二套活动或商人数据。

### 一句话查询的低操作成本

玩家应能用一句自然语言查询高频问题，例如当前轮换、商人库存、装备来源或本周优先事项。回答由 `d2-service` 内部确定性能力生成事实和证据，AI 只负责理解问题与组织表达。

### 主动提醒和变化通知

后续可以基于官方数据快照识别真正变化，例如周更完成、仄开放、目标装备在售或限时活动即将结束。通知必须说明触发时间、数据来源和时效，不根据固定日历或历史库存伪造开放状态。

## 当前不做

- 不接入或调用命运之小日向 Bot。
- 不采集其 QQ 消息、私有接口或未公开数据。
- 不实现 QQ 指令、群机器人或外部品牌入口。
- 不把日报、周报、商人和掉落查询复制进 AI 工作台。
- 当前不建设后台订阅、系统通知或推送基础设施。

## 重新启用条件

只有在首页每日 / 每周数据、商人 Offer 时效、装备目标和官方来源证据稳定后，才重新评估摘要优先级、变化检测和提醒能力。重新启用时应先形成独立任务与验收标准，不直接并入现有功能。
