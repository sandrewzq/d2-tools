# 本地配装工作台、护甲优化与 DIM 导入

> 状态：Backlog
> 更新时间：2026-07-30

## 定位

“配装”菜单同时管理 Bungie 游戏内配装和 d2-tools 本地方案，但两者承担不同职责：

- Bungie 游戏内配装是已经发布到游戏中的正式槽位，用于直接应用当前完整配置。
- d2-tools 本地方案是独立应用内部的设计、导入、优化、编辑、核对和执行对象，可以完整，也可以保留缺失装备或待确认配置。
- 护甲优化、DIM 导入、当前装备复制、游戏内槽位复制和攻略解析都进入同一个本地方案工作台，不各自维护另一套方案或页面结构。
- 本地方案成功应用后，可以把当前角色状态保存到用户选择的 Bungie 游戏内槽位；两者不自动同步，也不隐式覆盖。

d2-tools 必须独立实现完整流程。`d2-armor-solver` 只作为护甲计算规则和交互参考，`d2-skill` 只作为 Bungie 配装 API、结构化输出和 `plan / execute` 安全边界参考；产品运行时不得嵌入外部页面、启动外部 CLI 或要求用户安装其他工具。

全局 AI 抽屉可以解析攻略、解释候选和填写工作台条件，但不承载方案列表、方案编辑器或写操作状态。

## 领域对象

### Bungie 游戏内配装

游戏内配装来自 Bungie `CharacterLoadouts`，是正式、可直接应用的对象。

- 读取并显示官方返回的槽位、名称、图标、颜色、装备实例和 `plugItemHashes`，通过 Manifest 解析可确认的装备、子职业、技能、星象、碎片和模组信息。
- 支持官方 `EquipLoadout`、`SnapshotLoadout`、`ClearLoadout` 和 `UpdateLoadoutIdentifiers` 能力；名称、图标和颜色只能使用 Bungie 允许的标识定义，不伪造自由文本重命名。
- 每件装备按实例 ID 投影当前账号位置、当前装备差异和本地方案引用；未定位时不得使用同名物品替代。
- 主目录显示已有内容的槽位；空槽进入保存目标选择器。清空、覆盖和修改标识都必须明确确认。
- 应用游戏内槽位直接调用 Bungie，由 Bungie 决定最终结果；d2-tools 不在调用前偷偷改写槽位内容。

### 本地方案

本地方案是 d2-tools 的统一配装工作对象，按职业保存完整或不完整的目标配置。

- 保存方案名称、职业、装备目标、指定实例、目标 Plug、子职业配置、护甲优化条件、说明和来源信息。
- 装备条目至少区分目标定义 `itemHash`、已选择实例 `selectedInstanceId`、目标 `plugHashes` 和允许候选条件；账号匹配状态由当前账号快照重新计算，不作为永久事实保存。
- 未拥有装备、尚未选择实例、无法确认的 Plug 和只读攻略条件都可以保留在方案中，但必须标明缺失、待确认或仅记录。
- 本地方案支持新建、编辑、重命名、复制、删除、显式保存、方案对比和安全应用。
- 保存本地方案只写入 d2-tools 数据，不触发 Bungie 写操作。
- 当前旧 `LoadoutTemplate` 只保存当前装备实例，不是目标模型；当前没有正式迁移负担，实施时直接替换旧 store、IPC、ViewModel 和兼容操作区，不长期维护两套本地方案。

### 方案来源

来源只记录方案最初如何进入工作台，不限制后续编辑和应用能力：

- `manual`：从空白工作台创建。
- `current-equipment`：从当前角色已装备状态创建。
- `bungie-loadout`：从游戏内配装槽复制。
- `dim-link`：从 DIM 分享链接导入。
- `guide`：从攻略文本、网页、视频文案或图片解析结果创建。

护甲优化器不是方案来源。任何来源的方案都可以在工作台中使用护甲优化器，并保留原始来源和后续修改时间。

## 本地方案工作台

统一流程：

1. 点击“新建本地方案”或选择一个导入 / 复制入口。
2. 进入本地方案工作台。
3. 设置名称、职业、目标和约束。
4. 选择武器、具体实例和目标 Perk。
5. 选择、锁定或排除护甲，并设置异域、六维目标、碎片变化和模组预算。
6. 计算多个真实账号护甲候选组合。
7. 选择一个候选结果写入当前工作台。
8. 核对完整方案、缺失项、账号位置和执行计划。
9. 显式保存为本地方案。
10. 应用方案；成功后可选择保存到 Bungie 游戏内槽位。

本地方案工作台是唯一编辑入口。空白创建、DIM 导入、当前装备复制、游戏内槽位复制和攻略生成只负责预填工作台，用户确认并保存前不得直接产生不可见的正式方案。

### 武器与配置

- 三个武器槽可以选择账号已有具体实例，也可以只指定武器定义并暂不绑定实例。
- 可以保存明确目标 Perk；候选实例必须使用真实 socket、当前 Plug 和可切换 Plug 核对。
- 同一武器存在多个满足条件的实例时必须由用户选择，不能静默选择名称相同的任意实例。
- 子职业、技能、星象、碎片和模组优先保存稳定 Hash；无法通过当前 API 安全应用的配置保留为“仅记录”。
- 机灵、载具、飞船、公会战旗、徽标、终结技和动作不进入核心装备应用清单。

### 护甲优化

护甲优化器是本地方案工作台内部的计算能力，不是独立方案类型或独立持久化页面。

- 输入当前职业、六维最低目标、优先属性、碎片属性变化、`+5 / +10` 模组预算、固定异域、锁定实例、排除实例和允许来源位置。
- 直接消费账号中真实护甲实例、部位、职业、六维属性和调整信息，不要求用户重复手工录入已有护甲数量。
- 锁定用户已经选择的护甲，只计算其余槽位；也允许从零计算全部五个护甲槽。
- 输出多个候选，每个候选必须包含五件具体实例、最终属性、模组分配、目标差值、属性浪费、当前已装备数量、转移数量和不满足约束的原因。
- 候选列表是临时计算结果；只有用户选择的候选写入工作台并随本地方案保存，不保存所有未选候选。
- 已保存方案可以重新进入工作台，用原约束和最新账号快照重新优化，并选择更新当前方案或另存副本。

护甲算法应迁入 `packages/core` 的纯 TypeScript 模块，复用 d2-tools 已有账号和护甲属性模型。不得嵌入 `d2-armor-solver` 的单文件 HTML、UI 或 `localStorage`。

## DIM 导入

DIM 导入是本地方案的正式创建入口，必须保留。

- 支持 DIM 配装分享链接（`dim.gg/...`）的单向导入，由 d2-tools 自己完成链接解析、结构验证、预览和账号匹配。
- DIM 只是一种外部交换格式；DIM 服务不可用只能影响导入入口，不能影响本地方案、护甲优化和游戏内配装能力。
- 解析结果先进入导入预览，再预填本地方案工作台；用户确认并保存后才创建正式本地方案。
- 尽量保留 DIM 中可确认的职业、子职业、技能、星象、碎片、武器、护甲、Perk、模组和原始分享链接。
- 链接无法读取、格式变化或关键字段不足时不创建半成品方案，保留原始错误和恢复方式。
- DIM Wishlist 是武器 Roll 匹配规则，继续归 T2 仓库推荐与清理工作台，不属于 DIM 配装导入。

## 攻略导入与账号匹配

- 普通文字、网页、视频文案和图片可以通过已配置 AI 解析为结构化条件，并进入同一个本地方案工作台。
- 攻略可以只描述局部构筑；未提及槽位保持未指定，不自动补齐或猜测。
- 武器按本体和明确 Perk 匹配；异域护甲精确匹配；普通护甲通过护甲优化器和用户约束选择具体实例。
- 俗称、简称和同名歧义必须让用户确认。
- AI 只负责解析条件、解释结果和协助筛选真实候选，不伪造账号外装备、不隐式执行写操作。
- 原始攻略条件、解析警告、账号证据和用户调整结果随方案保存，以便后续重新核对。

## 应用与发布

“应用本地方案”和“保存到游戏内槽位”是两个连续但独立的步骤。

### 应用本地方案

- 只能应用到与方案职业一致的目标角色；职业不一致时要求切换角色。
- 应用前生成完整 `plan`，列出其他角色到仓库、仓库到目标角色、替换装备、批量装备和已验证 Plug 切换步骤。
- 全程优先使用实例 ID；未绑定实例或存在多个候选时必须先完成选择。
- 物品正由其他角色装备时，计划必须列出受影响角色和必要的替换步骤，一次确认后执行，不逐件弹窗。
- 只有当前实例 `reusablePlugs` 或其他明确可写能力证明可用的 Plug 才能进入执行步骤；其余配置保持“仅记录”。
- 任一步失败时停止后续操作，刷新账号实际状态，并分别报告已成功、失败和未执行步骤；不伪造事务回滚。
- 不完整方案可以保存，但应用时只执行已确认且可执行的部分，并在确认页突出剩余缺口。

### 保存到游戏内槽位

- 只有方案已经应用并通过账号刷新核对后，才提供“保存到游戏内槽位”。
- 用户选择真实 Bungie 槽位；覆盖已有槽位必须确认，空槽可以直接保存。
- 调用 `SnapshotLoadout` 保存当前角色状态，并允许使用 Bungie 合法的名称、图标和颜色标识。
- 保存成功后刷新游戏内配装和账号快照，但不自动修改或删除本地方案。

## 界面边界

配装菜单保留两个一级视图：

- `游戏内配装`：官方槽位目录、完整配置、当前账号核对和官方写操作。
- `本地方案`：方案目录、创建入口和方案详情。

本地方案的“新建”“导入 DIM”“从当前装备创建”“复制游戏内配装”和“从攻略生成”都进入同一个全宽工作台。护甲优化是工作台内部章节，不增加第三个一级 Tab，也不使用小弹窗承载完整求解流程。

工作台默认采用“配置目录 / 当前编辑区域 / 方案摘要”三栏结构：

- 配置目录：基础信息、子职业、武器、护甲、属性与模组。
- 当前编辑区域：字段、装备候选、护甲计算结果和选择操作。
- 方案摘要：完整度、缺失项、最终属性、账号位置和执行准备状态。

原型必须先更新 `全应用视觉原型.html` 的配装章节、功能绑定表和状态矩阵，再迁入共享 `packages/ui`。不得继续保留旧模板兼容页面或为 DIM、攻略、优化器复制多棵 JSX。

## 当前不做

- d2-tools 云端方案同步、公开分享社区和多人协作编辑。
- 直接读取用户 DIM 私有方案库；第一期只处理用户主动提供的 DIM 分享链接。
- 在未确认执行计划时自动转移、装备、切换 Plug 或覆盖 Bungie 槽位。
- 通过名称猜测具体实例，或把账号外装备描述为已经可用。
- 自动拆解、购买或执行其他不可逆游戏操作。

## 实施切片

1. **实现：本地方案领域重建**：建立本地方案、装备目标、配置目标、来源、护甲约束和账号匹配结果的明确模型，替换旧 `LoadoutTemplate`。
2. **实现：游戏内配装能力补齐**：读取完整 Plug 和标识定义，接通应用、快照、清空和修改标识，并补齐实例位置与当前装备差异。
3. **实现：本地方案工作台状态模型**：统一空白创建、当前装备、游戏内槽位、DIM 和攻略预填流程，支持编辑、保存、复制、删除和重新打开。
4. **实现：护甲优化核心**：将护甲求解、现有配装优化、候选解释和真实账号实例匹配迁入 `packages/core` 与 `packages/app`。
5. **实现：DIM 分享链接导入**：完成解析、结构验证、预览、工作台预填、错误恢复和来源追踪。
6. **实现：方案应用与发布**：建立 `plan / execute / refresh` 闭环，接通转移、装备、可验证 Plug 切换和保存到 Bungie 槽位。
7. **整理：配装视觉规格与共享 UI**：更新冻结原型、功能绑定表和状态矩阵，再重建唯一共享配装页面并删除旧模板兼容 UI。
