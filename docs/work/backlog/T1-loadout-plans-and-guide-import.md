# 配装方案与攻略导入

> 状态：Backlog
> 更新时间：2026-07-24

## 定位

“配装”菜单以 Bungie 游戏内配装为主，本地配装方案为辅助。两者不是同一种对象，保存和应用操作必须明确区分。

全局 AI 抽屉保持独立：可理解当前页面、解释结果并在用户确认后执行应用操作，但不承载配装方案的主页面、历史或状态。

## 对象与术语

### 游戏内配装

游戏内配装是 Bungie 保存的角色配装槽，是正式、可直接应用的对象。

- 读取并显示 Bungie 可提供的信息：名称、图标、所属角色 / 职业、槽位、保存的装备实例，以及这些实例在当前账号中的位置和可定位状态。
- 不显示颜色，也不伪造 Bungie 未提供的已保存 Perk、子职业、技能、星相、碎片或模组配置。
- “应用游戏内配装”只调用 Bungie `EquipLoadout`，不由 d2-tools 预先转移或逐件装备；成功后刷新账号状态。
- “保存当前配装”只调用 Bungie `SnapshotLoadout`，把目标角色当前已装备状态写入用户明确选择的槽位；空槽可选，覆盖已有槽位必须确认。
- 游戏内配装槽的重命名、删除等 Bungie 未开放能力不在 d2-tools 伪造。
- 主列表只显示已有内容的游戏内槽位；空槽仅在保存当前配装的槽位选择中出现。

### 本地配装方案

本地配装方案是 d2-tools 本地保存、按职业绑定的可编辑方案，可完整也可不完整。它不自动同步到 Bungie 槽位。

- 方案条目保存装备定义、目标 Perk 和当前账号的 `selectedInstanceId`；候选列表仅用于编辑时选择实例。
- 方案允许包含未拥有装备；未拥有条目的 `selectedInstanceId` 为空。
- 方案定义可携带 Perk 条件；当前第一期不包含子职业、技能、星相、碎片、模组、护甲属性、护甲充能、锻造或大师杰作。
- 支持新建、重命名、删除和显式保存。保存只写本地数据，不触发 Bungie 写操作。
- 既有“本地模板”不做兼容迁移；当前没有用户，旧模型、旧 store 和混合 UI 可直接删除。

## 创建与导入

本地配装方案可从以下入口创建：

1. 从当前角色创建：默认收录全部已装备武器和护甲，并记录武器当前已选 Perk。
2. 从 Bungie 游戏内配装复制：仅复制 Bungie 官方可读的装备实例，不猜测官方未返回的 Perk 或其他配置。
3. 从配装攻略导入：第一期直接支持 DIM 配装分享链接（`dim.gg/...`），不依赖 AI。应用读取链接中的结构化装备和明确 Perk，先展示导入预览，用户确认后才创建本地方案；链接无法读取、格式变化或字段不完整时不写入方案并明确提示。普通文字、网页、视频和图片仅在已配置 AI 时可导入和解析；未配置 AI 时禁用这些入口并说明原因。
4. 在本地方案中手动编辑：允许增删装备条目、替换或清空指定实例、设置或清空目标 Perk。

攻略可以是完整构筑或局部条件；未提及槽位保持未指定，不自动补齐。

DIM Wishlist 不是配装分享链接，而是武器 Perk / Roll 匹配规则；它属于 T2 仓库推荐与清理工作台，不进入本任务的攻略导入。

## 攻略装备匹配

第一期只做装备与明确 Perk 的真实匹配：

- 默认核对当前角色，同时列出仓库和其他角色中的可转移候选及其位置。
- 武器按本体精确匹配；攻略明确写出 Perk 时，以真实实例 socket / 可切换 Perk 核对。
- 异域护甲精确匹配；传说护甲只确认对应部位是否有可用装备。
- 俗称、简称或同名歧义必须让用户确认，不能模糊命中。
- 原武器缺失或不具备目标 Perk 时，只列出账号内同一武器槽位、同一武器类型的真实候选；攻略明确 Perk 时，候选也必须命中该 Perk。
- AI 只协助解析条件并筛选真实仓库候选，不评分、不排序、不推荐账号外装备。
- 结果展示原始条件、实例 / socket 证据、候选、位置、缺失与待确认项，不输出“可照抄”等主观结论。

攻略记录、内容快照和用户调整版仅保存在本机。链接攻略可形成新旧版本；账号资料刷新或已知写操作成功后，已保存攻略和关联本地方案重新匹配。

## 应用本地配装方案

“应用本地方案”是独立于“应用游戏内配装”的批量操作：

- 仅能应用到与方案职业一致的当前角色；职业不一致时提示切换角色。
- 应用前展示完整执行计划，用户一次确认后执行。
- 已指定且可执行的条目会转移、装备，并切换方案指定的可用 Perk；未拥有、未指定实例或未选候选的条目保留为未完成，不阻塞其他条目。
- 若物品正由其他角色装备，执行计划先完整列出受影响角色和物品；用户确认后统一处理，不逐件弹窗。
- 任一步失败时停止后续操作，刷新账号实际状态，并分别报告已成功和失败项；不伪造回滚。
- 应用本地方案不写入 Bungie 槽位。用户需要时可在之后单独“保存当前配装”到 Bungie 槽位。

## 当前不做

- d2-tools 本地方案的导出、分享和导入，延后至稳定版发布后；第一期仅例外支持外部 DIM 配装分享链接的单向导入。
- 本地方案与 Bungie 槽位的自动关联、自动覆盖或隐式同步。
- 技能、子职业、星相、碎片、模组、护甲属性和护甲充能匹配 / 应用。
- 根据社区来源、外部网页或 AI 推测给出装备强度结论。

## 界面边界

- 游戏内配装与本地配装方案的具体排版后续单独设计并更新冻结原型。
- 业务上两者必须独立呈现，不能再按来源混成同一类“配装条目”。
- 不新增左侧“攻略”菜单，也不将完整配装流程塞入全局 AI 抽屉。

## 实施切片

1. **实现：配装领域重建**：替换旧本地模板模型，建立游戏内配装、本地配装方案、方案条目和账号匹配结果的明确边界。
2. **实现：Bungie 游戏内配装**：按当前角色读取、展示官方可读字段，接通应用和保存当前配装到指定槽位。
3. **实现：本地配装方案**：完成创建、编辑、显式保存、删除、批量应用、跨角色确认、Perk 切换与真实刷新。
4. **实现：攻略导入与匹配**：接入全输入方式、版本记录、装备 / Perk 匹配和候选绑定。
5. **整理：配装页视觉规格**：完成新的配装页面原型、功能绑定表和状态矩阵后，再迁入共享 UI。
