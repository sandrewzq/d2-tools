# Bug #109 英文模板的栏位名过不了导入校验

## 症状

仓库菜单下载的**英文推荐模板**，照说明填好后导不回来：六个栏位列——`Barrel or Sight`、`Magazine`、`Masterwork`、`Perk 1`、`Perk 2`、`Origin Trait`——每一格都报

> 无法在这把武器任一已列版本的对应官方栏位中精确确认。

武器名本身不报错，报错全在栏位上。

## 复现与证据

把导出的英文模板（含自带示例行）当数据行喂给 `previewWeaponRecommendationCsv`（本机只读副本 + 桌面端同一份产品代码），得 **11 条异常**，全部落在上述六列。同一份文件里：

- 把 `Perk 1` 的值从官方英文名换成中文官方名（`喂食狂热`），**不再报错**；
- 中文模板的示例行（同一批实测）0 条异常。

也就是说，判据看的是**名字是不是当前资料库语言里的官方名**，与模板的语言无关。

## 根因

栏位（枪管 / 弹匣 / 大师 / Perk / 起源特性）的官方名是按**资料库当前语言**的定义核对的：

- 送到导入期的定义里，每个插件只有一份名字——`projectCommunityMatchDefinition`（`packages/desktop/src/main/workers/gameDataWorker.ts:211`）只取 `displayProperties.name`，没有中英两套。
- 资料库语言来自 `config.data.manifest_language`（默认 `zh-chs`），且 `manifest_language_follows_interface: true` 时跟着界面语言走。中文界面 + 中文资料库，英文栏位名就一个也对不上。
- 已有的英文定义池只补了**武器名**：`loadEnglishItemDefinitions`（`packages/desktop/src/main/ipc/community.ts:397`）拿文件里写过的英文名去查 hash，只造 `{hash, displayProperties: {name}}` 这种桩定义，没有插件、没有插槽信息——即使把池子扩到插件，也要先有 hash → 英文插件名的查询接口。

所以英文模板目前只在「界面语言 = 资料库语言 = 英文」时才导得回来；中文界面下点「下载英文模板」，拿到的是一份注定导不回来的文件。

## 影响范围

- 缺陷来自第二批加「英文名称 / 弹药类型」两列时的语言依赖（2026-09-24），与第四批加的「武器ID」列无关；加了这一列也一样。
- 中文模板不受影响。

## 可选改法（未定）

1. 英文模板的示例行与表头说明改成**资料库语言的官方名**，并在模板里写明「栏位名要用资料库语言的官方名」——代价最小，但英文模板就只剩列名是英文。
2. 下载时按资料库语言判断：语言不匹配就不导出英文模板，或导出时给出提示。
3. 给插件也补一份英文定义池，让栏位名按英文核对——要新开 hash → 英文插件名的查询接口，工作量最大，还要处理中英混写的文件。

倾向 1 + 2 组合：模板始终导得回来，语言不匹配时不静默给一份废文件。
