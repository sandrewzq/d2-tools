# T88：资料库查询：装备模式去掉筛选框，Perk 展开后左栏筛关联武器

> 状态：✅ 已通过实窗验收（2026-09-19）
> 合同：`docs/work/references/ui-specs/application-workspaces.md`
> 来源：原记于 `docs/todo.md` 的 T88 行，2026-09-19 迁入本文件，细节以本文件为准。

## 一、问题

装备查询是精确查询、结果不多，高级筛选基本用不上；
Perk 反查武器动辄几百件，才是筛的地方。

## 二、改法（已改完）

1. 装备模式左栏只剩模式、主搜索、清空，不再渲染任何筛选控件
   （`LibraryEquipmentFilter` 与其计数函数保留原样，只从界面下线）；
2. Perk 模式左栏在「关联分类 / 关联装备」之下新增固定四个维度的分面——
   位置、属性、弹药类型、框架，取值来自当前展开 Perk 的关联武器，
   取值旁的数字是「再选上它会剩几件」（统计该取值时排除它自己这一维，
   否则选完一项后同维其余取值全变 0）；数字为 0 且未选中的取值禁用；
3. 展开「关联装备」时一次读完全部关联武器（桌面主进程单次上限 100 条，渲染层顺序取完），
   否则数字只能算出已取回的那部分；
4. 图标与配色复用共享战斗图标语言——位置用槽位字形、属性用官方伤害图标、
   弹药类型用弹条，配色走同一组元素 token，选中态压过元素色；
5. 顺手修掉 `.library-mode-tabs` 的 `repeat(3, minmax(0, 1fr))`：
   只有两个页签，第三列是死的，还把「Perk 与框架」挤成两行。

## 三、已知代价

同一时刻只筛一个 Perk——左栏只有一块面板，展开哪个就作用于哪个。

换展开的 Perk 曾会沿用上一个 Perk 的条件，2026-09-19 按用户决定改为清空：
左栏记住上一次展开的 Perk（`relatedFilterPerkKeyRef`），展开别的 Perk 时把
位置 / 属性 / 弹药类型 / 框架四个维度清回 `defaultLibraryPerkRelatedFilter`；
收起再展开同一个 Perk 不清，条件对这个 Perk 仍然有效。改动只在
`packages/ui/src/library/LibraryPageContentView.tsx` 的 `handlePerkExpand`，
不涉及 `packages/app` 的筛选模型。
