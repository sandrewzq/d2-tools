# 资料库异域护甲定义详情

> 状态：代码已实现，待 CI
> 更新时间：2026-07-13

## 问题

资料库定义详情当前把所有装备的 `perks` 都按武器槽位解释。异域护甲的 socket 1、2、3 通常引用同一个部位模组池，因此页面会把“快速球”“火力无限”或抗性模组重复显示成“枪管 / 瞄具”“弹匣 / 电池”“第 4 列”。

Bungie 原始定义已经提供正确的异域固有特性：

- 炎阳护腕：`氦气螺线`，plug category 为 `intrinsics`。
- 星火协议：`融合掌控`，plug category 为 `intrinsics`。

这些固有特性位于护甲后部 socket，当前 UI 只读取 socket 0–5，反而将真正需要展示的数据截掉。

## 目标

资料库详情根据装备分类选择展示模型：武器继续展示武器定义结构；护甲展示 DIM 风格的护甲定义概览。资料库只解释 Manifest 定义，不伪装成玩家持有的装备实例。

## 异域护甲详情结构

### 身份区

展示：

- 图标与名称。
- 稀有度。
- 职业限制。
- 护甲部位与护甲类型。
- 官方来源提示与当前公开渠道。

不展示光等、装备锁定状态或收藏解锁状态。

### 属性数据限制

本地 Bungie Manifest 核对结果表明，炎阳护腕和星火协议的定义只包含旧的“防御 / 能量”等零值字段，没有 DIM 截图中的六维属性。DIM 展示的 `0 / 25 / 0 / 0 / 30 / 20，总计 75` 来自具体装备实例或固定收藏 Roll，不是当前 `DestinyInventoryItemDefinition` 可确认的资料库定义数据。

因此资料库不能直接复刻 DIM 的六维数值。未接入可信的“固定收藏 Roll”官方来源前：

- 不展示六维数值或总属性。
- 不用零值占位伪装成定义属性。
- 保留未来接入独立官方数据源后的展示位置，但必须明确数据来源。

### 异域固有特性

从物品 socket 的固定 plug 中读取 `plug.plugCategoryIdentifier === "intrinsics"` 的定义，展示：

- 特性图标。
- 官方中文名称。
- 官方中文说明。

同一特性按 hash 去重。普通护甲没有可靠固有特性时不显示该区域。

### 护甲插槽说明

资料库不展开通用模组池、部位模组池、着色器池、大师杰作池或装饰池。后续如需展示插槽，只展示“通用护甲模组槽”“臂铠模组槽”等静态槽位类别，不展示玩家已安装内容。

## 不进入资料库的数据

以下内容属于当前装备实例或账号状态，不从 DIM 界面照搬：

- 实际属性 Roll 与总属性。
- 当前能量等级。
- 已安装模组。
- 已应用装饰与着色器。
- 收藏、解锁、锁定和装备状态。
- 大师杰作状态。

## 数据与组件边界

- `packages/core`：从固定 socket 提取异域固有特性摘要，避免把 reusable/randomized 模组池当成特性。
- `packages/app`：在资料库结果模型中承载护甲定义摘要。
- `packages/ui/src/library`：根据 `group_key` 分流武器和护甲详情；护甲绝不调用武器列标签函数。
- Desktop / Web / Prototype：继续消费同一个共享资料库页面，不复制详情结构。

## 异常与降级

- 六维属性缺失：隐藏属性区，不回退到实例数据或零值。
- 异域特性缺失：显示“资料库暂未提供异域固有特性”，不回退到模组池。
- 分类无法确认：只展示通用定义字段、来源与渠道，不展示武器或护甲专属结构。

## 验收标准

- 炎阳护腕显示“氦气螺线”及官方说明。
- 星火协议显示“融合掌控”及官方说明。
- 两件护甲都不再显示“武器定义结构”“枪管 / 瞄具”“弹匣 / 电池”或重复模组候选。
- 不展示 Manifest 无法确认的六维属性或总属性。
- 武器详情现有 Perk 列展示不受影响。
- 本地不运行自动化验证；push 后由 CI 执行行为、类型和质量检查。
