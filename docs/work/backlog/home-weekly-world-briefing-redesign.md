# 首页本周游戏世界简报重设计

## 目标

将首页从不可靠的“每日 / 遗失区域”聚合页改为无需 Bungie 账号登录的“本周游戏世界简报”。首页只展示 Bungie 公开接口或经过校验的公开机器数据能够确认的世界状态；获取不到、已经过期、来源冲突或只能推测的数据不生成区块。

设计基准为 1920×1080 桌面窗口。首页沿用现有 `ProductShellHost` 和工作区侧栏，只重做 `packages/ui/src/home/` 内容层，不改共享工作区 chrome。

## 范围

首页展示：

- 每周重置时间和剩余时间。
- 当前夜幕或宗师先锋警戒。
- 本周轮换突袭。
- 本周轮换地牢。
- Bungie 明确返回的铁旗、节日活动等限时事件。
- Bungie 明确返回的本周奖励或声望加成。
- 仄商人的在场状态、离开时间和可确认库存。
- 经过稳定公开源确认的异域任务轮换、试炼状态和重点可刷奖励。
- 每项数据的低权重来源与更新时间。

首页不展示：

- 每日区域和每日重置卡片。
- 遗失区域及九个星球候选数据。
- 通过 Manifest 候选定义、固定日历或硬编码轮换推测的活动。
- 账号个人完成进度、角色任务清单和仓库状态。
- 任何要求用户登录 Bungie Profile 才能读取的数据。
- 尚未接入真实 Perk 读取前的“好 Roll”判断。
- 尚未接入收藏对比前的“已拥有”判断。
- 错误、等待、不可用和待确认占位卡片。

## 数据边界

| 内容 | 主要证据 | 展示条件 | 失败行为 |
|---|---|---|---|
| 每周重置 | Bungie 固定重置规则和当前时间 | 始终可计算 | 仅隐藏异常格式，不影响其他内容 |
| 夜幕 / 宗师 | 经过校验的公开 API / JSON / 版本化数据文件 | 当前周、活动和奖励字段完整且未过期 | 不生成夜幕区 |
| 轮换突袭 | 经过校验的公开 API / JSON / 版本化数据文件 | 当前周、高亮状态和活动名称可确认 | 不生成突袭区 |
| 轮换地牢 | 经过校验的公开 API / JSON / 版本化数据文件 | 当前周、高亮状态和活动名称可确认 | 不生成地牢区 |
| 异域任务轮换 | 经过校验的公开 API / JSON / 版本化数据文件 | 当前周、任务名称和有效期可确认 | 不生成异域任务区 |
| 限时事件 / 加成 | `GetPublicMilestones` | 名称和活动类型能明确解析 | 不生成对应卡 |
| 仄商人 | Bungie Public Vendors API 和 Manifest | 仄处于 enabled 状态且库存可读 | 整个仄面板隐藏 |
| 仄库存 | Vendor sales、物品定义和货币定义 | 物品名称可解析 | 丢弃单个不可读物品 |
| 仄位置 | Vendor 当前 location index 和 Manifest 位置定义 | 两端都可解析 | 不显示位置字段 |
| 仄离开时间 | Vendor `nextRefreshDate` | 时间有效且晚于当前时间 | 不显示倒计时字段 |

Manifest 只负责把 hash 翻译为名称、图标、类型和说明，不能单独证明某项活动当前生效。

首页禁止长期抓取普通网页正文。外部数据源必须是公开 API、JSON 或版本化数据文件，并提供或允许计算 `fetched_at`、`expires_at` 和数据版本。周常数据跨过每周重置、每日数据跨过每日重置后立即失效；多来源冲突时不选择其中一项，而是隐藏对应区块。

用户账号接口不再作为首页依赖。Desktop、Web 和 Prototype 在未登录 Bungie 的情况下必须能够加载同一份世界简报。

## 信息架构

首页采用“本周情报”布局，并与设置页等菜单共享产品标准圆角面板、中文 UI 字体、标题层级、间距和状态色。页面不使用独立 HUD 网格、方角细线框、等宽英文标签或大 Hero，也不通过固定高度制造空白。

### 页面标题区

- 左侧显示“本周游戏世界简报”和低权重英文眉题。
- 右侧显示距离每周重置的剩余时间。
- 来源更新时间放在现有顶部状态区或页面底部元数据，不新增大状态卡。

### 本周作战桌

桌面首屏由三层连续区域组成：

- 顶部周常情报带：夜幕 / 宗师占主要宽度，高亮突袭、高亮地牢和异域任务按列展示；同一类别的多项活动使用紧凑行，不合并成斜杠字符串。
- 主体库存区：左侧展示仄的完整可读库存，右侧是实时情报栏。
- 底部来源栏：只展示来源类型、更新时间和失效规则，不生成独立状态卡。

实时情报栏承载限时活动、试炼、周加成和重点可刷奖励。某项没有稳定数据时只移除该行或区块，其余内容自然上移；页面和面板高度由真实内容决定，不强制撑满 1080 高度。

### 夜幕主卡

- 展示活动名称、勇士类型、威胁和可见奖励。
- 奖励在夜幕区右侧形成独立信息列，主信息与奖励在同一横向情报带中完成。
- 缺少奖励时只隐藏奖励区，活动卡仍可显示。

### 轮换与事件卡

- 卡片只保留类型、活动名称和一条可确认说明。
- 不显示“待确认”“等待同步”等状态。
- 同一分类存在多个确认条目时，使用紧凑行完整展示当前来源确认的条目，并显示数量；不合并成斜杠字符串。

### 仄商人面板

仄是首页一级信息，不是底部状态标签。面板包含：

- 仄商人名称和已确认状态。
- 可解析时显示当前位置。
- 可解析时显示离开倒计时。
- 已读取库存数量。
- 首页展示仄当前返回的全部可读库存，不再截断为四件；当前接口返回 12 件时完整展示 12 件。
- 每件物品展示真实名称、类型、图标和价格。
- 桌面宽屏默认使用四列库存矩阵；中等宽度使用三列，窄屏使用两列或单列。
- 点击物品进入商人页并定位对应库存；整块标题可进入完整商人页面。

首页不对物品添加“推荐”“好 Roll”或“已拥有”标签，直到对应真实数据和规则接入。

## 状态与错误处理

- 页面采用 fail-closed：没有证据就没有卡片。
- 单个分类失败不影响其他分类。
- 仄库存中单个物品解析失败时丢弃该物品，不降级为 hash 或占位名称。
- 所有分类均为空时，首页只保留标题、重置时间和一个简短说明，不渲染空的作战桌框架。
- 刷新期间保留上一次成功快照，避免卡片闪烁；没有旧快照时使用稳定骨架，不显示推测内容。
- 任一外部 provider 失效时清除依赖该来源的活动区块；Bungie Public Vendors 与其他独立来源继续显示。

## 响应式与交互

- 1920×1080 是主要视觉验收尺寸，优先让完整 12 件库存和全部有效周常信息进入首屏。
- 中等桌面宽度将库存从四列降为三列，并保持右侧实时情报栏可读；空间不足时实时情报栏落到库存下方。
- 窄屏和移动端改为单列：周常情报、仄、实时状态依次排列。
- 所有可点击卡片具备至少 44×44px 的交互目标和可见键盘焦点。
- 动效只用于首次加载和卡片更新，持续 150–300ms，并遵守 `prefers-reduced-motion`。
- 状态不能只靠颜色表达，必须同时使用文字或图标。

## 模块边界

- 共享 UI 实现在 `packages/ui/src/home/` 和 `styles.css` 的 `.home-*` 规则中。
- 首页 ViewModel 负责把 weekly summary 和 vendor source 转换为可选卡片，不让 JSX 直接判断 Bungie 原始响应。
- 新增稳定来源注册边界 `WorldBriefingSourceRegistry`，每个 provider 只负责读取一种公开机器数据并返回统一的时间戳、有效期、来源和状态。
- Bungie 原始活动识别继续留在 `packages/core/src/weekly/`。
- 仄的 enabled、位置、刷新时间和库存解析留在 core / app 数据层，不把 vendor hash 判断散落到首页组件。
- Prototype 和 Web 只更新 mock / adapter，继续消费同一个 `HomePageContentView`。
- 不修改共享 `ProductWorkspace`、全局 token 或其他菜单内容。

## 测试与验收

行为测试至少覆盖：

- 每日和遗失区域内容不再出现在首页。
- 每种本周分类有确认数据时生成卡片，无数据时完全隐藏。
- 夜幕缺少奖励时仍显示活动主体。
- 仄未到访或库存不可读时整块隐藏。
- 仄库存展示全部可解析物品，不再截断为四件。
- 仄位置和离开时间分别按可用性独立显示。
- 多来源返回重复活动时按稳定标识去重，来源冲突时隐藏对应分类。
- 1920×1080 下顶部周常情报带、完整 12 件仄库存和实时情报栏无大面积空洞。
- 移动端按既定顺序单列展示。

最终验证运行：

- 首页定向行为测试。
- `npx pnpm@9.15.0 verify:ui`。
- 如果触及 Desktop adapter 或真实 Bungie 接线，再运行 `npx pnpm@9.15.0 verify:desktop`。
- `npx pnpm@9.15.0 visual:home`，人工检查 1920×1080 对齐、文字密度、仄库存和空数据状态。

## 验收标准

- 首页不再展示任何遗失区域或每日内容。
- 所有可见活动都能追溯到当前有效的公开 API、JSON 或版本化数据文件，Manifest 不作为激活证据。
- 仄到访且库存可读时，首页能看到完整可读库存，而不是四件摘要或单一状态标签。
- 任一数据源失败不会产生错误信息墙或猜测卡片。
- 1920×1080 下周常情报带、完整库存矩阵和实时情报栏使用统一产品面板语言，首屏没有由固定高度产生的大面积空洞。
- Prototype、Web 和 Desktop 继续共享同一首页内容组件。
