# Bug #106 同一个中文名对应多件装备，CSV 里的第二行被导入判重拦下

## 症状

导入 `LGpig推荐表_导入模板.csv` 报的 29 行异常里，有 6 行是「同一件武器同一个来源」重复。它们跟 Bug #105 的空格问题不是一回事，名字本身在资料库里查得到。

应用按「武器身份 + 来源」判重（`weaponIdentityKey`：`英文名称` > `武器ID` > `武器` 三选一）。只写中文名时，一个中文名只能代表一件装备，第二行起就被判成重复，只剩第一行。

## 三种成因

| 页面上的行 | 真相 |
|---|---|
| `隐士` × 2 | 撞译。微型冲锋枪是 The Recluse，融合步枪是 The Eremite，中文都译成「隐士」 |
| `食莲者` × 2 | 两个版本。旧版 `3922217119`（`releases.v820.season`，绝版原版）和重发版 `837298567 / 924095500`（`releases.v970.core`）；`item_version_relation` 里 `837298567` 的 canonical 是 `924095500` |
| `故我在` × 5 | 同一件装备。5 张卡都是刀剑 `1681583613`，页面按框架摊开写 |

## 处理

改在数据源侧（`攻略/脚本/extract-starside-pve-farming.mjs`），应用侧的判重规则不动。脚本是站点的 HTML 快照转 CSV，本来不读资料库。

新加可选参数 `--manifest <search.sqlite 路径>`：同名多行时去库里取候选，再用**页面自己的图标 URL** 收窄到这一行指的那一版。三条判断路径：

- 各行图标命中不同的 hash 集合，就各填各的。`隐士` 走这条：微型冲锋枪 = `1050806815 / 3257283337`，融合 = `3347946548`。
- 各行图标相同（多个版本共用一张图），就在行数正好等于发布版本数时，按版本从早到晚对应页面上到下的顺序。`食莲者` 走这条：旧 = `3922217119`，新 = `837298567 / 924095500`。
- 两条都走不通就留空并写进报告。`故我在` 的 5 行在库里只有 1 个版本，填 ID 也分不开。

`故我在` 另外在模板层合并：异域页同一个武器身份的行合成 1 行，备注用 ` ｜ ` 分隔各张卡。异域行没有随机器官位、Perk 列本来就空，合并不会拼出页面没推荐过的组合；传说页的 Perk 列有内容，不合并。

每次运行的判断都写进 `抓取元数据.json` 和 `来源与使用说明.md` 的「武器ID 处理记录」，可以逐条核对。不传 `--manifest` 时行为与从前一致，只多一条「仍有同身份多行」的提示。

## 配对结果的独立核对

用页面推荐的 perk 到 `perk_related_items` 反查它关联哪些武器版本，和填进去的 `武器ID` 逐条对照：

| 行 | 页面推荐的 perk | 结果 |
|---|---|---|
| 隐士 · 微型冲锋枪 | 冲击支撑、混沌重塑、武器大师、失衡弹药 | 4 条全落在 `1050806815 / 3257283337` 里，无一条落到融合步枪上 |
| 隐士 · 融合 | 嫉妒刺客、受控连射、洪涝 | 3 条全落在 `3347946548` 里 |
| 食莲者 · 旧 | 边打边劫、枯萎凝视 | 「边打边劫」在全库里只关联 `3922217119` |
| 食莲者 · 新 | 冲击支撑、空中扳机、失衡弹药、狂乱、集体行动、枯萎凝视 | 6 条全落在 `837298567 / 924095500` 里，「空中扳机」只在 v970 |

两边零交叉，说明按发布版本配对的判断这次是对的——它靠的是「页面把新旧版本按时间顺序排」，不是硬证据，换了页面就得重新核对。

模板行数从 344 变成 340（`故我在` 5 行合 1 行）。异域行的备注顺带补上了原来被整列丢弃的 `异域参数`（武器类型 / 赛季）。

## 尚未验证

- 应用侧的 Bug #105 改动还没 build，`packages/services` 的 exports 指向 `dist/`，所以拿新模板导入跑的仍是旧代码。要先 `pnpm --filter @d2-tools/services build`。
- 填了 `武器ID` 之后，perk 校验用的定义池会从「同名全版本」收窄到这几个 hash，可能冒出新的 perk 提示。
- 上面的交叉核对是直接查资料库做的，没有走应用的真实导入路径。未运行本地自动化验证，由后续本地测试、CI 或 Release 负责。
