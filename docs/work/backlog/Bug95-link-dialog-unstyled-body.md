# Bug #95：「从链接同步」弹框里按钮压在输入框上，说明挤在按钮右边

> 状态：🟢 已修复并自检通过（2026-09-17）
> 现象（用户截图，原文「样式乱了」）：仓库 → 推荐来源 → 「从链接同步」弹框里，
> 「读取链接」按钮压在链接输入框的下边框上，右下方那句「链接会跟着这份来源记下来…」
> 又跟按钮挤在同一行、贴着按钮的垂直中线。

## 核实：把弹框按真实标记与真实样式表重建出来量

沿用 Bug #94 的做法——静态页 + 真实构建出来的 CSS，用无头浏览器量尺寸，不靠看截图猜。
量到的修前尺寸（视口 1200，容器宽 920）：

```
弹框        x=240  宽 920
弹框正文     display: block          ← 没有布局，退回默认行内/块流
输入框      x=153  y=411  宽 894  高 34
「读取链接」 x=153  y=445  宽 70   高 30   ← 紧贴输入框下沿，没有间隙
说明一句     x=227  y=453  宽 496  高 13   ← 起在按钮右侧，垂直方向与按钮重叠
```

## 根因：这一块样式的类名跟着「粘贴文本」通道一起失踪了

全仓样式表里 `.vault-wishlist-link-body` 与 `.vault-wishlist-link-dialog` **一条规则都没有**。
弹框的排布（输入在左、按钮与输入同排靠右、说明另起一行）原本挂在**「粘贴文本」那个通道的类名**
`.vault-wishlist-paste` 下；T63 删掉粘贴通道、弹框改用新类名时，标记换了、样式没跟过来，
于是新弹框退回默认流：输入框独占一行，按钮换行落在它正下方（挨着，看着像压上去），
说明作为行内元素接在按钮后面，与按钮同处一个行盒。

同一次排查还发现同一族的第二个问题：人工表格导入弹框的宽度覆盖
（本意是收窄到 720px）写在基础宽度规则**前面**，且只用单类名，被基础规则按源序盖掉，
实测渲染出来一直是 920px——写了等于没写。

## 处置

1. **给链接弹框补上它自己的布局**（`02-workspace.css`）：正文两栏栅格、
   `minmax(0, 1fr) auto`，按钮与输入底对齐，说明整行另起并在窄屏跟随收成单栏。
2. **把「粘贴文本」留下的选择器全部删掉**：样式表里三处（正文两栏、标签栏、
   窄屏 700px 以下收单栏的清单）都还写着那个已删除通道的类名。窄屏那份清单里换成链接弹框的正文，
   否则窄屏下它不会收成单栏。
3. **让两个弹框的宽度覆盖真正生效**：改用「基础类 + 自己的弹框类」的复合选择器，
   与源序无关，人工表格弹框与链接弹框都按内容收窄到 720px。
4. **标题那一栏吃掉剩余宽度**：不收的话它按内容宽参与换行，右下角的「关闭」会被挤到单独一行。

## 这次的教训

「删通道」不只是删标记与逻辑，**它名下挂着的样式也要一起办**：类名换掉而样式没换，
表现不是「少了一块样式」，而是退回默认流——看起来像样式写错了，实际是样式根本没到。
所以守卫按「这个类名必须有布局规则 + 已删通道不许在样式表里留选择器」写，而不是断言某条具体数值。

## 验收判据

1. 「从链接同步」弹框里，链接输入框与「读取链接」按钮同一行，按钮与输入框底对齐，两者之间有间隙。
2. 说明那一句独占一行、灰色，不与按钮挤在同一行。
3. 弹框按内容收窄（720px），标题在左、关闭在右上，标题过长时换行而不是把关闭挤走。
4. 窄窗口下三者依次纵向排列，互不重叠。
5. 人工表格导入弹框宽度与链接弹框一致（同样 720px，不再是 920px）。
6. 五道闸门全绿。
