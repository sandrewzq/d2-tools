# 配装攻略导入与账号匹配

> 状态：Backlog
> 更新时间：2026-07-24

## 定位

这是“配装”菜单的业务能力，不是通用攻略系统，也不是全局 AI 抽屉的子页面。

用户导入一篇配装攻略后，应用提取其中的配装要求，以当前账号和当前角色的真实数据逐条核对，并生成可编辑的配装草稿。结果只展示事实、证据、候选和缺口，不替用户给出主观的“可照抄”结论。

全局 AI 抽屉是独立的通用对话能力：可理解任意页面、分析数据，并在用户确认后调用应用操作。它可以解释配装页中的结果，但不承载本功能的主页面、历史或草稿状态。

## 用户流程

1. 用户进入“配装”菜单，选择导入配装攻略。
2. 输入文字、攻略链接或攻略图片，并选择当前角色。
3. 应用提取攻略内容；自身无法读取链接、视频文本或图片时，调用已配置的 AI。没有可用 AI 或提取失败时，明确提示并保留可继续编辑的输入，不伪造结果。
4. 应用展示解析出的条件、无法唯一识别的词和原始来源；用户可创建“用户调整版”，原始解析版本保持不变。
5. 应用先刷新账号数据；刷新失败时由用户决定是否使用标明时间的本地缓存。
6. 应用以真实账号、Manifest 和已配置数据源逐条展示匹配证据、候选、可达性和缺口。
7. 用户保存为配装草稿，在配装页继续选择候选、编辑和应用；本功能不自动转移或装备物品。

## 支持范围

### 输入与版本

- 支持文字、公开链接和图片输入；视频页面可使用标题、简介、可取得的字幕或文字内容。
- 链接攻略在打开时重新读取；内容变化后保留新旧版本，用户可分别查看、匹配和生成草稿。
- 每个版本本地保存原文快照、链接、图片副本或引用、读取时间和解析结果，不上传云端。
- 用户修改解析结果时创建独立的用户调整版；原攻略新版本不会自动改动既有用户调整版。

### 解析与匹配

- 覆盖武器、护甲、异域、Perk、职业、子职业、技能、星相、碎片、模组、护甲总属性、护甲充能及装备配置状态。
- 只有攻略原文明确写出的必需条件才参与硬性匹配；无法确定的内容显示为待确认，不影响其他已确认条件。
- 俗称、简称和同名歧义不能直接模糊命中，必须列出候选让用户确认。
- 武器拥有目标 Perk 但当前未选中时，作为候选展示，并明确需要切换 Perk。
- 护甲需要区分当前已满足、使用账号已有模组后可满足、以及因装备或模组缺失而无法满足。
- 默认先检查当前角色，同时列出其他角色和仓库中的可转移候选；位置、角色限制和当前配置必须如实显示。
- 账号装备变化、已知写操作成功或资料刷新成功后，后台重新计算已保存配装攻略和草稿；已选装备变为不可用时保留选择并标记原因，不自动替换。

### 数据来源与替代

- 账号事实只来自最新 Bungie Profile、Manifest 和对应实例 / socket 数据。
- DIM Wishlist、应用维护的社区来源、用户配置的个人知识库或指定来源，可作为“可靠替代方案”；每条必须显示来源、版本、适用条件和命中依据。
- 多个可靠来源冲突时全部列出，不由系统合并成结论。
- AI 推测与实时公开网页检索结果只能标为“AI 参考”，必须附原链接和读取时间，不能作为可靠替代或账号事实。
- 可靠替代与 AI 参考都不改变原攻略的匹配事实。

### 配装草稿

- 攻略导入生成的是配装菜单中的普通可编辑草稿，并保留“查看攻略”入口以追溯来源、版本、条件和匹配证据。
- 一套配装可有多个武器候选；草稿按槽位保留全部候选，由用户选择具体物品，不自动批量生成排列组合。
- 即使必需条件缺失，也允许创建未完成草稿；缺失条件必须原样保留。
- 草稿与最新账号数据动态同步；已选装备、候选和缺口随数据变化更新，但应用不擅自替用户换装。
- 删除攻略记录时，必须询问是否保留关联草稿。

## 界面边界

- 入口、导入过程、解析结果、历史版本和草稿均属于“配装”菜单。
- 后续专业 UI 设计需同时支持攻略历史浏览、搜索 / 快速切换和独立详情阅读；具体布局、分栏和视觉样式暂不在本需求中冻结。
- 全局 AI 抽屉可以引用当前配装上下文、解释结果或提出修改建议；所有修改必须由用户确认后才写入用户调整版或草稿。
- 不新增左侧“攻略”菜单，不把配装攻略工作流塞入全局 AI 抽屉。

## 非目标

- 不把这套能力泛化为活动机制、任务收集、养成资源或武器评测攻略。
- 不自动装备、转移、分解物品，也不绕过现有写操作确认。
- 不把 AI 推测、名称模糊匹配或过期外部数据伪装成真实账号命中。
- 不做完整 D2ArmorPicker 级别的全局优化器。

## 实施切片

1. **实现：配装攻略领域与现有功能对照**：盘点并收口现有 `guideParsing`、`guideMatching`、`loadoutDraft` 与真实配装菜单的字段、操作和缺口，取消旧侧栏工作台作为产品入口的假设。
2. **实现：攻略导入、版本与用户调整版**：建立文字 / 链接 / 图片输入、AI 降级、版本快照、歧义确认和本地历史。
3. **实现：真实账号证据与配装可达性**：用实例、socket、角色位置、模组和属性真实数据完成逐项匹配、候选与缺口展示。
4. **实现：来源分级与草稿联动**：接入可靠替代、AI 参考、动态草稿和配装页内的来源追溯。
5. **整理：配装菜单 UI 方案**：在功能与状态矩阵明确后，单独完成专业 UI 设计和冻结原型，再迁入共享 UI。

## 当前实现与待重做项

仓库已有文字解析、名称匹配和草稿保存的基础链路，但它仍按“侧栏攻略工作台”组织，且存在昵称解析有限、角色范围未收口、同名实例与 socket 证据不足、护甲仅单件阈值匹配、可靠来源未进入匹配、以及 UI 未承载版本和草稿追溯等问题。

因此 T1 的首步不是继续扩展旧侧栏，而是以配装菜单为唯一产品入口完成对照后重做。
