# 配装攻略导入与账号匹配

> 状态：Backlog
> 更新时间：2026-07-24

## 定位

这是“配装”菜单的功能，不是通用攻略系统，也不是全局 AI 抽屉的子页面。

用户导入一篇配装攻略后，应用提取其中的装备条件，以当前账号的真实数据逐条核对，并生成可编辑的配装草稿。全局 AI 抽屉保持独立：它可以理解当前页面、解释结果并在用户确认后执行应用操作，但不承载配装攻略的历史、结果或草稿页面。

## 第一期范围

第一期保留完整的导入与记录流程，但只做**装备匹配**。不把技能、模组或属性优化混入首期交付。

### 输入

- 支持粘贴文字、DIM 等结构化配装链接、普通网页、视频和图片。
- 结构化配装链接优先直接读取字段；普通内容先提取为配装条件。
- 应用无法读取链接、视频文字或图片时，使用已配置的 AI 提取；AI 不可用或失败时明确提示，不伪造结果。
- 支持完整构筑和局部配装。未被攻略提及的槽位保持未指定，不自动补成完整配装。

### 装备匹配

- 默认先核对当前角色，同时列出仓库和其他角色中的可转移候选，并如实显示位置。
- 武器按本体精确匹配；攻略明确写出 Perk 时，必须以真实实例 socket / 可切换 Perk 核对。
- 武器拥有目标 Perk 但当前未选中时，作为候选显示，并明确需要切换 Perk。
- 攻略点名异域护甲时精确匹配；传说护甲只确认对应部位是否有可用装备。
- 不唯一的俗称、简称或同名歧义必须让用户确认，不能模糊命中。
- 攻略点名武器缺失，或该武器没有攻略要求的 Perk 时，列出账号内同一武器槽位、同一武器类型的真实候选；攻略明确 Perk 时，候选也必须命中该 Perk。
- 结果只展示攻略原始条件、真实实例 / socket 证据、候选、位置、缺少项和待确认项。不输出“可照抄”等主观结论。

### AI 的边界

- AI 可以从非结构化内容中识别装备、Perk、槽位和武器类型。
- 装备缺失时，AI 只协助从真实仓库数据筛选同槽位、同类型候选；不评分、不排序、不推荐账号外装备。
- AI 不能把猜测显示为账号事实，也不能把替代候选写成原攻略已匹配。

### 首期不做

- 不匹配职业、子职业、技能、星相、碎片、模组、护甲属性、护甲充能。
- 不检查锻造、大师杰作等完整 Roll 条件。
- 不根据社区来源、外部网页或 AI 推测给出装备强度结论。
- 不自动装备、转移或分解物品。

## 记录与草稿

- 攻略记录和快照仅保存在本机本地数据目录。
- 链接攻略在打开时重新读取；有新内容时保留新旧版本，用户可分别查看、匹配和创建草稿。
- 用户修改解析条件时创建用户调整版，原始版本保持不变。
- 账号装备变化、已知写操作成功或资料刷新成功后，后台重新匹配已保存攻略和关联草稿。
- 攻略生成的草稿是配装菜单中的普通可编辑草稿，保留“查看攻略”入口以追溯来源、版本和匹配证据。
- 草稿只保存攻略明确条件和相应候选；未指定槽位不自动补全。已选装备后来不可用时保留选择并标记原因，不自动替换。

## 界面边界

- 导入、历史、版本、逐条对照和草稿都属于“配装”菜单。
- 后续专业 UI 设计需要支持历史浏览、搜索 / 快速切换和独立详情阅读；具体布局、分栏和视觉样式单独设计后冻结。
- 不新增左侧“攻略”菜单，不把完整工作流塞入全局 AI 抽屉。

## 实施切片

1. **实现：配装攻略字段与既有代码对照**：盘点并收口现有 `guideParsing`、`guideMatching`、`loadoutDraft` 与配装菜单的字段和操作，删除旧侧栏工作台作为产品入口的假设。
2. **实现：全输入方式与本地版本记录**：建立结构化链接直读、普通内容 / AI 提取、失败降级、快照和用户调整版。
3. **实现：装备与 Perk 的真实账号匹配**：完成当前角色、仓库、其他角色的实例、socket、位置与候选匹配。
4. **实现：配装草稿与动态重匹配**：在配装菜单保存可追溯草稿，并在账号数据变化后更新真实候选和缺口。
5. **整理：配装菜单 UI 方案**：在功能与状态矩阵明确后，单独完成专业 UI 设计和冻结原型，再迁入共享 UI。

## 当前实现与待重做项

仓库已有文字解析、基础名称匹配和草稿保存链路，但它仍按旧侧栏工作台组织，且昵称解析有限、角色范围未收口、同名实例与 socket 证据不足，UI 也未承载版本和草稿追溯。

T1 的首步不是继续扩展旧侧栏，而是以配装菜单为唯一产品入口，按第一期范围完成对照和重做。
