# T68：本地文件导入的预览与起名也搬进弹框（四条导入路同形）

> 状态：✅ 已通过实窗验收（2026-09-19）
> 用户诉求（三张截图 + 原文「你这个起名的样式怎么还不一样」「文件为什么不能用弹框呢」）：
> 本地文件那一条路的「来源名」看着和另外两条不一样；用户选了改法 **B——先开框、框里再选文件**。

## 一、今天四条导入路各自的样子

「来源名」那一行（`ImportIdentityChoice`，标签「来源名」+ 新建来源 / 覆盖同名来源）是四条路共用的**同一个组件**。
差别不在组件里，在**这张卡摆在哪个面上**：

| 入口 | 起点 | 预览与起名在哪 |
|---|---|---|
| 人工推荐表格 | 弹框内「选择表格文件」 | 框内 |
| 从链接同步 | 弹框内粘链接 | 框内（T66 改的） |
| 来源行「同步」 | 弹框 | 框内 |
| **导入文本文件（本地文件）** | **页面上直接弹系统选文件对话框** | **页面内** ← 唯一一个 |

## 二、为什么这是缺陷，不是「位置不同」

1. **量出来的差别只有宽度，但宽度就是 3 倍**：同一个组件、同一套 CSS 规则，框内那张卡受弹框
   `min(720px, …)` 约束，页面内那张卡跟着工作区宽度走。实测（真实样式表 + 无头浏览器注入真实类名）：
   来源名输入框 **490px（框内）vs 1476px（页面内）**，提示语那一行 672 vs 1658；
   把三者塞进同样 720px 的容器后，输入框、按钮、间距、字号**逐项相同**。
   也就是说用户看到的「样式不一样」＝ 面板宽度不一样，规则一个没差。
2. **只有这条路没有「放弃」**：另外三条都有 关闭 / Escape / 点遮罩＝放弃这次导入；页面上那张卡
   只有「新建来源 / 覆盖同名来源」两个按钮，选错了文件**没有任何一步能把它放下**——
   今天的出口是「去点一下『从链接同步』，它开框时会顺手清掉」（`openLinkDialog` 的第一行）。
3. **一处内容两个落点**：预览卡与反馈行都要在页面与框内各渲染一次，于是多出一个
   `dimFilePreview && !linkDialogOpen` 例外。这个例外本身就是「同一件事有两个面」的证据。
4. **来历**：T63 定的本来是「链接弹框读取成功即关框、复用页内那张卡」，T66 把链接路改成框内确认后
   明确「这条没动」，页面卡就只剩本地文件这一个用户；`user-guide.md` 随后把这件事写成了
   「位置不同」——即把实现残留写成了设计。

## 三、改法（B：先开框、框里再选文件）

页面「导入文本文件」不再直接弹系统选文件对话框，而是**先开一个弹框**，框里第一步就是「选择文件」——
与「导入人工推荐表格」完全同一个模子：

1. 页面按钮 → 开框（标题「导入愿望单文本」）。开框即开始一次新导入：清掉上一份预览与名字、清掉反馈。
2. 框内一行步骤：「选择愿望单文本文件」+ 一个「选择文件」按钮（读取中显示「读取中」）。
3. 选完 → 预览卡落在**框内**（文件名、条数、问题行、展开冗余、来源名、新建 / 覆盖都在这一张卡里）。
4. 关闭按钮 / Escape / 点遮罩 = 放弃这次导入（未确认的内容不写库，框里那张未确认的卡一并收掉）。
5. 确认成功 → 收框，再刷新来源与文档清单。
6. 删除页面内那张卡与 `!linkDialogOpen` 例外；反馈行只留在框内（遮罩是 62% 黑又占满屏幕，
   页面底部那行字用户看不见——T66 已经为链接路记过这一条）。

**不变量**：任何时刻只有一份待确认预览，且它只可能出现在**当前开着的那一个框**里。
两条路各自开框时都清空上一份，所以不再需要记「这份预览是哪条路读来的」。

## 四、明确不做

- 不动另外三条路（表格弹框、链接弹框、来源行「同步」）的流程与文案。
- 不改入口的两个按钮本身（「从链接同步」/「导入文本文件」都还在这一行、还是主次两个）。
- 不加「关掉就丢掉，确定吗」的二次确认：框里还没写库，与另外三条路的关闭语义一致。
- 不改服务层 / IPC / 存储结构：这次只改「卡片摆在哪个面上」。
- 沿用 `useModalFocusTrap`（Escape + Tab 循环 + 打开时聚焦首个动作），不为这一个框另写一套。
- 不新增测试文件（AGENTS.md：普通 UI / 接线改动不新增测试）。

### 实测（真实样式表 + 无头浏览器，1680×900，`data-density="compact"`）

同一个 `ImportIdentityChoice` 在四条路上的实际排布（探针注入与产品代码同形的标记）：

| 测量项 | 表格（弹框） | 本地文件（弹框） | 链接（弹框） | 改动前那张页面卡 |
|---|---|---|---|---|
| 框宽 | 720 | **720** | 720 | 无弹框 |
| 卡片宽 | 694 | **694** | 694 | 1680 |
| 身份行宽 | 672 | **672** | 672 | 1658 |
| 来源名输入框 | 490×32 | **490×32** | 490×32 | **1476×32** |
| 按钮 | 70×30 / 94×30 | **同** | 同 | 同 |
| 输入框→按钮 / 按钮→卡片右边 / 提示→输入框底 | 12 / 11 / 6 | **同** | 同 | 同 |
| 字号（标签 / 输入 / 按钮 / 提示） | 12 / 12 / 12 / 12 | **同** | 同 | 同 |

三个弹框**逐项同值**；最右一列是 T68 之前本地文件那一路的位置（输入框 1476px，正好是弹框里的 3 倍），

## 七、验收判据

1. 仓库 → 推荐来源 → 「导入文本文件」点下去**先出现弹框**，框里有「选择文件」；选完文件的预览、
   问题行、来源名、新建 / 覆盖全在这个框里，页面导入区不再冒出一张卡。
2. 这个框的 关闭 / Escape / 点遮罩都能把它收掉且不写库；再点「导入文本文件」是干净的一次新导入。
3. 「来源名」这一行在「表格导入」「从链接同步」「本地文件」三个框里**同宽同形**（实测逐项同值）。
4. 四条路（含来源行「同步」）的确认卡都在弹框内，没有哪条路把卡片留在页面上。
5. 五道闸门全绿。

## 八、请用户复验

重新打包后进 仓库 → 推荐来源：

- 「导入文本文件」→ 应先出框，框里点「选择文件」选一份 `.txt`；预览与起名都该在框内，
  边距、输入框长度与「从链接同步」「导入人工推荐表格」两个框一致。
- 关掉这个框（关闭 / Esc / 点框外）后再点一次「导入文本文件」：应该是一张干净的空框，
  没有上一次选的文件残留。
