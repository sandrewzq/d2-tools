# Bug #98：来源行并排三个数字、四种口径，一个说明都没有，「292 / 305」看着像有一个是错的

> 状态：🟢 代码已改并自验通过（2026-09-17），待用户复验

## 现象

用户截图提问（原文）：

> 「292和305还是不一样啊，少的是什么？你这样会让用户产生疑问，会以为程序有bug。你先分析下原因」

同一屏上：左侧来源清单写 **292**，右侧这一行写 **1679 条规则 / 422 把武器 · 当前账号影响 305 件**。

## 核实：两个数都是对的，差的是「不在仓库里」的那 13 件

拿用户账号的快照算过（只读，未动应用数据）：

| | 数量 |
|---|---|
| 这份来源点名的武器（清单自己的规模） | 422 把 |
| 仓库 1093 件里被它点到的 | **292 件** ← 左边那个数 |
| 角色**身上 / 背包 / 邮政官**里被它点到的 | **13 件** |
| 全账号合计 | **305 件** ← 右边那个数 |

那 13 件逐一点名（都是武器，只是没放进仓库）：

- 术士身上：蝎狮、红鲱鱼
- 术士背包：英勇利刃、故我在、战狮、寄生虫、完美悖论、主原料、格网队长、虚假偶像、咒骂、阿莱索尼得
- 泰坦身上：拜龙教镰刀

所以两个数字口径不同、各自成立：左边是「勾上它，**本页仓库**会筛出多少件」，右边是「这份来源在**整个账号**里点到多少件」。292 + 13 = 305。

## 但缺陷成立：这一行能读出四种口径，页面上一个字都没解释

| 数字 | 它回答的问题 | 会被读错成 |
|---|---|---|
| 1679 条规则 | 这份清单写了多少条 | — |
| 422 把武器 | 这份清单**点名**了多少把武器（与你有几件无关） | 「我有 422 把」 |
| 305 件 | 其中你的账号里有多少件（含角色身上、背包、邮政官） | 「仓库里有 305 件」 |
| 292（左侧清单） | 其中有**几件在仓库里** | 「和 305 对不上，程序有 bug」 |

真正的问题不是数字算错了，而是**并排摆着的数字谁也不说明自己是什么**，其中两个还是「同一件事的两个范围」——看起来就该相等，实际不该。

## 处置（用户 2026-09-17 拍板：甲 + 乙）

- **甲**：行上把两个范围都写出来、用同一套词——「**仓库 292 件 / 全账号 305 件**」。左边清单那个 292 立刻在行上找到同一句话，305 明确是更大的那个范围。
- **乙**：把「422 把武器」改成一眼看出「清单点名」的说法——「**列出 422 把武器**」。
  不用用户建议的「覆盖」：界面上「覆盖 N 件」已经是左侧清单的悬停文案（意思是「本页能筛出多少件」），同一个词给两个意思会加重混乱。

落到三条：

1. 来源行与详情弹框标题统一成同一套说法。来源行**分三句、一句一行**：
   - `1679 条规则`（这份来源写了多少条）
   - `列出 422 把武器`（它点名了哪些武器，与你有几件无关）
   - `仓库 292 件 / 全账号 305 件`（对你的影响，两个范围并排）
   悬停说明「列出」「仓库 / 全账号」各指什么，用户不必猜。
   详情弹框标题不设宽度、是一行通排的文字，仍用前两句拼成的长句（`1679 条规则 · 列出 422 把武器`）。
2. **「仓库」这个数由服务端算，不在界面层去凑**：账号快照本来就在主进程读过一次（现在把仓库 + 角色身上 / 背包 / 邮政官一起数成一张表），改成同时给出**两张表**，来源行同时拿到两个数——两者天然对得上（全账号 = 仓库 + 角色侧）。
   不从界面右侧那个数去凑左边：左侧清单的数**跟着当前筛选走**（在搜索框里打字它会变），搬到管理行上会变成一个会跳的数字。
3. **两处来源行 + 详情弹框标题共用同一份文案函数**：同一句话不许在两处各写一遍（Bug #91 两份清单的教训）。

### 为什么是「三句」而不是「两句」（排班量出来的，不是估的）

上面 甲 的第一版是**两句**：`1679 条规则 · 列出 422 把武器` / `仓库 292 件 / 全账号 305 件`。
写完之后拿真实样式表（`packages/desktop/dist/renderer/assets/index-BndxTHyY.css`）+ 无头 Chromium
把这一行摆出来量，结果：

| | 数字栏宽 | 那一句占多宽 | 余量 | 折行 |
|---|---|---|---|---|
| 两句版 `1679 条规则 · 列出 422 把武器` | 210px（定宽） | **198px** | 12px | 1 行 |
| 两句版 `12985 条规则 · 列出 4220 把武器` | 210px | 202px | — | **2 行**（「武器」被挤下去） |

数字栏是**定死 210px** 的（T67 立的规矩：写成「下限 210、内容再长就撑开」时两行会重新错开，
`architecture-maintenance.test.ts` 里按着这一条）。12px 余量意味着**规则数一上万就折行**——
一张上万条规则的愿望单并不稀奇，折下来正是 T67 当初要修的毛病。

三句版实测（同一套样式表，页宽 1400 / 1200 / 1050 / 990 / 900 / 820 / 760 / 700 / 660 / 640 / 560 一路量下来，
含 5 位数压力行）：

| 句 | 占用 | 余量 | 折行 |
|---|---|---|---|
| `1679 条规则` | 82px | 128px | 1 行 |
| `列出 422 把武器` | 89px | 121px | 1 行 |
| `仓库 292 件 / 全账号 305 件` | 153px | 57px | 1 行 |
| `12985 条规则` (5 位) | 91px | 119px | 1 行 |
| `列出 4220 把武器` (5 位) | 97px | 113px | 1 行 |
| `仓库 1292 件 / 全账号 1305 件` | 168px | **42px** | 1 行 |

三句都在一行内、最紧的一句还剩 42px；窄屏（≤700px）收回单栏、改成左对齐后同样不折行。
行高由 73px 变 94px（一行变两行小字），这是拆句的代价，换来的是任何位数都不折。


## 不做（如实记录）

- **不改左侧清单那个数的口径**：它跟着当前筛选走，是筛选条的既有约定（同一栏里类型 / 位置 / 槽位的数量也都这样）。
  由此带来一个明摆着的口径差：行上的「仓库」是**这份来源在仓库里一共有多少**（不受筛选影响），
  清单上的数是**当前筛出来多少**。默认没有筛选时两处相等；筛选生效时清单的数会变小、行不动。
  行在管理面板里，那里没有筛选条，跟着筛选走反而是错的。
- **不改「读不到账号快照时显示 0」这个既有兜底**：两个范围一起为 0，不会互相矛盾；要改成「读不到就不显示」是另一件事。
- **不改规则行的「当前账号影响 N 件」**：单条规则已经写明口径，且它没有「仓库」这一层的用法；本次只动来源行那一处。
- **不改确认文案里的「当前账号约 N 件实例受影响」**：那是停下这份来源前的后果说明，全账号口径才对。

**如实记录三处：**

- 结构守卫第一版用了宽松写法（只断言「文件里出现过 `title={…}`」），被详情弹框标题那一处
  蒙混过去——把行上的说明删掉它照样绿（改坏没杀掉）。已改成**按行锚定**：说明与那几行数字
  必须出现在同一段标记里，弹框标题另有一条自己的断言。这是 T64 早就记过的坑，还是踩了一次。
- **用户看到的两个数其实不在同一屏**：左边那个数在「浏览装备」页的筛选栏，右边那一行在
  「推荐来源」页，两个页签不会同时显示。所以这次的改法不是「把两个数凑成一样」，而是
  把行上那句写清楚到「拿另一个页签上的数来对也对得上」。
- **拆三句是量出来的、不是想出来的**：甲 的第一版按两句做完、自验也过了，是我自己回头拿
  真实样式表量了一下才发现 198px / 210px、只剩 12px。要是只凭截图看，在用户那份
  「1679 条规则」的真实数据上**看起来完全正常**——12px 的余量肉眼看不出来，
  只有上到五位数才现形。这一条也说明「截图看着没问题」不等于没问题，
  这个页面的排版照 T67 的规矩必须以真实样式表量出的数字为准。

## 请用户复验

进 仓库 → 推荐来源：

1. 来源行现在分三句：`1679 条规则` / `列出 422 把武器` / `仓库 292 件 / 全账号 305 件`。
   前两句是**这份来源自己的规模**，第三句是**对你的影响**；第三句里左边那个数应当与你
   在「浏览装备」页筛选栏上看到的仓库数字一致（那个数跟着筛选走，没筛选时相等）。
2. 停在这三行数字上，应当弹出一句说明，分别解释「列出」「仓库」「全账号」各指什么。
3. 点「查看详情」，弹框标题那一行应当是同一套说法（`… · 1679 条规则 · 列出 422 把武器`）。
4. 如果换了装备、把武器从角色身上放进仓库，这两个数应当各自跟着变——仓库数会加，全账号数不变。
