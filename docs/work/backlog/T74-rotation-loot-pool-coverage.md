截图里四张卡（本周轮换突袭：国王的陨落 / 最后一愿；本周轮换地牢：二象性 / 晚星之主）

读本地缓存 `~/Library/Application Support/d2-tools/home-briefing-cache.json`（`saved_at` 2026-09-17T17:00Z）：

| 条目 | `loot_pool` | `rewards` 原值 |
|---|---|---|
| 国王的陨落 | `undefined` | `[{name:"突袭装备", item_type:"装备阶级5"}]` |
| 最后一愿 | `undefined` | `[{name:"突袭装备", item_type:"装备阶级5"}]` |
| 二象性 | `undefined` | `[{name:"强力装备", item_type:"装备阶级5"}]` |
| 晚星之主 | `undefined` | `[{name:"强力装备", item_type:"装备阶级5"}]` |

**结论：不是接口失败，也不是渲染 bug。** 接口返回了数据（只有占位奖励），是两层叠加把内容清空了：

1. 数据集未覆盖这四个活动 → `loot_pool` 保持 `undefined`；
2. UI 回退到 `rewards` 后按「只留武器」过滤，而 `装备阶级5` 不是武器、`group_key` 也为空 → 滤成空数组 → 空态。

顺带：空态文案「公开接口尚未返回可读奖励」在这里是**不准确**的，接口返回了，只是返回的不是武器；
T45 对同类情况的口径是「轮换已确认，掉落关系尚未核对」（`T45-weekly-farming-checklist.md:388`）。

## 二、链路与代码位置

```
Bungie CharacterActivities（角色周挑战）
  └─ core/weekly/liveData.ts:856 / :872      生成 rotating_raid / rotating_dungeon 条目
       related_hashes = [activityHash, ...challengeObjectives]     ← [0] 恒为活动 hash

  └─ core/weekly/summary.ts:234              原样带进 priorities[kind].entries
  └─ desktop/main/runtime/homeBriefing.ts:190  attachRotatingLootPools：查数据集，命中才写 loot_pool

  └─ 两边都空 → is-pending 空态
```

「N 项已确认」与掉落池是**两个独立事实源**（前者来自角色周挑战，后者来自数据集），
所以会出现「2 项已确认」但掉落池全空的组合——这个组合本身没错，是数据没接上。

数据集：`services/src/community/activityLoot.ts:46`（`activityLootDatasetV1`），
消费方两处：`desktop/main/runtime/homeBriefing.ts`（首页卡）与
`desktop/main/ipc/library.ts:161,168`（T45 本周刷取）。

## 三、为什么以前有、现在没有

- 数据集 `revision: "2026-09-10.1"`、`verified_at = "2026-09-10"`，只录了 4 个活动：
  门徒誓约 `1441982566`、救赎的边缘 `1541433876`、贪婪之握 `4078656646`、战争领主的废墟 `2004855007`；
- 在 `bdf6f00` → `f9f90bc` → `0cc46bc` 三个提交里数据集**一字未改**，从未跟过轮换；
- 9-16 那周重置是功能上线（9-10/9-11）后**第一次轮换变更**，四个活动全换走；
- 叠加 `0cc46bc` 把该栏从「本周奖励」（不过滤）改成「掉落池」（只留武器），
  连原本会显示的「突袭装备」占位文案也一起被滤掉。

**根因：给一个每周变动的量配了一份静态快照，而且快照只覆盖了当时当周的轮换。**

## 四、可行方法（已在本机 Manifest 上实测跑通）

Manifest 里**没有** activity → 掉落的直接字段：

- 活动定义的 `rewards` 只有占位（实测国王的陨落 `1374392663` 的 `rewardItems` 是 `3808930390` 等 4 个通用项）；
- `challenges[].displayRewards` 也只有「突袭装备 / 强力装备」。

唯一真源是 **Collectible 的 `sourceString` / `sourceHash`**：

```
活动「国王的陨落」
  → Collectible.sourceString「来源：“国王的陨落”突袭」→ sourceHash 160129377
  → 该 source 下全部 Collectible → 过滤武器桶（1498876634 / 2465295065 / 953998645）→ 7 把枪
```

实测结果：

| 活动 | sourceHash | 实测可显示 |
|---|---|---|
| 国王的陨落 | 160129377 | 扎乌利的克星 / 梅拉恩的惩戒 / 恶意触碰 / 弥达的清算 / 切尔奇斯的末日 / 亚斯明的抗争 / 库里姆的终界（+ 6 个「痛苦」变体） |
| 最后一愿 | 2455011338 | 千语 / 霸权 / 变形术 / 唠叨龙骨 / 旧日羁绊 / 灵巫力量 / 野兽国度 / 巅峰捕食者 |
| 二象性 | 1282207663 | 不可饶恕 / 不散恐惧 / 享乐主义 / 宿命 / 心影 / 新目标 / 风暴猎人 |
| 晚星之主 | 2463956052 | VS寒冷抑制 / VS重力滞止 / VS速度指挥 / VS热电推进 + 破冰者 |

**自校验**：同一方法复现了现有数据集 4 条的 sourceHash——门徒誓约 `1007078046`、
救赎的边缘 `2700267533`、贪婪之握 `675740011`、战争领主的废墟 `613435025`，四个全中。
说明这套推导与当初人工核对用的是同一条链。

**覆盖范围**：同一方法扫全库，可覆盖约 **30 个突袭 / 地牢**
（玻璃拱顶 25 项、预言 17、克洛塔的末日 15、梦魇根源 13、门徒誓约 13、救赎的边缘 13、
深岩墓室 7、守望者尖塔 7、永恒沙漠 7、二象性 7、深渊机灵 6、战争领主的废墟 5、

## 五、必须处理的坑（实测踩到）

| # | 坑 | 实例 |
|---|---|---|
| 1 | 名称匹配歧义 | `利维坦` 同时命中 5 个 source（本体 / 星之塔 / 遗落利维坦 / 奇珍异兽园）；`预言` 同时命中「预言地牢」与「万斯修士的失落预言」任务源 |
| 2 | 一个活动多个 source | 永恒沙漠 `596084342`（突袭）+ `2127551856`（史诗突袭） |
| 3 | 变体重复 | `（专家）`（门徒 / 救赎 / 国王）、`（痛苦）`（国王）、`（失时）`（玻璃拱顶）、`（巴洛克）`（利维坦）；不归并时玻璃拱顶从 13 虚涨到 25 项 |
| 4 | 粒度止于活动级 | Manifest 做不到「哪个遭遇战掉哪把」，UI 措辞不能写成遭遇战掉落 |
| 5 | 语言 | `sourceString` 随界面语言变化（英文为 `Source: "King's Fall" Raid`）；匹配规则要么双语，要么保证只用当前加载的那份 Manifest |
| 6 | **SQL 直查会静默漏数据** | 官方 sqlite 的 `id` / `itemHash` 对 ≥ 2^31 的 hash 存为**有符号负数**，而 JSON 里是正数：直接 `join on i.id = c.itemHash` 会漏掉一半装备（实测第一轮统计把国王的陨落从 13 项算成 6 项、晚星之主从 5 项算成 1 项）。两边都要归一到无符号再比。应用侧已有 `toUnsignedHash` / `toSignedHash`（`definitionReader.ts:28,33`）不成问题，但写生成脚本直查时容易踩 |

## 七、B 不是「彻底解决」——四层拆解

| 层 | 谁能解决 |
|---|---|
| 数据新鲜度（轮换变更、Manifest 更新、新赛季新活动） | **B 彻底解决**；A 解决 90% |
| 数据完整性与精度 | **两者都不解决**：遭遇战级分布需 DIM 类人工数据；图样 record 映射（`pattern_record_hash`）推不出来；日落 / 不可获得内容 Manifest 不标；名称歧义只能收窄不能消除 → **自动推导之外仍需一层人工覆盖表** |
| 语言 | B **新增**的脆弱面（A 没有） |
| 对玩家的价值 | **两者都不解决**，见第九节 |

其中 `pattern_record_hash` 是硬骨头：`buildWeeklyFarmingCatalogResource` 的
`buildPatternProgress` 依赖它算红框 / 图样进度，Manifest 里推不出「武器 → 图样 record」的映射。
B 要保留这条能力就得多做一个独立索引；不做就得给 T45 降级（未覆盖活动不显示图样进度）。

## 八、建议

1. **先做 A**：让本周四张卡立刻有内容，同时把「每周失效」根掉（A 覆盖全部活动后，
   轮换换到哪个都能命中）。A 跑一阵后，名称匹配的边界规则也就摸清了。
2. **B 作为后续**：等 A 验证过匹配规则，再把同一套规则搬进索引构建器，B 就只剩搬运工作。
3. **无论 A/B**：都要有「自动推导 + 人工覆盖表 + 覆盖率告警」的结构，
   不要假设 100% 自动；覆盖表专门收 `利维坦` / `预言` 这类歧义项与人工确认的例外。
4. **变体归并**要顺手做（否则条数虚高），归并后与社区掉落表对拍。

## 九、待另开号的独立事项（本次只记录，不含在 A/B 内）

2. **`pattern_record_hash` 的自动推导**（B 的前置条件）。
3. **两处顺带发现的隐患**（是否开号待定）：
   - 空态文案不准确（第二节末）；
