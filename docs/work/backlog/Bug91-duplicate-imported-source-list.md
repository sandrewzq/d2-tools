# Bug #91：推荐来源页有两份「已导入来源」清单，删除动作也有两条实现

> 状态：🟢 代码已改并自验通过，待用户复验（2026-09-16）
> 现象（用户截图提问「红框部分不是重复了吗」，v0.0.26）：仓库 → 推荐来源**同一页**上，
> 导入区下面有一份「已导入来源（1）· sayalarry · 70 条规则」，页面下方又有一份「已导入来源」
> 加「当前来源 1 个」，同一份 sayalarry 出现两次，各带一个删除按钮。

## 核实：两份清单是同一个集合，两个删除是同一件事的两份实现

下栏那份的来源不是「来源实例」，而是**按导入文档聚合**出来的（服务层 `GROUP BY 文档`，一行一次导入，名字取文档标题）。所以两处列的集合与粒度完全相同，下栏还给得更多：武器数、当前账号影响件数、启用 / 停用状态。上栏那份是导入区自己的遗留——它多出来的只有「来路」（文件导入 / 在线导入 / 粘贴导入）。

两个删除按钮更值得处理，因为它们是**同一件事的两份实现，而不是同一个函数的两个入口**：

| 入口 | 实际做了什么 |
|---|---|
| 上栏「移除」 | 按名字算出文档键，删文档行；**不碰覆盖状态** |
| 下栏「删除」 | 删文档行之外，按「文档键 + 它下面全部实例键」清掉规则排除与来源覆盖，并给出说明文案 |

证据：用户库里那条 `sayalarry = 已移除`、时间停在 2026-09-13 的残留覆盖行，就是上栏那条通道删过东西留下的（旧版本的键写法）。另外上栏那条通道顺带做的「DIM 文档派生的装备目标清理」，下栏这条也有（由存储层给出的 `stored_source_changed` 驱动），而且下栏还多做了匹配缓存失效——也就是说下栏是超集，上栏是旧且不完整的那个。

## 处置（用户 2026-09-16 拍板：只留下面的来源管理区）

1. **导入区不再列已导入来源**，只留导入 / 导出操作；来源清单、规则数、武器数、启用状态与删除只在下面的来源管理区一处。
2. 上栏独有的「来路」标签不再显示（用户知道自己是怎么导入的；导入成功提示与来源名已经说明了对象）。上栏那句「来源名就是覆盖依据，同名只能覆盖」在导入弹框的来源名提示里本来就有同义说明，不搬家。
3. **把旧删除通道整条删掉**：按钮 → 渲染层动作 → preload 成员 → IPC 通道 → 服务函数（连只有它用的读取函数一起），避免以后再有人误用这条不完整的实现。
4. 「移除全部来源」的确认文案里「只想移除其中一份，请用上方来源行的「移除」」要改指新的位置，不能指向已删除的按钮。

## 验收判据

1. 推荐来源页只剩一份「已导入来源」清单（来源管理区），地址栏内不再有第二份。
2. 导入（新建 / 覆盖）成功后，这份清单、规则数、武器数、启用状态当场更新——Bug #90 的行为保持不变。
3. 「移除全部来源」的确认文案不再指向已删除的按钮。
4. 删除导入只剩一个入口，行为不变：数据、规则、覆盖状态一起清除，愿望单派生的装备目标清理与匹配缓存失效照旧。
5. 旧通道整条消失：全仓搜不到它的按钮、渲染层动作、preload 成员、IPC 通道、服务函数，以及只被它使用的读取函数。
6. 全仓没有留下只为旧清单服务的死代码（来路格式化函数等）。
7. `pnpm typecheck` / `pnpm test:behavior` / `pnpm test:architecture` / `pnpm docs:check` / `pnpm test:quality` 全绿，且判据 1–4 各有变异能变红。

## 验证结果（2026-09-16）

**判据 1–4 的变异对拍**（`packages/ui/test/vault-recommendation-sources-refresh.test.tsx`，7 条用例；每条变异只让它该管的用例变红，改完全部还原并 `grep -rn "MUTATION"` 确认无残留）：

| 变异 | 内容 | 变红的用例 |
|---|---|---|
| M1 | 在导入区重新塞回一份「已导入来源」清单块（列同一批来源名） | 「页面里只有一份已导入来源清单，导入区只做导入与导出」 |
| M2 | 把「移除全部来源」的确认文案退回旧版（不指向保留下来的删除入口） | 「移除全部来源」的确认说明指向保留下来的那个删除入口 |
| M3 | 来源管理的「删除」改成只停用（`removed` → `disabled`） | 删除导入只剩来源管理一处，删除后清单当场少一行 |

判据 5（旧通道整条消失）不靠变异，靠全仓检索：`recommendation:documents:remove`、`removeRecommendationDocument`、`listDimWishlistDocuments` 三个名字在 `packages` 下（排除 `node_modules` 与 `dist`）零命中；`typecheck` 也保证渲染层动作与 `VaultWishlistActions` 成员不会留下悬空引用。判据 6（无遗留死代码）同理：来路格式化函数零命中。

**判据 7 的五个门 + `pnpm check`**：`pnpm typecheck` 7 个包全过；`pnpm test:behavior` 139 个文件 566 条用例全过；`pnpm test:architecture` 15 个文件 66 条用例全过；`pnpm docs:check` 与 `pnpm test:quality`（导出检查 / UI 合同 / 许可证）全过；`pnpm check`（文档策略 + 编码 + `git diff --check`）全过。

**待用户复验**：判据 1–4 是界面行为，需要用户在重新构建的桌面端里过一遍——同一页只剩一份「已导入来源」清单、导入 / 覆盖后清单当场更新、清空确认文案指向来源管理区、删除仍只有一个入口。
