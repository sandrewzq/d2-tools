# T20：武器推荐与仓库整理

> 更新时间：2026-09-04
> 状态：🟡 阶段 0–12 产品基线已完成；当前只推进阶段 13 的严格数据、核心 Roll、缓存与刷新收口
> 优先级：P1

## 1. 产品目标

仓库页不是替玩家决定分解什么，而是帮助玩家完成四件事：

1. 快速判断一把武器是否符合某个推荐来源。
2. 在同名武器之间优先比较最有价值的核心 Perk。
3. 保护锁定、配装引用、玩家手动保留和无法安全判断的实例。
4. 由玩家确认整理、锁定或转移，最终分解仍回到游戏内完成。

玩家工作流固定为：

```text
打开仓库，立即看到本地账号快照
  → 按位置、类型、来源结论或整理状态筛选
  → 在卡片上先看核心 Roll 结论
  → 有同名副本时进入同名整理
  → 需要证据时打开详情查看六项完整对照
  → 玩家显式锁定、标记或转移
  → 游戏内完成最终分解
```

系统不得自动生成“应该分解”的结论，不得自动锁定、自动解锁、自动保留或自动写入待处理。

### 2.2 四人工来源 CSV

- `攻略/T20-武器推荐知识库/武器推荐.csv` 目前是历史基线，不是可直接激活的运行时真相。
- CSV 固定 31 列，一行表示一个“官方武器身份 + 人工推荐来源”。
- `推荐来源` 只允许 Aegis、LGpig、YXCRALLXY、Sayalarry，DIM 不写入该 CSV。
- 武器身份优先使用官方英文名，其次使用已验证武器 ID，最后才使用无歧义的官方中文名。
- 同名历史、复刻、普通和高阶版本共享名称级推荐；不同官方英文身份即使中文同名也保持独立。
- 空白、`任意 / 无 / None / N/A / -` 表示来源未要求该栏位，不进入分母。
- 导入必须先预览，确认时再次核对文件指纹和 Manifest；存在任一阻塞项时不得生成确认令牌。
- 校验或写入失败不得部分导入，也不得覆盖当前数据库。

### 2.3 严格语义规则

人工来源的武器、第一列、第二列、大师、Perk 1、Perk 2 和起源特性只允许：

1. 官方 Hash 精确命中；或
2. 规范化后的 Bungie 官方全名完全相同。

明确禁止：

- 双向 `contains`、前后缀和“候选唯一”包含匹配。
- 简称、旧译、同义词或人工推断关系。
- 大师属性词干或属性族合并，例如“填装/装填”“操控/操控性”。
- 自动把“伤害”改为“冲击”。
- 无法证明时静默忽略并继续激活。

“候选只有一个”只表示搜索结果唯一，不能证明输入与候选语义相同。例如官方池只有“操控性”时，输入“操控”仍必须阻止。

### 2.5 DIM 原生语义

- 一条 DIM 规则是一个完整 Hash 组合，组合内全部必需，多条组合任选其一。
- 不把 DIM 转成普通六栏计数，不跨组合累计 Perk。
- 同栏多个必需 Perk 按原始完整组合匹配。
- 只有一个 Perk 栏时按单项规则匹配。
- 特殊异域插槽保留原始结构。
- 旧 Hash 只有在官方身份能够精确确认时才映射。
- Hash 无法确认时显示“该 DIM 规则无法核对”，不能判定为未符合。

历史 39 条 DIM 结构提示包括：

- 13 条同栏多必需项或跨栏关系。
- 12 条只有单个 Perk 栏。
- 3 条特殊异域插槽。
- 11 条附加 Hash 无法映射。

应用默认从 GitHub 检查并更新固定 commit 对应的 `voltron.txt`；网络或解析失败时继续使用上一次成功数据，并允许导入 `.txt / .wishlist` 文件。

### 2.6 SQLite 激活与旧库兼容

当前 schema version 4 是历史基线，阶段 13 必须增加：

- `semantic_validation_version`
- `validated_manifest_version`
- 四人工来源 CSV 指纹
- DIM revision 与原文件指纹
- 数据集激活状态

旧库处理规则：

- 缺少当前语义标记的人工来源库固定为 `unverified`。
- 旧文件保留供回退和人工查看，但不得参与核心状态、保护、排序或留拆判断。
- 旧 SQLite 中现有 40 条“伤害”不得自动改成“冲击”。
- 新 CSV 全量通过后才在单事务中整体替换人工来源关系表。
- DIM 数据链独立激活，不因人工 CSV 暂不可用而停止工作。
- 旧 JSON 只允许执行一次性事务迁移；迁移后保留磁盘文件但运行时忽略。

## 3. 实例匹配

### 3.1 匹配输入

每个账号武器实例至少需要：

- `instanceId` 与 `itemHash`
- 官方武器身份
- 当前启用 Plug
- 该实例实际拥有的可切换 Plug
- 真实 socket 角色
- Roll 完整性与稳定指纹
- 位置、锁定、装备和精确配装引用
- 玩家本地整理标签

Manifest 可掉落池、角色级解锁项和账号级候选不得冒充该实例实际拥有的 Roll。推荐按武器身份共享，但结论必须按 `instanceId` 独立计算。

### 3.2 六项指标与优先级

四人工来源最多核对六项：

1. 第一列：枪管、瞄具、弓弦等。
2. 第二列：弹匣、电池、箭矢等。
3. 大师属性。
4. Perk 1。
5. Perk 2。
6. 起源特性。

价值优先级固定为：

```text
Perk 1 / Perk 2
  > 第一列 / 第二列
  > 大师 / 起源特性
```

核心 Roll 只看来源明确要求的 Perk 1 和 Perk 2。`x/y` 表示六项中全部明确要求的事实符合度，不是评分。

### 3.3 玩家决策状态

| 状态 | 判定 | 玩家文案 |
|---|---|---|
| `full` | 全部明确要求均符合 | 全部符合 |
| `core` | 核心 Perk 全部符合，但其他栏位有缺失 | 核心符合 |
| `close` | 没有完整双核心要求，或仅能形成接近结论 | 接近推荐 |
| `key_missing` | 来源明确要求的 Perk 1 或 Perk 2 至少一栏不符 | 关键缺失 |
| `weapon_only` | 来源只推荐武器身份 | 仅推荐这把武器 |
| `uncheckable` | 实例 Roll 不完整或规则无法安全核对 | 数据不完整 / 无法核对 |

同为 `5/6` 时：

- 缺第一列或大师，但核心双 Perk 齐全：`核心符合`。
- 缺 Perk 1 或 Perk 2：`关键缺失`。

仓库卡片显示核心结论，`符合 x/y · 缺少某栏` 作为次级证据。完整六项证据只在详情和同名整理展开。

### 3.4 同名整理与保护

- 同名历史、复刻和高阶版本进入同一组，`itemHash` 作为版本证据展示。
- 同名组先按 `full / core / close / key_missing / weapon_only / uncheckable` 分层，再比较 `x/y`、用途、锁定和配装保护。
- PVE 清怪、PVE 输出、PVE 功能和 PVP 可以分别保留，不强制同名只留一把。
- 独特 Roll 只表示组合少见，不代表强度。
- 不得仅凭“同名”“5/6”或黑盒分数判断哪把更好。

强制保护至少包括：

```text
游戏内已锁定
精确配装引用
玩家手动保留
独特 Roll
来源冲突
Roll 或官方身份不完整
推荐库未覆盖或未验证
```

## 4. 缓存、刷新与详情

### 4.1 本地数据分层

| 数据 | 本地策略 | 失效条件 |
|---|---|---|
| 装备定义、图标、官方名称、Manifest 插槽池 | 按 Manifest 版本持久缓存 | Manifest 版本变化 |
| 四人工来源推荐 | SQLite 按数据集 revision 保存 | 新 CSV 严格激活 |
| DIM Wishlist | SQLite 按 commit/revision 保存 | DIM 新版本激活 |
| 账号实例当前 Roll | 随权威账号快照保存 | Profile 版本或实例 Roll 变化 |
| 实例匹配摘要 | 按 Roll 指纹与数据 revision 缓存 | Roll、Manifest、推荐或算法版本变化 |
| 完整可掉落池 | 玩家展开后按 Manifest 版本缓存 | Manifest 版本变化 |

匹配缓存至少记录：

```text
account_key
instance_id
item_hash
roll_fingerprint
roll_complete
manifest_version
knowledge_revision
dim_revision
matched_count / requirement_count
core_matched_count / core_requirement_count
priority_state
matching_algorithm_version
```

位置、光等、锁定、装备状态和玩家标签不进入 Roll 指纹。武器只是在仓库、背包或已装备之间移动时，应更新位置事实，但不重复计算相同 Roll。

### 4.2 账号刷新

账号、仓库和配装页消费同一个中央账号 Store：

1. 启动或进入页面先展示最后一次成功快照。
2. 用户点击同步时执行权威读取，穿透 Repository 和 Renderer 的短时缓存。
3. 使用 Bungie Profile 版本水位线拒绝晚到的旧响应。
4. 游戏内手动移动装备后，玩家同步一次即可统一更新全部页面。
5. 应用内转移、装备、锁定和配装操作必须等待真实 Profile 确认后提交新快照。

禁止固定轮询、切页刷新、隐藏页面刷新或后台线程静默替换可见列表。推荐数据更新只使匹配 revision 失效，不应额外触发 Bungie Profile 请求。

账号写后一致性的详细实现与真实账号验收记录继续由 [Bug #22](Bug-22-account-refresh-write-consistency.md) 维护，T20 只消费该统一合同。

### 4.3 详情渐进加载

打开同一把武器时不得重复加载已经存在的数据：

- 首屏立即使用账号快照展示当前启用与实例实际拥有 Roll。
- 本地图标、定义、推荐摘要和已算匹配同步读取，不出现详情全局 Loading。
- 完整可掉落池默认折叠，玩家主动展开后才读取并缓存。
- 同名版本、攻略长说明和在线状态分区加载，失败只影响对应区块。
- 切换详情对象时，旧对象返回不得覆盖新对象。
- 详情负责完整证据和高级操作；常见锁定与整理应在列表和同名整理直接完成。

## 5. 仓库页面工作流

现有三个视图保持，不增加第四个仓库页面：

### 5.1 筛选列表

- 默认范围为“仓库整理”；角色背包、已装备、邮政官和全账号武器由玩家主动选择。
- 武器卡固定显示身份、装备事实、最多两条来源结论和真实位置。
- 人工来源示例：`核心符合 · Aegis 符合 5/6 · 缺枪管`。
- 核心缺失示例：`关键缺失 · Aegis 符合 5/6 · 缺 Perk 2`。
- DIM 示例：`符合 1 套推荐` 或 `接近推荐 · 缺 1 项`。
- 支持多选、批量锁定和批量本地整理；操作前显示数量、保护项和失败项。

### 5.2 同名整理

- 按核心状态汇总同名实例。
- 一次选择一个来源展开六项矩阵，不跨来源拼接。
- 支持按核心状态筛选、多选和批量锁定。
- 比较结果只提供证据，不自动决定保留哪一把。

### 5.3 推荐与目标

- “武器推荐”和“个人目标”继续保持独立页签。
- 支持按来源状态、数据完整性、人工标记和位置筛选。
- 可以从实例直接打开详情或对应同名组。
- 人工来源不可用时显示可执行的数据状态；DIM 仍可独立使用。

### 5.4 单件详情

- 复用统一详情页，不新增平行页面。
- 推荐区按“攻略推荐 / DIM / 我的推荐”组织，只显示有内容的来源。
- 先显示核心结论，再展示来源用途、评级、说明和六项证据。
- DIM 保持完整组合卡，不伪装成人工来源 `x/y`。
- 异域固定配置显示“仅推荐这把武器”，不伪造随机 Roll。

## 7. 验收标准

### 数据

- 四人工来源 CSV 与 DIM 原生 Wishlist 完全拆分。
- 四人工来源在当前 Manifest 下严格校验为 0 阻塞。
- “操控 → 操控性”“伤害 → 冲击”等宽松关系被准确阻止。
- DIM 作者、说明、标签、原始 Hash 和完整组合不会丢失。
- 旧人工来源 SQLite 未验证时不参与任何留拆结论。
- 导入失败不会留下半套数据库或覆盖上一套有效数据。

### 匹配

- 每个 `instanceId` 使用自身实际拥有 Roll 得到独立结果。
- 核心状态只看来源明确要求的 Perk 1/2。
- 同为 `5/6` 时，缺低优先级项与缺核心 Perk 显示不同主结论。
- DIM 无法确认的规则显示“无法核对”，不误判为未符合。
- 同名组按核心状态汇总，但不产生自动保留或分解决策。

### 缓存与刷新

- 同一武器重复打开详情不会重复读取已有 Roll、定义、图标或推荐摘要。
- 完整可掉落池只在玩家展开时加载，并按 Manifest 版本复用缓存。
- 游戏内移动装备后，手动同步能使仓库、账号和配装页一起更新。
- 晚到的旧 Profile 响应不会恢复已经失效的装备位置。
- 页面不存在固定轮询、切页刷新或后台线程静默替换列表。

### 安全与 UI

- 卡片、推荐结果、账号紧凑卡、同名整理和详情使用一致的核心状态。
- 列表和同名整理支持显式单件/批量锁定，并显示保护项和失败项。
- 推荐结论不会自动修改玩家标签或游戏锁定状态。
- 锁定、配装引用、手动保留、独特 Roll、来源冲突和数据不完整均受保护。
- 最终分解只能由玩家在游戏内完成。
- 护甲页面、护甲筛选和 Armor Planner 不受 T20 改造影响。

## 8. 不在本任务范围

- 自动或远程分解 Destiny 2 装备。
- 自动创建配装或覆盖玩家手动标签。
- 把未获授权的第三方资料打包进公开安装包。
- 批量抓取或镜像 light.gg。
- 使用 AI 猜测武器、Perk、版本或作者未表达的组合。
- 护甲清理和 Armor Planner 规则改造。
