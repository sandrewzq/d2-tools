# T17：武器详情 DIM 启发式重设计

> 状态：待实施
> 优先级：P1
> 范围：仅武器详情；不改护甲详情、资料库列表、仓库列表、商人页面和共享页面外壳

## 背景

当前资料库、仓库、商人和首页中的武器都已经进入同一个共享武器详情组件。现有功能和数据边界基本完整，但页面的信息权重更接近“完整资料档案”，用户打开武器后需要滚动较长距离才能看到当前 Roll、可切换 Perk 和操作入口。

DIM 的可借鉴点是：点击装备后快速呈现当前 Roll、把主操作与辅助操作分组、把技术信息和低频内容渐进展开。本任务只吸收这些信息架构经验，不复制 DIM 的小尺寸弹窗、互斥 Tab 或高密度视觉。

## 设计目标

1. 把武器详情定位为“Roll 与配置工作区”，让玩家首屏快速回答“这把武器当前是什么配置、是否值得保留”。
2. 保持资料库定义、商人售卖和账号实例共用一套 `WeaponDetailContent`，只通过对象上下文表达真实差异。
3. 保持武器与护甲的领域内容分离；护甲详情不因本任务改变章节、属性或模组结构。
4. 保留完整来源、实时状态、目标匹配、升级、AI 和写操作反馈，不以视觉压缩为理由隐藏真实能力。
5. 保持鼠标优先；保留关闭按钮、遮罩、Drawer 和待提交状态保护，不新增本轮不需要的方向键或手柄导航体系。

## 推荐信息架构

武器详情继续使用共用详情外壳、连续滚动正文和右侧实例栏，但武器内容采用以下顺序：

1. 当前配置
2. 属性与获取
3. 目标匹配
4. 升级与附加能力
5. AI 分析

“我的同名武器”作为右侧实例栏的对象切换与操作区域，不再单独复制一章长列表。章节导航仍然只负责滚动定位，不改为互斥 Tab。

## 页面设计

### 身份区

- 主视觉优先显示图标、武器名称、类型、栏位、弹药、元素和反勇士能力。
- 右侧显示入口、当前查看、位置和发布版本。
- Hash、定义版本、光等上限编号、装备编号等技术字段继续放入“武器定义信息”折叠区。
- 不在顶部重复显示“随机配置”“固定配置”等配置分类标签；配置类型在“当前配置”章节表达。

### 当前配置

- 首先显示当前 Roll 摘要：玩法取向、已选 Perk、可切换插槽数量和对象状态。
- 配置网格按真实 `socket_index` 排列，第一轨为固有能力或武器框架，后续轨道承载真实有效插槽。
- 资料库定义显示完整 Perk 池且只读；商人 Offer 显示售卖 Roll 且只读；账号实例显示当前已选项和实际可切换项。
- 用户点击 Perk 后进入“待应用”状态，明确显示变更数量、取消和应用操作。
- 写入失败后保留用户选择并提供重试；切换对象或关闭详情时不得静默丢弃待应用选择。

### 属性与获取

- 属性区与获取区采用约 60/40 的视觉比例，属性优先回答当前装备状态。
- 同时区分当前实际值、资料库标准值和待应用变化；差异必须有文字，不依赖颜色。
- 获取方式区分历史获取途径和本次实时发现的入口。
- 当前可获得、当前可购买、条件不满足和接口无法判断必须分别表达。
- 来源为空时使用紧凑局部空态，不保留大块无意义空白。

### 右侧实例栏

- 标题使用“我的同名武器”，当前对象使用“当前装备”等玩家文案。
- 当前装备、主要操作和次要操作置顶；装备、转移、锁定等操作沿用现有真实 action。
- 标签、备注、复制摘要和加入配装草稿放入辅助折叠区。
- 同版本装备只突出位置、光等、Roll 差异、锁定状态和标签，不突出内部实例编号。
- 宽屏右侧停靠；中小宽度转为可关闭 Drawer，保留关闭按钮和遮罩。

### 颜色与文案

- 蓝色表示当前查看、当前选中和导航定位。
- 绿色只表示真实改善、成功确认或明确可购买。
- 橙色表示待应用、条件限制或需要注意的状态。
- 红色表示失败或明确不可执行。
- 玩家界面默认不出现 Hash、Manifest、Profile、Vendor、Offer 等内部术语。

## 数据与入口边界

| 当前对象 | 必须保留 | 禁止推断 |
|---|---|---|
| 资料库定义 | 定义属性、完整 Perk 池、版本、官方来源 | 当前实例 Roll、账号拥有状态、远程写操作 |
| 商人售卖 | 售卖 Roll、价格、限制、刷新时间、购买状态 | 账号实例已拥有、可远程切换 Perk |
| 账号实例 | 实际属性、当前 Perk、位置、锁定、装备和转移状态 | 定义池候选等同于本件已拥有项 |

三种入口必须继续消费同一个 `WeaponDetailContent`，不能为资料库、仓库或商人新增平行详情页面。

## 实施切片

### 实现：武器详情首屏层级

- 调整武器身份区高度和信息优先级。
- 将当前配置摘要和当前 Roll 入口前置。
- 调整武器章节导航文案和定位顺序。

### 实现：武器配置工作区

- 优化 Perk 网格、当前选择和可切换项的视觉区分。
- 收紧完整 Perk 池的次级展开表现。
- 补齐待应用状态的关闭、对象切换和失败恢复保护。

### 实现：武器实例栏

- 将右栏整理为当前装备、主操作、次操作、辅助折叠区和同名装备列表。
- 简化同名装备卡片字段。
- 保持宽屏停靠与中小屏 Drawer 两种布局。

### 整理：武器详情状态语义

- 收紧状态颜色使用范围。
- 清理玩家可见的内部术语。
- 确认资料库定义、商人售卖和账号实例在加载、空、失败、部分可用和进行中状态下都保留已有能力。

### 整理：合同与验收材料

- 若采用“当前配置”作为第一章，同步更新 `docs/work/references/ui-specs/equipment-details.md` 和 `docs/work/references/equipment-detail-and-knowledge-analysis.md` 中的武器章节顺序。
- 更新武器详情验收清单，明确三种对象模式、明暗主题、宽屏停靠和 Drawer 状态。
- 保留临时 HTML Demo 作为视觉讨论材料，不将其作为产品实现或长期页面。

## 验收标准

- 资料库、仓库、商人和首页打开同一武器时，页面结构和样式一致，仅对象数据和可用操作不同。
- 护甲详情的结构和样式不发生变化。
- 首屏可以看到武器身份、当前 Roll 摘要和至少一部分真实 Perk 配置。
- 当前配置、属性、来源、目标匹配、升级和 AI 仍在同一滚动档案中可访问。
- Perk 待应用、写入中、成功、失败和重试状态真实表达，关闭或切换对象不会静默丢失用户选择。
- 右栏在宽屏停靠，在中小宽度可通过鼠标按钮、遮罩和关闭按钮完成打开与关闭。
- 不出现横向滚动条；长名称、来源描述和 Perk 文案可以换行。
- 不新增资料库专用武器详情页面，也不把 Demo HTML 迁入正式产品目录。

## 不在本任务范围

- 护甲详情重新设计。
- 资料库搜索、筛选和结果列表改造。
- 仓库或商人页面整体布局改造。
- 全局 Shell、主题 token、共享窗口尺寸和其他菜单样式改造。
- 新增手柄导航体系、方向键导航或独立输入设备架构。
