# T67：「已导入来源」清单的排版——数字列不再跟着按钮个数跑，四个动作统一形状

> 状态：🟢 代码已改并自验通过，待用户复验（2026-09-17）
> 用户诉求：「排版设计ui优化一下，现在很难看」，看过四张对比图（现在 / 甲 / 乙 / 丙）后拍板

## 今天的问题（真实样式表 + 无头浏览器实测）

量的是 仓库 → 推荐来源 → 「已导入来源」清单的两行（就是用户截图里的两份来源）。
数字栏的宽度下限写的是 210px，而它左边缘的位置取决于**这一行有几个按钮**：

| 量什么 | 结果 |
|---|---|
| 一行的宽度（1720 的窗口） | 1694 |
| 来源名的文字宽度 | 235 |
| 名称栏实际占宽 | 1196（1720）/ 1076（1600）/ 756（1280） |
| 数字栏在**第 1 行**的位置 | x = 1241 |
| 数字栏在**第 2 行**的位置 | x = 1293 |
| 两行的差 | **52px**（= 「同步」按钮 45 + 间距 6 + 取整） |

也就是说：**上面那行多一个「同步」，下面那行的数字就整体往右挪 52px**。
从 1720 一路量到 720，每个宽度上都差这 52px——因为差多少只由「按钮个数」决定，与窗口宽度无关。

同一批测量里还看到三件事：

- 数字栏宽度固定 210，而框里最长的一行字只有 185 → 右边永远空 25；上面那行「1679 条规则」只有 71 宽，
  所以数字块的右边缘是锯齿状的（71 / 185 来回差 105）。
- 来源名和「1679 条规则」都是 14px、字重 700 —— 一行里两个一样响的标题。
- 「停用」是透明底 + 透明边，看起来就是个文字标签；「删除」是整行唯一有颜色的实心块（暗红底 + 近白字）。

## 改法（用户选定的「乙」）

**数字仍然独立成一列，但真的对齐。** 三处：

1. **按钮栏的宽度由最宽的那一行决定，不再由当前这一行的按钮个数决定。**
   列表与行共用同一套栏宽（行用 `subgrid` 接上列表的栏），于是「有几个按钮」与「数字栏落在哪儿」彻底无关。
   两个清单（来源管理页 / 数据面板）各自的按钮集合不同，各按各自最宽的一行算，互不牵连。
2. **数字栏定宽到 210px**（原来写的是「下限 210、内容再宽就让它长」，内容一长两行又会错开），
   数字右对齐、用等宽数字（`tabular-nums`），条数用更亮的字色。
3. **四个动作统一成一个形状**：都是同样的描边按钮，只靠文字颜色分轻重——
   查看详情 / 同步正常色，停用暗一档，删除用红描边（不再填红）。点下去之后的确认框仍是警告的地方。

## 明确不做

- **不动顶部那条汇总带**：乙这一版保留「当前来源 N 个 / 已启用 N 个」原样。
- **不改列表宽度上限**：只有甲、丙封顶 1080，乙不封顶。
- **不动本地文件预览卡、导入弹框、规则详情弹框**：规则行（`vault-managed-rule`）的排布一个字节不改。
- **不加图标、不折叠菜单、不改按钮文案与行为**：点了做什么一字不变。
- **不动鼠标划过左边浮出的那圈高亮**：它在乙这一版里原样保留（那块地方点不动是另一件事，
  要改再单独说，见「如实记录」）。

## 验收判据

1. 两行来源的数字栏左右对齐（按钮个数不同也对齐）。
2. 「同步」在读取中把文案换成「同步中」时，两行之间不出现错位（实测整列一起移动 12px，见下）。
3. 窄屏（700 以内）行收回单栏，与今天一样纵向排开，不出现横向滚动。
4. 四个动作形状一致，删除是红描边而不是红实心；点下去的行为与今天一字不差。
5. 规则详情弹框里的规则行排版与今天一模一样。
6. 五道闸门与 `pnpm check` 全绿。

## 验证记录（2026-09-17）

改完后用同一份静态页（真实标记 + 真实构建出来的样式表）再量一遍，七个宽度各量两行：

| 窗口宽 | 数字栏左边缘（行 1 / 行 2） | 差 | 按钮区 | 横向溢出 |
|---|---|---|---|---|
| 1720 | 1241 / 1241 | 0 | 226 | 无 |
| 1600 | 1121 / 1121 | 0 | 226 | 无 |
| 1280 | 801 / 801 | 0 | 226 | 无 |
| 1000 | 521 / 521 | 0 | 226 | 无 |
| 760 | 281 / 281 | 0 | 226 | 无 |
| 700 | 33 / 33（已收单栏、靠左） | 0 | 650（整行） | 无 |
| 640 | 33 / 33（已收单栏、靠左） | 0 | 590（整行） | 无 |

按钮区从改前的「行 1 少一个按钮就窄 52」变成**两行同宽 226**：这个宽度由行 1（四个按钮）决定，
行 2 只有三个按钮也占同一栏，所以数字栏不再逐行错位。改前 1720 时是 1241 / 1293。

模拟「同步中」（这一行四个按钮全转 disabled、同步文案变成三个字）复量：按钮区 226 → 238，
数字栏整列一起从 801 移到 789（12px），两行仍然对齐。这是三字文案比两字宽出来的量，
要消掉只能给按钮钉一个写死的宽度、或改掉这个文案——两者都超出「乙」的范围，故如实记录、不取。
改前同样存在这类位移（而且上面还压着那 52px 的固定错位），所以这不是新引入的毛病。

700–760 之间这条窄带里名称栏会收到 181–221px，长来源名折成两行、两行高度不一致；
这是改前就有的（两边的栏目宽度下限都还是 210 那条），「乙」不处理。

1. `.vault-managed-source-list` 排两栏 `minmax(0, 1fr) max-content` + `column-gap: 10px`；
