# Bug #101：账号页挂着一份没人读的「愿望单」数据

> 状态：✅ 代码已改并自验通过，待用户复验（2026-09-17）
> 发现于 Bug #100 收尾时顺带扫属性链。与本 Bug 无关——它不是那个按钮留下的，
> 是本来就死在那儿的。

## 一、是什么

账号页对外声明它要收一份「愿望单」（账号快照里的那份 DIM 文本规则），
上层也老老实实每次都把这份数据算出来、传进去——**而账号页从头到尾没有读过它一次**。

于是这份数据每个渲染周期都被搬一趟，界面上一处都不用它。它不是「暂时没接上」：
账号页的愿望单相关内容（本周刷取清单的社区匹配等）走的是另外两条属性，
与这一条没有关系。

**为什么值得清**：这正是「死通道」——一个属性只要还挂着，下一个读代码的人就会以为
「账号页在这一层拿到了愿望单」，而实际没有；要加相关内容时也会误以为数据已经在手。
按 T56 与 Bug #100 的先例，没人走的路不留。

## 二、删到哪一层

| 层 | 位置 | 处置 |
|---|---|---|
| 属性声明 | `desktop/.../features/account/AccountPage.tsx` | 删 `wishlist` 属性（它从未被读），类型导入随之收窄 |
| 渲染层接线 | `desktop/.../pages/providers/AccountMenuProvider.tsx` | 删那一行传参 |

**留**：账号快照里的这份数据本身、以及 `setImportedWishlist` 的写入与「变化时回流」那一路——
仓库页仍在读它（来源行按愿望单武器 Hash 判断影响范围），这不是死数据，只是账号页那一支没在用。
