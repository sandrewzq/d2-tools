# 统一装备详情与知识分析

> 状态：设计已确认，待开发
> 更新时间：2026-07-15

## 目标

让资料库、仓库和商人入口共用一套装备详情内容模型，同时正确区分装备定义、当前商人售卖品和账号真实实例。详情需要统一属性、官方获取来源、完整 Perk 池、推荐 Roll、大师杰作、模组、同版本实例和 AI 分析，并消除商人、来源、拥有状态和 Roll 的重复数据。

本需求不重新定义商人页面结构，也不负责判断官方来源。商人和官方来源数据由
[商人结构、覆盖与官方获取来源](vendors-and-drop-sources.md) 提供。

## 术语约定

- **Perk**：一个独立的武器能力或插槽选项，例如“心无旁骛”。
- **Perk 池**：当前装备版本在 Manifest 中可能出现的全部 Perk 候选。
- **Roll**：一件账号实例或商人 Offer 实际生成的完整配置，包含枪管、电池、各列 Perk 和大师杰作。
- **当前启用 Perk**：Roll 中每个支持切换的插槽当前生效的 Perk。
- **推荐 Roll**：面向 PvE、PvP 或具体玩法目标的一套目标 Roll；同一装备可以存在多套推荐 Roll。
- **模组建议**：推荐记录中的独立附加建议，不属于 Roll。

界面统一使用“完整 Perk 池”“本件 Roll”“售卖 Roll”“当前启用 Perk”“Roll 内可切换”“PvE 推荐 Roll”和“PvP 推荐 Roll”。不再使用“实例 Perk”“推荐组合”或无法区分单项与整套配置的“当前推荐”。

## 玩家文案规则

玩家界面的标题、说明、按钮、空状态、状态消息和 AI 文案统一遵循 [玩家文案字典](../../player-facing-language.md)。该字典是内部术语到玩家用语的唯一对照来源；本需求不再维护第二份映射表。

Hash、Manifest 构建号、接口字段缺失原因和证据对象名称只能出现在开发者诊断工具中，不能作为装备详情的默认内容。

## 已确认原则

- 资料库和仓库共用同一套装备详情。
- 商人售卖品也复用相同装备定义、属性和 Perk 数据能力。
- 入口只决定默认查看对象，不维护三套详情页面。
- 资料库入口默认不选择账号实例。
- 仓库入口默认选择用户点击的账号实例。
- 商人入口默认选择用户点击的当前 Offer。
- 资料库中选择“我的同名装备”后，得到与仓库入口相同的实例内容和操作。
- 所有官方获取方式在资料库、仓库和商人详情中都保留，不因入口不同而隐藏。
- UI 布局和视觉方案后续单独设计，本文件只确定内容和数据规则。

## 领域对象

### 装备定义

由当前 Manifest 中的具体装备 `hash` 决定，包含：

- 名称、图标、稀有度和说明。
- 武器类型、框架、槽位、伤害属性和弹药类型。
- 是否可锻造、支持强化、为专家版或异域装备。
- 基础属性。
- 完整 Perk 池。
- 官方获取来源。

### 当前商人售卖品

商人 Offer 中实际在售的武器内容，可能包含：

- 当前售卖 Roll 和可切换 Perk。
- 当前售卖属性。
- 实际大师杰作和已安装模组。
- 价格、刷新、职业限制、购买条件和购买状态。

商人售卖品不是账号实例，不计入拥有数量，也不能装备、转移、锁定或设置实例标签。

### 当前账号实例

玩家账号中具有实例 ID 的真实武器，包含：

- 实际属性。
- 拥有的全部可选 Perk 和当前启用项。
- 实际大师杰作、等级和当前模组。
- 光等、位置、锁定和装备状态。
- 本地标签、备注和配装引用。

## 装备身份与版本

装备名称用于发现知识和同名版本，当前详情的 `hash` 是版本和后续数据的边界。

同名但不同 `hash` 的普通版、专家版、复刻版或重新发行版分别保留。切换版本后，基础属性、官方来源、Perk 池、推荐 Roll、我的同名装备和 AI 分析全部跟随当前 `hash` 更新。

“我的同名装备”只统计当前 `hash` 的真实实例，不跨版本混合。

## 属性规则

### 三种数值

1. 基础值：Manifest 装备定义提供的官方属性。
2. 当前售卖值：基础值叠加商人 Offer 中实际生效的 Perk、大师杰作和模组。
3. 当前实例值：基础值叠加账号实例中实际启用的 Perk、大师杰作和模组。

售卖品或实例存在时，每项属性保存：

```text
基础值
当前值
差值
差值来源
改善或降低
```

不能简单把正数标为改善。充能时间和拉弓时间降低通常更好，射程、稳定性和操控性通常提高更好。

无法可靠计算时显示当前值暂不可计算，不能把基础值冒充实例值，也不能生成虚假差值。

### 属性范围

当前阶段只使用 Bungie 官方数值和可追溯修正，例如冲击、射程、稳定性、操控性、填装速度、射速、弹匣、辅助瞄准、后坐方向、缩放、空中效率、充能时间、拉弓时间和弹药生成。

暂不生成 DPS、TTK、首领总伤害、精确伤害衰减距离、实际换弹时间或击杀所需弹数。

## 官方获取来源

详情消费 [商人结构、覆盖与官方获取来源](vendors-and-drop-sources.md) 产出的单一来源结果。

内容只保留：

- Bungie 商人和 Offer。
- Bungie 当前活动直接奖励。
- Manifest 官方来源提示。
- 来源查询是否完整和数据更新时间。

账号拥有、社区内容、知识库和 AI 均不能生成官方获取来源。

商人、价格、刷新、购买条件和售卖 Roll 只完整存在于来源 Offer。其他详情内容可以引用该 Offer，但不能再保存第二份商人摘要。

## 完整 Perk 池

完整 Perk 池只适用于存在随机配置的武器，并且只包含构成武器 Roll 的插槽：

- 固有特性或武器框架。
- 枪管或瞄具。
- 弹匣或电池。
- 特性列。
- 起源特性。
- 武器确实存在的其他 Roll 插槽。

不包含大师杰作、武器模组、着色器、装饰、击杀记录器、锻造纪念物或其他视觉和追踪插槽。

强化 Perk 与普通 Perk 建立关联，不作为毫无关系的两个候选。

每个 Perk 可以引用以下事实：

- 当前实例拥有。
- 当前实例启用。
- 当前商人 Offer 使用。
- 知识库推荐。
- DIM 个人目标。

这些引用不复制商人价格、实例位置或推荐理由。

如果实例数据返回了当前 Manifest 池中没有解析到的 Perk，保留该 Roll 中的真实 Perk，并标记“未在当前 Manifest Perk 池中解析到”。

## 当前 Roll

当前实例显示该实例拥有的全部可选 Perk，并明确当前启用项。

- 当前属性只按启用项计算。
- 知识库和 DIM 匹配检查实例拥有的全部可选项，不只检查当前启用项。
- 大师杰作、模组、外观和记录器不算作 Roll。

当前商人 Offer 使用相同规则，但只能使用 Bungie Offer 明确提供的数据。接口没有返回完整属性或插槽时留空，不根据名称猜测。

## 异域武器分支

固定配置的异域武器使用独立详情结构，不套用传说武器的随机 Roll 和完整 Perk 池界面：

- 优先展示异域固有能力及其生效方式。
- 使用“固定配置”展示全部固定 Perk，不提供随机 Roll 筛选。
- 催化剂独立展示获取提示、完成条件、进度和完成后的属性或能力变化。
- 属性区域同时展示基础值、催化增加值和最终值。
- 账号状态区分未拥有、已拥有、催化进行中和催化已完成。
- 可以提供 PvE / PvP 使用建议，但不做推荐 Roll 命中判断。
- 获取方式、外观和账号中的同名武器继续复用统一来源与账号能力。

异域武器并非全部固定配置。存在可变 Perk 或可塑形配置的异域武器时，仍优先展示异域固有能力和催化剂，但可变插槽复用随机 Roll / 配置编辑能力；不能因为稀有度为异域就隐藏真实可变插槽。

玉兔原型使用本机中文资料库中的真实定义：固定配置为“愚者宿命 / 多边形膛线 / 大口径弹药 / 边打边劫 / 萤火虫”；催化完成条件为熔炉竞技场击杀 250，完成后稳定性增加 30。

## 大师杰作与模组

没有选择商人 Offer 或账号实例时，只显示推荐大师杰作和推荐模组。

选择当前商人售卖品时显示：

- Offer 实际大师杰作、等级、模组和真实属性影响。
- 知识库推荐大师杰作和模组。
- 当前售卖内容与推荐的差异。

选择当前账号实例时显示：

- 实例实际大师杰作、等级、模组和真实属性影响。
- 知识库推荐大师杰作和模组。
- 当前实例与推荐的差异。

未满级大师杰作只计算当前等级的实际加成。无模组时明确记录为空，不能把推荐模组当成已经安装。

需要兼容锻造武器等级、强化固有特性、强化 Perk、专家模组、固定大师杰作和没有对应插槽的武器。

## 我的同名装备

“我的同名装备”包含当前 `hash` 下所有具有实例 ID 的真实装备：

- 已装备。
- 角色背包。
- 仓库。
- 邮政官。

不包含收藏解锁、已经失效的配装引用、没有实例 ID 的记录或其他同名不同 `hash` 版本。

用户可以在同版本实例之间切换。切换后同步更新：

- 当前 Roll 和当前启用项。
- 实际属性和差值。
- 大师杰作和模组。
- 光等、位置、锁定和装备状态。
- 标签、备注和配装引用。
- 推荐匹配和 AI 分析对象。

只要选择了真实账号实例，不论从资料库还是仓库进入，都提供相同实例操作：装备、转移、锁定或解锁、本地标签、备注、同版本比较、复制摘要和加入配装草稿。游戏 API 不支持的拆解操作不提供。

## 推荐知识

### 来源优先级

推荐来源按字段使用以下优先级：

1. 用户指定并确认保存的个人知识。
2. 内置知识库。
3. AI 查询的外部知识。

用户未指定的字段可以由内置知识补充，内置知识也缺失时才使用外部知识。不同来源冲突时明确说明，不能静默拼成一条不存在的推荐。

DIM Wishlist 保留为用户手动导入的个人目标，不属于系统默认推荐，也不依赖 DIM API。

### 名称解析

知识库按武器和 Perk 名称维护，不要求人工维护 `hash`。

使用时：

1. 当前详情已经确定具体装备 `hash`。
2. 按当前装备名称查询知识库。
3. 在当前版本的对应 Perk 插槽中解析知识库名称。
4. 只有解析到当前 Perk 池的内容才能用于推荐。
5. 不匹配时显示“知识库推荐不适用于当前版本”，不让 AI 猜测版本。

### 推荐内容

一条推荐记录可以包含：

- 武器名称。
- PvE、PvP 或通用模式。
- 推荐 Roll 名称和优先级。
- 各 Perk 插槽候选，单个插槽允许多个替代选项。
- 推荐大师杰作。
- 独立的模组建议。
- 使用场景和推荐理由。
- 更新时间。

不保存虚构采用率、Light.gg 排名或没有出处的社区热度。

推荐 Roll 的匹配结果包含完全命中、部分命中和未命中，并分别说明当前启用 Perk、Roll 内可切换 Perk、大师杰作和模组建议差异。

## AI 分析

AI 允许使用三类知识：

1. 用户指定知识，优先级最高。
2. 内置知识库。
3. AI 自行查询的外部知识，优先级最低。

外部知识必须保留网站、链接和查询时间。无法提供出处时只能标记为 AI 推测。外部知识只用于 Roll、模组、大师杰作和玩法分析，不能修改 Bungie 官方获取来源。

AI 可以结合 Manifest、商人 Offer、账号实例、同版本实例和知识库进行解释与比较，但不能虚构采用率或把低优先级内容覆盖高优先级知识。

分析对象由当前查看内容决定：

- 资料库装备：解释武器定位、完整 Perk 池、知识库推荐和官方来源。
- 当前商人售卖品：比较售卖 Roll、属性、大师杰作、模组、账号已有实例和知识库，回答是否值得购买。
- 当前账号实例：比较实际 Roll、属性、同版本实例和知识库，回答是否值得保留及如何使用。

知识库没有当前武器时，AI 可以查询外部知识或解释官方 Perk 效果，但必须明确来源，不能把外部结论伪装成内置知识库推荐。

## 用户知识持久化

用户在对话中提供的新知识可以立即用于当前分析，但不能自动持久化。

持久化流程：

1. AI 识别新的武器知识。
2. 提示当前只在本次对话生效，并说明可以保存到个人知识库。
3. 保存前列出武器、模式、Roll、大师杰作、模组、理由和将覆盖的内置字段。
4. 用户明确确认后才保存。
5. 保存后个人知识优先级最高，并支持查看、修改、删除、禁用和恢复内置知识。

AI 外部查询结果默认只缓存。用户明确确认保存后，才以“用户确认的外部知识”进入个人知识库，并保留原始链接。

## 当前实现基础

以下能力已存在，可以作为迁移基础：

- 资料库和商人入口可以按精确装备 `hash` 读取同一份定义详情。
- 账号拥有状态能够汇总仓库、角色背包、已装备和邮政官。
- 仓库实例可以按装备 `hash` 定位。
- 商人库存能够保留当前售卖 Perk，避免用 Manifest 候选池冒充当前 Roll。
- Desktop 已有共享装备详情弹框、当前实例选择、同名实例汇总、写操作、DIM 导入、本地推荐表和 AI 分析基础。

此前 backlog 中记录的真实账号验收结果继续有效：

- 商人入口和资料库入口已经能对同一件装备读取相同定义和账号拥有数据。
- 仓库中的“海盗之怒”能按 `hash` 精确定位实例。
- 只在术士背包中的“升华”能正确显示背包拥有数量。
- 商人“海盗之怒”能保留仄的来源路径和当前售卖 Roll。

但现有“Perk 优先双栏方案 A”、`current / historical / unknown` 获取分类、独立 `vendorContext` 摘要和 Light.gg AI 网页读取不再代表最终需求，需要按本文件重新收口。

## 开发切片

### 切片 1：统一详情领域模型

- 拆分装备定义、商人 Offer 和账号实例。
- 建立基础值、售卖值、实例值和修正来源。
- 统一来源、Perk、推荐和同版本实例引用，删除重复摘要字段。

### 切片 2：资料库与仓库共用详情

- 资料库默认展示装备定义，不自动选择实例。
- 仓库默认选择点击的实例。
- 资料库选择“我的同名装备”后复用完整实例能力。
- 相同 `hash` 实例支持切换和同步分析。

### 切片 3：商人 Offer 接入

- 商人入口选择当前 Offer。
- 使用 Offer 实际 Roll、属性、大师杰作和模组计算售卖值。
- 与基础值、知识库和账号实例比较。
- 购买后刷新账号数据并切换到真实实例。

### 切片 4：知识库与推荐匹配

- 以名称维护内置和个人知识。
- 在当前 `hash` 的 Perk 池中解析名称。
- 支持字段级优先级、替代选项和完整、部分、未命中结果。
- DIM 只作为个人目标，不作为默认推荐。
- 移除 Light.gg 网页读取和虚构社区采用率依赖。

### 切片 5：AI 与个人知识

- 按用户、内置、外部顺序组合知识。
- 为外部知识保留出处和查询时间。
- 根据资料库装备、商人售卖品或账号实例选择分析对象。
- 用户确认后才保存到个人知识库。

### 切片 6：UI 设计与跨端落地

- 随机 Roll 武器参考：[传说武器详情原型](../references/传说武器详情原型.html)。
- 固定配置异域武器参考：[异域武器详情原型](../references/异域武器详情原型.html)。
- 传说与异域护甲参考：[统一护甲详情原型](../references/统一护甲详情原型.html)。护甲共用一套页面骨架，按定义能力显示异域固有特性、诡计护甲、套装效果和特殊插槽；没有 Offer 或账号实例时不得展示虚构属性 Roll。
- 所有原型都使用玩家可理解文案；真实资料与演示账号状态必须明确区分。
- 内容和数据规则稳定后再设计正式布局。
- 正式页面进入 `packages/ui`，Prototype、Web 和 Desktop 共用。
- 不沿用当前参考 HTML 作为最终实现依据，除非后续视觉验收重新确认。

## 完成标准

1. 资料库、仓库和商人入口消费同一套装备详情领域模型。
2. 装备定义、商人售卖品和账号实例的数据不会互相冒充。
3. 官方来源、账号拥有和 Perk 数据各自只有一份事实来源。
