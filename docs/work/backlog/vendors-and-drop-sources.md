# 商人结构、覆盖与掉落来源

> 状态：Backlog
> 更新时间：2026-07-15

## 目标

统一商人页面结构、商人覆盖和装备掉落来源。用户应能确认商人当前卖什么、库存属于哪个页面、刷新信息是否可靠，以及某件装备是当前可获取还是只有历史来源线索。

商人覆盖和掉落来源作为一个需求推进：商人解析产出标准化库存、来源路径和时效；掉落来源在此基础上汇总商人、任务、活动、世界池和历史来源。两部分共享领域数据，但不把非商人来源耦合进商人解析。

## 当前基础

已有能力：

- 首页本周世界简报主体。
- 仄及其子库存、价格、声望和等级奖励已经可用，并已作为统一商人结构的首个配置接入。
- 资料库中的装备来源线索。
- 当前公共商人、角色商人、公共活动和 Manifest 历史线索的区分。

这些已完成内容不再作为待办重复维护。

## 需求范围

### 统一商人结构与覆盖

所有商人页面统一组合以下四种结构，不再维护每个商人的独立解析流程：

1. 声望与等级：声望进度、等级、重置次数和等级奖励。
2. 售卖库存：当前页面直接售卖、兑换或领取的物品。
3. 子库存：由父入口进入的库存，可递归嵌套。
4. 任务：任务、悬赏和已放弃任务。

作用域、出现条件、购买动作、刷新周期、展示方式和递归保护是结构配置，不新增页面结构类型。

- 完成机灵模组 A/B 数据和界面验收。
- 仄保持当前已验收的页面顺序和内容，但改用统一结构定义，不保留仄专属编排流程。
- 逐个确认所有目标商人的主库存、子库存、声望、等级奖励、任务和刷新结构。
- 每个商人只声明结构配置、父子 Vendor、分类索引和展示顺序，不复制完整解析器。
- 单个库存或定义不可读时局部降级，不影响其他商人。

商人事实规则：

- 当前是否出现、当前库存和购买状态以授权后的 Bungie `Destiny2.GetVendors` live data 为准。
- `DestinyVendorDefinition` 只用于名称、候选页面和周期分类，不能证明商人当前在线或商品当前可买。
- 优先展示 live `nextRefreshDate` 或商品级 `overrideNextRefreshDate`；没有 live 时间时只显示保守的日刷新、周刷新或未知周期。
- Manifest 候选商人应动态抽取，产品展示白名单只能控制优先级，不能冒充完整官方清单。

### 统一掉落来源

- 在资料库装备详情中展示账号是否已拥有，并可跳转仓库定位。
- 区分“当前可确认获取”“历史来源线索”“来源未知”。
- 当前可获取结论必须来自有效 live API、活动状态或明确维护且带版本的数据；Manifest 来源描述不能单独作为当前可刷证据。
- 来源不可用或相互冲突时显示未知，不使用关键词或 AI 猜测。

## 非目标

- 不重新设计已完成的首页本周世界简报。
- 不建立 `DailySignal` 或另一套首页日报模型。
- 不在本任务中实现“小日向今天有什么”“枪匠卖什么”等自然语言问答。
- 不解析攻略，不负责仓库保留或清理建议。
- 不手写长期维护的全部商人和轮换大表。

- 记录不可见、无库存、子库存缺失和定义缺失时的降级表现。

### 切片 2：统一商人结构

状态：已完成（2026-07-15）

- 以仄为首个完整配置，保持现有输出不变并删除仄专属编排代码。
- 建立声望与等级、售卖库存、子库存和任务四种结构。
- 支持角色、账号、公会作用域，职业和活动条件，购买、兑换、聚焦、解码和领取动作，以及子库存递归防环。
- Manifest 分类 identifier 和 `previewVendorHash` 已进入领域模型；未配置商人可自动识别四种结构，已核对商人只配置顺序、父子 Vendor 和例外。
- 仄与萨瓦拉已作为首批结构配置，仄保持原有页面输出，萨瓦拉按截图固定声望、周常奖励、聚焦和传承聚焦结构。

### 切片 3：商人覆盖

状态：代码覆盖已完成，待真实账号逐商人验收（2026-07-15）

- 按实际 live 响应逐个接入并确认库存层级、声望、奖励和刷新信息。
- 优先接入萨瓦拉、浪客、枪匠和霍桑，再处理艾可拉、拉乎尔、泰斯及活动商人。
- 形成商人能力矩阵，未支持字段明确留空，不复制其他商人的推断。

当前实现：

- 仄、萨瓦拉、浪客、枪匠和霍桑使用已核对的结构配置；配置只规定顺序、分类、作用域、动作和明确的父子 Vendor。
- 枪匠商品保留 Live `socketPlugHashes` 并解析实际插槽名称，详情中单独展示“当前售卖 Perk”，不再用 Manifest 候选池冒充当前 Roll。
- 拉乎尔的材料交换与聚焦破译分别标记为兑换和解码动作。
- 艾可拉、泰斯、伊娃及其他商人由 Live 父入口和 Manifest `previewVendorHash` 自动生成子库存；只有 Live 返回入口时才展示。
- 公会、账号、角色作用域和活动条件保留在结构元数据中；循环引用和共享子 Vendor 由统一图遍历处理。
- 单个子 Vendor 缺失或不可读时保留父入口或其他区块，不使整个商人页面失败。

### 切片 4：掉落时效与账号拥有状态

状态：已完成并通过真实账号验收（2026-07-15）

- 统一当前可获取、历史线索和未知状态。
- 接入账号收藏或实例数据，展示已拥有状态和仓库入口。

当前实现：

- 只有当前角色商人、公共商人或公共活动的 Live 命中会标记为“当前可获取”。
- 仅有 Manifest 来源字段时标记为“历史来源线索”，没有 Live 和 Manifest 证据时标记为“来源未知”。
- 商人 Live 库存会补充完整来源路径，例如“浪客 → 聚焦破译 → 武器”。
- 账号拥有状态汇总仓库、角色背包、已装备和邮政官实例，并显示各位置数量。
- 仓库内存在实例时提供“在仓库定位”，自动进入仓库、清除其他筛选并按装备 Hash 精确定位。
- 商人来源查询失败但商人工作区已有授权 Live 库存时，仍使用商人工作区作为当前可获取证据；不会退回 Manifest 猜测。

真实账号验收结果：

- 当前商人售卖的“海盗之怒”显示“当前可获取”，并显示“仄 → 奇异装备优惠”实时来源路径。
- 当前 Live 数据未命中的“天堂暴政”显示“历史来源线索”，并保留 Manifest 的“救赎花园突袭”提示。
- 仓库中的“海盗之怒”正确显示拥有数量，“在仓库定位”会清除原筛选并按装备 Hash 精确定位到 1 件实例。
- 只在术士背包中的“升华”正确显示“术士背包 1 件”，且不提供仓库定位按钮。

## 完成标准

1. 机灵模组 A/B 均完成真实数据验收。
2. 仄和目标商人全部使用统一四结构编排，不再保留商人专属解析流程。
3. 目标商人的库存、子库存、声望、任务和刷新结构均有明确支持或降级结果。
4. 资料库装备详情能区分当前可获取、历史来源线索和未知。
5. 资料库能显示账号是否拥有装备，并可定位到仓库。
6. 所有可见结论都有可追溯来源，不把 Manifest 候选或 AI 推断显示成实时事实。
