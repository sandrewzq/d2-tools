# 商人覆盖与掉落来源

> 状态：Backlog
> 更新时间：2026-07-14

## 目标

在已完成的首页本周世界简报、仄库存和资料库来源线索基础上，补齐尚未验收的商人结构与装备来源能力。用户应能确认商人当前卖什么、库存属于哪个页面、刷新信息是否可靠，以及某件装备是当前可获取还是只有历史来源线索。

## 当前基础

已有能力：

- 首页本周世界简报主体。
- 仄及其子库存、价格、声望和等级奖励。
- 资料库中的装备来源线索。
- 当前公共商人、角色商人、公共活动和 Manifest 历史线索的区分。

这些已完成内容不再作为待办重复维护。

Manifest 商人结构、父子 Vendor 关系和特殊情况的完整人工核对表见
[商人结构与 Manifest 核对表](../references/商人/manifest-vendor-structure-audit.md)。

## 未完成范围

### 商人覆盖

- 完成机灵模组 A/B 数据和界面验收。
- 逐个确认非仄商人的主库存、子库存、声望、等级奖励和刷新结构。
- 为每个商人明确实际支持状态，不直接套用仄的专属解析规则。
- 单个库存或定义不可读时局部降级，不影响其他商人。

商人事实规则：

- 当前是否出现、当前库存和购买状态以授权后的 Bungie `Destiny2.GetVendors` live data 为准。
- `DestinyVendorDefinition` 只用于名称、候选页面和周期分类，不能证明商人当前在线或商品当前可买。
- 优先展示 live `nextRefreshDate` 或商品级 `overrideNextRefreshDate`；没有 live 时间时只显示保守的日刷新、周刷新或未知周期。
- Manifest 候选商人应动态抽取，产品展示白名单只能控制优先级，不能冒充完整官方清单。

### 掉落来源

- 在资料库装备详情中展示账号是否已拥有，并可跳转仓库定位。
- 区分“当前可确认获取”“历史来源线索”“来源未知”。
- 当前可获取结论必须来自有效 live API、活动状态或明确维护且带版本的数据；Manifest 来源描述不能单独作为当前可刷证据。
- 来源不可用或相互冲突时显示未知，不使用关键词或 AI 猜测。

## 非目标

- 不重新设计已完成的首页本周世界简报。
- 不建立 `DailySignal` 或另一套首页日报模型。
- 不在本任务中实现“小日向今天有什么”“枪匠卖什么”等自然语言问答。
- 不解析攻略，不负责仓库保留或清理建议。
- 不手写长期维护的全部商人和轮换大表。

## 开发切片

### 切片 1：机灵模组验收

- 使用真实账号分别验证 A/B 情形。
- 记录不可见、无库存、子库存缺失和定义缺失时的降级表现。

### 切片 2：非仄商人覆盖

- 按实际 live 响应逐个接入并确认库存层级、声望、奖励和刷新信息。
- 形成商人能力矩阵，未支持字段明确留空，不复制其他商人的推断。

### 切片 3：掉落时效与账号拥有状态

- 统一当前可获取、历史线索和未知状态。
- 接入账号收藏或实例数据，展示已拥有状态和仓库入口。

## 完成标准

1. 机灵模组 A/B 均完成真实数据验收。
2. 目标非仄商人的库存、子库存、声望和刷新结构均有明确支持或降级结果。
3. 资料库装备详情能区分当前可获取、历史来源线索和未知。
4. 资料库能显示账号是否拥有装备，并可定位到仓库。
5. 所有可见结论都有可追溯来源，不把 Manifest 候选或 AI 推断显示成实时事实。
