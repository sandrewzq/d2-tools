# T18：仓库重复实例决策工作台

> 状态：✅ 开发完成，待整体验收
> 优先级：P1
> 更新时间：2026-08-28

## 1. 产品结论

武器同名对比有较高玩家价值，护甲同名对比有条件价值，其他装备暂不值得投入复杂比较界面。

这个功能的目标不是展示一张更大的装备数据库表，而是帮助玩家完成一个具体决策：

> 这几件装备是否可以互相替代？我现在应该保留哪一件？下一步是否需要进入游戏内处理？

“同名”只能作为发现重复实例的入口，不能作为比较语义。武器和护甲必须使用不同的决策视图：

| 类型 | 玩家主要决策 | 目标视图 |
|---|---|---|
| 同一武器、同一版本的多个实例 | 选择 PVE / PVP / 特定目标的实例 | 武器用途与 Perk 决策卡 |
| 同名但不同武器版本 | 判断是否属于同一可替代对象 | 版本关系提示 + 有限比较 |
| 同职业、同部位的护甲 | 选择能满足配装属性目标的实例 | 护甲目标匹配卡 |
| 其他装备 | 判断是否只是重复占位 | 简单摘要，不进入复杂比较 |

## 2. 背景与当前问题

当前仓库同名整理已经具备左侧分组、实例卡片、比较基准、证据、整理状态、按需读取完整 Roll 和待应用状态，但仍有以下产品问题：

- “同名”同时包含同一 Hash 多实例与同名不同 Hash，玩家容易把不同版本误认为可直接替代。
- 比较基准虽然只是对照工具，但单选形式容易被理解为系统推荐。
- `Perk 3 不同`、`总值 +5` 这类信息是事实差异，不足以回答是否值得保留。
- 武器比较主要集中在 Socket，没有优先表达 PVE / PVP、目标命中和配装用途。
- 护甲比较展示裸属性差异，但没有表达职业、部位、能量、配装缺口和关键属性档位。
- 所有重复组排序优先级相同，低价值重复会淹没真正需要玩家决策的实例。
- 完整 Roll 读取不能阻塞首屏判断，也不能让玩家误以为“数据没加载就无法整理”。
- 应用中的整理标签只代表本地判断，不能伪装成游戏内已经解锁、转移、拆解或切换 Perk。

## 3. 产品目标

### 3.1 玩家目标

玩家进入仓库后能够：

1. 快速找到最值得处理的重复组。
2. 看到武器与护甲各自真正有用的差异。
3. 理解系统提供的是事实和证据，而不是未经确认的销毁建议。
4. 在应用中完成判断、标记和处理计划。
5. 需要执行时，明确跳转到装备详情或游戏内操作链路。

### 3.2 系统目标

- 同一实例的紧凑快照、Manifest 定义和本地证据优先用于首屏。
- 完整可切换 Perk 作为按需增强信息，不阻塞当前启用项比较。
- 武器与护甲共享整理状态和页面骨架，但不共享具体比较字段。
- 保护证据、推荐证据和玩家整理决定分层展示，不能互相冒充。
- 保留现有待应用、离开保护、冲突确认和精确本地标签写入边界。

## 4. 非目标

- 不把同名比较扩展成完整的装备数据库矩阵。
- 不自动替玩家选择保留、待复查或待处理。
- 不自动解锁、转移、拆解、穿戴或切换游戏内 Perk。
- 不在仓库页直接执行真实 Socket 修改；真实 Perk 切换继续在装备详情完成。
- 不把武器和护甲强行统一成同一套字段或同一套推荐算法。
- 不为低价值的其他装备建立复杂属性比较器。
- 不把“比较基准”定义为系统推荐，也不限制一组只能保留一件。
- 不因展示完整 Roll 而默认读取所有账号细节或定义池候选。

## 5. 术语与分组规则

### 5.1 玩家文案

首层入口继续保留“同名整理”以兼容现有用户认知，但组内必须显示明确关系：

- `同一版本 · 多个实例`
- `同名不同版本`
- `同职业同部位 · 多件护甲`
- `仅名称相同 · 需确认`

后续可以将入口升级为“重复实例”，但本任务不要求一次完成全局文案迁移。

### 5.2 武器分组

1. 优先按稳定定义 Hash 分组；组内是多个真实实例时，进入武器决策卡。
2. 剩余装备按规范化名称发现同名不同版本，但必须显示版本关系，不得与同 Hash 实例混为一组。
3. 版本、赛季、资料片或内容包摘要来自 Manifest / definition 事实；无法确认时显示“版本信息未返回”，不得展示内部 Hash 代替。

### 5.3 护甲分组

护甲的有效比较对象优先按以下维度收敛：

1. 职业。
2. 部位。
3. 护甲定义或护甲套装。
4. 名称。

同名但不同职业、不同部位的护甲不应作为一个“谁更好”的比较组。名称相同只是筛选条件，职业、部位和配装目标才是决策边界。

### 5.4 低价值组

如果一组实例满足以下条件，可标记为“低决策差异”并降低排序优先级：

- 没有锁定、装备、配装、愿望单或目标证据。
- 当前启用 Perk / 属性没有明显差异。
- 不存在版本关系或可执行能力差异。

低价值组仍由玩家主动标记，不自动写入整理状态。

## 6. 目标用户工作流

### 6.1 进入仓库后的总流程

```text
进入仓库
→ 选择武器 / 护甲
→ 按“需要决策程度”查看重复组
→ 查看组摘要与保护 / 目标证据
→ 进入武器决策卡或护甲目标卡
→ 选择比较对象或直接查看差异
→ 给每个实例标记保留 / 待复查 / 待处理
→ 应用本组状态
→ 需要执行时打开装备详情或生成游戏内处理清单
```

### 6.2 武器工作流

```text
选择武器重复组
→ 确认是同一版本还是同名不同版本
→ 查看 PVE / PVP / 愿望单 / 配装命中
→ 查看当前启用 Perk 与框架
→ 比较关键 Perk 槽位和武器用途
→ 按需展开“所有可切换项”
→ 分别决定保留、待复查或待处理
→ 打开详情执行游戏内 Perk 或装备操作
```

武器允许多件同时保留。系统不能因为某一件 PVE 命中，就把另一件 PVP 命中实例自动视为冗余。

### 6.3 护甲工作流

```text
选择护甲重复组
→ 确认职业、部位和套装
→ 查看总值、六维分布、最高属性和关键档位
→ 查看当前配装目标缺口
→ 查看能量、模组占用和配装引用
→ 判断是否值得进入 Armor Planner / 应用配装
→ 标记保留、待复查或待处理
→ 需要执行时进入配装或游戏内穿戴流程
```

护甲比较不输出“唯一最佳件”。如果两件护甲分别适合不同职业目标或不同配装，应该明确显示“用途不同，均可保留”。

### 6.4 应用与游戏的边界

| 能力 | 应用负责 | 游戏内负责 |
|---|---|---|
| 找出重复 | ✅ | — |
| 比较事实与证据 | ✅ | — |
| 保留 / 复查 / 待处理标签 | ✅ 本地标签 | — |
| 切换实际 Perk | 打开详情、准备计划 | ✅ |
| 转移 / 穿戴 | 发起并核对流程 | ✅ 执行实际状态 |
| 解锁 / 拆解 | 结构化确认、记录计划 | ✅ 执行 |
| 处理结果核对 | ✅ 重新读取并显示 freshness | ✅ 提供真实状态 |

应用中的“已决定”不等于游戏内“已处理”。界面必须分别使用“已应用标签”和“待游戏内处理”等状态。

## 7. 类型化比较设计

### 7.1 武器决策卡

每张卡固定按以下顺序排列：

1. **身份**：图标、名称、类型、弹药、光等、版本、实例尾号。
2. **用途**：PVE、PVP、愿望单、目标、配装、锁定、已装备。
3. **差异结论**：与当前对照对象相比，哪些关键槽位或框架不同。
4. **当前配置**：当前启用 Perk、框架和关键武器属性。
5. **可切换项**：按需展开实例真实拥有且可验证的 Socket 选项。
6. **整理决定**：保留、待复查、待处理、未标记。

差异摘要示例：

- `PVE 目标命中；Perk 3 与对照不同`
- `PVP 目标命中；已进入配装`
- `当前配置相同；仅实例状态不同`
- `同名不同版本；暂不判断是否可替代`

禁止只用颜色或内部 Hash 表达差异，必须同时提供短文字结论。

### 7.2 护甲目标卡

每张卡固定按以下顺序排列：

1. **身份**：职业、部位、护甲套装、光等、实例尾号。
2. **属性结论**：总值、最高属性、与对照的差值。
3. **目标匹配**：命中的属性目标、缺口、关键档位变化。
4. **安装条件**：能量容量、已用能量、剩余能量、模组占用。
5. **用途证据**：配装引用、锁定、已装备、目标命中。
6. **整理决定**：保留、待复查、待处理、未标记。

差异摘要示例：

- `总值 +4；恢复少 10；命中当前虚空术士目标`
- `总值相同；纪律高 10；适合当前配装`
- `属性更高但能量不足；需要进入 Planner 复核`
- `同名但职业不同；不可直接替代`

属性差异不能只按线性总值排序。需要优先表达目标命中、档位提升和具体配装缺口。

## 8. 组列表与排序

左侧组列表继续使用键盘可导航的 roving focus，并新增决策摘要：

- 类型：武器 / 护甲。
- 关系：同一版本 / 同名不同版本 / 同职业同部位。
- 实例数量。
- 未决定数量。
- 保护证据数量。
- 目标或推荐命中数量。
- 明显差异数量。
- 是否有待应用状态。

默认排序按以下优先级降序：

1. 有配装、锁定、愿望单或目标证据。
2. 有明显用途或属性差异。
3. 有待处理冲突。
4. 未决定实例较多。
5. 仅同一版本重复。
6. 无明显差异的低价值组。

排序必须是解释性的。组列表可显示“2 件命中目标 · 1 件有保护”，不能显示无法解释的内部评分。

## 9. 数据与缓存策略

### 9.1 首屏数据

首屏优先使用本地账号快照、Manifest definition cache 和本地目标 / 愿望单 / 配装关系：

- 名称、图标、类型、版本摘要。
- 当前启用 Perk。
- 护甲属性、职业、部位、能量摘要。
- 锁定、装备和配装引用。
- 本地标签与证据。

### 9.2 完整 Roll

- 只读取真实实例拥有且来源包含 `instance` 的可复用项。
- 不把 `character`、`profile`、`manifest` 定义池候选伪装成该实例可切换项。
- 读取过程不阻塞当前启用项比较。
- 控件始终可见；数据未就绪时明确禁用并显示原因。
- 读取成功后由玩家主动切换到“所有可切换项”。
- 读取失败提供重试；失败时保留当前启用项结论。
- 详情资源应进入已有统一账号实例缓存，避免同一实例被仓库页、详情页重复请求。

### 9.3 数据来源标识

涉及缓存或异步详情的字段必须标明：

- 当前快照。
- 正在刷新。
- 过期快照。
- 未读取。
- 读取失败。

不能因为暂时没有完整详情，就把“没有差异”当成事实。

## 10. UI / UX 约束

- 保持共享仓库工作区的响应式容器，不新增平台专用页面。
- 宽屏采用左侧组浏览器 + 右侧决策卡；中屏允许折叠左栏；窄屏按组列表 → 决策详情的页面栈切换。
- 不使用整页横向滚动矩阵承载武器和护甲所有字段。
- 卡片按身份、事实、证据、整理决定分层，事实和玩家决定不能混在同一视觉层。
- 差异必须同时提供文字标签和稳定状态样式，不依赖颜色单独表达。
- 左侧组列表使用 roving focus；打开组后初始焦点落在组标题或第一张卡的明确控件。
- 比较基准使用“设为对照”语义，不使用“推荐”语义。
- `Escape`、返回按钮和页面栈返回必须保留当前组与焦点。
- 待应用状态继续使用离开保护；应用本组状态前继续执行保护证据冲突确认。
- 不新增“批量销毁”主按钮。未来批量处理必须建立在明确的待处理清单和二次确认之上。

## 12. 验收标准

### 功能验收

- 武器同一版本多实例与同名不同版本在界面上可明确区分。
- 护甲比较至少同时显示职业、部位、总值、六维、目标缺口和能量摘要。
- 武器比较至少同时显示当前 Perk、用途证据和关键槽位差异。
- 完整 Roll 未读取时，当前启用项仍可正常比较和整理。
- 完整 Roll 读取失败时，不给出“完全相同”或“没有差异”的错误结论。
- 玩家可以同时将多件武器或护甲标记为保留。
- 保护证据和推荐证据不会自动写入玩家整理状态。
- 应用只写入本地标签；游戏内操作必须通过明确的详情或处理交接完成。
- 待应用状态、离开保护、冲突确认、撤销和下一未整理组继续可用。

### 交互验收

- 键盘可在组列表和实例卡控件间完成导航，初始焦点明确。
- 窄屏不依赖横向滚动矩阵；组列表和详情可按页面栈返回。
- 切换“当前启用 / 所有可切换项”不会重排其他卡片或丢失整理状态。
- 组排序和摘要能解释为什么该组排在前面。
- “比较基准”不会被视觉或文案表达成系统推荐。

### 数据验收

- 首屏不因完整 Roll 详情读取而阻塞。
- 同一实例的详情请求可复用统一缓存，不因多个页面入口重复请求。
- 所有差异结论都能追溯到真实账号快照、实例详情、Manifest 或本地证据。
- 过期、未读取、失败和当前快照状态在界面上可区分。

## 13. 风险与取舍

| 风险 | 处理方式 |
|---|---|
| 同名不同版本被误当成替代品 | 强制显示关系类型和版本摘要 |
| 玩家把基准当成系统推荐 | 使用“设为对照”，并单独展示推荐证据 |
| 只比较总值导致错误保留 | 护甲以目标缺口和档位为主，不只按总值排序 |
| PVE / PVP 多用途被压成单一结论 | 允许多件同时保留，分别显示用途命中 |
| 完整 Roll 读取速度影响体验 | 本地快照先渲染，完整详情按需读取并缓存 |
| 自动化批量处理造成误拆 | 本任务只做本地决定和处理清单，不新增自动拆解 |
| 比较字段持续增加导致页面再次膨胀 | 首屏只保留决策字段，其他事实进入详情或展开区 |

## 14. 完成定义

当以下条件全部满足时，T18 才算开发完成：

1. 武器和护甲已经使用不同的决策视图，而不是同一套字段模板。
2. 同一版本、同名不同版本和护甲上下文关系已经明确表达。
3. 玩家可以从组列表直接理解“为什么需要处理这一组”。
4. 武器卡能够支持用途选择，护甲卡能够支持目标匹配。
5. 应用判断、应用标签和游戏内执行边界没有混淆。
6. 首屏不依赖完整 Roll 实时读取，且异步失败有清晰恢复路径。
7. 现有本地标签、保护证据、待应用状态和导航保护没有回归。
8. UI 合同、领域模型和 app 派生模型已经同步更新，Desktop / Web 继续使用同一共享页面。
