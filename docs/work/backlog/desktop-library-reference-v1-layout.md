## 设计边界

- 全局外壳沿用已确认的 [首页与全局外壳 v4](desktop-home-global-shell-v4.md)。
- 资料库页参考外部“Destiny 2 武器出处查询”原型的信息组织方式，但不照搬实现。
- 配装页面本轮先不动。
- 资料库页仍坚持只展示可确认数据；来源待补时明确标记，不补猜测。

## 参考原型要点

外部原型的核心体验是“武器出处查询工具”：

- 搜索入口突出，支持按武器名称、perk、出处搜索。
- 来源类型筛选清晰。
- 结果按获取优先级分组，例如当前可获取、等轮换、已下架或待确认。
- 武器卡片包含来源、推荐 perk、简短出处说明和武器基础信息。
- 详情页突出出处来源、推荐 Perk 组合、备注说明和武器信息。

## 资料库页结构

资料库页采用 tab 组织：

1. 出处查询：默认入口，参考外部原型，面向武器出处和获取优先级。
2. Perk 查询：保留现有 Perk 检索、关联装备和分组筛选。
3. 掉落状态：展示实时状态、公共商人、角色商人、公共活动等可确认来源。
4. 收藏与历史：保留最近查询、收藏和取消收藏能力。
5. 别名：保留装备 / Perk 别名维护能力。

## 出处查询首页

出处查询是资料库默认视图：

- 顶部展示资料库日期和 Manifest 状态。
- 资料库非最新或组件缺失时，应明确提示搜索、详情、perk 池和来源判断可能受影响。
- 搜索区支持武器名称、perk 或出处。
- 来源筛选包括：全部来源、当前可获取、等轮换、商人、活动、副本、已下架或待确认。
- 结果按获取优先级分组：
  - 当前可获取。
  - 等轮换 / 周常。
  - 已下架或待确认。
  - 来源待补。

## 武器卡片

武器卡片应包含：

- 武器名。
- 来源类型 badge。
- 获取优先级 badge。
- 推荐 perk 标签。
- 出处说明。
- 武器类型、元素或弹药等基础信息。
- 详情入口。

卡片只展示可确认数据。来源字段不足时使用“来源待补”状态，不写暗示性结论。

## 武器详情

详情页或详情区域应包含：

- 标题、武器类型、元素、弹药、框架。
- 出处来源。
- 推荐 Perk 组合。
- 刷取判断。
- 备注说明。
- 实时状态：公共商人、角色商人、公共活动等。
- 社区推荐摘要。
- 收藏和打开装备详情入口。

## 保留现有能力

现有资料库能力继续保留：

- 装备 / Perk 分开检索。
- 装备分类、稀有度、位置、弹药、框架筛选。
- Perk 关联分类和关联装备筛选。
- Manifest 状态、后台更新和搜索阻断。
- 实时状态查询。
- 掉落来源、刷取判断和 Perk 池展示。
- 收藏、历史和别名。

## 实现注意

- 优先重排 `LibraryPage.tsx` 的结构，不重写搜索和 Manifest 数据流。
- 资料库日期和 Manifest 风险应在全局外壳、资料库页顶部和受影响结果中保持一致。
- 外部原型中的大标题和营销式居中结构不直接套用；桌面端仍采用紧凑工具台风格。
- 资料库详情可以借鉴外部原型的清晰分区，但要适配本项目装备详情和来源判断能力。
