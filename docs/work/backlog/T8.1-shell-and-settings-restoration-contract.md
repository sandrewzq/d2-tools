# T8.1 共享框架与设置页还原合同

> 状态：对照中
> 更新时间：2026-07-23
> 视觉真相：`docs/work/references/ui-prototypes/全应用视觉原型.html` 的最终计算样式

本合同是 T8 的共享 Shell 与设置菜单切片。它约束本切片涉及的 JSX、CSS 和平台接线；其他菜单的内容层可按各自的四份对照并行实施，不依赖本合同先完成。

## 范围与非范围

- 范围：顶部栏、组合状态条、侧栏、页面标题区、主内容滚动所有权、AI 抽屉、后台任务 Dock，以及设置菜单八个分区。
- 范围：`packages/ui` 的共享 Shell 与设置页、Desktop / Prototype 必要的真实数据接线。
- 经用户确认，本合同扩展为全应用收口的第一阶段：共享 Shell 固定后，首页、账号、仓库、配装、资料库和商人逐菜单合并 archive/default 为唯一内容视图。每个菜单仍须先完成自身的结构、绑定、状态和差异对照；不得通过平台入口或 `presentation` 参数选择不同视觉树。
- 不修改三个冻结 HTML 原型；不复制其 mock 数据、固定数量或演示反馈到产品代码。

### Shell 导航专项规格卡

侧栏主导航不得根据“线性”“按钮组”等文字解释自行实现。开始改动前必须逐一从冻结原型获取并登记普通项、当前项和窄栏项的：导航容器 margin / padding / 背景 / 四边边框 / 圆角；按钮高度 / padding / 四边边框 / 分隔线归属；当前项背景 / 边框 / 阴影 / 图标和文字色；图标块尺寸 / 背景 / 边框 / 间距；以及 `1280`、`980`、`760` 的差异。未登记完整不得改 `.shell-nav`、`.shell-nav button` 或 `.shell-nav-mark`。

Prototype 通过前必须先与冻结 HTML 的同状态导航截图和计算样式逐项一致；随后必须在 Desktop 实际页面重复检查。任何一端出现内缩圆角按钮、额外外框、边框归属不同、旧 CSS 覆盖或加载旧资源，该区域立即退回“对照中”。

本轮从冻结 HTML `.main-nav` 实测得到的导航规格如下，后续实现只能映射这些值，不能按“线性导航”字面含义改写：

| 视口 | `.main-nav` 容器 | 普通项 | 当前项 | 图标块 |
|---|---|---|---|---|
| `1280` | `margin: 8px 6px`；`border: 1px solid var(--object-border)`；`radius: 4px`；`background: var(--section-bg)`；`overflow: hidden` | 高 `42px`；`grid: 24px + 1fr`；`gap: 8px`；`padding: 0 10px`；仅 `border-bottom: 1px solid var(--section-divider)` | 与普通项同尺寸、无自身圆角；`background: var(--selected-bg)`；`box-shadow: inset 0 0 0 1px var(--selected-border)` | `22px` 方块；`radius: 4px`；内部 SVG `16px`，不是文字图标 |
| `980` | 同上，随 `70px` 侧栏收缩为 `57px` 宽 | 高 `42px`；仅图标，文字隐藏；无额外 padding | 同上 | 居中 `22px` 图标块 |

容器负责唯一的外框与圆角；子项只负责内部底部分隔和当前项 inset 边框。不得把容器边框、圆角或 margin 下沉到当前按钮，也不得用文字替换冻结原型的 SVG 图标。

## 一、共享框架合同

### 1. 原型结构表

| 原型区域 | 产品稳定标识 | 目标结构与视觉所有权 | 响应式行为 |
|---|---|---|---|
| 顶部栏 | `shell.topbar` | 单一 `.shell-titlebar`，内部仅为品牌、连续状态条、全局工具和窗口控制；边框由顶部栏与状态组合组各自唯一所有 | 窄宽时工具区优先保留图标，状态条按原型断点换行或收缩，不建立横向轨道 |
| 品牌 | `shell.brand` | 品牌标记、`d2-tools` 和副标题是一个无额外卡片的品牌组 | 不因窗口变窄改变顶部栏高度或挤压状态条重叠 |
| 状态组合组 | `shell.status-strip` | 状态项共享一圈外框和内部单线分隔；tone 只改变圆点，不能改变边框、背景、尺寸或间距 | 文案缩短/换行遵循最终原型，不显示独立胶囊或浏览器 button 外观 |
| 左侧栏 | `shell.sidebar` | 账号摘要、主导航和底部动作纵向排列；菜单项只由菜单边界和选中背景表达，不被通用卡片样式包裹 | 窄宽缩为原型窄栏，文字按原型隐藏或保持，不出现横向滚动 |
| 页面标题区 | `shell.page-header` | 使用原型的 eyebrow、标题、描述和真实页面 action，不引入旧页面独立标题壳 | 标题、描述和 action 换行，不遮挡正文 |
| 主内容 | `shell.page-content` | 普通菜单唯一 `page` 纵向滚动所有者；页面内容不建立第二个同轴滚动容器 | `1280px`、`980px`、`760px` 都无水平滚动和裁剪 |
| AI 抽屉 | `shell.assistant` | 抽屉头、模式切换、内容区和关闭动作使用统一框架；对话、任务和 overlay 分别拥有指定纵向滚动 | 小屏不压缩主页面到横向溢出；抽屉内容独立滚动并阻止 overscroll 传递 |
| 任务 Dock | `shell.task-dock` | 右下任务摘要和 Popover 使用原型边框、层级和状态；正文预留安全区 | 出现时不遮挡正文末尾；窄宽按原型尺寸和安全区收缩 |

### 2. 功能清单与绑定表

| 原型区域 | 真实数据 / action | 约束 |
|---|---|---|
| 状态组合组 | `ShellStatusItem[]`、可操作状态 action | 状态 key 负责逻辑，显示 label 只负责文案；不复制原型固定状态 |
| 顶部工具 | 主题、界面语言、GitHub、设置、AI、窗口控制 | 图标按钮的 title / aria-label 与真实 action 保持；无平台窗口控制时只隐藏该组 |
| 账号摘要 | 当前账号、角色数、仓库实际容量 | 不手写容量分母，不新增“打开小日向”侧栏入口 |
| 页面标题 | `ProductShellHost` 的当前页面元数据和真实页面 action | 内容页不得再复制标题区 |
| AI 抽屉 | AI 会话、上下文、任务助手、关闭 action | 保留加载、失败、无配置和发送中状态 |
| 任务 Dock | `ShellBackgroundTaskItem[]`、打开诊断 action | 无任务时不渲染 Dock；Popver 只展示真实任务 |

### 3. 状态矩阵

| 状态 | 顶部状态条 | 主内容 | AI / 任务 |
|---|---|---|---|
| 正常 | 连续组合组，真实 tone 圆点 | 正常页面 | 默认关闭 |
| 加载 / 刷新 | 状态项可显示真实进行中说明，不改变组合边框 | 页面保持尺寸并呈现菜单自己的加载状态 | 对话或任务只在自身区域显示进行中 |
| 部分失败 | 已确认状态继续显示，失败项使用真实说明 | 菜单显示可用区域和缺失原因 | 不伪造回复或完成状态 |
| 无后台任务 | 无 Dock | 正常 | 无 Popover |
| 有后台任务 | Dock 和正文安全区同时出现 | 正文末尾可访问 | Popover 独立 overlay 滚动 |

### 4. 旧结构清理清单

- 删除与原型冲突的 Shell 旧尺寸、独立状态胶囊、重复边框和平台专属 chrome 覆盖；不通过更高 specificity 叠加修补。
- Shell 只保留一个页面标题区、一个主内容滚动容器、一个 AI 抽屉和一个任务 Dock。
- Shell 专属 CSS 只能由 `packages/ui/src/styles/shell/` 负责；菜单 CSS 不得覆盖 `.shell-*`。

## 三、视觉验收与停止条件

### 分区实施门禁

设置的每一个分区必须独立走完下表，任一栏未登记或仍有未关闭差异时，不得修改下一个分区，也不得将设置页、Prototype 或 Desktop 标为已还原。

| 阶段 | 必填产物 | 通过条件 |
|---|---|---|
| A. 冻结结构 | 同一主题、同一视口下的冻结 DOM 顺序、可见文案、边框/背景所有权和断点记录 | 不以概览页或相邻分区代替；按当前分区记录 |
| B. 真实绑定 | 每一行/字段/按钮对应真实 ViewModel 字段、action、禁用条件与错误恢复 | 不允许 opaque 旧组件直接嵌入；若旧组件承载真实能力，先拆出字段与 action 再按冻结结构组合 |
| C. 状态矩阵 | 正常、加载、空/未授权、部分失败、禁用/进行中的内容与控件状态 | 不以 mock 成功、固定数量或隐藏功能填补空缺 |
| D. 差异清单 | `设置-分区-编号`、冻结表现、当前表现、修复位置、关闭证据 | 每项只能是“已关闭”或“阻塞”；不得以“局部样式一致”关闭 |
| E. 双端验收 | Prototype 与 Desktop 在相同 `light/dark × 1280/980/760 × 分区状态` 下的整屏对照 | 两端均无未关闭差异、无横向滚动、无旧 DOM/CSS 覆盖才可通过 |
