# T58 配装工作流原型（29 屏）

2026-09-20 定稿的配装工作台交互记录，配套 T58。原件留在 `.local-data/tmp/loadout-flow/` 没动，这里的是副本——`.local-data/` 被 git 忽略，放那里随时会丢。

## 这是什么

一份**可点着走的交互记录**，不是产品页面，也不是能改产品行为的第二套实现。

- 全应用 UI 只有 `packages/ui/src/loadouts/` 一处产品实现，这个原型不参与构建、不被任何包引用。
- 它定的是交互顺序和信息分层：哪一步出现什么、哪些状态要分开画、两个来源怎么互相指认。
- 里面的数字是**示例数据**，不是真实账号读取结果。要核对游戏里的数值别用它。

打开 `loadout-flow.html` 即可。单文件自包含：产品 CSS 已整份内联，无外链，无脚本依赖。

## 四条入法 × 主干七步

「29 屏按顺序排」本身不构成工作流，四条入法各走一条完整主干才是。

主干七步：1 定来源 · 2 装武器 · 3 定子职业 · 4 调护甲 · 5 挑候选 · 6 核对能不能穿 · 7 落盘。

| 入法 | 玩家为什么打开这个菜单 | 起点 |
|---|---|---|
| A 存下现在这一身 | 起点是身上这套，想以后一键换回来 | 身上这身 |
| B 抄一套 | 起点是攻略、视频或 DIM 链接，想把这套弄进游戏 | 外面抄来的 |
| C 凑一套 | 起点是「我仓库里有什么」，目标是六维达标 | 自己的库存 |
| D 改一套 | 起点是应用里已存的某套，只动其中一件 | 已存的一套 |

矩阵上一格「不经过」是信息，不是漏画。两条入法明确跳过挑候选：

- A 不强制跑护甲规划，没有可挑的候选，想跑就跑，不想跑直接把现状存下来。
- D 改的是已有方案，候选在设置变动那一刻就作废了，没有可挑的。

第 26–29 屏不属于任何一条入法，是四条路都会碰到的零件：分岔口、装备抽屉、游戏内配装、方案对比。前三个在矩阵里占 1–2 个格子，方案对比是支线，只在最后一格出现。

## 文件

| 文件 | 用途 |
|---|---|
| `loadout-flow.html` | 定稿的 29 屏，单文件自包含，直接打开 |
| `build-loadout-flow.mjs` | 生成上面那份 HTML，屏幕注册表（`SCREENS` / `PATHS` / `SPINE`）在这里 |
| `kit.mjs` | 两个原型共用的零件：示例数据、照产品 DOM 写的片段、护甲规划面板 |
| `kit.css` | 原型的候选样式，前缀 `lf-` / `t58f-` |
| `shoot-loadout-flow.mjs` | 逐屏截图，顺带跑一批结构守卫 |
| `lf-sizes.json` | 上一轮出图的每屏尺寸和状态，出图脚本会重写它 |

搬进来时只改了 `build-loadout-flow.mjs` 和 `kit.mjs` 里指向仓库根的那一行：新位置离根四层，原来三层。改动仅限取 `packages/ui/src/styles.css` 的路径。

## 重新生成

```bash
node build-loadout-flow.mjs      # 重出 loadout-flow.html
node shoot-loadout-flow.mjs      # 重出 29 张 lf-*.png + lf-all.png
```

`build` 会把 `packages/ui/src/styles.css` 整份内联进 HTML，所以重出的效果取决于当时那份 CSS，不会等于 2026-09-20 那一版。留档的是现在这份 HTML；重出会覆盖它，动手前先想清楚。

`shoot` 需要 playwright，跑之前会先删掉同目录所有 `lf-*.png`。图不进仓库（`.gitignore` 已挡），要留就地留着，`lf-all.png` 一张 8 MB。

截图还在 `.local-data/tmp/loadout-flow/`（30 MB）；那边是临时目录，丢了用上面两条命令重出。
