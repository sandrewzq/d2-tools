# T63：DIM 文本的来源入口收成两条路——本地文件 + 用户给的链接

> 状态：🟢 代码已改并自验通过，待用户复验（2026-09-17）
> 缘起（用户原话）：「你就做错了！！！不应该从 github 读取！！！这条路删了。粘贴文本也删了。
> 应该是两条路：1. 本地文件上传 2. 在线文档同步，给你一个愿望单文本链接，类似这种
> `https://raw.githubusercontent.com/mcljw97/DIMLGpigWeaponWishlist/refs/heads/main/DIMLGpigWeaponWishlist%20by%20moc.txt`」

## 用户拍板的两件事

| 问题 | 选择 |
|---|---|
| 链接要不要跟着来源保存、以后能一键再同步 | **记住链接**：来源行上带「同步」，点一下重新拉取，内容有变再确认覆盖 |
| 贴链接的输入框放哪 | **弹框里输入**（与「导入表格文件」一致：先读取预览，再命名与确认） |

## 终态：DIM 文本这一组只有两条路

| 路径 | 说明 |
|---|---|
| 本地文件上传 | 选 `.txt` / `.wishlist` 文件（现状不变） |
| 在线文档同步 | 用户在弹框里贴一个愿望单文本链接；下载后走**与本地文件完全相同的一条流水线**：语法解析 → 定义池校验 → 预览（可导入条数 / 跳过行数 / 问题示例）→ 命名与确认（新建 / 覆盖）。链接随来源保存，来源管理里可再次同步 |

**删掉的两条**：
1. **固定地址在线导入**——从写死的 GitHub 仓库拉 `voltron.txt`（含 GitHub commits API、commit SHA、ETag 元数据那一整套）。这条路径前一周被用户判定为设计错误：来源不该由程序替用户选好，更不该写死上游地址。
2. **粘贴文本**——行内展开的文本框 + 解析预览通道（含它专用的服务端保存入口）。

顺带闭合的两个旧残留：在线路径过去**不走导入期校验**（同一份内容走在线和走本地，问题行处理结果可能不同），现在两条路共用同一条校验流水线；在线路径过去会**卡在「读取中」最长三分半且无法取消**（两段请求各自 30 秒 / 180 秒 + 界面兜底 210 秒），新的链接读取给单一超时并且失败即报错、当前数据不动。

## 存储与身份

- 链接落在既有的文档级字段上：`source_url` + `origin='url'` + `fingerprint`（+ 上游给的 `ETag` / `Last-Modified` 有就存进 `revision`）。**不需要改 schema**。
- 「有没有新内容」的判据是**内容指纹**：重新下载后与库里这份来源的指纹比对，相同即「已是最新」，不同才进入覆盖确认。不再依赖任何 GitHub 专有元数据。
- 谁可以同步：`origin='url'` 且带链接的来源行。本地文件来源没有链接，因此没有「同步」按钮。
- 覆盖仍按**名字**走既有通道（用户命名、显式选择新建或覆盖，不静默写入）；同步时名字预填为该来源名，于是只剩「覆盖」可点。
- 命名默认值沿用同一条规则：链接取 URL 里最后一段文件名、去掉扩展名（含百分号转义要先还原）——它就是「文件名去扩展名」，不因为名字来自链接而另立规则。

## 读取链接的边界（全部写进实现与用例）

| 项 | 规则 |
|---|---|
| 协议 | 只允许 `http` / `https`；其余（`file:`、`javascript:`、`data:` 等）直接拒绝 |
| 大小 | 与本地文件同口径，超过 128 MB 不读 |
| 超时 | 单一超时（60 秒），到点即报错，当前数据不动 |
| 重定向 | 跟随，但落地后仍必须是 `http` / `https` |
| 凭据 | 不带 cookie、不带任何本机凭据；只发一个可识别的 UA |
| 失败 | 一律保持现有数据不变，错误文案给出「换本地文件导入」的退路 |

## 分层

下载、解析、校验都在 Desktop 主进程（与本地文件同一条落库链路），Renderer 只负责输入链接、展示预览与确认。**下载不是格式知识**：链接进来的是愿望单文本，格式差异仍然只存在于解析适配层（DIM 适配器）。

## 验收判据

1. DIM 文本这一组只有「从链接同步」与「导入文本文件」两个入口，没有粘贴文本；全仓没有任何写死的上游地址。
2. 贴用户的示例链接能读取、预览、起名、写入；写入后来源行带「同步」。
3. 对同一链接再点「同步」：内容没变时明确告知「已是最新」，库不动；内容变了才进入覆盖确认。
4. 链接导入与本地文件导入在同一个文件上的**校验结果一致**（同样的可导入条数、跳过行数与问题示例）。
5. 非法链接（非 http(s)）当场拒绝；下载失败或超时保持现有数据不变。
6. 五个闸门全绿。

**逐条自验**：1、4、5、6 已由测试与守卫覆盖并复跑通过（证据见〈实施记录〉）；2、3 与用户给的示例链接有关——读链接、预览、起名、写入、再同步这条链在测试里是用桩网络逐段钉住的（真实链接不查 DNS、不碰网络），**示例链接本身请你在应用里点一次确认**。

改坏清单（原则：一处只改一行、只改一个条件）：

- **下载边界（10）**：协议白名单改 `return true`；私网判定改 `if (false)`；跳转后的复校验收成只校验第一跳；缺 Location 不报错；跳转次数上限不判；声明体积上限不判；流式体积上限不判；内容类型白名单不判；请求头里塞一个 `Cookie`；`redirect: "manual"` 改成 `"follow"`。
- **链接来源（10）**：网页源码不拒收；空文本不拒收；失败时不拖「换本地文件」这句退路；非法链接也拖退路话术；指纹恒为空串；把「用户填的链接」存成跳转后的地址；版本号优先级写反；文件名不来自链接；不还原百分号转义；目录链接拿目录名当文件名。
- **同步判定（4）**：按链接匹配改成取第一行；链接比较不归一化（大小写 / 转义 / 末尾斜杠对不上）；导入时不写指纹；覆盖时不先删旧文档。
- **界面（8）**：所有来源行都显示「同步」；没变化也弹预览；同步确认后不重读来源列表；同步不预填来源名；读取失败也关弹框；没变化不说「已是最新」；预览卡显示用户填的链接而不是最终地址；默认名不剥扩展名。
- **守卫（7）**：入口多一条（把 `data-dim-link` 改名）；文案退回三条路；设置页重新列出固定地址；下载层引用解析器（下载开始认识格式）；确认时不重跑共用校验；界面自己发 `fetch`；仓库里塞回一个固定上游地址。

### 如实记录

1. **一处没有单点变异可杀**：`dimWishlistSourceSync.test.ts` 的「本地文件来源没有链接，因此查不到」。文件来源本就不带 `source_url`，把按来源地址查询里的 `origin = 'url'` 过滤去掉，结果不变——这条留着当设计说明，不假装它有护栏。用户可见的那一半（**只有带链接的来源行才显示「同步」**）由界面用例按「所有行都显示同步」的变异钉住。
2. **顺带修掉一处测试盲区**：`etag 优先于 last-modified` 第一次跑时漏网——原用例只测「上游没给 ETag」，两个字段的优先级写反看不出来。已把用例扩成「两个都在时以 ETag 为准，缺 ETag 才落到 Last-Modified」，该变异随即被杀死。
3. **不需要改 schema**，与计划一致：链接落在既有的 `source_url` / `origin='url'` / `fingerprint` / `revision` 上。
