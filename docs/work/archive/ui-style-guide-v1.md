# d2-tools UI 样式规范 v1

> 2026-06-25 · 用于指导后续 UI / UX 重构。本文档只定义样式系统、页面结构和组件规范，不讨论暗色模式切换。

## 1. 设计目标

d2-tools 的 UI 目标不是“换个更好看的暗色主题”，而是建立一套：

- 专业桌面工具感
- 高信息密度但可扫描
- 层级明确
- 少装饰
- 长期使用不累
- 同一套系统感强

### 最终气质

- **DIM**：任务模型、对象组织、筛选和比较
- **JetBrains / DataGrip**：设置页秩序感、桌面工具稳定性
- **Linear**：克制、干净、现代
- **Ant Design**：控件语法一致性

---

## 2. 设计原则

### 2.1 主任务优先

每个页面必须能明确回答：

> 用户打开后第一眼要做什么？

因此页面必须有：
- 主区
- 辅助区
- 低频区

不能把所有块放成同等权重。

### 2.2 少层级、强区分

只保留三层容器语义：
- **页面底层**
- **主面板层**
- **子块 / 列表项层**

不要让一屏出现多个都像主卡片的大块。

### 2.3 轻边框、强排版

优先靠：
- 间距
- 字号
- 对齐
- 背景层级

来区分结构，少靠粗边框。

### 2.4 控件统一

输入框、select、按钮、badge、状态块必须统一，不允许每个页面自己长一套。

### 2.5 任务模型优先于炫技

d2-tools 本质是：
- 账号数据工具
- 仓库整理工具
- 配装分析工具
- AI 分析工具

视觉表达必须服务于“看、选、比、改”。

---

## 3. 全局视觉 token

### 3.1 间距体系

统一使用固定 spacing：
- `8px`
- `12px`
- `16px`
- `24px`
- `32px`

#### 用法
- **8**：图标与文字、badge 内边距、小间隔
- **12**：子块内部、列表项行内间距
- **16**：常规控件 padding、标准卡片 padding
- **24**：区块之间
- **32**：页面主区之间

#### 规则
- 不允许大量随机 spacing
- 同类组件必须使用同一档 spacing
- 页面内部优先节奏一致，不靠“看感觉”

### 3.2 圆角体系

统一三档：
- `8px`：输入框、按钮、列表项
- `12px`：主卡片、抽屉、设置面板
- `999px`：badge / pill / status chip

### 3.3 背景层级

只保留 3 层：
- **页面底层**：最深背景
- **主面板层**：略亮一档
- **交互层 / hover / selected**：再亮一档

### 3.4 边框体系

统一策略：
- 主面板：可有细边框
- 子块：尽量少边框
- 列表项：优先 hover / selected 背景，不靠边框
- 状态块：才使用更明确边框和强调色

### 3.5 字号体系

统一四档：
- **T1 页面标题**
- **T2 区块标题**
- **T3 正文**
- **T4 辅助说明**

### 3.6 按钮体系

统一三档：
- **主按钮**
- **次按钮**
- **幽灵 / 行内按钮**

### 3.7 状态语言

统一五种状态：
- neutral
- pending
- ready
- warning
- error

所有状态统一：
- badge
- 背景差
- 边框强度
- 文案语气

---

## 4. 页面结构规范

### 4.1 通用布局

所有页面都应遵循：
- 标题区
- 主工作区
- 辅助区 / 低频区

#### 禁止
- 多个同权重大面板横排堆满
- 全屏都像同一类卡片
- 没有主次

### 4.2 面板层级

页面内只使用三种容器级别：
- **L0：页面底层**
- **L1：主面板**
- **L2：子块 / 列表项**

---

## 5. 组件规范

### 5.1 卡片

卡片只用于“真正需要承载对象信息”的地方。

#### 适用
- 仓库装备
- 目标命中对象
- 同名对比对象
- 首页关键摘要

#### 不适用
- 普通设置项
- 普通列表项
- 说明文字块

### 5.2 列表

列表用于高频扫描项。

#### 适用
- 会话历史
- 设置分类项
- 资料库搜索结果
- 任务树节点
- 状态 / 日志条目

### 5.3 表单控件

统一以下控件语法：
- input
- select
- textarea
- checkbox
- switch

### 5.4 Badge / 状态块

所有状态提示都复用同一套 badge / status card 风格，不再各自发明 notice / hint / warning box。

---

## 6. 页面级规范

### 6.1 首页

首页是**日常工作台**。

#### 结构
- 首屏只留最重要的 2~3 块
- 今日必看、奖励进度、来源状态优先
- 次级信息下沉
- 不出现多个同权重大卡片

### 6.2 账号页

账号页是**当前角色操作台**。

#### 结构
- 当前角色是主对象
- 当前角色装备、背包并列主区
- 材料 / 货币 / 邮政官下沉为低频区
- 游戏内配装栏不在账号页展示，归到配装菜单

### 6.3 仓库页

仓库页是**高密度整理工作台**。

#### 结构
- 顶部工具栏
- 中部结果区
- 详情 / 批量操作按工作流展开

### 6.4 设置页

设置页是**桌面工具设置中心**。

#### 结构
- 左侧分类导航
- 右侧单主题主区

### 6.5 AI 助手

AI 助手是**分析工作台**，不是普通聊天工具。

#### 结构
- 顶部工具栏
- 主消息区
- 底部输入区
- 历史 / 上下文抽屉

### 6.6 装备详情

装备详情要保留游戏语义，但视觉上更像成熟桌面工具。

#### 结构
- 顶部：游戏内语义信息
- 底部：工具区

## 7. 推荐参考映射

| 页面 / 模块 | 最佳参考 |
|---|---|
| 设置页 | JetBrains / DataGrip |
| 首页工作台 | DIM / DBX / Linear |
| 账号页 / 仓库页 | DIM + DBX / WhoDB |
| AI 助手 | Chat2DB + Tabby + Linear |
| 全局侧边栏 / 会话列表 | Tabby + Linear |
| 装备详情 | 保留游戏语义，借鉴桌面工具排版 |
| 控件规范 | Ant Design |

---

## 8. 不做什么

- 不先换框架
- 不先做亮暗模式切换
- 不先做大主题重构
- 不先全量重写所有页面
- 不为了“高级感”增加装饰
- 不把每个页面都做成卡片墙

---

## 9. 成功标准

做完后，d2-tools 应该满足：
- 首页、账号、仓库、设置、AI 看起来是一套系统
- 主区 / 辅助区 / 子块层级清楚
- 表单控件统一
- 列表和卡片各司其职
- 状态语言统一
- 不再像开发中的页面
- 更像成熟桌面工具

---

## 10. 给 agent 的执行口径

如果交给 agent 开发，执行原则只有一句：

> 按 d2-tools UI 样式规范执行：任务模型靠 DIM，视觉秩序靠 JetBrains / Linear，控件语法参考 Ant Design。先统一全局样式 token，再改页面，不要逐页零散修补，不要只改颜色，不要增加装饰感。
