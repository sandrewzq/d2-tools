# 装备详情游戏内风格 UI 设计

## 背景

当前装备详情弹窗已经能展示护甲六维、武器属性、perk、社区推荐、同名对比、备注和写操作，但整体更像信息块顺序堆叠。用户希望装备详情 UI 更接近 DIM 和游戏内装备详情：打开后第一眼看到装备本体、光等、六维属性、总计和能量；工具能力继续保留，但不要压住核心装备信息。

本设计只覆盖共享装备详情弹窗的展示结构，不改 Bungie 数据解析、不做旧六维兼容、不重做社区推荐数据源。

## 目标

- 顶部核心区域按游戏内装备详情组织：标题条、装备图标、名称、类型、光等、六维属性、总计、能量。
- 护甲属性只使用 Armor 3.0 新六维：生命值、近战、手雷、超能、职业、武器。
- 下方采用 C 方案工具区，承载同名对比、社区推荐、AI、备注和写操作。
- 打开装备详情后，用户第一眼能确认这件装备是什么、强度多少、属性分布如何。
- 桌面端保持工具效率，不为了像游戏而丢掉 DIM 式对比和操作能力。

## 非目标

- 不做旧六维到新六维的映射或兼容展示。
- 不新增社区推荐来源，不在本任务内解决社区推荐重做。
- 不改写仓库筛选逻辑，不新增护甲优化器。
- 不引入拖拽移动、批量移动等完整 DIM 级装备管理能力。

## 设计

### 顶部游戏内详情区

装备详情弹窗顶部改为一张紧凑的游戏内风格卡片：

- 紫色标题条展示装备图标、装备名称、职业 / 部位 / 稀有度、光等。
- 护甲展示六维属性行，每行包含属性名、数值、横向进度条和右侧小标记。
- 属性顺序固定为生命值、近战、手雷、超能、职业、武器。
- 六维下面展示总计行和能量行。
- 武器详情沿用同一视觉语言，但属性列表使用武器属性：伤害、射程、稳定性、操控性、装填速度、弹匣、RPM 等当前已有字段。

### 下方工具区

红框核心详情区域下方进入工具区，不再继续堆大块普通卡片。工具区可以使用紧凑 tabs 或明确分组：

- 概览：来源、锁定、位置、详情加载状态。
- 同名对比：展示同名装备，护甲优先显示总值和新六维摘要，武器优先显示 perk / 推荐命中。
- 社区推荐：保留当前推荐展示入口和降级提示位置，具体数据源重做留给后续需求。
- 操作：备注、AI 分析、锁定 / 解锁、转移等写操作。

默认首屏应优先展示顶部核心详情和工具区入口。低频内容可以在工具区内折叠或放到后续分组，避免重新形成长信息流。

## 组件边界

主要改动范围控制在共享装备详情组件：

- `packages/desktop/src/renderer/shared/components/ItemDetailModal.tsx`
- `packages/desktop/src/renderer/shared/components/item-detail/`
- `packages/desktop/src/renderer/styles.css`
- 相关桌面端测试

不主动修改 `HomePage.tsx`、`VaultPanel.tsx`、`api/client.ts`、`ipc.ts` 等公共接线文件。

## 状态与异常

- 详情加载中时，顶部先显示基础装备信息；属性、perk、推荐等区块按当前数据可用性继续补齐。
- 没有护甲属性或武器属性时，不展示空的属性条，保留明确的加载或空状态提示。
- 社区推荐失败或降级提示继续使用现有来源状态视觉语言；本任务只调整它在详情弹窗里的承载位置。

## 验收

- 打开护甲详情，首屏顶部像游戏内装备详情：紫色标题条、六维属性、总计、能量顺序清晰。
- 护甲属性只出现生命值、近战、手雷、超能、职业、武器，不出现旧六维。
- 下方能找到同名对比、社区推荐、AI、备注和写操作，工具能力没有丢失。
- 武器详情在同一套视觉框架下能展示当前已有武器属性。
- 1366px 和 1920px 桌面尺寸下，标题、数值、按钮和分组不重叠、不溢出。
- 现有装备详情相关测试更新并通过。
