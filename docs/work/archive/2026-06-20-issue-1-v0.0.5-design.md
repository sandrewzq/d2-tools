# d2-tools 0.0.5 设计说明：Issue #1 整套方案

更新时间：2026-06-20

关联 Issue：
- [Issue #1: 筛查装备框架&一键挪动&调阅套装](https://github.com/sandrewzq/d2-tools/issues/1)

## 1. 背景

`d2-tools` 当前已经具备：

- Bungie OAuth 登录
- 账号、角色、仓库、资料库读取
- 基础筛选与搜索
- 部分写操作能力
- 本地配装模板雏形

但这几块能力仍然是分散的：

- “资料库筛选”缺少武器框架这一玩家高频维度
- “批量操作”主要附着在清理模式和个别快捷流程里，缺少统一入口
- “本地方案”已有存储能力，但还没有形成成熟的调阅、对比和高亮体验

Issue #1 本质上不是三个孤立功能，而是一条完整主流程：

`筛选武器 -> 选中一批 -> 批量挪动 -> 保存为本地方案 -> 后续调阅与对比`

`0.0.5` 的目标，是把这条主流程做成第一版可稳定使用的闭环。

## 2. 版本目标

`0.0.5` 的产品目标：

1. 支持按武器框架稳定筛选武器
2. 支持对筛选结果或手动选中结果进行统一批量挪动
3. 支持把当前装备保存为本地方案，并能后续调阅
4. 支持在视图中高亮某个本地方案涉及的装备
5. 支持轻量级方案对比

`0.0.5` 不追求完整复刻 DIM，也不把“本地方案”与“游戏内 Bungie 配装栏”混成一个概念。

## 3. 明确边界

### 3.1 本版本要做

- 武器框架数据归一
- 仓库页与资料库页的框架筛选
- 通用多选模型
- 统一批量挪动入口
- 本地方案保存、调阅、重命名、删除
- 本地方案高亮
- 轻量方案对比

### 3.2 本版本明确不做

- 自动换装优化器
- DIM 式拖拽换位
- 方案分享
- 云同步
- 真正的 Bungie 写操作撤销
- “仓库末位”这类 Bungie API 不支持的伪位置语义

### 3.3 产品约束

本地方案库是“查看与管理”的概念，不是“自动装备”的概念。

当前项目中已经存在：

- 最高光等自动装备
- Bungie 游戏内 loadout equip / snapshot

这些能力保留，但必须在 UI 和文案上与“本地方案库”明确分区，避免玩家误以为本地方案可以直接应用到游戏角色。

## 4. 用户主流程

### 4.1 仓库整理流程

1. 玩家进入仓库页
2. 通过武器类型、框架、弹药、标签等条件筛出目标装备
3. 通过全选、组选择或手动勾选形成“已选物品集合”
4. 选择目标位置并执行批量挪动
5. 查看成功 / 失败 / 跳过统计

### 4.2 方案保存流程

1. 玩家进入角色页或仓库页
2. 以当前角色已装备物品为基础保存本地方案
3. 输入方案名
4. 方案写入本地数据目录
5. 后续可在方案区重新调阅

### 4.3 方案调阅流程

1. 玩家选择某个本地方案
2. 查看方案中的武器、护甲、perk、框架、评分和位置
3. 当前视图中命中的装备被高亮
4. 可切换第二个方案做并排对比

## 5. 设计方案

采用“先补数据层，再串 UI 和业务流”的方案。

原因：

- 仅补 UI 会很快遇到数据不准、筛选不稳、批量选择逻辑不统一的问题
- 仅补单个功能会导致仓库页、资料库页、角色页继续各自为战
- 先统一数据和业务模型，后面加新功能也更稳

## 6. 模块设计

### 6.1 武器框架模型

新增统一的 `weapon_frame` 语义字段。

建议字段：

```ts
type WeaponFrameSummary = {
  key: string;
  name: string;
  category?: "adaptive" | "high-impact" | "rapid-fire" | "precision" | "lightweight" | "aggressive" | "other";
};
```

设计要求：

- 对外展示使用 `name`
- 内部筛选使用稳定 `key`
- 允许未知框架归入 `other`
- 仅对武器生效，非武器为空

来源策略：

- 从现有 item definition / sockets / intrinsic 相关定义中提取
- 若无法稳定解析，不展示虚假框架
- 坚持“数据不确定就不展示”

### 6.2 通用批量选择模型

新增统一的前端选择状态，不再把批量操作绑定在某个单独视图上。

建议字段：

```ts
type BulkSelectionState = {
  selected_item_keys: string[];
  source_view: "vault" | "account" | "library";
  selection_mode: "manual" | "filtered" | "duplicate-group" | "tagged";
};
```

能力要求：

- 支持手动勾选
- 支持当前筛选结果全选
- 支持同名对比组整组选中
- 支持标签结果批量选中
- 切换筛选条件后，仍能清楚展示当前已选数量

### 6.3 批量挪动模型

批量挪动统一收敛到一个“计划 -> 执行 -> 结果”流程。

建议目标：

- 仓库
- 当前角色
- 指定角色

建议执行结果：

```ts
type BulkTransferExecutionResult = {
  total: number;
  success_count: number;
  failed_count: number;
  skipped_count: number;
  failures: Array<{
    item_key: string;
    item_name: string;
    reason: string;
  }>;
};
```

说明：

- “垃圾集中（移至仓库末位）”不做伪位置能力
- 实际落地为“批量移至仓库 + 本地 junk 标签”

### 6.4 本地方案模型

当前已存在本地配装模板文件，需要扩展但不推翻。

现有文件：
- [templates.ts](D:/sandrew/d2-service/packages/core/src/loadouts/templates.ts)

建议补充字段：

```ts
type LoadoutTemplateItem = {
  hash: number;
  instance_id?: string;
  name: string;
  bucket_name?: string;
  weapon_frame_name?: string;
  perk_names?: string[];
  score?: number;
};

type LoadoutTemplate = {
  id: string;
  name: string;
  character_id: string;
  class_name: string;
  created_at: string;
  updated_at?: string;
  items: LoadoutTemplateItem[];
};
```

版本原则：

- 保持本地 JSON 存储
- 保证老模板可迁移
- 打开旧数据时做向后兼容补全

## 7. 页面与交互设计

### 7.1 仓库页

新增：

- 框架筛选区域
- 多选勾选框
- 已选数量条
- 批量挪动操作条
- 方案高亮状态

交互规则：

- 框架多选是 `OR`
- 框架与其他筛选条件叠加是 `AND`
- 当前筛选结果支持一键全选
- 批量执行时按钮进入 loading 态，并显示进度文案

### 7.2 资料库页

新增：

- 武器框架筛选维度

要求：

- 仅在武器结果上出现
- 与现有 group / tier / bucket / ammo 筛选共存
- 不让用户输入英文框架名作为主要使用方式

### 7.3 账号页 / 方案区

将“本地配装模板”升级为“本地方案库”。

新增：

- 方案列表
- 当前调阅方案详情
- 重命名
- 删除
- 第二方案选择器
- 并排对比视图

保留但分区：

- 游戏内 Bungie 配装栏
- 最高光等写操作

文案上明确：

- 本地方案库：仅保存和查看
- 游戏内配装栏：直接调用 Bungie 写操作

## 8. 错误处理与风险

### 8.1 框架解析失败

处理原则：

- 不展示错误框架名
- 归入未识别 / other
- 不因为框架解析失败影响整个物品展示

### 8.2 批量转移失败

处理原则：

- 允许部分成功
- 明确展示成功数、失败数、失败原因
- 刷新账号数据和操作日志
- 不因为单件失败导致整个结果不可读

### 8.3 角色背包空间不足

处理原则：

- 提前给出提示
- 执行后如发生失败，要按失败项回报
- 不伪造“已成功”

### 8.4 旧模板兼容

处理原则：

- 启动或读取时做数据兼容
- 缺失字段使用默认值补全
- 旧数据迁移后继续只使用新目录

## 9. 测试策略

### 9.1 核心层测试

- 框架解析测试
- 框架筛选测试
- 批量选择模型测试
- 批量挪动计划与结果整理测试
- 本地方案读写与迁移测试
- 方案对比整理测试

### 9.2 桌面层测试

- IPC wiring 测试
- 方案重命名 / 删除 / 调阅测试
- 批量挪动反馈测试
- 高亮状态渲染测试

### 9.3 手工验收

至少覆盖：

1. 按高冲击力框架筛脉冲步枪
2. 多选两个框架筛同类武器
3. 当前筛选结果全选并批量移至指定角色
4. 部分失败时看到结果统计
5. 保存当前角色为本地方案
6. 重启应用后仍能看到方案
7. 调阅方案时当前物品视图高亮命中装备
8. 选择两个方案做差异对比

## 10. `0.0.5` 范围分级

### P0

- 武器框架数据归一
- 仓库页框架筛选
- 资料库页框架筛选
- 通用多选
- 批量挪动到仓库 / 当前角色 / 指定角色
- 本地方案保存 / 调阅 / 重命名 / 删除
- 方案高亮

### P1

- 标签数量联动优化
- 批量挪动进度细化
- 更清晰的失败项列表
- 轻量方案对比

### P2

- 更高级的方案对比视图
- 更多筛选快捷入口
- 更强的方案与清理模式联动

## 11. 推荐开发顺序

1. 武器框架数据层
2. 框架筛选器与测试
3. 通用多选模型
4. 批量挪动中心
5. 本地方案库模型升级
6. 方案高亮
7. 方案对比基础版

## 12. 验收定义

若 `0.0.5` 完成，应满足：

1. 玩家能按武器框架筛选仓库和资料库中的武器
2. 玩家能把筛选结果或手动选中的装备统一批量挪动
3. 玩家能保存、重命名、删除本地方案
4. 玩家能重新打开软件继续看到本地方案
5. 玩家能调阅方案并在视图里看到命中装备高亮
6. 玩家能做基础方案对比
7. 整个体验不会让玩家误以为“本地方案库”可以直接自动换装

## 13. 本设计的结论

Issue #1 在 `0.0.5` 中应作为一个整套功能包落地，而不是拆成零散按钮。

最重要的不是“多几个入口”，而是把以下三层打通：

- 可被玩家理解的筛选维度
- 可被稳定执行的批量操作流
- 可被长期复用的本地方案库

完成后，`d2-tools` 会第一次具备接近 DIM 高频整理体验的核心闭环，但仍保持本地中文 GUI 工具的定位。
