# 全局视觉升级 v2 设计

> 2026-06-27 · 目标方向：C1 · 克制增强。本文档用于接续 `ui-style-guide-v1.md`，把“样式系统基础完成”推进到“用户第一眼能感知的全局视觉升级”。

## 背景

`ui-style-guide-v1.md` 已经完成 token、状态语言和部分共享 class 的基础建设，但实际界面变化仍偏弱。当前问题不是缺少 CSS 变量，而是全局视觉骨架还没有形成足够明确的桌面工具气质：页面底色、导航、主面板、工具栏、卡片、状态块、按钮和输入控件之间的层级差不够明显，打开应用后的第一眼仍接近旧版。

本轮目标不是重做业务流程，也不是把页面做成装饰性皮肤，而是在保持高信息密度和工具效率的前提下，让应用整体明显更成熟、更统一、更有质感。

## 视觉方向

采用 **C1 · 克制增强**：

- 比当前版本更深、更稳的页面底色。
- 主面板、侧栏、工具栏和卡片有明确层级。
- 主操作更醒目，但不使用大面积高亮或强发光。
- 选中态、hover、状态提示有可感知反馈。
- 保持桌面工具感，不走游戏皮肤化、不做亮色营销风。

参考气质：

- JetBrains / DataGrip：整体稳定、边界清楚、适合长时间使用。
- Linear：轻量、现代、排版克制。
- DIM：对象组织、筛选、比较和高密度信息呈现。

## 覆盖范围

本轮覆盖全局视觉骨架和主要页面入口：

- Shell：应用底色、左侧导航、页面内容区、右侧 AI 侧栏。
- 全局控件：按钮、输入框、select、textarea、checkbox、badge、状态块。
- 容器层级：页面底层、主面板、工具栏、子块、列表项、对象卡片。
- 主要页面：首页、账号页、仓库页、设置页、AI 助手。
- 重点对象：仓库装备卡片、资料库结果卡片、设置诊断行、AI 对话区、首页状态卡片。

装备详情顶部的游戏内语义视觉可以保留，但底部工具区要继续贴合全局桌面工具视觉。

## 视觉规则

### 颜色层级

颜色只承担层级和状态，不做装饰堆叠：

- 页面底层：更深，降低视觉噪音。
- 主面板层：比页面底层亮一档，用于页面主工作区。
- 交互层：用于工具栏、hover、选中和可点击对象。
- 强调色：冷蓝为主，只用于主操作、选中态、焦点态和关键状态。
- 警告、错误、成功状态继续使用统一 status 语义，不新增页面私有色系。

### 面板和边框

- 主面板允许细边框和轻阴影，用来形成桌面软件的稳定结构。
- 子块和列表项优先用背景差、间距和排版区分，不堆多层粗边框。
- 不再出现一屏多个同权重大卡片。
- 工具栏要像操作区，不像普通说明卡片。

### 字体和排版

- 页面标题、区块标题、正文、辅助说明四档必须清楚。
- 页面标题区要更稳定：标题、说明、关键操作位置固定。
- 卡片内部避免大段说明文字抢占对象信息。
- 按钮和标签文字必须在窄屏下不挤压、不竖排、不溢出。

### 控件

- 主按钮：冷蓝高对比，用于主要动作。
- 次按钮：暗色交互层，用于常规操作。
- 行内按钮：更轻，只用于对象行内操作。
- 输入框和 select 要和按钮同一套高度、圆角、边框和焦点态。
- badge 和 status-message 继续作为状态语言的唯一入口。

### 页面结构

- 首页：首屏强调今日必看、奖励进度、来源状态，不做卡片墙。
- 账号页：当前角色操作台视觉更聚焦，低频材料 / 邮政官下沉。
- 仓库页：顶部工具栏、结果区、整理 / 批量区视觉区分明显。
- 设置页：保持左侧分类导航 + 右侧单主题主区，强化桌面设置中心感。
- AI 助手：顶部工具栏、消息区、输入区、抽屉层级更清楚，避免像普通聊天小挂件。

## 不做项

- 不换前端框架。
- 不做亮暗模式切换。
- 不全量重写页面业务逻辑。
- 不引入大面积渐变、装饰光斑或营销式 hero。
- 不把 Destiny 视觉元素扩大成游戏皮肤。
- 不借视觉升级顺手重构跨端业务逻辑。

## 验收标准

完成后应满足：

- 打开应用第一眼能明显看出视觉升级，不只是状态块或按钮细节变化。
- 首页、账号、仓库、设置、AI 看起来属于同一套系统。
- 左侧导航、主工作区、右侧 AI 侧栏层级清楚。
- 主面板、工具栏、对象卡片、列表项、状态块各司其职。
- 主操作、选中态、hover、焦点态可感知但不过度发光。
- 1366px、1920px、窄屏下无明显文字挤压、重叠、竖排或按钮溢出。
- `ui-style-system.test.ts` 继续阻止回到旧式零散样式。

## 实施建议

建议采用“全局骨架优先，主要页面同步覆盖”的方式推进：

1. 先改全局 token 和 Shell 视觉骨架，让页面底色、导航、主区和 AI 侧栏形成 C1 方向。
2. 再改通用控件和共享组件：按钮、输入框、status-message、badge、tool-panel、toolbar、list-row、item-card。
3. 最后覆盖首页、账号、仓库、设置、AI 的主要容器和高频对象，保证第一眼能看到变化。

不建议只换颜色，也不建议直接全页面重排。前者变化仍不明显，后者容易和业务 UX 重构混在一起。
