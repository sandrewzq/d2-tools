# 账号页布局重构设计

> 日期：2026-06-22
> 状态：已确认骨架，待进入实现计划

## 1. 背景

当前账号页的问题不在于内容不够，而在于内容组织方式仍偏长信息流：

- 当前角色装备、DIM 工具、方案库、材料、货币、邮政官、活动等重块前后串联，导致滚动链路过长。
- 之前单纯放宽内容区，并没有解决“主操作区不聚焦”的根因。
- 用户明确希望账号页保留角色装备、背包、材料、货币、邮政官，因为这些都是副本中和日常使用中的高频信息。
- 同时，仓库页未来应走更接近 DIM 的全局 Inventory 工作台路线，承担跨角色整理、配装、筛选、对比和搬运。

因此，这次账号页重构的目标不是删信息，而是把信息重新分层，让账号页更像“单角色即时操作台”。

## 2. 已确认的产品边界

### 2.1 账号页职责

账号页用于处理“当前角色正在做什么、马上要换什么、手头还有什么”的即时问题，保留这些内容：

- 当前角色装备
- 当前角色背包
- 材料
- 货币
- 邮政官
- 少量当前角色直接相关的快捷动作，例如保存当前装备、套用方案、转移缺失件、装备最高光等

### 2.2 仓库页职责

仓库页不是本次重构对象，但边界需要提前固定：

- 未来仓库页承担更接近 DIM 的全局 Inventory 工作台职责
- 重点处理跨角色整理、全局搜索筛选、配装、对比、搬运和全局仓库操作
- 不把这类全局整理能力继续堆回账号页

## 3. 设计目标

本次账号页重构要同时满足以下目标：

1. 缩短主滚动链路，避免重新回到长页面信息流。
2. 让“当前装备 + 当前角色背包”成为首屏连续主视区。
3. 让页面阅读顺序更贴近游戏内角色页习惯：先看当前穿戴，再看随身可切换物品。
4. 材料、货币、邮政官保留，但整体下沉到低频区，不占主视线。
5. 保持当前业务能力，不做大范围功能删除或重写。

## 4. 选定方案

采用“上方一体化主区 + 下方低频区”的账号页骨架。

### 4.1 上方主区

上方主区承载当前角色的即时操作信息，分为三层：

1. 角色概览层
   - 角色切换
   - 当前角色摘要
   - 当前状态胶囊
   - 当前角色相关快捷动作

2. 当前装备区
   - 固定展示当前已装备武器和护甲
   - 保持稳定、可快速扫读的视区
   - 点击后进入现有装备详情弹窗链路

3. 当前角色背包区
   - 与当前装备区并列或紧邻展示，形成连续阅读体验
   - 只展示当前角色背包，不混入仓库全局整理语义
   - 支持按武器 / 护甲 / 消耗品 / 任务道具等快速切换或筛选

### 4.2 下方低频区

下方低频区整体承接副本中“偶尔看一眼”的信息：

- 材料
- 货币
- 邮政官

要求：

- 保留提醒能力，尤其是邮政官容量和高价值掉落提示
- 但视觉权重低于上方主区
- 不再固定占据右侧主视线

## 5. 页面结构

建议将账号页收敛为以下结构：

1. 页面标题区
   - 标题
   - 简短说明
   - 读取账号数据等主按钮

2. 角色切换区
   - 角色卡或 tab
   - 显示职业、光等、已装备 / 背包 / 邮政官数量

3. 当前角色概览区
   - emblem
   - 当前角色名称
   - 当前方案命中、写操作状态、副本状态等胶囊
   - 保存当前装备、套用方案、转移缺失件、装备最高光等等快捷动作

4. 主工作区
   - 左侧：当前装备
   - 右侧：当前角色背包

5. 低频信息区
   - 材料
   - 货币
   - 邮政官

## 6. 对现有实现的映射

本次设计应尽量复用现有账号页数据和交互，不重新发明接口。

### 6.1 可直接沿用的现有数据

- `accountSummary`
- `selectedCharacter`
- 当前角色装备与背包聚合结果
- 材料与消耗品统计
- 邮政官数据
- 当前方案命中与缺失件分析
- 现有装备详情打开逻辑

### 6.2 需要调整的现有区块

- `renderAccountPanel()`
  - 从“连续纵向堆叠”改成“概览 + 主工作区 + 低频区”

- `renderDimToolsPanel(selectedCharacter)`
  - 不再作为一个独立的大区块插在主流程中
  - 应拆解并收敛为当前角色概览区中的快捷动作，或并入当前角色相关操作区

- 本地方案库
  - 账号页只保留当前角色直接相关的简化入口或状态摘要
  - 完整方案管理不应继续占据账号页主空间

- 最近活动
  - 本次账号页主结构中不再作为主区块出现
  - 若仍需保留，应后续评估是否移出账号页

## 7. 交互原则

### 7.1 主区优先

- 页面打开后，用户不需要先滚动，第一屏就能完成“看当前装备”和“看背包候选”的主要动作。
- 当前装备与当前角色背包应在视觉上属于同一块工作区，而不是两个相互无关的大卡片。

### 7.2 信息密度更像工具，不像文章

- 减少描述性长文案
- 增加稳定尺寸的物品网格、槽位和状态胶囊
- 用位置和密度表达优先级，而不是靠大段说明文字

### 7.3 低频信息保留但下沉

- 材料、货币、邮政官不能删除
- 但必须让出首屏主注意力给装备和背包

## 8. 加载、空状态与异常路径

### 8.1 加载中

- 页面标题区保留“读取中”反馈
- 主工作区应使用和当前仓库 / 每日面板一致的稳定骨架或加载占位
- 不允许加载状态导致布局跳动

### 8.2 空状态

- 当前角色背包为空时，显示明确空状态，不压缩装备区布局
- 材料、货币、邮政官缺数据时，各自独立显示空状态，不影响其他区块可用性

### 8.3 异常状态

- 账号数据读取失败时，在页面顶部保留统一错误反馈
- 写操作未开启时，在当前角色快捷动作附近提示，不再散落到多个无关区块

## 9. 测试与验收

### 9.1 自动化测试

至少补这些测试：

- 账号页布局测试
  - 验证当前装备与当前角色背包属于同一主工作区
  - 验证材料、货币、邮政官位于主工作区之后

- 现有账号页交互测试
  - 角色切换
  - 当前装备点击打开详情
  - 当前角色背包点击打开详情
  - 当前角色快捷动作仍可触发

### 9.2 真实 GUI 验收

重点按以下顺序验收：

1. 打开账号页后，是否第一眼就能看到当前装备和当前角色背包
2. 副本前想换装备时，是否比原来少滚动、少找区块
3. 材料、货币、邮政官是否仍然容易找到，但不再抢主注意力
4. 角色切换后，主区是否仍然稳定，不会因为内容多少剧烈跳动

## 10. 范围外事项

以下事项不在这次账号页重构内：

- 仓库页整体 DIM 化改造
- 全局拖拽搬运体验
- 完整配装优化器
- 跨角色全局 Inventory 工作台
- 活动复盘页重构

这些能力后续应在仓库页或其他专门工作区推进，不继续挤入账号页。

## 11. 实施方向摘要

实现阶段应优先做这些事：

1. 先重排账号页结构，确认主区和低频区骨架
2. 再把现有角色相关动作收敛到概览区
3. 再下沉材料、货币、邮政官
4. 最后清理仍残留的长信息流区块

这次改动的成功标准不是“更宽了”，而是账号页真正从长文档式页面变成单角色即时操作台。
