# 玩家使用指南

这份文档面向普通玩家，按真实使用顺序说明 d2-tools 怎么安装、登录和日常使用。

## 1. 安装与启动

1. 下载 Windows x64 安装器 `d2-tools-setup-<version>.exe`。
2. 运行安装器，选择安装位置。
3. 安装完成后启动 d2-tools。

d2-tools 不需要你手动安装 Node.js、Python 或 Docker。

## 2. 数据目录与升级

默认数据目录：

```text
%APPDATA%\d2-tools
```

这里会保存：

- Bungie 配置
- OAuth token
- 资料库缓存
- 仓库标签和备注
- DIM 愿望单导入
- 操作日志和诊断数据

安装或更新程序时，这些数据不会被自动删除。

## 3. 首次启动

首次打开时，你会先进入引导或配置状态。你至少需要完成两件事：

1. 填写 Bungie 配置
2. 登录 Bungie

更详细的 Bungie Application 创建步骤见 [Bungie 配置指南](bungie-setup.md)。

## 4. 登录 Bungie

填好 `API Key`、`Client ID` 和 `Client Secret` 后：

1. 点击“登录 Bungie”
2. 浏览器会打开 Bungie 授权页
3. 登录并授权
4. 浏览器回跳后，软件会保存 token

如果授权完成后软件仍然没有进入首页，先看 [常见问题](faq.md) 里的登录章节。

## 5. 初始化资料库

登录完成后，点击“初始化资料库”。

这一步会下载 Destiny 2 资料库，用于：

- 中文装备名搜索
- perk 搜索
- 来源摘要
- 资料库页查询

资料库可以重复更新，不会影响你的 Bungie 配置和本地标签。

## 6. 首页：今日 / 本周

首页主要用来快速看：

- 每日重置
- 每周重置
- 今日行动建议
- 本周重点
- 已接入并且可确认的数据来源状态

这里的原则很简单：只显示 Bungie API 或本地资料库能确认的内容。拿不准的数据会明确显示为空或未接入，不靠猜。

## 7. 账号页

账号页会自动读取当前 Bungie 账号数据，主要包括：

- 角色 tab 切换
- 当前光等
- 当前装备
- 角色背包（“其他”分类仅显示记忆水晶）
- 邮政官
- 材料与消耗品摘要

你可以在这里执行以下常用操作：

- 一键装备最高光等

“装备最高光等”会优先从当前角色、角色背包和仓库里找更高光等的装备，执行前会确认，不会直接分解装备。

## 8. 仓库页

仓库页是 d2-tools 目前最接近 DIM 日常使用体验的部分。

你可以在这里：

- 按武器、护甲、装备、其他查看仓库
- 按位置、弹药、护甲属性、锁定状态、本地标签筛选
- 给装备加本地标签：保留 / 关注 / 可清理
- 写本地备注
- 查看同名装备对比
- 复制清理清单
- 用清理模式把目标装备解锁并转移到角色背包

### 8.1 同名对比

“同名对比”模式适合处理：

- 同一把武器有多件不同 roll
- 同名装备分散在不同位置
- 想快速决定哪件留、哪件标成可清理

你可以：

- 选中一件作为基准
- 选择其余候选
- 选择可清理候选
- 直接点”保留这件，其余关注”
- 直接点”保留这件，其余可清理”

### 8.2 清理模式

清理模式不会直接分解装备。它只帮助你：

- 批量解锁
- 批量转移到角色背包
- 生成更容易在游戏里核对的定位信息

最终分解仍然需要你进入游戏手动完成。

### 8.3 推荐来源

装备详情和仓库匹配可以读取三类本地推荐来源：

- DIM Wishlist
- 自定义推荐规则
- 用户明确确认后保存的“我的推荐”

自定义推荐规则需要你明确导入。d2-tools 不默认内置未授权的第三方表格数据，也不会把这类本地文件描述成自动更新的社区榜单。
在装备 AI 分析中输入的新知识默认只对本次分析生效；只有在保存确认框中明确确认后，才会写入“我的推荐”。详情推荐和 AI 上下文不会为此自动读取社区网页。

在“设置 → 推荐来源”中管理 DIM Wishlist 或自定义推荐规则：

1. 点击“选择文件”导入 Wishlist、JSON 或 CSV；只有需要时才展开“粘贴文本”。
2. 核对待启用预览中的表名、规则数和 PVE / PVP / 通用模式覆盖。
3. 点击“启用这份数据”。保存完成后，当前账号的社区匹配会立即重新计算。

移除已启用的来源需要再次确认。仓库“目标与推荐”只显示当前账号的真实命中结果和紧凑来源状态，不再承载低频导入表单。

JSON 格式示例：

```json
{
  "title": "中文社区推荐",
  "rules": [
    {
      "item_hash": 123,
      "perk_hashes": [11, 22],
      "mode": "pve",
      "note": "清怪组合",
      "source_label": "自定义推荐规则"
    }
  ]
}
```

CSV 格式示例：

```csv
title:中文社区推荐
item_hash,perk_hashes,mode,note,source_label
123,"11,22",pve,清怪组合,自定义推荐规则
456,33|44,pvp,对战组合,自定义推荐规则
```

字段说明：

- `item_hash`：武器 hash。
- `perk_hashes`：推荐 perk hash 列表，JSON 用数组，CSV 可用逗号、竖线、分号或加号分隔。
- `mode`：`pve`、`pvp` 或 `general`。
- `note`：这组推荐的简短说明。
- `source_label`：详情页显示的来源名称；不填时显示“自定义推荐规则”。

### 8.4 装备目标

仓库“目标与推荐”中的装备目标用于保存长期想刷取或想保留的武器与护甲条件。新建目标会写入独立目标库；旧本地目标规则和 DIM Wishlist 在你明确保存或清空对应来源时单向同步，不会覆盖用户目标、攻略目标或 Armor Planner 目标。

武器目标按具体 Manifest 版本和 Perk 归属校验。发现多个同名版本时会保持待确认，不会自动选择；未通过校验的目标不参与仓库或详情命中。护甲待刷目标保存属性、职业和槽位等抽象条件，不会伪造装备 Hash 或实例 ID。Armor Planner 派生的缺口使用单件基础属性门槛进行提示，并保留框架、第三属性、调整、套装和大师杰作上下文；属性命中不代表完整身份已经满足，仍需回到 Planner 复核。

目标命中只在仓库筛选、同名整理和装备详情中提供证据，不会自动收藏、加标签、锁定、转移或改变整理决定。独立装备目标库已包含在设置页创建的便携备份中。

攻略派生的目标行可以选择“返回攻略”；Armor Planner 缺口目标可以选择“查看 Planner 引用”。前者只在派生关系仍有效时打开具体攻略，攻略已删除时目标仍可继续使用但不会假装定位成功。后者会带着稳定的结果 ID 和候选 ID 进入配装页，完整求解结果并未持久化，因此只能用于核对来源并按当前账号、Manifest 和规则重新计算。

## 9. 资料库页

资料库页用于查资料，不直接读取你的仓库内容。

你可以：

- 搜索装备中文名
- 搜索装备英文名
- 搜索 perk
- 保存常用别名
- 看来源、基础说明和 perk 关联信息

它更像“本地 Destiny 资料查询”，不是仓库页的替代品。

## 10. 攻略页

攻略页用于把粘贴文本、个人笔记或带来源地址的攻略正文保存在本机，方便长期搜索和整理。

1. 选择“新建攻略”。
2. 填写标题、分类和可选标签。
3. 选择来源类型。选择“来源链接”时必须填写有效的 HTTP(S) 地址，也可以记录作者或站点名称。Desktop 可以选择“读取链接正文”，先检查最终地址、正文分段、大小、警告和预览，再决定是否采用为当前草稿正文。
4. 保存后，从左侧按使用中、已归档、收藏或分类筛选，也可以在中间搜索标题、分类、标签、来源和当前正文。

编辑攻略时，标题、分类、标签、收藏、归档和来源信息只更新文档元数据；正文内容发生变化时会创建新的不可变快照。采用链接预览只修改当前草稿，必须继续选择“保存攻略”才会写入本机。预览区最多显示前 4000 个字符，但选择采用时会使用本次读取到的完整正文；若读取本身触发 20 万字符上限，来源说明会明确提示。应用不会执行页面脚本，也不会绕过登录、验证码或付费墙；Web 预览不读取远程正文。

阅读区可以选择“提取要求”。应用会从当前正文生成职业、子职业、异域护甲、武器、护甲属性、模组、星相和碎片候选，并显示置信度和原文行引用。逐项复选后选择“确认所选候选”只保存确认；确认后可以另行选择“同步已确认武器”。只有具体武器名称能唯一对应一个 Manifest 版本，且每个攻略 Perk 在该武器定义内也唯一时才会写入正式目标库；武器类型、元素、用途、同名多版本和多 Perk 定义只显示问题，不会自动选择。正文变化后需要针对新快照重新提取和确认。

确认结果包含护甲属性或异域护甲时，阅读区会生成独立的“Armor 约束草稿”。这里的属性是五件护甲聚合目标，不是单件掉落门槛；选择“送到配装工作台审阅”会创建未保存的本地方案草稿，并保留攻略文档、正文快照、提取和约束成果引用。职业、模组预算、异域实例、套装和位置范围仍需在配装页复核，应用不会自动运行 Armor Planner 或保存方案。

确认后还可以选择“生成配装候选”。Desktop 会刷新当前账号，按已选角色核对已确认的武器和异域护甲要求，并生成绑定账号指纹的 `loadout_candidates`。唯一完整命中的实例默认选中；同名多实例、抽象要求和只满足部分 Perk 的装备只作为替代候选。选择“交给配装页审阅”后仍需逐项复选，缺口和待确认项会保留在方案说明中；账号不一致或已选实例从当前快照消失时会阻止生成草稿并要求重新匹配。

阅读区还会显示当前正文、最近更新时间、历史快照摘要，以及“派生成果与追溯”。后者只保存稳定关系和标识，用于查看这篇攻略已经生成的正式装备目标、Armor 约束、账号配装候选，以及从 Armor 约束或账号候选显式保存的本地方案，不复制账号快照或完整成果正文。正式装备目标会打开仓库“推荐数据”并定位到具体目标行；已保存本地方案会打开配装页的具体方案。

归档会把文档移出“使用中”，之后可以在“已归档”中恢复。删除会永久移除本地文档、提取确认和对应派生关系；已经保存的装备目标或本地方案仍作为独立业务对象保留。攻略正文、提取确认和派生关系已包含在设置页创建的便携备份中。

## 11. 配装页攻略导入

在配装页切换到“本地配装方案”，从创建菜单打开“从攻略生成草稿”。粘贴攻略或配装说明后选择“解析并预填”，应用会依次完成解析、账号对照和草稿生成；确认结果后再显式保存本地方案。

- 解析攻略：把职业、子职业、异域、武器、perk、属性和模组拆成结构化要求。
- 对照账号：只根据当前账号、仓库、目标规则、资料库和已导入推荐判断，不猜测未接入数据。
- 生成草稿：把已拥有装备生成可保存配装草稿，把缺口保留为清单。
- 保存草稿：写入本地方案；装备、转移或游戏内写操作仍需要你在界面里确认。

如果某个要求无法确认，配装草稿会放进“待确认”，不会当成事实。护甲属性按五件护甲的聚合目标进入 Armor Planner；旧六维名称、同名武器或异域多实例都需要人工复核。攻略页交接的账号候选会先显示确定命中、替代项和缺口，只有勾选项进入未保存草稿。旧版本侧栏任务入口保存过文本时，这里会自动恢复；只有成功生成草稿后才清除旧副本。

接受库存或升级候选后，本地方案会保存护甲结果引用、规则版本和来源版本。结果缓存过期时仍保留已经选择的真实实例，但再次调整护甲候选前需要重新计算。待刷模式的候选如果包含缺口，可以选择“保存待刷缺口”写入独立装备目标库；重复保存同一结果候选不会创建重复目标。

从攻略候选或攻略 Armor 约束形成的本地方案会在摘要区显示来源，并可选择“返回原攻略”。这个入口通过派生关系索引定位具体文档，不从方案说明文本中猜测 ID；攻略被删除后方案仍可编辑和使用，但会明确提示来源关系已失效。装备目标带回的 Armor 结果引用只显示稳定结果 ID 和候选 ID，不能恢复未持久化的完整旧候选，必须按当前账号和规则重新计算。

本地方案中的每个装备目标都绑定当前账号真实实例后，可以在“方案应用”区域复制 DIM 链接。导出会再次核对实例 ID、装备 Hash 和目标 Plug 的插槽位置；理论上限、待刷目标、缺失实例或无法定位的 Plug 会直接显示阻断原因，不会生成伪完整链接。子职业技能、星相和碎片只有在保留原始插槽索引时才能完整交接，当前缺少索引的配置会在导出区明确提示。

应用本地方案时，确认后会先刷新账号并重新核对完整步骤。如果装备位置、实例、目标角色、可写 Plug 或方案缺口已经变化，应用会在任何写操作发生前停止，并要求根据最新账号状态重新确认。

开始执行后，每个转移、装备和 Plug 步骤会记录同一组计划、确认和执行引用。需要排查部分成功或失败时，可以在“设置 -> 诊断与操作日志”中查看执行引用，失败项还可以复制包含完整关联 ID 的脱敏诊断。

执行结束后会额外保存一条“执行验证”记录，结果分为通过、部分完成、不一致和不可用。它和逐步日志使用同一个执行引用，可以用来确认 Bungie 接口成功后账号状态是否也已实际更新。

## 12. AI 助手

AI 助手采用聊天框方式，而不是固定报告按钮。

它可以基于你当前已载入的数据回答问题，例如：

- 这周我优先该刷什么
- 我仓库里哪些装备疑似重复
- 哪些武器适合先保留
- 我现在最值得整理的部分是什么

当问题明确涉及装备定义、Perk、账号已拥有装备、当前商人库存、本地攻略、本地配装缺口或 Armor 3.0 护甲目标时，工作台会在发送给模型前自动运行对应的应用内只读能力。攻略搜索只发送命中的摘要、最多三个相关章节摘录、当前正文快照引用和已经人工确认的要求，不会把整篇攻略或未确认候选直接交给模型。每轮最多运行三项，不会执行转移、装备、锁定或其他写操作；回答底部的“数据引用”用于标识本轮真实读取结果及状态。

Armor 规划问题必须同时写明泰坦、猎人或术士，以及至少一个当前六维目标，例如“术士护甲生命值 100、手雷 100”。库存、理论和待刷问题会复用配装页同一套 Armor Planner。旧六维名称、缺少职业、缺少数值目标或升级基线不明确时不会自动求解，需要先在配装页确认。

商人能力读取当前已缓存库存，不会代替商人页的手动刷新。能力没有命中、账号未登录、库存不可用或结果不完整时，助手应明确说明限制，不能把缺失数据补成事实。

每次成功问答都会创建一个轻量上下文快照，记录页面和账号范围、Manifest 版本、能力结果引用及实际提示内容指纹，不重复保存完整账号装备正文。恢复历史会话时，如果当前数据已经变化，顶部上下文入口会显示“已恢复历史快照”；继续提问会携带有限的历史对话，并基于当前数据创建新快照。失败的请求不会写入会话历史。

应用会在本机保留最近 100 条 AI 只读能力审计，只记录能力名、脱敏查询摘要、结果 ID、状态、耗时、警告码和证据 ID。设置页的“复制脱敏诊断导出”会附带最近的能力审计，不包含完整 AI 提示、账号装备正文、Token 或 API Key。

明确询问配装、构筑或攻略整理时，成功回答下方会出现“配装草稿”。选择“交给配装页”只会打开配装页的攻略文本面板，并带入 AI 目标、整理结果、上下文快照和数据结果引用；仍需选择角色、执行解析与账号核对，然后显式保存本地方案。AI 工作台不会直接创建方案或执行装备操作。

Armor 规划返回候选时会显示“护甲方案对比”，标明模式和达标候选数量。交给配装页后只预填原始职业与六维目标，候选最终属性不会变成新的目标；底层规划结果会作为证据保留，仍需重新检查模组预算、套装、位置范围和实例选择。

明确要求把某件装备加入配装、作为目标或准备刷取时，成功回答下方会显示“装备目标候选”。交给配装页后先逐项复选：账号中已有的候选会绑定真实实例，只有资料库定义的候选会保留为待获取目标。确认只生成未保存草稿，不会自动保存、转移或装备。

支持的模型接口：

- OpenAI Responses
- OpenAI Chat Completions
- Anthropic Messages

如果没配置 AI，页面会提示你先去设置页完成配置。

## 13. 设置页

设置页主要管理：

- Bungie 配置
- AI 配置
- 本地数据目录状态
- 写操作开关
- 操作日志与诊断信息

如果你只是浏览账号和仓库，不需要开启写操作。

## 14. 写操作边界

写操作包括：

- 锁定 / 解锁
- 装备到角色
- 从仓库取出到角色
- 从角色移入仓库
- 一键装备最高光等

写操作默认关闭。即使开启，也仍然需要 Bungie Scope 和确认流程。

d2-tools 不支持直接分解装备。

## 15. 常见日常流程

### 15.1 初次跑起来

1. 配置 Bungie
2. 登录 Bungie
3. 初始化资料库
4. 自动读取账号
5. 进入仓库页开始整理

### 15.2 清理仓库

1. 进入仓库页
2. 用同名对比查看重复组
3. 保留一件，其他标成关注或可清理
4. 进入清理模式
5. 批量解锁并转移到角色背包
6. 进游戏按清单手动分解

### 15.3 冲最高光等

1. 进入账号页
2. 选择角色
3. 点击“装备最高光等”
4. 确认操作

### 15.4 让 AI 帮你分析

1. 先在设置页完成 AI 配置
2. 读取账号和仓库数据
3. 打开 AI 助手
4. 直接输入你的问题
